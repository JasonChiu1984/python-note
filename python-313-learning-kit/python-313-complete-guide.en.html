Part I | Core syntax and the standard library

C01 | Understanding code blocks and names

This section covers core syntax available in Python 3.13. match, dataclass, TaskGroup, and type parameter syntax were introduced in 3.10, 3.7, 3.11, and 3.12, respectively. Start with data and control flow, then learn functions and objects before moving on to exceptions, types, modules, and asynchronous code.

Python uses indentation to delimit blocks. The headers of statements such as if, for, def, and class end with a colon, and their bodies are indented one level further. Engineering projects typically use four spaces per level. Four spaces is a style convention; the actual syntax requirement is consistent block indentation. Do not mix tabs and spaces. Lines can break naturally inside parentheses, which is usually easier to maintain than trailing backslashes.

supply_c = 7.2
return_c = 12.1

if return_c - supply_c >= 4.0:
    message = (
        "冰水溫差符合本次範例條件："
        f"{return_c - supply_c:.1f} °C"
    )
    print(message)

Names are case-sensitive: pump_id and Pump_ID are different names. Names cannot begin with a digit. Python allows certain Unicode characters in identifiers, but mixing look-alike characters makes review more difficult. Use consistent naming conventions for equipment identifiers and function names. # begins an inline comment. The first string in a function, class, or module can serve as a docstring, accessible to help() and other tools. A triple-quoted string is not, in itself, general comment syntax.

Reserved words such as class, return, and None cannot be used as ordinary variable names. A soft keyword has syntactic meaning only in specific contexts, as in the relevant uses of match, case, _, and type. Query the current interpreter directly for the complete list to avoid mixing lists from different versions. Built-in names such as list and str are not reserved words, but you should avoid shadowing them with variables of the same name.

import keyword

print(keyword.iskeyword("class"))       # True
print(keyword.issoftkeyword("match"))   # True
print(keyword.kwlist)
print(keyword.softkwlist)

Official sources: Lexical analysis, keyword.

C02 | Numbers, strings, f-strings, and bytes

int is suitable for counts, addresses, and bitmasks. Its size is limited by available memory, with no fixed 32-bit or 64-bit upper bound. float is suitable for general calculations involving continuous quantities, but uses binary floating-point representation, so some decimal fractions cannot be stored exactly. complex represents complex numbers. bool represents truth values. Although it inherits from an integer type, data validation should still explicitly distinguish numerical readings from on/off states.

import math
from decimal import Decimal

raw_count = 12_500
register = 0x20
ratio = 3 / 2                 # 1.5
whole = -3 // 2               # -2，向負無限大取整
close = math.isclose(0.1 + 0.2, 0.3)
bill = Decimal("0.1") + Decimal("0.2")

Decimal("0.1") constructs an exact decimal from decimal text. Passing a float to Decimal preserves the approximation already present in that float. Choose relative and absolute tolerances appropriate for the problem, especially close to zero. round() rounds a value, while f"{value:.1f}" controls its display without changing the original reading.

str stores text. Single and double quotes work the same way for basic string literals. Escape sequences such as \n and \t represent special characters. Raw strings such as r"C:\logs\ahu" reduce escaping, but cannot end in an odd number of backslashes. Strings are immutable, so methods such as replace() and strip() return a string result. Indexing works on Unicode code points. One visible glyph can span several code points.

point = "T10"
value = 24.375
label = f"{point}: {value:.1f} °C"   # T10: 24.4 °C
debug = f"{point=}, {value=}"       # 顯示名稱與值
literal = f"{{point}} = {point}"   # 雙大括號表示文字大括號

payload = "送風溫度".encode("utf-8")
text = payload.decode("utf-8")
frame = bytes([1, 3, 0, 32])
first_byte = frame[0]              # 1，索引結果是整數

bytes is an immutable sequence of bytes. bytearray is mutable. Choose an encoding when converting between text and bytes. Decode only the text fields of a binary packet with decode(). For multi-byte integers, check byte order, signedness, and field length. One example is int.from_bytes(frame[2:4], "big").

C03 | Name binding, mutability, and copying

a = b binds the name a to the object referenced by b; it does not copy the data. Arguments received by a function also involve object references: the caller sees changes made to a shared list, but rebinding a parameter inside the function to another list does not reassign the caller's variable. Distinguishing changes to an object from changes to a name is more accurate than memorizing labels such as pass-by-value or pass-by-reference.

from copy import deepcopy

original = {"AHU01": {"setpoint": 24.0}}
alias = original
shallow = original.copy()
deep = deepcopy(original)

original["AHU01"]["setpoint"] = 25.0
print(alias["AHU01"]["setpoint"])    # 25.0
print(shallow["AHU01"]["setpoint"])  # 25.0
print(deep["AHU01"]["setpoint"])     # 24.0

A shallow copy creates a new outer container, but nested objects inside it may still be shared. A deep copy recursively copies content that can be copied, with different costs and semantics. External resources such as connections and files cannot be copied arbitrarily like ordinary data. When creating a configuration snapshot, first decide which fields need to be independent, then choose a copying strategy.

list, dict, and set are generally mutable; numbers, str, bytes, and tuple are generally immutable. However, a tuple's immutability restricts only its element references; it does not freeze lists inside it. The list in ([1],) still supports append(). == compares values, while is checks whether two references identify the same object. Use value is None to check for a missing value, and do not rely on incidental results from small-integer caching or string interning.

Another common pitfall is rows = [[0] * 3] * 2: both rows point to the same inner list. Use [[0] * 3 for _ in range(2)] to create independent rows in two-dimensional data. del name removes a name binding; it does not remove every other name referencing that object, nor does it guarantee that external resources are closed immediately.

Official sources: Object data model, Shallow and deep copying.

C04 | Operators and precedence at a glance

An operator's behavior depends on the object types involved. For example, + can add numbers or concatenate strings, while | can perform integer bitwise operations, set unions, or dictionary merges. Identify the operands before interpreting the symbol.

Matrix multiplication @ Provided by types that support this protocol; ordinary numbers and lists do not directly provide matrix operations
Comparison == != < <= > >= 0 <= valve <= 100 is a valid chained comparison
Logical and or not Uses short-circuit evaluation; and and or can return operands and are not guaranteed to return bool
Membership in、not in "T10" in readings tests dictionary keys.

-2**2 is equivalent to -(2**2) and produces -4. 2**-2 allows a negative exponent on the right and produces 0.25. For compound bitwise conditions, write (status & 0b1000) != 0 so reviewers can immediately see the scope of the mask. = belongs to assignment statement syntax; it is not part of the expression precedence hierarchy above.

status = 0b1010
fan_proven = (status & 0b0010) != 0
has_alarm = (status & 0b1000) != 0
state = "異常" if has_alarm else "正常"

reading = 0.0
wrong_default = reading or 24.0          # 得到 24.0，吞掉有效零值
safe_default = 24.0 if reading is None else reading

C05 | Containers, slicing, unpacking, and comprehensions

Container Typical data Key behavior
list Temperatures in chronological order Ordered and mutable; may contain duplicate values
tuple One (point, value) record Ordered, with immutable element references; a single element requires a comma: (7.2,)
dict Measurement point names mapped to readings Lookup by key; preserves insertion order; keys must be hashable
set The set of devices offline in the current cycle Unique elements; do not rely on iteration order
frozenset An immutable set of measurement points Cannot be modified; suitable when a hashable set is required

An empty dictionary is {}; an empty set is set(). When a dictionary key is missing, d[key] raises KeyError. d.get(key) can return a default value, but distinguish a missing key from a key that exists with the value None. Mutating methods such as list.append() and list.sort() usually return None. Do not write values = values.sort().

values = [23.5, 24.0, 24.5, 25.0]
latest = values[-1]
recent = values[-2:]              # [24.5, 25.0]
alternate = values[::2]           # [23.5, 24.5]
reversed_values = values[::-1]
first, *middle, last = values

points = ["T10", "T11", "T12", "T13"]
readings = dict(zip(points, values, strict=True))
hot = {point: value for point, value in readings.items() if value >= 24.5}
rounded = [round(value, 1) for value in values]
unique_values = {value for value in values}

Slicing uses start:stop:step, and stop is excluded from the result. Ordinary sequence slicing allows ranges that extend beyond the bounds, but direct indexing can still raise IndexError. The step cannot be zero. For a list, a[:] makes a shallow copy and does not copy nested contents. During unpacking, a starred target receives the remaining items as a list. Without a starred target, the number of items on each side must match.

[*old, new] unpacks an iterable. {**defaults, **overrides} merges mappings, with later keys overwriting earlier keys of the same name. By contrast, **kwargs in a function call does not allow a value for the same parameter to be supplied twice. Comprehensions are suitable for clear transformations and filtering. When there are two or three nested levels with side effects, an ordinary loop is easier to debug. (x * 2 for x in values) is a lazy generator expression; it does not immediately construct a complete list.

Official sources: Data structures, zip and built-in functions.

C06 | if, match, loops, and loop else clauses

if checks conditions from top to bottom and executes only the first matching branch. Empty containers, zero, None, and similar values are generally treated as false, but a missing value and a valid zero often have different meanings in the application. For monitoring data, handle missing values before comparing upper and lower limits. For floating-point data that may contain NaN, explicitly decide how to handle invalid values as well.

def classify_temperature(value):
    if value is None:
        return "missing"
    elif value >= 28.0:
        return "high"
    else:
        return "normal"

match performs structural pattern matching. It can examine dictionaries, sequences, literals, and type structures; it is more than shorthand for a multi-branch if. A guard is an additional condition checked after a pattern matches. An ordinary bare name in a pattern usually captures a variable rather than reading an existing constant. To match a constant, use a literal or an attribute with a qualified name. _ means that portion is not captured.

def describe_event(event):
    match event:
        case {"kind": "temperature", "value": float(value)} if value >= 28:
            return f"高溫 {value:.1f} °C"
        case {"kind": "offline", "device": device}:
            return f"{device} 離線"
        case _:
            return "其他事件"

Here, float(value) is a class pattern that matches a floating-point object and captures its value; it does not apply a float() conversion to a string. Dictionary patterns allow extra keys by default. If unknown fields must be rejected, validate them separately. A pattern also does not automatically guarantee that a number falls within the engineering measurement range.

for retrieves items from an iterable one at a time; range(3) produces 0、1、2. Use enumerate() when you need an index and zip() to traverse data in parallel. Consider strict=True when both inputs should have the same length. while checks its condition at the start of each iteration. break exits the innermost loop, continue advances to the next iteration, and pass is a placeholder statement that performs no operation.

readings = {"T10": 24.0, "T11": 25.5}
for point, value in readings.items():
    if value > 28.0:
        print("第一個高溫點", point)
        break
else:
    print("本輪沒有找到高溫點")

A loop's else clause runs when iteration is exhausted normally or the condition becomes false. break skips it. It does not mean that the if condition failed on the final iteration. Leaving through return or an exception also prevents execution from reaching this else clause. Adding or deleting dictionary keys during iteration is error-prone; first build a list of keys to delete or create a new filtered result.

Official sources: Control flow tutorial, Compound statements and pattern matching.

C07 | Function parameters: positional, keyword, and variadic arguments

Functions transform inputs into outputs so that reading parsing, unit conversion, and status evaluation can each be verified independently. return exits a function immediately. Without an explicit return value, the result is None. return value, quality returns one tuple; it does not create two independent output channels. Defining a function also creates an object, so functions can be passed as arguments, returned, or stored in containers.

def summarize(device, /, offset=0.0, *samples, unit="°C", **metadata):
    """回傳指定設備的平均讀值摘要。"""
    if not samples:
        raise ValueError("至少需要一筆讀值")
    mean = sum(samples) / len(samples) + offset
    return {"device": device, "mean": mean, "unit": unit, "metadata": metadata}

summary = summarize("AHU01", 0.2, 24.0, 26.0, unit="°C", floor=3)
Parameter position Example Calling rule
Before / device Must be supplied by position
After / and before * offset May be supplied by position or keyword
*samples Multiple readings Collects the remaining positional arguments into a tuple
After *samples or a bare * unit Must be supplied by keyword
**metadata Additional fields Collects the remaining keyword arguments into a dict

If you do not need to accept an arbitrary number of positional arguments, you can write def convert(raw, /, *, scale=0.1): .... When *samples is already present, do not add a separate bare *. At the call site, *values and **options unpack data. In a definition, the stars specify how arguments are collected or restricted. Understand these uses separately.

Ordinary default values are evaluated when def executes to create the function, not recreated for each call. def collect(value, history=[]): ... causes multiple calls to share the same list. Usually, change this to history=None and create a new list inside the function. If None is itself a valid input that must be distinguished, create a unique sentinel object.

def collect(value, history=None):
    if history is None:
        history = []
    history.append(value)
    return history

ranked = sorted([("T10", 25.0), ("T11", 23.0)], key=lambda item: item[1])

lambda creates an anonymous function containing a single expression, suitable for a short sort key. For work involving multiple validation steps, retries, or side effects, use a named def with a docstring. Function parameter annotations do not automatically convert strings to numbers or reject incorrect types; responsibility for validation must still be assigned explicitly.

Official sources: Functions and special parameters, Function definitions.

C08 | LEGB, closures, and decorators

LEGB is a useful starting point for understanding name lookup in ordinary functions: Local is the current function, Enclosing is an outer function, Global is the containing module, and Builtins contains built-in names. If a function contains an assignment to a name, that name is generally treated as local. Reading it before assignment may raise UnboundLocalError. if and ordinary for blocks do not create a separate local scope as functions do.

global makes assignments affect a module-level name; it does not declare a global variable shared by the entire application. nonlocal lets an inner function rebind an existing name in the nearest enclosing function scope where it is bound. Modifying the contents of an outer list differs from rebinding the outer name; the former does not necessarily require nonlocal. Classes and type parameters have additional scope rules. To access an instance attribute inside a method, write self.name. Do not treat the class body as an ordinary enclosing function.

def make_counter():
    count = 0
    def increment():
        nonlocal count
        count += 1
        return count
    return increment

counter = make_counter()
print(counter(), counter())   # 1 2

A closure preserves access to names in an enclosing scope; it does not automatically capture their values at the moment it is created. If multiple lambda: i functions are created in a loop, later calls usually read the same final value. To preserve the data at that moment, use a factory function or capture the current value in a default parameter, as in lambda i=i: i. When reading closure state, also consider whether other calls may have modified it.

A decorator takes a function or class and returns a replacement object. Placing @audit above a function is roughly equivalent to executing fn = audit(fn) after the definition. Multiple decorators are applied starting with the one closest to the function. Use functools.wraps to preserve information such as the name and docstring, which helps with tracing behavior and generating documentation.

from functools import wraps

def audit(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):
        result = fn(*args, **kwargs)
        return {"operation": fn.__name__, "result": result}
    return wrapper

@audit
def normalize(raw):
    return raw / 10.0

print(normalize(245))  # {'operation': 'normalize', 'result': 24.5}

This decorator deliberately changes the return format, so callers must understand the new contract. When using decorators in engineering programs, check whether they change exceptions, return types, or when calls occur. Examining only the wrapped function body is insufficient.

Official sources: Execution and name resolution model, functools.wraps.

C09 | class, dataclass, and object protocols

A class brings state and operations together in the same object. self is the conventional name for the instance parameter. When obj.method() is called, the object becomes the method's first argument. __init__() initializes an instance that has already been created and cannot return another object. Class attributes are shared by instances. A separate list of readings for each device should generally be created in __init__().

from dataclasses import dataclass, field

@dataclass
class DeviceSnapshot:
    device: str
    temperature_c: float
    alarms: list[str] = field(default_factory=list)

    @property
    def temperature_f(self):
        return self.temperature_c * 9 / 5 + 32

    @classmethod
    def from_raw(cls, device, raw):
        return cls(device, raw / 10.0)

    @staticmethod
    def valid_name(name):
        return bool(name) and name.isascii()

dataclass can generate methods for initialization, representation, equality comparison, and other behavior from its fields. default_factory=list gives each instance its own list. frozen=True prevents ordinary field reassignment, but does not recursively freeze lists stored in fields. It is not an input validator either: a float annotation does not automatically reject strings. property gives computation or controlled access the appearance of an attribute. A read-only property has no setter, but other mutable fields can still be changed.

classmethod receives the class as cls and is suitable for an alternative construction entry point; when inherited, it can also create subclass instances. staticmethod receives no implicit self or cls and suits small utilities related to the class's concept that do not depend on instance state. If a utility is not closely related to the class, a module-level function is usually easier to discover.

class Sensor:
    def __init__(self, name):
        self.name = name

class CalibratedSensor(Sensor):
    def __init__(self, name, offset):
        super().__init__(name)
        self.offset = offset

super() calls the next implementation along the method resolution order. In multiple inheritance, it does not mean a fixed reference to one particular parent class. For cooperative multiple inheritance, method signatures and the use of super() must be coordinated. Ordinary composition relationships, such as a monitoring service having a sensor, can often be represented by one object holding another without immediately resorting to inheritance.

Special method Corresponding operation Design purpose
__repr__ repr(obj) Provide an identifiable diagnostic representation
__str__ str(obj) Text intended for readers
__len__ len(obj) Container length
__iter__、__next__ for、next() Iterable and iterator protocols
__getitem__ obj[key] Index or key access
__eq__、__hash__ Equality and hashing Maintain consistency when designing objects to use as keys
__enter__、__exit__ with Resource acquisition and release
__call__ obj(...) Make instances callable

These methods form object protocols that integrate custom types with Python syntax. Do not add every operator to an equipment object simply because you can. If a mutable object is used as a dictionary key, also ensure that the basis for its equality or hash does not change while it is stored there.

C10 | Iterators, yield, and yield from

An iterable is an object that can provide an iterator. An iterator tracks its current position and can be advanced with next(). iter(values) obtains an iterator, which raises StopIteration when exhausted. A list can provide new iterators repeatedly, whereas a particular generator can generally be traversed only once. After it is passed to sum(), a later traversal may have no data left.

def valid_values(rows):
    for row in rows:
        value = row.get("value")
        if value is not None:
            yield float(value)

rows = [{"value": "24.1"}, {"value": None}, {"value": "25.3"}]
stream = valid_values(rows)
print(next(stream))       # 24.1
print(list(stream))       # [25.3]
print(list(stream))       # []

When a function contains yield, calling it returns a generator; the function body does not advance until iteration begins. Each yield pauses execution and preserves local state, which is useful for parsing trend files one record at a time. This does not mean each record is necessarily read from hardware in real time; the function body still determines the actual data source. A generator may also raise a conversion exception only when a particular record is consumed.

yield from iterable delegates iteration to another iterable. In addition to forwarding values one by one, it supports send(), throw(), closing, and return-value propagation between generators. For basic data streams, start by understanding delegation of individual items.

def merge_batches(batches):
    for batch in batches:
        yield from batch

print(list(merge_batches([[24.0, 25.0], [26.0]])))

Lazy processing can reduce intermediate containers, but not every source automatically saves memory. If an earlier step has already loaded the entire file into a list, wrapping later processing in a generator does not remove that earlier allocation. itertools.islice(), chain(), and pairwise() support slicing a stream, chaining streams, and calculating differences between adjacent items. Steps that require sorting usually need to collect the relevant data first.

Official sources: Iterators and generators, yield expressions, itertools.

C11 | Exceptions, exception chaining, and ExceptionGroup

Exceptions separate normal results from failure paths. A try block should cover only operations that may fail as expected and whose failures can be handled here. Catching exceptions around too much code can misclassify programming errors as input problems. Multiple except clauses are checked from top to bottom for a matching class; specific exceptions usually belong before general ones. If no suitable handler is found, the exception propagates outward through the call chain.

class InvalidReading(ValueError):
    pass

def parse_temperature(raw):
    try:
        value = float(raw)
    except (TypeError, ValueError) as exc:
        raise InvalidReading(f"無法解析溫度：{raw!r}") from exc
    else:
        return value
    finally:
        pass  # 若此函式取得資源，必要清理應明確放在這裡

Use else for work that should run only when try completes normally. Exceptions raised there are not caught by the preceding except clauses. finally runs on both normal and exceptional exit and is suitable for necessary cleanup. Do not use return inside it to override the original return value or exception. Abrupt process termination, power loss, and similar events are also outside the language's cleanup guarantees.

raise can re-raise the exception currently being handled, while raise NewError(...) from exc explicitly preserves the underlying cause. from None only suppresses the displayed exception chain; it does not fix the error. except Exception does not include every subclass of BaseException. Interrupts, exits, and cancellation have their own control-flow meanings and should not be swallowed indiscriminately. assert is suitable for checking invariants during development, but optimization options may remove it, so it cannot replace validation of external input.

failures = [ValueError("T10 格式錯誤"), TimeoutError("AHU02 逾時")]
try:
    raise ExceptionGroup("本輪採樣失敗", failures)
except* ValueError as group:
    print("資料格式失敗數", len(group.exceptions))
except* TimeoutError as group:
    print("逾時數", len(group.exceptions))

ExceptionGroup represents multiple failures, and except* handles them in groups according to the exceptions they contain, so more than one branch can run during a single handling operation. Unhandled portions still propagate outward. A single try cannot mix except and except*, and an except* block cannot contain return, break, or continue. Groups can be nested, so len(group.exceptions) counts only immediate children; it cannot always be treated as the total number of failures at the leaf nodes.

Official sources: Exceptions tutorial, Exception classes and chaining, except* rules.

C12 | with and contextmanager: expressing lifetimes in code structure

with describes entering and leaving a resource scope. Files, locks, and some connection objects support this protocol. Entry calls __enter__(). After successful entry, leaving the block calls __exit__() and passes it the exception information. Returning a truthy value from __exit__() can suppress an exception, so check whether a custom context manager swallows failures when reviewing it.

from contextlib import contextmanager
from pathlib import Path
from tempfile import TemporaryDirectory

@contextmanager
def temporary_output(directory):
    with TemporaryDirectory(dir=directory) as owned_dir:
        yield Path(owned_dir) / "snapshot.tmp"

TemporaryDirectory first creates a directory dedicated to the current task and, on exit, cleans up only resources within that directory. Cleanup responsibility should follow how resources are created and owned.

A generator wrapped with @contextmanager should yield exactly once. Prepare resources before yield; the yielded value is bound to the name after as, and execution resumes with cleanup after the block is exited. If the block raises an exception, that exception reappears at the generator's yield point. If you intend only to log the exception without swallowing it, use raise again after handling it.

Expressing a resource's lifetime with with makes it harder for callers to forget to close it. Multiple context managers can appear in a single with, and they exit in the reverse order of entry. If entering the second resource fails, the first, which was entered successfully, can still exit. When the number of resources is dynamic, see contextlib.ExitStack instead of manually nesting multiple try/finally blocks.

Official sources: contextlib, The with statement.

C13 | typing: making data contracts explicit

Type annotations help readers, editors, and static checking tools. Python does not enforce runtime data validation merely because annotations are present. list[float] describes the element type, while float | None allows a missing value. Allowing None and allowing an argument to be omitted from a call are different things; the latter still requires a default value.

from collections.abc import Sequence
from typing import Protocol, TypedDict

type PointMap = dict[str, float]

def first[T](items: Sequence[T]) -> T:
    if not items:
        raise ValueError("序列不可為空")
    return items[0]

class SampleBox[T]:
    def __init__(self, value: T):
        self.value = value

class Reader(Protocol):
    def read(self, point: str) -> float: ...

class Reading(TypedDict):
    point: str
    value: float
    quality: str

type PointMap = ... is a type alias. T preserves the relationship between input and output types; for example, first() returns the element type of its input sequence. Generics describe relationships; they do not mean Python automatically generates specialized machine code for each type. An alias also does not create a new runtime numeric type, and a type alias cannot simply be used as an ordinary class argument to isinstance().

Protocol describes which members an object must provide to work with other code. It is useful for separating monitoring logic from different communication implementations, and a class that satisfies the interface does not have to inherit from it explicitly. TypedDict describes dictionary fields, but remains an ordinary dict at runtime; it does not automatically check for missing keys, extra keys, or types. Validating external JSON still requires parsing and validation code.

Any allows dynamic operations through the type checker, reducing type guarantees. object indicates that the type is unknown, but supported operations must be established before use. For unknown external input, using object with isinstance() to narrow the type generally preserves more of the value of type checking. isinstance(value, (int, float)) also accepts bool. If the application's rules do not accept Boolean values as numbers, exclude them explicitly.

Official sources: typing, Generics and type parameters.

C14 | Modules, import, entry points, and environment management

A .py file is usually a module. Modules divide a program by responsibility, such as parsing, calculation, reporting, and entry points. import math brings the module name into the current scope, whereas from math import isclose brings in the specified name. Ordinary importing executes a module's top-level statements and uses the module cache. The top level should therefore contain definitions and necessary initialization, without accidentally starting long-running data collection when the module is imported.

# 假設此檔名為 report_cli.py

def main() -> int:
    print("產生監控摘要")
    return 0

if __name__ == "__main__":
    raise SystemExit(main())

When a file is run directly, its entry module is named __main__. python -m package.module launches it as a module, which is usually better suited to relative imports within a package. Avoid naming your own files after common standard library modules, such as json.py or typing.py, because the search path may find your file first. from module import * makes the origin of names unclear; explicit imports are usually preferable for maintenance.

A virtual environment isolates a project's packages; it is not a container or a mechanism for isolating permissions. It should generally be recreated on the target system from dependency declarations rather than moved as an entire directory. C15 | Files, JSON, and choosing standard library modules

Text files use str and binary files use bytes. Use "r" to read, "w" to write and truncate an existing file, or "a" to append. Adding "b" selects binary mode. Specify the encoding and expected file location. Use Path to compose paths and perform basic operations with the platform's path conventions.

import json
from pathlib import Path
from tempfile import TemporaryDirectory

snapshot = {"device": "AHU01", "temperature_c": 24.5, "online": True}
with TemporaryDirectory() as directory:
    path = Path(directory) / "snapshot.json"
    with path.open("w", encoding="utf-8") as file:
        json.dump(snapshot, file, ensure_ascii=False, indent=2, allow_nan=False)
    with path.open("r", encoding="utf-8") as file:
        restored = json.load(file)
    print(restored["temperature_c"])

dump/load work with file objects, while dumps/loads work with string data. ensure_ascii=False displays Chinese characters directly. allow_nan=False rejects nonstandard JSON representations of non-finite floating-point values. JSON object keys are strings, tuples usually become arrays, and datetime values, custom classes, and binary packets do not automatically retain their original types. Successfully parsing JSON only means the format can be read; fields, types, units, and measurement ranges still need separate validation.

C16 | async syntax and basic TaskGroup usage

Without yield, async def defines a coroutine function, and calling it produces a coroutine object. The work usually still needs to be started with await, scheduled as a task, or launched through asyncio.run() before it runs. await waits for an awaitable to complete and suits asynchronous operations that cooperate with the event loop. It does not automatically turn an ordinary blocking function into an asynchronous one.

import asyncio

async def read_simulated(point: str) -> tuple[str, float]:
    await asyncio.sleep(0)
    return point, 24.5

async def collect() -> dict[str, float]:
    async with asyncio.TaskGroup() as group:
        tasks = [
            group.create_task(read_simulated(point))
            for point in ("T10", "T11", "T12")
        ]
    return dict(task.result() for task in tasks)

# 在一般 Python 腳本入口執行：
# print(asyncio.run(collect()))

TaskGroup manages multiple tasks within a structured scope: it waits for the group's work to finish before leaving async with. When a task fails with an ordinary exception, the other unfinished tasks are canceled; the corresponding failures are collected and raised outward as an exception group. Exceptions such as interrupts and exits have specific handling rules. Callers should decide which failures are recoverable instead of merely converting every exception into an empty result.

async for works with asynchronous iterators and can wait each time it retrieves the next item. When it contains yield, async def creates an asynchronous generator. async with is used with context managers whose entry or exit itself requires waiting, corresponding to __aenter__() and __aexit__().

async def simulated_stream():
    for value in (24.0, 24.5, 25.0):
        await asyncio.sleep(0)
        yield value

async def summarize_stream():
    values = []
    async for value in simulated_stream():
        values.append(value)
    return sum(values) / len(values)

An ordinary script can call asyncio.run(main()) once at its entry point. In an environment that already has a running event loop, use that environment's top-level await or integration mechanism; you cannot arbitrarily nest asyncio.run() calls in the same thread. Cancellation is usually delivered at an await point. Cleanup can go in finally, and cancellation signals should not be swallowed unintentionally. Asynchronous syntax handles waiting and cooperation; choosing multiple cores, threads, or processes is a separate architectural decision.

Official sources: Coroutines and TaskGroup, Asynchronous statements, Asynchronous generators.

2. ReadOnly, TypeIs, and type defaults

ReadOnly describes write restrictions for a TypedDict key. NotRequired describes whether the key can be omitted. The qualifiers can be combined. TypeIs lets a checker narrow both branches, so implement the type predicate accurately. If your application distinguishes bool from int, validate this explicitly because the former subclasses the latter.

from typing import ReadOnly, TypedDict, TypeIs

class Point(TypedDict):
    name: ReadOnly[str]
    value: float

class Sample[T = float]:
    def __init__(self, value: T) -> None:
        self.value = value

def is_text(value: str | bytes) -> TypeIs[str]:
    return isinstance(value, str)

def to_text(value: str | bytes) -> str:
    return value if is_text(value) else value.decode("utf-8")

A type parameter default applies when an argument is omitted and no other type can be inferred. Explicit Sample[int] still selects integers. T = float has no runtime conversion effect. Use a compatible type checker to verify narrowing in both branches.

Queue backpressure and shutdown

  1. Producers write to a bounded Queue(maxsize=...). A full queue makes a blocking write wait. Set wait limits or a discard policy appropriate for the workload.
  2. Match each successful get() with one task_done() after processing, typically in finally.
  3. Stop accepting new work, then call shutdown(). Consumers drain the queue and handle queue.ShutDown or asyncio.QueueShutDown to exit when the queue is empty.
  4. join() waits for unfinished work to be acknowledged. With immediate=True, pending items can be drained without running. A returning join() can therefore include discarded items.
  5. queue.SimpleQueue has no shutdown(), task_done(), or capacity limit. It can carry a finite result set. For large streams, consume results continuously or choose a bounded channel.

Further practice: runnable example, field case and self-check

3.13 added two small but useful standard-library features: copy.replace() unifies "copy with some fields changed", and warnings.deprecated (PEP 702) makes a retired API warn at run time and get flagged by type checkers.

Runnable example：copy.replace() and warnings.deprecated

PointConfig is a frozen dataclass; copy.replace() returns a new object with a different scale and leaves the original untouched. With @deprecated, every call to read_point() emits a DeprecationWarning and type checkers flag the call site.

Download example extension-example-en.py

"""Python 3.13: copy.replace() for modified copies of immutable objects, warnings.deprecated for retiring APIs (needs 3.13+)."""
import copy
import warnings
from dataclasses import dataclass


@dataclass(frozen=True)
class PointConfig:
    name: str
    addr: int
    scale: float = 1.0


@warnings.deprecated("read_point() is deprecated; use read_points() for batch reads")
def read_point(cfg: PointConfig) -> float:
    return 225 * cfg.scale


def read_points(cfgs):
    return {c.name: 225 * c.scale for c in cfgs}


if __name__ == "__main__":
    sat = PointConfig("SAT", 0, 0.1)
    new = copy.replace(sat, scale=0.01)               # works for dataclasses, namedtuples, datetime, ...
    print("Original:", sat)
    print("Modified:", new, "; original unchanged:", sat.scale)
    with warnings.catch_warnings(record=True) as w:
        warnings.simplefilter("always")
        read_point(sat)
        print("Warning from the old API:", w[0].category.__name__, "-", w[0].message)
    print("New API:", read_points([sat, new]))

Field case：Changing one point's scale changed every point sharing its config

A program kept point settings in mutable objects. To try a new scale someone set cfg.scale directly, and every point referencing the same object changed with it; the reports were wrong for a whole day. With frozen dataclasses and copy.replace(), a change can only create a new object.

Another common problem is old APIs that can never be removed because nobody knows who still calls them. @deprecated makes callers see the warning immediately in tests (run with -W error::DeprecationWarning) and in the editor.

  1. Use frozen=True dataclasses for configuration objects.
  2. Create variants with copy.replace() instead of mutating the original.
  3. Mark functions being retired with @deprecated, naming the replacement and the removal version.
  4. Run CI tests with -W error::DeprecationWarning to find remaining callers.

Exercises and self-check

  1. Which types support copy.replace()?

    Show answer

    Any object implementing __replace__. In the standard library that includes dataclasses, namedtuples, datetime, date, time, SimpleNamespace and code objects. Custom classes gain support by defining __replace__.

  2. What does copy.replace(sat, unit="°C") do?

    Show answer

    It raises TypeError: a dataclass's __replace__ calls the constructor with the new arguments, and PointConfig has no unit field.

  3. Why does the example use catch_warnings(record=True) with simplefilter("always")?

    Show answer

    By default a DeprecationWarning is shown only when triggered from __main__, and only once per location. Recording with "always" makes the example capture and print the warning reliably.

  4. Why is the result of read_points {'SAT': 2.25}, with only one entry?

    Show answer

    Both configs are named SAT, so the second value (225 × 0.01 = 2.25) overwrites the first (22.5) under the same key. In practice point names must be unique; check this when loading configuration.
