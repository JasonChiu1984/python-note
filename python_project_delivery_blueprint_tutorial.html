Overview

適合已經看過多條 Python 工程教材，但開始卡在「每章都會，專案還是不好交」的人。這條路線用一個 reference project 把治理、可靠性、觀測、驗證與發布證據綁起來，讓你能從教學內容直接落到團隊交付。

Architecture

整合式專案的重點不是塞更多框架，而是明確切出輸入、核心、證據與操作邊界。

層級責任在範例中的對應
Input收集 operator config 與 device snapshot，避免髒資料直通核心ServiceConfig.from_mapping()、Snapshot
Core做 validation、idempotency、alarm、fail-safe 決策DeliveryCoordinator.run_cycle()
Evidence保留 health、event、release evidence，支援交接與稽核MemoryOutbox、build_release_evidence()
Verification讓交付不是口頭宣稱，而是可重跑的檢查unittest、smoke script、HTML parse

Configuration

參數必須可讀、可驗證、可預設，不要把 timeout、polling、alarm threshold 寫死在 service 裡。

設定用途失敗時策略
site_name標記交付對象與更新範圍空值直接拒絕啟動
poll_interval_seconds控制採集週期小於 1 秒視為配置錯誤
temperature_alarm_c定義告警門檻使用保守預設 45°C
max_batch_size控制單輪輸出量避免一次吞入過多資料

Flow

執行順序

  1. 載入設定並驗證。
  2. 讀取 snapshot，檢查資料是否重複。
  3. 判斷 alarm、健康狀態與 fail-safe 訊號。
  4. 寫入 outbox event 與 release evidence。
from project_delivery_blueprint.config import ServiceConfig
from project_delivery_blueprint.domain import Snapshot
from project_delivery_blueprint.service import DeliveryCoordinator, MemoryOutbox

config = ServiceConfig.from_mapping({
    "site_name": "plant-a",
    "poll_interval_seconds": "15",
    "temperature_alarm_c": "42.5",
    "max_batch_size": "4",
})
outbox = MemoryOutbox()
service = DeliveryCoordinator(config=config, outbox=outbox)
report = service.run_cycle([
    Snapshot(device_id="boiler-01", message_id="m-001", temperature_c=38.2, status="ok"),
    Snapshot(device_id="oven-02", message_id="m-002", temperature_c=47.1, status="warning"),
])
print(report.processed_count, report.alarm_count, outbox.events[0]["kind"])

Troubleshooting

整合式專案最常失敗在邊界不清楚，而不是 API 不會用。

問題原因處理方式
資料重複進入下游沒有 message id 去重在核心服務保留 processed id 集合
告警條件不一致門檻散落在多處集中放在 ServiceConfig
有 smoke，沒 release evidence只驗功能，沒輸出交付摘要固定產出 evidence dict 或 JSON
章節很多，但團隊仍不會交接少了 runbook 與責任邊界把 operator action 與 failure mode 寫入 README / 教材

Best Practices

這條路線的核心不是功能量，而是建立一個團隊可延伸的交付骨架。

先收斂責任

把 config、domain、service、evidence 分開，之後要換成 FastAPI、OPC UA 或實體 DB 時，邊界才不會崩。

先有驗收，再談擴充

每新增一條專題，都應同時有 smoke、測試與更新紀錄，不要只補教學頁面。

保留 fail-safe 思維

工業或資料同步場景，寧可降級、告警、停發，也不要在不確定時默默寫入錯誤結果。
