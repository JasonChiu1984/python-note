十種協定的優缺點與使用場景

協定優點限制使用場景
Modbus TCP／RTU設備支援廣，連續暫存器可批次讀取，RS-485 可共用既有配線。單位、比例、有號值及字序依設備點表。多站串行輪詢時，一站逾時會拖長整輪。變頻器頻率、電表功率、流量計瞬時量與累積量。既有 RTU 設備可用 TCP／RTU 閘道集中採集。
BACnet樓控物件可帶單位、品質與告警。支援的點可用 COV 推送變更，減少持續輪詢。裝置對 COV、批讀及分段的支援有差異。跨 VLAN 要處理探索、BBMD／路由，或規劃 SC Hub。AHU、DDC、冰水系統、BMS。以 EBO 聚合送風溫度、設備狀態、排程與告警。
OPC UA資料有型別、品質、時間戳及可瀏覽的結構，適合跨系統訂閱。須維護 NodeId 與憑證。大量訂閱需要伺服器資源，資料採樣與發布各有週期。PLC／工業閘道到 SCADA、Historian、MES。把溫度、設備狀態與品質一併提供給上位系統。
MQTT發布端和訂閱端可獨立部署，同一批遙測可被多個系統接收，支援 QoS 和會話設定。需要 broker 與 topic 規劃。資料格式、去重、逾期及業務確認由應用處理。各機房閘道上送遙測、跨站告警、能源資料與資料平台整合。
Zigbee低功耗，適合電池端裝置。具路由能力的節點可以延伸覆蓋。訊號受牆面、金屬櫃和同頻干擾影響。電池裝置會休眠，更新受回報條件與週期影響。既有空間加裝室溫、濕度、門磁或占用感測。透過協調器橋接到 MQTT。
PROFINET IO循環 I/O 更新可配置，有模組／通道診斷，RT 和 IRT 支援不同即時要求。設備、GSDML、組態工具及網路配置須相容。IRT 需要支援的硬體與拓樸。PLC 遠端 I/O、驅動器與機台控制。需要同步的多軸運動則核對 IRT 支援。
PROFIBUS DP成熟的主站循環 I/O，既有 DP 設備多，可直接讀站與模組診斷。RS-485 線長受速率限制，終端、接頭或站號配置錯誤可影響整段。既有產線的 DP 變頻器、ET 200 遠端 I/O 或控制設備保留與改造。
CC-LinkClassic 以位元和字交換循環 I/O，三菱 PLC 的 Link Refresh 便於映射到 CPU。須核對站種、占用站數與刷新區；Classic、IE Field Basic、IE Field 和 IE TSN 的設備與配置不同。三菱 PLC、遠端 I/O、變頻器。既有 Classic 用專用匯流排，乙太網路案依設備支援選 IE 版本。
EtherNet/IP使用標準 Ethernet 傳輸 CIP，結合循環 I/O 與非循環服務。依裝置與 Scanner 核對 RPI、通訊負載及支援的安全 Profile。PLC 與工業乙太網路 I/O、驅動、診斷。
EtherCAT同一幀交換多站過程資料，支援 Distributed Clocks 的裝置可同步。週期和整體延遲由主站、站數、資料量及 PLC 任務影響，並非固定值。多軸同步、快速遠端 I/O、量測。

線速是實體鏈路每秒可傳的位元數。更新週期是連續兩次取樣、輪詢或循環 I/O 之間的時間。端到端延遲從來源變化到 Python、SCADA 或 BMS 看見新值為止，還會受到 PLC 掃描、閘道、排隊、重送及上位系統刷新影響。

協定相對速度與比較條件驗收時量哪一段
PROFINET IO若需求是短週期且低抖動的控制 I/O，優先比較 RT／IRT。部分 RT 設備可配置至 250 µs，需核對控制器及裝置支援。實際 I/O 更新週期、最大抖動、watchdog 超時及故障恢復。
PROFIBUS DP專用主站可循環交換 I/O，適合有固定掃描預算的控制。站數、資料量和線速會改變週期，與 CC-Link 的快慢要按相同 I/O 負載實測。從站輸入變化到 PLC 程序映像更新及最壞循環時間。
CC-LinkClassic 與 IE 版本均有循環資料交換。Classic 的 link scan 與 PLC refresh 都影響速度。選 IE 版本時需分辨 IE Field Basic、IE Field 和 IE TSN。從遠端站變化到主站 RWr／RX，再到 PLC 刷新區的時間。
ModbusTCP 在同一區網讀單一連續點塊時，通常較低速 RTU 更快。若 TCP 之後仍要轉 RTU，多站串行掃描及逾時通常主導更新。同時記錄單次請求往返與全部站點掃描 P95／P99。
BACnetIP／SC 的 COV 可在變化後通知，免等下次輪詢。採輪詢時受排程與批讀影響，MS/TP 還要等 token。數值越過 COV 增量後到 BMS 入庫的時間，並比較批讀的整輪時間。
OPC UA在同一區網，訂閱速度主要看採樣及發布設定。例：100 ms 採樣加 500 ms 發布，兩層等待在理想無積壓時合計可接近 600 ms，另加來源及網路時間。來源變化到訂閱端接收的時間，核對伺服器實際採用的兩個週期。
MQTT同一區網且 Broker 無積壓時，立即發布可比等待固定掃描更早到達。跨站、重送與離線積壓會增加延遲。Publisher 到 Subscriber 的延遲，分開記錄固定發布週期及恢復後補送。
Zigbee電池感測器通常以事件或上報週期更新。即使無線封包很快到達，長上報週期仍會使溫度資料更新較慢。從感測器實際變化到 MQTT 橋接端的新鮮讀值，另記上報間隔與漏報。
EtherNet/IP循環 I/O 以 RPI 配置，Explicit 訊息不等同循環；RPI 不是端到端延遲保證。量 PLC 程式映像更新、最大循環間隔、連線逾時及恢復。
EtherCAT典型 100 Mbit/s 全雙工 EtherCAT 段；線速不是過程資料週期。量物理事件至控制程式／輸出、循環抖動與裝置同步誤差。

上位監控可用同一個來源變化、相同網段與相同點數，比對 Modbus TCP 輪詢、BACnet COV、OPC UA 訂閱與 MQTT 即時發布的端到端 P95／P99。比如 1 秒輪詢單是等待下次輪詢就可能接近 1 秒，COV 或立即發布則在各自條件成立後送出。

通訊速度、安全性與驗收

十個協定家族各列線速／更新、安全與驗收；窄畫面會依協定將三欄直向排列。看各協定詳細介紹。

協定線速、更新與延遲安全能力現場驗收
Modbus線速、更新與延遲RTU 常見 9,600／19,200 bit/s。TCP 使用乙太網路，更新取決於點塊、站數、設備回應與逾時設定。安全能力傳統 Modbus TCP／RTU 無原生驗證或加密。支援 Modbus Security 的 TCP 端點可用 TLS 與 X.509 憑證。傳統設備用 OT 分區及存取規則限制讀寫。現場驗收量測一整輪、單站逾時時的掃描，以及寫入是否被限制。
BACnet線速、更新與延遲MS/TP 常見設備檔位如 38.4／76.8 kbit/s，更新受 token 週期、站數與負載影響。IP／SC 仍要量測實際 COV 或批讀延遲。安全能力傳統 BACnet/IP、MS/TP 本身無加密。BACnet/SC 使用 TLS WebSocket 和憑證，跨入傳統 BACnet 分段後依該段的能力保護。現場驗收確認 Device Instance、COV 續訂、跨網單播與探索、憑證過期，以及重連取回目前值。
OPC UA線速、更新與延遲由伺服器採樣與 publishing interval 決定更新。例：100 ms 採樣、500 ms 發布，另加 PLC 與網路延遲。查 Server 實際接受的參數。安全能力正式端點使用 SignAndEncrypt、信任清單及應用憑證，再按使用者角色授權。SecurityPolicy=None 不提供通訊簽章或加密。現場驗收記錄 SourceTimestamp、狀態碼、訂閱遺漏。檢查不受信任憑證及未授權寫入是否被拒。
MQTT線速、更新與延遲無固定週期。延遲由發布頻率、QoS、Broker 排隊、網路與重連決定。安全能力部署 TLS 驗證 Broker，按需啟用 mTLS。由 Broker 實作帳號與 topic ACL；跨 Broker 轉送時逐段驗證。現場驗收從發布到訂閱端量測延遲，測重複、離線積壓、訊息逾期及沒有授權的 topic。
Zigbee線速、更新與延遲2.4 GHz 原始速率 250 kbit/s。感測點實際更新受上報條件、休眠、多跳與重送影響。安全能力使用 AES-128 與金鑰機制。限制加入期間，保護金鑰及協調器，另為橋接 Broker 設 TLS 與 ACL。現場驗收核對上報間隔、漏報、離線與電量。分開測射頻連線及橋接發布。
PROFINET IO線速、更新與延遲常見 100 Mbit/s 乙太網路。PI 列出的 RT 可配置週期範圍為 250 µs 到 512 ms，實際由控制器與設備共同決定。IRT 依硬體與同步配置驗收。安全能力確認控制器、設備與工程工具支援的 PROFINET Security Class 與功能。既有裝置以 OT 分區、限制工程存取、保護交換器埠為主。現場驗收量測循環更新、抖動、watchdog 與恢復時間。驗證資料狀態 IOPS／IOCS 與診斷。
PROFIBUS DP線速、更新與延遲典型銅纜 DP RS-485 為 9.6 kbit/s 至 12 Mbit/s。主站循環受速率、站數、I/O 長度和重試影響。安全能力傳統 DP 無原生加密或裝置鑑別。限制匯流排實體接入及 PLC 工程介面存取。現場驗收核對線長與終端，量測 Data_Exchange、週期及一站中斷對其他站的影響。
CC-Link線速、更新與延遲Classic 為 156 kbit/s 至 10 Mbit/s。IE Field Basic 使用 100 Mbit/s 乙太網路，循環需按站數與 CPU 實測。兩者的線速都只是掃描時間的其中一項因素。安全能力Classic 無原生加密或裝置鑑別。保護匯流排及工程介面。IE 系列依版本和設備規格確認，使用 OT 網路分區。現場驗收量測 link scan、CPU refresh、站離線後舊值的品質標示，以及恢復時間。
EtherNet/IP線速、更新與延遲量實際循環、RPI 與 PLC 工作週期。CIP Sync 可提供時鐘同步，但不保證端到端延遲。安全能力CIP Security 須端點支援並啟用；依模式或政策核對加密、鑑別及完整性。現場驗收在正常及負載高時核對更新、逾時、重連和未授權操作是否被拒。
EtherCAT線速、更新與延遲典型 100BASE-TX 段為 100 Mbit/s，全雙工。Distributed Clocks 的同步精度與反應延遲分開。安全能力不因使用 Distributed Clocks 或功能安全機制就假定網路加密；限制工程與主站介面。現場驗收量最長更新間隔、watchdog、資料失效與故障恢復。
20 台 RTU 的輪詢估算。若每台讀取兩個 Holding Register，請求 8 bytes、回應 9 bytes，在 9,600 bit/s、8E1 下，每台光是 17 bytes 的傳輸就約 19.5 ms。20 台合計約 390 ms，還要加幀間靜默、設備處理及例外等待。如果輪詢目標是 1 秒，需實測正常及單站離線情境。

以正常負載、尖峰負載及單站離線三種情境記錄完整掃描週期、端到端 P95／P99、逾時率與恢復時間。對需要確定時限的控制 I/O，另核對規定的最長更新與 watchdog。跨設備量測端到端時間時，先同步並確認時鐘誤差。

Modbus
版本、資料流與適用
RTU 是序列請求／回應，按站號與功能碼解讀；TCP 以 MBAP 識別交易和長度。TCP→RTU 閘道的下游匯流排仍串行，應按實際 Unit ID 映射與整輪截止時間驗證。

MQTT
版本、資料流與適用
Publisher→Broker→Subscriber。QoS 定義傳輸交付行為，不提供時限；MQTT 5.0 的 Session Expiry／Message Expiry 分別管會話與訊息，retained 不是一般歷史佇列。

依 Broker 配置 TLS 伺服器身分，必要時 mTLS；按帳號／角色設定 topic ACL。TLS 保護相連的一段，並不自動保護橋接的每段。

帶唯一訊息 ID 與時間戳，在斷線／重連重播查重複、過期、積壓與恢復。驗證被拒的 topic，驗收「應用只處理一次」須另外設計冪等。

版本、資料流與適用

安全配置與限制
規範使用 AES-128；限制允許加入窗口，依設備能力查入網憑據、網路金鑰及更新。射頻側與 Zigbee→MQTT 橋接的帳號、TLS 和 ACL 應分開審查。

PROFINET IO

FC03：讀 Unit 7 的兩個 Holding Register

示例以 PDU offset 0 起算。面板或手冊可能寫 40001；兩者的對應仍須看原廠。交易識別碼可由 Client 分配，此處固定為 0x002A 方便核對。

請求：00 2A | 00 00 | 00 06 | 07 | 03 00 00 00 02
回應：00 2A | 00 00 | 00 07 | 07 | 03 04 41 B0 00 00
      交易ID  協定ID   長度    單元       PDU

MBAP 長度欄計算「後續位元組」：包含 Unit ID 與 PDU，不含前六個位元組。回應中的 04 是資料的位元組數；依教材指定的高位字在前解讀 41B0 0000 才得到 IEEE 754 的 22.0。傳統 Modbus TCP ADU 不附 RTU CRC。應分別驗證交易 ID、Protocol ID=0、Length、Unit ID、功能碼及例外回應。

"""Run a local AHU01 teaching endpoint for Modbus TCP, BACnet/IP or OPC UA."""

import argparse
import asyncio
from datetime import datetime, timezone
from itertools import cycle
import struct


def modbus_response(unit: int, pdu: bytes) -> bytes:
    function = pdu[0]
    if unit != 7:
        return bytes([function | 0x80, 0x0B])
    if function != 3:
        return bytes([function | 0x80, 0x01])
    if len(pdu) != 5:
        return bytes([0x83, 0x03])
    address, count = struct.unpack(">HH", pdu[1:])
    if (address, count) != (0, 2):
        return bytes([0x83, 0x02])
    return struct.pack(">BBf", 3, 4, 22.0)


async def modbus_exchange(reader, writer):
    try:
        async with asyncio.timeout(5):
            while True:
                header = await reader.readexactly(7)
                transaction, protocol, length, unit = struct.unpack(">HHHB", header)
                if protocol != 0 or not 2 <= length <= 254:
                    break
                pdu = await reader.readexactly(length - 1)
                reply = modbus_response(unit, pdu)
                writer.write(struct.pack(">HHHB", transaction, 0, len(reply) + 1, unit) + reply)
                await writer.drain()
    except (asyncio.IncompleteReadError, TimeoutError, ConnectionError):
        pass
    finally:
        writer.close()
        await writer.wait_closed()


async def modbus_server(port):
    listener = await asyncio.start_server(modbus_exchange, "127.0.0.1", port)
    async with listener:
        print(f"Modbus TCP 127.0.0.1:{port}, Unit 7, FC03, offset 0", flush=True)
        await listener.serve_forever()

async def opcua_server(port):
    from asyncua import Server, ua

    server = Server()
    await server.init()
    endpoint = f"opc.tcp://127.0.0.1:{port}/lab/"
    server.set_endpoint(endpoint)
    server.set_security_policy([ua.SecurityPolicyType.NoSecurity])
    ns = await server.register_namespace("urn:example:plant")
    ahu = await server.nodes.objects.add_object(ns, "AHU01")
    point = await ahu.add_variable(ua.NodeId("AHU01.SAT", ns), "SAT", 22.0)
    snapshots = []
    for bus in ("PROFINET", "PROFIBUS", "CCLink"):
        node_id = ua.NodeId(f"AHU01.{bus}.Snapshot", ns)
        node = await ahu.add_variable(node_id, f"{bus}Snapshot", bytes.fromhex("01 00 DC"))
        snapshots.append(node)

    async with server:
        print(f"OPC UA {endpoint}, urn:example:plant", flush=True)
        for value in cycle((22.0, 22.5, -5.0, None)):
            now = datetime.now(timezone.utc)
            status = ua.StatusCodes.Good if value is not None else ua.StatusCodes.BadNoData
            await point.write_value(ua.DataValue(
                ua.Variant(value, ua.VariantType.Double if value is not None else ua.VariantType.Null),
                ua.StatusCode(status), SourceTimestamp=now,
            ))
            valid = value is not None
            packed = struct.pack(">Bh", int(valid), round(value * 10) if valid else 0)
            for snapshot in snapshots:
                await snapshot.write_value(ua.DataValue(
                    ua.Variant(packed, ua.VariantType.ByteString), SourceTimestamp=now,
                ))
            await asyncio.sleep(2)

"""Eight read-only protocol mapping exercises. Run with Python 3.11+."""

import argparse
from dataclasses import asdict, dataclass
import json
import math
from pathlib import Path
import struct
from typing import Literal

Quality = Literal["good", "uncertain", "bad"]


@dataclass(frozen=True)
class Reading:
    source: str
    value_c: float | None
    quality: Quality


def temperature(source: str, value: float | None, quality: Quality = "good") -> Reading:
    if quality == "bad":
        return Reading(source, None, quality)
    if isinstance(value, bool) or not isinstance(value, (int, float)) or not math.isfinite(value):
        raise ValueError("Expected a finite temperature")
    return Reading(source, float(value), quality)


def modbus_float(registers: list[int], *, low_word_first: bool = False) -> float:
    if len(registers) != 2 or any(type(x) is not int or not 0 <= x <= 65535 for x in registers):
        raise ValueError("Expected two unsigned 16-bit registers")
    high, low = registers[::-1] if low_word_first else registers
    return struct.unpack(">f", struct.pack(">HH", high, low))[0]


def modbus_demo() -> Reading:
    # Unit 7, FC03, zero-based start address 0, count 2. Sample response words.
    return temperature("modbus:7/holding/0", modbus_float([0x41B0, 0x0000]))


def bacnet_read(source: str, value: float, units: int | str, flags: list) -> Reading:
    if units != 62 and str(units) not in {"62", "degreesCelsius", "degrees-celsius"}:
        raise ValueError("BACnet point must use degrees Celsius")
    # In-alarm is a process alarm and can coexist with a valid reading.
    _, fault, overridden, out_of_service = flags
    quality = "bad" if fault or out_of_service else "uncertain" if overridden else "good"
    return temperature(source, value, quality)


def bacnet_demo() -> Reading:
    # Typed ReadProperty results. Units 62 = degrees Celsius.
    return bacnet_read("bacnet:device/420101/analogInput/1", 22.0, 62, [False] * 4)

    return ("good", "uncertain", "bad", "bad")[status_code >> 30]

    if message["schema"] != 1 or message["point"] != "AHU01.SAT":

def read_input_image(protocol: str, point: str, payload: bytes, quality: Quality) -> Reading:
    # The PLC's export contract fixes a 16-bit signed big-endian field and 0.1 °C scaling.
    # Read only a consistent PLC snapshot and reject failed stations before decoding.
    source = f"{protocol}:{point}"
    if quality == "bad":
        return Reading(source, None, quality)
    if len(payload) != 2:
        raise ValueError("Expected exactly two input bytes")
    (deci_c,) = struct.unpack(">h", payload)
    return temperature(source, deci_c / 10, quality)


def fieldbus_ua_frame(protocol: str, point: str, payload, ua_quality: Quality) -> Reading:
    if ua_quality == "bad":
        return read_input_image(protocol, point, b"", ua_quality)
    if not isinstance(payload, (bytes, bytearray, list, tuple)):
        raise ValueError("Expected a ByteString or Byte array")
    frame = bytes(payload)
    if len(frame) != 3 or frame[0] not in (0, 1):
        raise ValueError("Expected valid flag (0 or 1) followed by two input bytes")
    quality = ua_quality if frame[0] == 1 else "bad"
    return read_input_image(protocol, point, frame[1:], quality)


def fieldbus_read(protocol: str, snapshot: dict) -> Reading:
    if protocol == "profinet":
        point = f"{snapshot['device']}/{snapshot['slot']}/{snapshot['subslot']}"
        valid = snapshot["valid"]
    elif protocol == "profibus":
        point = f"station/{snapshot['station']}/I{snapshot['input_offset']}"
        valid = snapshot["data_exchange"]
    elif protocol == "cc-link":
        point = f"station/{snapshot['station']}/RWr0"
        valid = snapshot["link_ok"]
    else:
        raise ValueError(f"Unknown fieldbus: {protocol}")

    if type(valid) is not bool:
        raise ValueError("Expected a Boolean station or submodule status")
    if not valid:
        return Reading(f"{protocol}:{point}", None, "bad")
    if protocol == "cc-link":
        word = snapshot["rwr0"]
        if type(word) is not int or not 0 <= word < 65536:
            raise ValueError("Expected an unsigned RWr word")
        payload = word.to_bytes(2, "big")
    else:
        payload = bytes.fromhex(snapshot["bytes"])
    return read_input_image(protocol, point, payload, "good")

    if args.serial:

            args.target, baudrate=args.baudrate, parity=args.parity,

def read_broker(args):
    import paho.mqtt.client as mqtt

    # Keep a small handoff so callback processing cannot create an unbounded backlog.
    events = Queue(maxsize=1)

    def offer(event):
        try:
            events.put_nowait(event)
        except Full:
            pass  # A sample or error is already waiting for the one-shot reader.

    def on_connect(client, userdata, flags, reason_code, properties):
        if reason_code.is_failure:
            offer(ConnectionError(f"Broker refused connection: {reason_code}"))
            return
        client.subscribe(args.topic, qos=1)

    def on_subscribe(client, userdata, mid, reason_codes, properties):
        if any(code.is_failure for code in reason_codes):
            offer(PermissionError(f"Broker refused subscription: {reason_codes}"))

    def on_message(client, userdata, message):
        if message.topic != args.topic or message.retain:
            return
        if args.protocol == "zigbee":
            try:
                state = json.loads(message.payload)
            except (UnicodeError, ValueError):
                return
            if not isinstance(state, dict) or "temperature" not in state:
                return
        offer(message.payload)

    client = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2, protocol=mqtt.MQTTv5)
    if not args.loopback_plaintext:
        client.tls_set(ca_certs=args.ca)
    client.on_connect = on_connect
    client.on_subscribe = on_subscribe
    client.on_message = on_message
    client.connect(args.host, args.port, keepalive=30)
    client.loop_start()
    try:
        try:
            payload = events.get(timeout=args.wait)
        except Empty as exc:
            raise TimeoutError("No matching non-retained reading before the deadline") from exc
        if isinstance(payload, Exception):
            raise payload
        adapter = zigbee_read if args.protocol == "zigbee" else mqtt_read
        return asdict(adapter(args.topic, payload))
    finally:
        client.disconnect()
        client.loop_stop()

Overview

先比角色，不先背欄位

現場最容易出錯的不是記不得 port，而是拿錯心智模型。先知道每個協定站在哪一層，後面才不會把 polling、subscription、routing、broker 混在一起。

Architecture

協定差異本質上是責任邊界差異

同一筆溫度資料，在四個協定中會呈現為 register、NodeId、BACnet object、MQTT payload。比較時要從責任邊界看，不是只看是否可讀寫。

Modbus

Modbus：register-based polling

最常出現在 PLC、meter、VFD 與 RTU/TCP 網段。Python 常扮演 poller、decoder、gateway adapter。

OPC UA

OPC UA：semantic model + subscription

最常出現在 SCADA、MES、historian 與跨系統語意整合。Python 常扮演 client、integration agent、edge translator。

閱讀 OPC UA 深度研究：資訊模型、訂閱復原與憑證

BACnet

BACnet：object model + building automation routing

最常出現在樓宇自控、HVAC、BMS。Python 常扮演 gateway、監控側 integration、資料轉換器，而不是直接替代全部現場控制。

MQTT

MQTT：publish/subscribe uplink

最常出現在 edge uplink、cloud telemetry、event publish。Python 常扮演 publisher、subscriber、payload normalizer 或本地 buffer manager。

閱讀 MQTT 深度研究：QoS、會話、重送與 Broker

需要跨區分發時，Gateway 可先送到 OT DMZ Broker，消費服務再寫入事件庫。這不是必要的多跳；選擇依資料規模和隔離策略。無論採用哪一條，網頁斷線不應讓 PLC 停止本地控制。詳見工業資料採集 Gateway 架構。

方式最適合代價與補救
RESTful API（HTTPS）根據資源路徑讀快照、歷史、點位目錄和告警紀錄；容易分頁、快取與逐請求授權。大量客戶端頻繁輪詢會放大負載。快照可用 ETag／If-None-Match + 304，歷史用查詢上限、分頁游標和索引，廠內權限資料不共用公開快取。
WebSocket（WSS）長連線、雙向訊息，適合即時畫面、事件告警和訂閱區域選擇。傳輸是全雙工，但本章設計只允許訂閱遙測，不寫 PLC。長連線有心跳、重連、記憶體、授權失效和慢客戶成本。TCP 保證當前連線的位元組順序，不保證跨重連的應用訊息補發。

同一條 AHU 串流：三個常用接口

  1. GET /api/v1/assets/ahu-01/snapshot：回目前點位與 last_seq。快照與游標必須代表同一個一致性切點，後者不能另外讀最新序號。
  2. GET /api/v1/assets/ahu-01/events?after_seq=42&limit=200：供稽核與補傳，依 seq 升冪，回傳 next_after_seq。完整歷史報表另用 UTC 的明確半開時窗；分頁以固定高水位避免查到一半範圍不斷成長。
  3. wss://monitor.example.test/ws/v1/assets/ahu-01：建立連線後送 {"type":"subscribe","after_seq":42}；伺服器先重播 seq > 42，再切到即時，切換不能漏掉中間到達的事件。這是自訂應用協定，WebSocket 不自帶這些語意。

序號屬於特定資產串流、單調且持久，不是所有設備共用的序號。此算例訂閱完整資產串流，所以可用 last_seq + 1 查缺口；若服務另做過濾、多分區或重建串流，改用服務端定義的游標或分區水位，不能把所有數字跳號都判成漏資料。保存原始觀測時間，補送不刷新資料年齡。BAD 或 STALE 不可用 0 取代。

斷線回復：42 → 44 不是直接顯示 44

取快照畫面從 seq 42 開始
→
接事件重複序號忽略
→
缺口或斷線保留游標，補齊 43 再套用 44
→
已超過保留窗標示歷史缺口並重取快照

快照適合恢復當前畫面，不應用來宣告歷史已補回。建議在 HTTP 回 410 或 WSS 送 resync_required 時，清楚標出這是站點 API 的契約。伺服器設每連線的緩衝上限，慢客戶可斷開後按游標補資料；只對畫面允許的資料合併最後值，不合併須完整保存的告警事件。

安全與驗收

  • HTTPS／WSS 驗證 TLS 與身分；HTTP 每個資源、WebSocket 建連後每次訂閱都按站點／設備授權，權限撤回或憑證過期時停止分發。對瀏覽器限制 Origin，Origin 不取代驗證。不要把長效憑證放在網址、Topic 或日誌。
  • 協調 proxy idle timeout、服務端心跳與重連抖動。心跳只證明連線活著，不代表某一台 AHU 最近有採樣。監控最後有效時刻、資料品質、p95 送達延遲、佇列深度、重連數和補送成功率。
  • 驗收先用離線資料：故意重複 43、不送 43 卻先送 44、縮短保留窗，以及停住消費端。確認重複不套用、缺口不假裝成功、過期要求新快照、慢客戶不拖住別人。PLC 控制與急停應另驗收，不連到這份示範。
