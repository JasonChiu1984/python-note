Overview

先比角色，不先背欄位

現場最容易出錯的不是記不得 port，而是拿錯心智模型。先知道每個協定站在哪一層，後面才不會把 polling、subscription、routing、broker 混在一起。

Architecture

協定差異本質上是責任邊界差異

同一筆溫度資料，在四個協定中會呈現為 register、NodeId、BACnet object、MQTT payload。比較時要從責任邊界看，不是只看是否可讀寫。

Modbus

Modbus：register-based polling

最常出現在 PLC、meter、VFD 與 RTU/TCP 網段。Python 常扮演 poller、decoder、gateway adapter。

OPC UA

OPC UA：semantic model + subscription

最常出現在 SCADA、MES、historian 與跨系統語意整合。Python 常扮演 client、integration agent、edge translator。

BACnet

BACnet：object model + building automation routing

最常出現在樓宇自控、HVAC、BMS。Python 常扮演 gateway、監控側 integration、資料轉換器，而不是直接替代全部現場控制。

MQTT

MQTT：publish/subscribe uplink

最常出現在 edge uplink、cloud telemetry、event publish。Python 常扮演 publisher、subscriber、payload normalizer 或本地 buffer manager。

Troubleshooting

選錯協定心智模型時最容易怎麼壞

很多整合失敗不是 library 問題，而是用 Modbus 的想法去理解 OPC UA，或用 MQTT 的想法去期待 BACnet discovery。
