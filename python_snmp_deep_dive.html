SNMP 通訊及安全性深度研究

從管理物件的語意，到可驗收的輪詢、通知、計數器證據與 SNMPv3 信任邊界。以工控管理網為背景，實驗只用合成資料，不連線設備。

研究問題與適用界線

RQ1：量到的究竟是什麼？

HTTP 或 ICMP 可達不代表介面流量讀值可信；型別、索引、時間與中斷旗標共同決定樣本能否比較。

RQ2：如何量測而不干擾設備？

分析 UDP 遺失、逾時重試、GetBulk 回覆大小與週期預算。先確立管理流量容量，再追求完整性。

RQ3：保密是否等於授權？

否。USM 負責訊息層的身分鑑別、時間檢查與隱私；VACM 判定身分可讀寫哪些物件。網路隔離與端點受管仍須另證明。

SNMP 適合交換器、UPS、環控等設備的維運監視，並非 PLC 快速掃描、安全聯鎖或現場控制迴路的替代。本文是標準導讀與離線方法驗證，沒有做真實站點壓測或弱點測試。

架構與兩條資料流

輪詢：建立趨勢基線

排程 → 請求 → 回覆關聯 → 校驗來源、OID、型別與時間 → 分級入庫。收集時刻不是設備內部計數器取樣時刻；記錄 RTT 及來源限制。

通知：縮短事件感知

Trap 不要求應用層確認。Inform 會等待 Response，可重傳，接收端須防重複；確認只代表協定對端回覆，不保證告警已寫入資料庫。

SNMPv1、v2c 採 community-based 存取，本身不提供加密，不能以「字串難猜」取代訊息鑑別與保密。v2c 增加 GetBulk、Inform 與 Counter64 脈絡；SNMPv3 是架構與安全模型，不代表每個 v3 設定都已加密。[S1–S4、S11]

MIB、OID、實例：不要只抄一條數字

SMI 定義型別、命名和 MIB 模組規則，MIB 定義物件語意；線上回覆依協定提供 varbind，結合物件實例 OID 和值。MIB 檔可離線解析名稱與型別，但不保證設備支援、可讀或立即更新。不同廠商 enterprise subtree 需對應型號、韌體與 MIB 版本。

物件實例用途與注意事項
sysUpTime1.3.6.1.2.1.1.3.0管理子系統重新初始化後的 TimeTicks（百分之一秒）；不必然等於主機開機時間，TimeTicks 本身也會環回。
ifOperStatus1.3.6.1.2.1.2.2.1.8.<ifIndex>操作狀態的列實例；要與管理設定 ifAdminStatus 分離，不把刻意關閉告警成線路故障。
ifHCInOctets／ifHCOutOctets1.3.6.1.2.1.31.1.1.1.6.<ifIndex>／...1.10.<ifIndex>64 位累加 octets；讀值不是 bps。收集器須記錄介面身分並處理重啟、重新索引與 discontinuity。
ifCounterDiscontinuityTime1.3.6.1.2.1.31.1.1.1.19.<ifIndex>表示最近一次計數器中斷時的 sysUpTime。裝置實際回傳 TimeTicks 0，表示自管理子系統上次初始化以來未發生相關中斷；未回傳、逾時或 noSuchInstance 都不是零。採集器仍須追蹤已知重啟或介面重配。

標量實例以 .0 結尾，表格用 INDEX 所定義的列鍵；複合鍵不一定只有一個整數。管理資產資料用「設備身分＋受管 context＋介面身分」作系列鍵，不能直接跨設備或跨重啟把相同 ifIndex 視為同一條線。常見 Counter32/64 會環回、Gauge32 非累加計數、TimeTicks 不是 UTC。[S5、S6、S10]

PDU 操作、回覆邊界與容量設計

GetRequest / GetNextRequest
Get 取已知實例；GetNext 逐一取字典序後繼，回覆可能離開目標 subtree。以數字 arc 陣列比較前綴，不用字串前綴混淆 .1 與 .10。
GetBulkRequest
v2 型 PDU 以 non-repeaters 與 max-repetitions 限制候選回覆；輸出可能少於期望，也可能有 endOfMibView。收集器應檢查 OID 進度、subtree 與回覆大小，必要時縮小批次或分欄。單次可完成的列數並不保證固定。
Response / Report
Request-id 對應 PDU 呼叫；v3 的 message id 屬訊息處理層。Report 用於模型回饋（例：時間不同步），不等於原請求成功。v2 型回覆的 noSuchObject／noSuchInstance／endOfMibView 是特殊 varbind 值；不能當成 0，亦不同於逾時。
SetRequest
是狀態修改，另外審核存取與操作授權。監控使用者不應獲得 write view；流程設計不以現場設備寫入來測試這篇教材。

輪詢預算（假設算例）：120 台每 30 秒各取 1 個成功交易，平均 4 個交易／秒（請求與回覆各 1 個資料包，未含失敗、IP 分片與其他協定資料）。全站同時發送則不是平均 4 個；依設備錯開排程。若 6 台逾時、每台最多 1 次重試、每次等 0.8 秒，這 6 台合計占用 9.6 collector-slot 秒。即使有併發，仍要逐站限制同時請求數、重試、回覆大小與整輪 deadline，避免故障時放大管理流量。

回覆偏大時：以受控環境先量回覆 octets、分片跡象、RTT p95／p99 與 request failure rate，縮小 GetBulk 批數後再用相同負載比較。沒有回覆不能直接判定「設備離線」：還可能是 ACL、超時、限制、分片、版本／安全模型／context 不符。[S2–S4]

計數器推導與離線 Python 實驗

同一連續系列，令 Δt=t₂−t₁、M=2^width、d=(C₂−C₁) mod M。真實候選是 d+kM，其中 k 是非負整數。必須先證明時間單調、介面與世代相同、沒有 discontinuity，再依容量與經過時間限制候選；只剩一個才估速。無法排除隱藏的設備重設時，連續性仍是假設，不靠模數自動解決。

保守採集策略：同一序列在 10 秒增加 1,000 octets，若兩次標記都實際回傳零，該組可得 800 bit/s；任一次缺少標記則標為 missing-discontinuity-marker 並不產出速率。兩次有效標記不同（例如 0 變成 5），或採集器已知重啟／重新映射，則標為 discontinuity。超出 TimeTicks 0～4,294,967,295 或型別不符的是無效標記，不視為中斷證據。

算例：15 秒流入 octets 從 100,000 到 125,100,000，速率 8 × 125,000,000 ÷ 15 ≈ 66.67 Mbit/s。以 1 Gbit/s 為單向名目速率，使用率約 6.67%。全雙工進、出方向應分開；IF-MIB octets 定義和導線上的所有開銷未必相同，不宣稱是實體媒介占用百分比。

Counter32 在連續 1 Gbit/s 假設下約 2³² × 8 ÷ 10⁹ ≈ 34.36 s 即可環回。60 秒取樣時，兩個讀值之差即使為正也可能不唯一；改用可取得的 Counter64 或適當縮短取樣間隔，不用讀到相同值就判零流量。速率分母用實際單調時計間隔，而非設定的 nominal interval；ifHighSpeed 是估計值、單位為 10⁶ bit/s，須對照實速、媒介與設備文件。

"""Synthetic IF-MIB analytics. No network, credentials or packet construction."""
from dataclasses import dataclass
import math
import unittest


@dataclass(frozen=True)
class Sample:
    # Collector monotonic timestamp; all samples must share the same clock.
    t_s: float
    agent: str
    if_index: int
    octets: int
    # Collector-assigned continuity epoch; changes on known restart/remapping.
    epoch: int
    # Returned TimeTicks (including zero), or None if no evidence was returned.
    discontinuity: int | None


@dataclass(frozen=True)
class Rate:
    quality: str
    bps: float | None = None
    utilization_pct: float | None = None


def evaluate(a: Sample, b: Sample, *, width: int, capacity_bps: int,
             max_gap_s: float = 90.0) -> Rate:
    """Return an explicit quality state rather than treating gaps as zero."""
    if width not in (32, 64) or type(capacity_bps) is not int or capacity_bps <= 0:
        raise ValueError("invalid counter width or capacity")
    if not math.isfinite(max_gap_s) or max_gap_s <= 0:
        raise ValueError("invalid gap limit")
    modulus = 1 << width
    if any(type(x.octets) is not int or not 0 <= x.octets < modulus
           or type(x.if_index) is not int or x.if_index <= 0
           or not x.agent or not math.isfinite(x.t_s) for x in (a, b)):
        return Rate("invalid-sample")
    if (a.agent, a.if_index) != (b.agent, b.if_index):
        return Rate("different-series")
    dt = b.t_s - a.t_s
    if not math.isfinite(dt) or dt <= 0:
        return Rate("time-order")
    if dt > max_gap_s:
        return Rate("stale-gap")
    if a.epoch != b.epoch:
        return Rate("discontinuity")
    markers = (a.discontinuity, b.discontinuity)
    if any(m is not None and (type(m) is not int or not 0 <= m < 1 << 32)
           for m in markers):
        return Rate("invalid-discontinuity-marker")
    if any(m is None for m in markers):
        return Rate("missing-discontinuity-marker")
    if markers[0] != markers[1]:
        return Rate("discontinuity")
    max_octets = capacity_bps * dt / 8
    delta = (b.octets - a.octets) % modulus
    if delta > max_octets:
        return Rate("capacity-exceeded")
    if delta + modulus <= max_octets:
        return Rate("ambiguous-wrap")
    bps = 8 * delta / dt
    return Rate("ok", bps, 100 * bps / capacity_bps)


class Cases(unittest.TestCase):
    def test_good(self):
        a = Sample(0, "synthetic-a", 7, 100_000, 1, 0)
        b = Sample(15, "synthetic-a", 7, 125_100_000, 1, 0)
        x = evaluate(a, b, width=64, capacity_bps=1_000_000_000)
        self.assertEqual(x.quality, "ok")
        self.assertAlmostEqual(x.bps, 66_666_666.666667, places=5)
        self.assertAlmostEqual(x.utilization_pct, 6.666666666666667)

    def test_single_wrap(self):
        x = evaluate(Sample(0, "a", 1, (1 << 32) - 16, 1, 0),
                     Sample(1, "a", 1, 16, 1, 0),
                     width=32, capacity_bps=100_000_000)
        self.assertEqual(x, Rate("ok", 256.0, 0.000256))

    def test_multiple_compatible_deltas(self):
        a = Sample(0, "a", 1, 10, 1, 0)
        b = Sample(60, "a", 1, 20, 1, 0)
        self.assertEqual(evaluate(a, b, width=32, capacity_bps=1_000_000_000),
                         Rate("ambiguous-wrap"))

    def test_gap_and_restart(self):
        a = Sample(0, "a", 1, 100, 1, 0)
        for b, quality in [(Sample(91, "a", 1, 200, 1, 0), "stale-gap"),
                           (Sample(1, "a", 1, 10, 2, 0), "discontinuity"),
                           (Sample(1, "a", 1, 10, 1, 5), "discontinuity")]:
            self.assertEqual(evaluate(a, b, width=64, capacity_bps=1_000_000_000),
                             Rate(quality))

    def test_missing_is_not_reported_zero(self):
        for left, right, wanted in (
            (0, 0, Rate("ok", 800.0, 0.00008)),
            (None, None, Rate("missing-discontinuity-marker")),
            (None, 0, Rate("missing-discontinuity-marker")),
            (0, None, Rate("missing-discontinuity-marker")),
            (0, 5, Rate("discontinuity")),
        ):
            with self.subTest(left=left, right=right):
                a = Sample(0, "a", 1, 1000, 1, left)
                b = Sample(10, "a", 1, 2000, 1, right)
                self.assertEqual(evaluate(a, b, width=64, capacity_bps=1_000_000_000), wanted)

    def test_timeticks_domain(self):
        valid = (1 << 32) - 1
        a = Sample(0, "a", 1, 1000, 1, valid)
        for marker in (valid, valid + 1, -1, True, 5.0, "5"):
            with self.subTest(marker=marker):
                b = Sample(10, "a", 1, 2000, 1, marker)
                wanted = Rate("ok", 800.0, 0.00008) if type(marker) is int and marker == valid else Rate("invalid-discontinuity-marker")
                self.assertEqual(evaluate(a, b, width=64, capacity_bps=1_000_000_000), wanted)

    def test_bad_samples(self):
        a = Sample(1, "a", 1, 10, 1, 0)
        for b, quality in [(Sample(1, "a", 1, 20, 1, 0), "time-order"),
                           (Sample(2, "b", 1, 20, 1, 0), "different-series"),
                           (Sample(2, "a", 1, -1, 1, 0), "invalid-sample"),
                           (Sample(2, "a", 1, 4_000_000_000, 1, 0), "capacity-exceeded")]:
            self.assertEqual(evaluate(a, b, width=32, capacity_bps=1_000_000_000),
                             Rate(quality))


if __name__ == "__main__":
    unittest.main(verbosity=2)

SNMPv3 資安：USM 與 VACM 分層

安全層級訊息鑑別／完整性隱私部署解讀
noAuthNoPriv無無不是生產遙測安全基線。部分 discovery 初始交換不表示後續允許明文遙測。
authNoPriv有無無法隱藏 varbind；只有確定無機密風險且政策允許時才例外採用。
authPriv有有優先使用受管讀取。USM 隱私保護 scopedPDU；不等於整個封包頭與流量模式都不可見。

Engine 身分、金鑰及時間新鮮度

securityEngineID 同時影響 USM 鑑別及 localized key；contextEngineID／contextName 用來定位管理資料，不能當作帳號或當成必定等於安全引擎。需要 Response 的 confirmed 處理一般以接收側為 authoritative engine（管理者送 Get、通知端送 Inform）；不要求回覆的 Trap 以發送端為 authoritative。代理更換、VM 還原、重複 Engine ID 或狀態遺失時，應重新驗證信任、金鑰與狀態，而非停用驗證繞過錯誤。

USM 鑑別下使用 authoritative engine 的 snmpEngineBoots 和 snmpEngineTime 判斷 timeliness；規格使用 150 秒時間窗並區分權威與非權威方的更新／接受條件。這是引擎相對狀態，不等於要求兩台的 UTC 秒數相減，也不保證應用事件不會重複。應用層仍須去重和記錄每個監控來源的狀態遷移。

演算法與帳號

跨設備基線可優先驗證 RFC 7860 的 HMAC-SHA-2 與 RFC 3826 的 AES-128 CFB 是否共同支援，記錄具體演算法而非只寫「v3」。歷史 USM 選項不宜當新部署預設；不同廠商較長 AES 選項有相容性差異，不能只看位數。分別管理 auth／priv 憑證及獨立監控身分，不把祕密寫在教材、命令歷史、程式碼或報告。輪替時使用可回退但不降級到 v2c 的變更程序。

VACM 範例原則：收集端只給必要的 system 與 IF-MIB 物件 read view，不給 write；通知可見範圍另定。先用合成規格驗證允許／禁止，再配合系統擁有者做最小量、授權過的驗收。AuthPriv 不提供所有傳輸模型同樣的憑證語意；若使用 TLS／DTLS 的 SNMP Transport Model，另循 RFC 6353 與設備支援設計，不把它當成 USM 的設定旗標。[S1、S4、S7–S9、S12]

工控部署與可證偽的驗收

威脅／失敗控制驗收證據
跨區任意管理管理平面與控制流量分區；依實際方向控制管理站／設備／通知接收端，不將 UDP 161／162 暴露給非管理網段。配置差異、授權來源清單、受控驗證結果及防火牆拒絕統計；源位址限制不取代加密鑑別。
過度權限或降級AuthPriv、最小 read view、區分唯讀與操作角色；停用未授權 v1／v2c。例外限有期限的管理隔離，絕不自動降級。文件列演算法、security level、view、軟體版本與輪替紀錄；測試設定允讀 OID 可用、禁讀被拒，無寫入要求。
監視平台誤判攜帶來源標籤、序列鍵、時間與品質；按重啟、延遲、缺窗和假零事件區分，不從資料快取回填成即時。離線測試，斷訊／重啟的授權維護演練，以及每輪告警的事件時間與入庫時間。
輪詢影響控制限制速率、批量、併發、重試並做排程抖動；以採集任務可停止和故障不放大為要求。受控的同部門測試前後，報控制週期、CPU、管理交易 p95、失敗率及輪詢完整度，不只報成功個數。
告警遺失、重複或洩密Trap／Inform 分別驗證，接收端依事件身分與時間去重並保留來源。通知 payload 僅出現需要的欄位。不能僅以接收確認宣稱入庫；核對發送、接收、持久化、告警與排除規則各一份證據。

最小研究計畫

  1. 基線固定韌體、MIB 版本、管理網路、區間與樣本量。先跑離線計數器測試；拒絕輸出需保留原因。
  2. 經核准的隔離環境分兩組，只改 GetBulk 分批大小，記錄請求數、回覆大小、逾時率和控制設備的資源曲線；觀察 p95 尾端而非只看平均。
  3. 第二個實驗只改授權 view，用既有測試資料對照允許與拒絕結果。若使用外部管理平台，先取得責任人審核；不把安全演練和產線有效性混為一談。
  4. 交付附樣本數、分母、失敗案例與範圍。沒有真實設備或權限時只報離線結果，不虛構密碼套件或相容性實測。

"""手動以 BER 編碼 SNMPv2c GetRequest，並示範 Counter32 回捲時的速率計算（標準函式庫）。

SNMPv1/v2c 的 community 以明文傳送，只適合隔離的管理網段；需要認證與加密時用 SNMPv3（authPriv）。
"""


def tlv(tag, value: bytes):
    n = len(value)
    length = bytes([n]) if n < 128 else bytes([0x80 | ((n.bit_length() + 7) // 8)]) + n.to_bytes((n.bit_length() + 7) // 8, "big")
    return bytes([tag]) + length + value


def integer(v):
    return tlv(0x02, v.to_bytes(max(1, (v.bit_length() + 8) // 8), "big", signed=True))


def oid(dotted):
    parts = [int(x) for x in dotted.split(".")]
    body = bytes([40 * parts[0] + parts[1]])
    for p in parts[2:]:
        chunk = [p & 0x7F]
        p >>= 7
        while p:
            chunk.insert(0, 0x80 | (p & 0x7F))
            p >>= 7
        body += bytes(chunk)
    return tlv(0x06, body)


def get_request(community, request_id, oids):
    varbinds = tlv(0x30, b"".join(tlv(0x30, oid(o) + tlv(0x05, b"")) for o in oids))
    pdu = tlv(0xA0, integer(request_id) + integer(0) + integer(0) + varbinds)
    return tlv(0x30, integer(1) + tlv(0x04, community.encode()) + pdu)      # version 1 = v2c


def rate(prev, curr, seconds, bits=32):
    delta = curr - prev if curr >= prev else curr + 2 ** bits - prev
    return delta / seconds


if __name__ == "__main__":
    pkt = get_request("public", 0x1234, ["1.3.6.1.2.1.1.3.0", "1.3.6.1.2.1.2.2.1.10.1"])
    print(f"GetRequest {len(pkt)} bytes：", pkt.hex(" "))
    print("sysUpTime.0 OID 編碼：", oid("1.3.6.1.2.1.1.3.0").hex(" "))
    print("community 'public' 以明文出現在封包中：", b"public" in pkt)
    prev, curr = 4_294_000_000, 1_500_000            # ifInOctets 在兩次輪詢間回捲
    bps = rate(prev, curr, 60) * 8
    print(f"Counter32 回捲：{prev:,} → {curr:,}，60 秒平均 {bps / 1e6:.2f} Mbps")
    print(f"同樣流量若用 1 Gbps 滿載，Counter32 約 {2 ** 32 * 8 / 1e9:.0f} 秒就回捲一次；高速介面請改讀 ifHCInOctets（Counter64）")

工程現場案例：UPS 與 PDU 的 SNMP community 都是 public

某機房的 UPS、PDU 與交換器都開著 SNMPv2c，community 為預設的 public，而且和辦公網路同一個 VLAN。任何人用免費工具就能讀取設備資訊；若 write community 也是預設值，甚至能修改設定。範例顯示 community 字串直接以明文出現在封包中，網路上任何能看到流量的人都能取得。

改善方式是改用 SNMPv3 authPriv（帳號、認證與加密），把管理介面移到獨立管理網段，關閉不需要的 write 權限。流量監控則要改讀 64 位元計數器：1 Gbps 介面滿載時，32 位元計數器約 34 秒就回捲一次，輪詢週期稍長就會算錯。

  1. 盤點所有開啟 SNMP 的設備、版本與 community／帳號。
  2. 改用 SNMPv3 authPriv，停用 v1／v2c；短期無法停用時至少更換 community 並限制來源 IP。
  3. 管理介面放在獨立 VLAN，只允許監控主機存取 UDP 161。
  4. 流量計算一律使用 ifHCInOctets／ifHCOutOctets（Counter64），並處理回捲。

練習題與自我檢查

  1. OID 1.3.6.1 的前兩個數字為什麼編碼成單一位元組 0x2B？

    看解答

    BER 規定前兩個數字合併為 40 × X + Y：40 × 1 + 3 = 43 = 0x2B。這是為了節省一個位元組，也是手動解析 OID 時最常出錯的地方。

  2. 若 OID 中有一個數字是 300，會被編成哪些位元組？

    看解答

    300 = 0b1_0010_1100，以 7 bits 分段為 0000010 與 0101100，前段加上續傳位元得到 0x82 0x2C。可呼叫 oid('1.3.300') 驗證。

  3. rate() 能處理一次輪詢間隔內回捲兩次的情況嗎？

    看解答

    不能。程式只能偵測「現值小於前值」，回捲兩次以上時差值會被低估且無法察覺。對策是縮短輪詢週期，或改用 Counter64。

  4. 依流程圖最後一關：同一介面 60 秒內 octets 增加 1,000,000,000，容量 1 Gbit/s，兩次 discontinuity 標記都回傳 0。用 Counter32 與 Counter64 各會得到什麼結果？

    看解答

    容量上限是 1,000,000,000 × 60 ÷ 8 = 7,500,000,000 octets。Counter32 的 M = 4,294,967,296，d + M = 5,294,967,296 仍不超過上限，代表「少算一圈」也合理，evaluate() 回傳 ambiguous-wrap，不產出速率。Counter64 的 M 遠大於上限，候選唯一，回傳 ok：約 133.33 Mbit/s，使用率約 13.33%。若任一次標記未回傳，則先停在第四關，回傳 missing-discontinuity-marker。

  5. 設備重開機後計數器歸零，rate() 會誤判成回捲嗎？如何區分？

    看解答

    會，因為現值小於前值。可同時讀 sysUpTime：若 sysUpTime 變小，代表設備重開機，該區間的速率應標示為無效，而不是當成回捲計算。
