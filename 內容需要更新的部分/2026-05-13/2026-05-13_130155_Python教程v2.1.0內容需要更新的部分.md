## 1. Overview

v2.0.0 已新增測試工程路線，補齊交付前的品質閘門。下一個專案開發缺口是上線後的可觀測性與維運能力：logging、metrics、tracing、health check、SLO、runbook、incident record 與 rollback evidence 仍分散在高階案例中，尚未形成獨立可循序學習的路線。

## 2. 更新範圍

| 檔案 / 資料夾 | 必要更新 |

| `python_observability_operations_tutorial.html` | 新增 28 張可觀測性與維運工程互動卡 |

| `CHANGELOG.md` | 新增 v2.1.0 版本紀錄 |

## 3. 必須補強的維運主題

| 主題 | 需補內容 |
|---|---|
| Logging | JSON structured log、trace id、error context、redaction |
| Metrics | request count、latency、error rate、dependency timeout |
| Tracing | span boundary、downstream call、correlation id |
| Health | liveness、readiness、dependency degradation |
| SLO | latency threshold、error budget、alert triage |
| Incident | timeline、runbook、rollback evidence、postmortem notes |
| Sample | 可執行 service simulator、telemetry collector、unittest、smoke script |

## 4. 驗收條件

- 入口頁顯示十一條路線，且包含「可觀測性與維運工程」卡片。
- 維運教材頁顯示 `v2.1.0` 與 28 張互動卡。
- `python-observability-completed` 進度在入口頁可顯示。
- `範例程式碼/observability_operations/scripts/run_observability_smoke.py` 可執行。
- `python3 -m py_compile` 通過新範例所有 Python 檔案。
- `PYTHONPATH=範例程式碼/observability_operations/src python3 -m unittest discover -s 範例程式碼/observability_operations/tests -v` 通過。
- demo smoke 能輸出 JSON logs、metrics、health 與 SLO evaluation。

## 5. 風險備註

- 本輪用標準庫建立最低可驗證 baseline；OpenTelemetry、Prometheus、Grafana、Alertmanager 可作為後續版本深化。
- 維運教材應聚焦可診斷與可回復，不應變成監控工具名詞表。
