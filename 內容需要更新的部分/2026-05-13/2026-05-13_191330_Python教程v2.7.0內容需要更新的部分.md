## 4. Configuration

CI/CD quality gate 教材要明確說明以下設定：

| 設定 | 建議內容 |
|---|---|
| Python stable lane | 以 Python 3.14.5 作為目前 stable baseline |
| Python beta lane | 以 Python 3.15.0b1 作為 preview readiness lane |
| blocking policy | stable lane、compile、unit、coverage、smoke 為 blocking |
| non-blocking policy | beta preview 可作為早期預警，不阻擋正式 release |
| evidence policy | 每次 gate 產出 JSON/文字報告，保留 command、status、reason |

## 7. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| CI YAML 只像範本，無工程判斷 | 在教材中加入 trigger、matrix、blocking policy |
| coverage 被誤解為唯一品質指標 | 說明 coverage 只是 gate，不代表需求完整 |
| beta lane 造成 release 誤阻擋 | 明確標註 beta preview 為 readiness signal |
| 本機與 CI 指令不一致 | 範例以同一支 `run_ci_gate.py` 作為本機與 CI 共用入口 |

## 8. Best Practices

- local gate 與 CI gate 應共用同一組命令。
- gate result 應能回溯到版本與 commit。
- workflow 應避免把 secret、deploy key 或 production credentials 寫在教材範例中。
- 工業現場部署前，CI/CD gate 應串接 deployment smoke 與 rollback note。
