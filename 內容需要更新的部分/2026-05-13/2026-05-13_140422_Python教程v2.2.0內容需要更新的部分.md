## 1. Overview

v2.1.0 已新增可觀測性與維運工程路線，補齊上線後診斷、SLO、health check 與 incident evidence。下一個專案開發缺口是安全工程與供應鏈治理：threat model、authn/authz、input validation、secret handling、dependency manifest、audit log、rate limit 與 security incident evidence 仍分散在高階案例中，尚未形成獨立可循序學習的路線。

## 3. 必須補強的安全主題

| 主題 | 需補內容 |
|---|---|
| Threat Model | assets、entrypoints、abuse case、risk rating |
| Identity | PBKDF2 password hash、constant-time compare、RBAC、deny-by-default |
| Input | schema、payload size、path traversal guard、safe error response |
| Secrets | env source、redaction、rotation、fake test secrets |
| Supply Chain | pinned dependency、manifest、hash、vulnerability evidence |
| Runtime | rate limit、audit log、alert runbook、incident containment |
| Sample | 可執行 security baseline、unittest、smoke script |

## 4. 驗收條件

- 入口頁顯示十二條路線，且包含「安全工程」卡片。
- 安全教材頁顯示 `v2.2.0` 與 28 張互動卡。
- `python-security-completed` 進度在入口頁可顯示。
- `範例程式碼/security_engineering/scripts/run_security_smoke.py` 可執行。
- `python3 -m py_compile` 通過新範例所有 Python 檔案。
- `PYTHONPATH=範例程式碼/security_engineering/src python3 -m unittest discover -s 範例程式碼/security_engineering/tests -v` 通過。
- demo smoke 能輸出 auth、policy、rate limit、audit 與 manifest gate 結果。

## 5. 風險備註

- 本輪用標準庫建立最低可驗證 baseline；OAuth2/OIDC、JWT rotation、pip-audit、SBOM、Sigstore、KMS、SIEM 可作為後續版本深化。
- 安全教材應聚焦可驗證控制與交付證據，不應變成工具名詞列表。
