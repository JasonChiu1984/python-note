## 1. Overview

依照審查報告，本輪應補齊 Python 教程在專案交付層最關鍵但仍分散的缺口：依賴與環境治理。

## 2. Architecture

需要新增一條獨立路線：

```text
Dependency Environment Governance
  -> runtime baseline
  -> virtual environment contract
  -> requirements / requirements-dev / constraints
  -> startup + verification commands
  -> dependency update / release evidence
```

| 項目 | 建議內容 |
|---|---|

## 7. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| CI 與本機依賴不一致 | 補 requirements / constraints 契約 |
| 開發套件跑進 production | 補 dev/prod 分層說明 |
| Python 版本升級後套件飄移 | 補 runtime 與 dependency 分開治理 |
| 啟動命令每章節不一致 | 補統一 startup / verify 命令 |

## 8. Best Practices

- 依賴治理要和發布治理一起交付。
- `requirements-dev.txt` 應顯式引用 `requirements.txt`。
- constraints 檔應視為可驗收文件，不是可有可無的附加品。
- 沒有可重現啟動命令與驗證命令，就不算完成專案交付教程。
