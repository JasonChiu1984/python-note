## 1. Overview

依照本輪審查，應補齊 Python 教程在大型專案持續演進層最缺的主題：`Architecture Governance`。

## 2. Architecture

需要新增一條獨立路線：

```text
Architecture Governance
  -> ADR / decision record
  -> package ownership
  -> import boundary rule
  -> deprecation policy
  -> refactor gate
  -> release evidence
```

## 4. Configuration

教材需固定補以下內容：

| 項目 | 建議內容 |
|---|---|
| ADR | decision、context、tradeoff、replacement trigger |
| module ownership | 哪個模組歸誰維護、允許依賴誰 |
| import boundary | 允許/禁止的跨層引用 |
| deprecation policy | deprecate、replace、remove 時程 |
| refactor gate | compile、unittest、boundary check、report |
| release evidence | governance report、smoke output、更新紀錄摘要 |

## 7. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| 重構後邊界持續漂移 | 補 module ownership 與 import rule |
| 舊 API 不斷累積 | 補 deprecation policy 與 sunset date |
| 功能測試都過但循環依賴增長 | 補結構檢查與 boundary guard |
| README、ADR、程式結構互相脫節 | 補集中治理報告與交付證據 |

## 8. Best Practices

- 架構治理要和 release 一起交付。
- ADR 要短而明確，不要寫成長篇設計文件。
- ownership 與 import rule 應可機械驗證，不要只靠口頭約定。
- 沒有結構驗證與 deprecation 時程，就不算完成大型專案治理教材。
