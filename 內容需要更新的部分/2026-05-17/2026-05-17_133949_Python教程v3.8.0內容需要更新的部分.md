## 7. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| 排程工作重複執行 | 補 lease 與 worker ownership |
| 工作失敗後從頭再跑 | 補 checkpoint / resume |
| 單筆壞資料阻塞整批 | 補 retry budget / dead-letter |
| 回補後無法交接 | 補 rerun evidence / operator notes |

## 8. Best Practices

- 批次工作要像 API 一樣有契約、證據與交付邊界。
- checkpoint 應在成功提交後更新，避免半成功狀態污染。
- retry budget 與 dead-letter 要一起設計，不要只做無限重試。
- 回補作業要可追溯，不要只靠口頭紀錄。
