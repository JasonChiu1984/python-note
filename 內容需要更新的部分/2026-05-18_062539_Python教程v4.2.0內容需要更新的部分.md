## 5. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| 學員知道很多主題但不會整包交付 | 補整合式 blueprint 與 sample |
| 教材與範例不同步 | 首頁、範例、changelog、更新紀錄同步更新 |
| 有測試但沒有交付證據 | 固定輸出 release evidence |

## 6. Best Practices

- 先以標準庫骨架收斂責任，再逐步引入框架。
- 教學 repo 的 reference project 應該能直接作為新專案起點。
- 每次升版都要能說清楚這版補的是哪一層工程能力。
