## 7. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| 新版程式無法讀舊資料 | 補 `compat reader` 與 `schema version adapter` |
| backfill 中斷後重跑成本高 | 補 `checkpoint`、`resume` 與 `summary report` |
| 回退程式後讀不到新資料 | 補 `rollback compatibility` 驗證 |
| 線上 drift 導致 migration 失敗 | 補 `preflight manifest` 比對 |
| 工業控制欄位意外變更 | 補 `command/telemetry` 分界與 `fail-safe` 預設 |

## 8. Best Practices

- 沒有 `schema manifest`，不要宣稱資料演進可治理。
- 沒有 `compat read/write`，不要直接做 `destructive change`。
- 沒有 `checkpoint` 與 `rollback` 驗證，不要把 `backfill` 當成已交付能力。
- 工業自動化場景下，控制資料演進要優先保守，不可假設現場資料一定乾淨一致。
