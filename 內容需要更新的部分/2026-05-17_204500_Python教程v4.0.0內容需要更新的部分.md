## 5. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| smoke 執行後 repo 變髒 | 補自動清理與索引還原 |
| index 多出測試條目 | 將 smoke entry 視為暫存，不納入正式資料 |
| 教材與實作一致但文件未更新 | 補本輪 dated 驗證與發布紀錄 |

## 6. Best Practices

- 驗證腳本要以「執行後 repo 仍乾淨」為目標。
- 正式知識庫只保留可交付內容，不保留測試殘留。
- 維護型發布也要有 dated 審查與更新紀錄。
