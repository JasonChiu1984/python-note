## 5. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| CLI 只有單一腳本難交接 | 補 `plan / apply / report` |
| dry-run 不安全 | 補明確副作用邊界 |
| 更新紀錄難引用命令結果 | 補固定成功訊號與 JSON report |

## 6. Best Practices

- 工程型 CLI 要視為交付物，不是個人腳本。
- 有風險的命令先提供 dry-run，再提供 execute。
- 更新資料應引用固定成功訊號與核心統計值。
