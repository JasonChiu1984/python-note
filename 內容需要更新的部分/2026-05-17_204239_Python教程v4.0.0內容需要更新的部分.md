## 4. Configuration

本輪需要固定下列契約：

- `entry id`：時間戳加 slug
- `index.json`：集中維護 metadata 與排序
- `entry.json` / `entry.md`：人機雙視角輸出
- `MCP`：`initialize`、`tools/list`、`tools/call`
- `驗證`：`py_compile`、`unittest`、`smoke`、HTML script parse、`git diff --check`

## 6. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| search 結果不穩 | 補 metadata 並檢查 index 是否已更新 |
| read 失敗 | 改由正式 `id` 讀取，不直接猜檔名 |
| MCP 無回應 | 檢查 stdio header framing |
| 測試資料過多 | 將 smoke/demo entry 視為驗證證據，避免混入無關輸入 |

## 7. Best Practices

- 以真實倉庫能力寫教材，不建脫節假範例。
- 所有驗證命令都要可重播。
- 審查、修正單、更新紀錄要有一致時間戳與版本號。
- 發布時排除不相關未追蹤資料夾。
