## 1. Overview

依照本輪審查，應補齊 Python 教程在「已存在實作但尚未納入教程」的缺口：`Local Knowledge Base MCP Engineering`。

## 2. Architecture

需要新增一條獨立路線：

```text
Local Knowledge Base MCP Engineering
  -> conversation export
  -> Markdown / JSON dual format
  -> index contract
  -> stable entry id
  -> stdio MCP initialize / tools/list
  -> search / read verification
  -> handoff / release evidence
```

## 4. Configuration

教材需固定補以下內容：

| 項目 | 建議內容 |
|---|---|
| export contract | 輸入格式、message normalize、title、summary、tags |
| storage contract | `index.json`、`entries/*.json`、`entries/*.md` |
| identity contract | timestamp + slug 的 stable entry id |
| MCP contract | `initialize`、`tools/list`、`tools/call search/read` |
| runtime contract | client `cwd`、server path、stdio 啟動方式 |
| release evidence | export 輸出、MCP search/read 結果、更新紀錄摘要 |

## 7. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| search 命中率差 | 補 `title`、`summary`、`tags` |
| read 找不到條目 | 改用 `index.json` 中正式 `id` |
| index 與 entry 不一致 | 只透過匯出腳本更新資料 |
| MCP server 讀不到知識庫 | 固定 client `cwd` 與 server 相對路徑 |

## 8. Best Practices

- 先守住 storage contract，再考慮擴充工具功能。
- 匯出時就把 metadata 補齊，不要後補。
- 教材要對應真實倉庫能力，不要使用脫節的示意範例。
- 更新紀錄要能直接引用驗證輸出，方便交接。
