## 4. Configuration

整合韌性教材要明確說明以下設定：

| 設定 | 建議內容 |
|---|---|
| timeout policy | 單次外部呼叫等待預算，避免 worker 或 request thread 被拖垮 |
| retry policy | max attempts、backoff、retryable status、fail-fast 分類 |
| idempotency policy | POST / command write 沒有 idempotency key 不允許 retry |
| rate limit policy | 避免壓垮外部 API、設備 gateway 或現場網路 |
| circuit breaker policy | 連續失敗後快速失敗，進入 degraded / alarm / fail-safe |
| evidence policy | attempts、retries、blocked、schema_errors、policy version 寫入 report |

## 7. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| retry 造成重複寫入 | 加入 idempotency key，或將 request 標記為不可重試 |
| 外部 API 429 | 降低 polling interval、加入 rate limiter 與 backoff |
| circuit breaker 開啟後無告警 | 將 circuit open 納入 metrics、structured log、runbook |
| response schema drift | 加入 schema validation 與 contract regression |
| 工業 gateway 故障 | 將 degraded、alarm、fail-safe、手動接管流程寫入教材 |

## 8. Best Practices

- timeout、retry、rate limit、circuit breaker 要一起設計，不可單點調參。
- 寫入整合必須先定義 idempotency，避免重複命令或重複寫入。
- 外部依賴錯誤要分類：timeout、429、5xx、schema_error、circuit_open 需要不同處理。
- 工業現場整合要把 polling interval、alarm handling、fail-safe strategy 與維護 runbook 一起交付。
