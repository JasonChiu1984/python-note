## 4. Configuration

事件可靠性教材要明確說明以下設定：

| 設定 | 建議內容 |
|---|---|
| outbox policy | 主資料與 event 需同時落地，再交由 dispatcher 處理 |
| max attempts | delivery / consume 失敗的重試上限與 DLQ 條件 |
| ordering policy | 以 stream key 定義同流順序邊界 |
| replay policy | replay reason、operator、結果都要留痕 |
| evidence policy | dispatch、duplicate、DLQ、replay 統計寫入 report |

## 7. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| publish 一直失敗 | 檢查 broker 健康度與 dispatch scheduler |
| duplicate side effect | 固定 event_id 並補 processed set |
| DLQ 堆積 | 先修正根因，再帶 replay reason 重放 |
| ordering 混亂 | 明確定義 stream 與序列邊界 |
| report 缺統計 | 補 dispatch、duplicate、DLQ、replay 指標 |

## 8. Best Practices

- 沒有 outbox，不要宣稱資料與事件一致。
- 沒有 idempotency，不要對副作用事件做盲目重送。
- DLQ 與 replay 要有 runbook，不是只留一個失敗清單。
- 事件可靠性數據要能被 release note 與營運維護引用。
