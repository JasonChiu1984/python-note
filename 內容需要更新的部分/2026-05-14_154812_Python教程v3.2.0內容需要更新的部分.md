## 4. Configuration

設定治理教材要明確說明以下設定：

| 設定 | 建議內容 |
|---|---|
| source precedence | defaults < env < secret file < CLI override |
| required secret | 缺 token 時 fail fast，不允許空值啟動 |
| validation policy | port、timeout、poll interval、write enable 需驗證型別與範圍 |
| redaction policy | release note / report 只顯示紅acted 後的 secret |
| feature flag policy | flag 要有 owner、expires_on 與 rollout note |

## 7. Troubleshooting

| 狀況 | 補強方向 |
|---|---|
| staging / prod 行為不同 | 比對 effective config report 與 source precedence |
| secret 洩漏到 log | 補強 redaction 邊界與 report writer |
| 啟動後才爆 timeout / port 錯誤 | 補 fail-fast validation |
| flag 長期殘留 | 補 owner、expiry 與清理流程 |
| gateway 寫入誤開 | 補 fail-safe 預設與顯式啟用規則 |

## 8. Best Practices

- 沒有 precedence contract，不要宣稱多環境設定可控。
- 沒有 redaction policy，不要把設定報告放進 release note 或 handoff。
- feature flag 要有生命週期，不是永遠保留的布林值。
- 工業自動化場景下，高風險設定要以保守預設與明確驗證為先。
