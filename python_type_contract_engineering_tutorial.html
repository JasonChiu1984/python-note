Python Type Contract Engineering

把型別提示變成可維護的工程契約

這條路線把 type hints 從語法裝飾提升到團隊級契約：TypedDict 描述外部 payload，dataclass 承載已驗證 domain state，Protocol 隔離依賴邊界，runtime validation 保護現場輸入，contract evidence 進入 CI 與 release 記錄。

Overview

型別提示要對齊專案風險

先決定要保護的邊界，再選 TypedDict、dataclass、Protocol 或 runtime validation。

Architecture

把外部 payload 和 domain state 分開

外部資料可能不可信；核心 model 應只接收已驗證資料。

Setup

從標準庫開始驗證契約流程

先用 unittest 與 smoke script 建立可重複驗收，再接 mypy 或 pyright。

Configuration

型別策略要分 blocking 與 warning

核心 schema 與 runtime validation 應阻擋 release；全域 strictness 可漸進導入。

Example

Type Contract 範例專案

範例用工業溫度點位示範 schema、alarm 與 fail-safe，但保持純 Python 標準庫。

cd 範例程式碼/type_contract_engineering
python3 -m py_compile src/type_contract_engineering/*.py scripts/run_type_contract_smoke.py
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 scripts/run_type_contract_smoke.py
Verification

驗收要同時看靜態契約與 runtime 行為

type hints、payload validation、alarm、fail-safe、report 都要能被測試。

Troubleshooting

常見問題多半來自邊界混用

不要讓外部 payload 直接流進核心 business logic。

Best Practices

讓型別契約支援重構與交付

型別策略應能幫團隊更快改、更穩交付，而不是增加無效儀式。
