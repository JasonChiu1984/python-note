Pandas 簡介

先理解表格資料模型

Pandas 的主角是 `DataFrame`：帶 index、columns、dtype 的表格資料。它很適合讀寫、清洗、join、groupby、時間序列與資料產品前處理。

指令說明

安裝、I/O、測試與環境診斷

Pandas 工程常見指令不是單一 CLI，而是安裝 extras、讀寫檔案、跑測試、檢查版本與打包驗收。資料工具尤其要測 sample data。

指令 / 參數用途適用時機常見錯誤
python -m pip install pandas安裝核心 pandas 與必要依賴venv、CI、一般專案裝到錯 Python 或忘記 venv
pip install "pandas[performance]"安裝效能相關 optional dependencies大型資料、groupby、eval/query 等效能敏感場景把所有 extras 都裝進 runtime 增加攻擊面
pip install "pandas[excel,parquet]"依 I/O 格式安裝 optional dependenciesExcel、Parquet、Feather、SQL 等格式用到才發現 ImportError
python -c "import pandas as pd; print(pd.__version__)"驗證 import 與版本安裝後 smoke test只看安裝成功沒真正 import
pd.read_csv(..., dtype=..., parse_dates=...)讀 CSV 並固定 schema資料管線入口讓 dtype 自動推斷導致資料漂移
pd.read_parquet(..., columns=..., filters=...)讀 Parquet 並做欄位/分割過濾大型資料湖或快取沒裝 pyarrow/fastparquet 或沒測 storage options
python -m build打包依賴 pandas 的專案wheel / sdist release漏 optional-dependencies

詳細應用

從 ETL 到 BI、時間序列與資料品質

Pandas 適合 tabular data。若資料已大到超出記憶體，或需要分散式運算，應切換到 SQL、Polars、DuckDB、Spark 或 chunk pipeline。

上線檢查表

Pandas 專案交付前 8 件事

資料工具上線前，請把 schema、dtype、missing、join cardinality、時間區間、效能、sample data 與 package extras 都驗收清楚。

Schema contract欄位、dtype、nullable、日期欄位都寫進測試。
Missing policyNA 是丟棄、補值、報錯還是保留，要明確。
Join cardinalitymerge 前檢查 one-to-one / one-to-many。
Time zone時間序列要定義 timezone 與邊界。
Chunk plan資料量大時要分批、欄位裁剪或改用 SQL/Parquet。
Sample datarelease smoke test 要包含固定 input/output。
ExtrasExcel、Parquet、SQL、Cloud 依賴用 optional extras 管理。
Runtime report記錄 pandas/NumPy/pyarrow 版本與平台。
