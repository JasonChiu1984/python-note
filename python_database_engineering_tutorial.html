Modeling

先定義資料契約，再寫查詢

資料庫不是儲存細節，而是專案契約的一部分。schema、constraint、index 與資料生命週期都要能被 review。

Migration

把 schema 演進做成可回放流程

正式專案不能靠手動改資料表。每次欄位、索引與約束都要有版本、驗收與 rollback 思路。

Transaction

交易邊界要比函式邊界更清楚

commit、rollback、retry、idempotency 與 lock 行為決定資料是否可靠。

Repository

讓業務邏輯不依賴 SQL 細節

Repository 與 Unit of Work 讓 service 能被測試，也讓資料庫實作可以演進。

Testing

資料庫測試要隔離、可重跑、可診斷

測試不是只跑 happy path，要覆蓋 constraint、rollback、concurrency 與 query regression。

Delivery

交付時要保留資料庫證據

release note 應包含 migration、seed、backup、restore drill、query plan 與 rollback 限制。
