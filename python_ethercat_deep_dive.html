EtherCAT 詳細協定說明

從一個乙太網路 frame 沿線處理，到主站如何配置、週期交換資料和診斷現場。用固定合成紀錄區分「資料有回應」與「資料可供監控使用」，不存取或控制設備。

架構圖｜一個 frame 走訪多個 SubDevice

原生循環程序資料直接封裝於乙太網路資料鏈結層，EtherType 0x88A4，不需要 IP、TCP 或 UDP 標頭；不要把 SubDevice 類比成每站一個 IP／Socket 的協定。一般 Ethernet 網段或 IP 路由器不能被假定能充當 EtherCAT 分支；以主站、EtherCAT junction、設備與廠商支援的媒體設計為準。

常見基礎 EtherCAT 使用 100 Mb/s 全雙工乙太網路；這是鏈路速率，不是整體更新週期、抖動、同步精度或故障回退時間。EtherCAT G 是另有規格的延伸，不能套用到全數設備。

Frame、Datagram 與定址不是同一件事

主站安排數個 datagram 可以共享同一 frame；一個 datagram 也能覆蓋多個已映射的 SubDevice。WKC 在各 datagram 尾部，不等於整個 frame 唯一的一個狀態。循環時可用邏輯讀寫命令（例如 LRD／LWR／LRW）。

工程中常見的三種定址
定址選定的對象何時使用
位置（auto-increment）依物理經過順序／相對位置選站啟動時探索拓樸，核對與組態中的站位一致。
配置站址（station）由主站配置的站址及該站暫存器位移針對已識別裝置做配置、狀態或診斷。不是 IPv4 位址。
邏輯（logical）程序映像區中的邏輯位址FMMU 將邏輯範圍對應到本地 ESC 記憶體與位元；用於循環 PDO 資料。

ESI、PDO、CoE、SDO：設定資料與即時資料分開

資料描述、循環映射與郵箱讀寫
名詞用途工程核對
ESI（XML）廠商提供的設備描述，給主站工程系統辨識與選擇能力。比對 Vendor ID、Product Code、Revision、PDO／同步模式；ESI 檔不等於裝置端 SII 資料。
PDO循環 I/O 的資料項與布局；通常不夾帶逐項物件索引。以設備觀點：RxPDO＝設備接收（主站輸出）、TxPDO＝設備傳送（主站輸入）。核對型別、bit offset、量尺與資料方向。
CoE／SDOCoE 為 CANopen over EtherCAT；如設備支援，SDO 走 mailbox，存取物件字典，使用 index/subindex。適合參數或診斷；不把每個週期的 I/O 都改成 SDO，也不假定所有物件可寫／所有 PDO 可重映射。
SyncManager（SM）管理 ESC 與設備應用端共享區域的存取同步。典型 SM0/1 為 mailbox，SM2/3 為程序輸出／輸入；實際通道與模式依設備。
FMMU將主站邏輯程序映像映射至裝置本地實體記憶體。確認各方向與長度，尤其不要拿錯版本 ESI。

專案在設定階段定義物件、PDO 對映和緩衝區後，週期內才按程序映像的固定布局交付資料。工程驗收要核對裝置說明、映射及主站的變數型別；單看值非零不足以確認實際有效。

BOOT 若支援，是韌體等特殊用途，非正常循環的一站。遇到狀態異常時，先保留要求狀態、實際狀態與 AL Status Code；不要在監控腳本不停重送運行狀態。不把 SAFEOP 名稱當作 SIL 或 PL：安全功能須由合格設計及專用安全措施負責。

同步和診斷｜DC、WKC 與資料時效各看什麼

DC：對齊裝置時基，不保證端到端延遲

Distributed Clocks（DC）在支援的設備上使用參考時鐘，主站估算傳播延遲並對齊本地時鐘，可依設備配置使用 SYNC0／SYNC1 對齊採樣或輸出。主站週期、訊框到達的餘裕、時鐘偏差、I/O 生效相位、外部時間來源是不同項目；部署時分開量。不要把 DC 宣稱成 TCP 時鐘同步、固定微秒更新或要求所有 SubDevice 都支援。

WKC：命令處理證據，不等於點值新鮮

WKC 按命令種類、裝置是否完成相應讀／寫及映射而變，預期值由主站依實際組態與命令計算，不應直接填「設備台數」。Beckhoff WcState 是衍生品質旗標：0 為上次資料交換有效；這和 wire datagram 的原始 WKC 整數不是同一欄位。相符的 WKC 不能保證感測器最新、資料尺度正確或輸出已在現場動作。若來源不提供可信取樣時間，可輸出「取樣時間未知」，不能拿上位接收時間冒充現場採樣時間。

故障層與可觀察證據
觀察項目可用於不能單獨證明
連線／CRC／期限埠斷線、媒體錯誤、沒有準時收到 frame單一資料區映射成功或值的新鮮度
WKC／WcState判斷預期 datagram 處理情況取樣時間、量測準確、遠端輸出已生效
ESM／AL Status確定是否已到 OP；診斷配置、狀態轉換同步精度、個別感測點有效
DC／時間偏差時鐘同步與配置是否滿足本設備的規範作業系統排程及完整控制迴路延遲
取樣時間與品質用對齊後時間檢核 age、缺值與重複資訊不受監控的設備也在健康運行

timeout、WKC 不符、狀態錯誤或取樣過期，當筆資料立即標成不可用；告警可另訂防抖。保留上一筆只作顯示時，要顯著標示舊值與取樣時間，不拿去作自動控制。下一步是記錄故障、核對線路與組態，按經核准的復歸流程恢復；現場輸出動作由原設備 watchdog、安全迴路與核准控制策略處理。

"""Evaluate fixed synthetic EtherCAT monitoring records; no I/O or fieldbus access."""

from dataclasses import dataclass
import argparse
import json
import unittest


@dataclass(frozen=True)
class Record:
    cycle: int
    state: str                    # Reported state of the monitored I/O domain
    wkc: int | None               # None = this frame did not return by deadline
    sample_ms: int | None         # Aligned sample timestamp; None if not supplied
    observed_ms: int
    dc_ok: bool                   # True/False per upstream monitor's own policy


def classify(records: tuple[Record, ...], *, expected: int,
             freshness_ms: int, require_dc: bool) -> list[dict]:
    """The result drives a dashboard, not equipment. All thresholds are fictional."""
    if expected <= 0 or freshness_ms < 0:
        raise ValueError("expected WKC must be positive; freshness cannot be negative")
    result = []
    failures = good = 0
    alarm = False
    previous_cycle = -1
    previous_observed = -1
    for r in records:
        if r.cycle <= previous_cycle or r.observed_ms < previous_observed:
            raise ValueError("records must be sorted by increasing monitor cycle and time")
        previous_cycle, previous_observed = r.cycle, r.observed_ms
        age = None if r.sample_ms is None else r.observed_ms - r.sample_ms
        if r.wkc is None:
            reason = "timeout"
        elif r.state != "OP":
            reason = "not_op"
        elif r.wkc != expected:
            reason = "wkc_mismatch"
        elif age is None:
            reason = "sample_time_unknown"
        elif not 0 <= age <= freshness_ms:
            reason = "stale_or_time_alignment"
        elif require_dc and not r.dc_ok:
            reason = "dc_out_of_policy"
        else:
            reason = "ok"

        if reason == "ok":
            good += 1
            failures = 0
            if good >= 2:
                alarm = False
        else:
            failures += 1
            good = 0
            if failures >= 2:
                alarm = True
        result.append({"cycle": r.cycle, "data_valid": reason == "ok",
                       "reason": reason, "age_ms": age, "alarm": alarm})
    return result


RECORDS = (
    Record(71, "OP", 3, 100, 101, True),
    Record(72, "OP", 3, 100, 109, True),   # WKC matches, but upstream sample is old
    Record(73, "OP", None, None, 110, True),
    Record(74, "OP", 3, 110, 111, True),
    Record(75, "OP", 3, 111, 112, True),
    Record(76, "SAFEOP", 3, 112, 113, True),
    Record(77, "OP", 2, 113, 114, True),
    Record(78, "OP", 3, 114, 115, False),
)


class MonitorTest(unittest.TestCase):
    def test_working_counter_does_not_prove_freshness(self):
        rows = classify(RECORDS, expected=3, freshness_ms=4, require_dc=True)
        self.assertEqual([x["reason"] for x in rows],
                         ["ok", "stale_or_time_alignment", "timeout", "ok", "ok",
                          "not_op", "wkc_mismatch", "dc_out_of_policy"])
        self.assertEqual([x["alarm"] for x in rows],
                         [False, False, True, True, False, False, True, True])
        self.assertFalse(rows[1]["data_valid"])

    def test_unknown_and_future_sample_time(self):
        data = (Record(1, "OP", 3, None, 9, True), Record(2, "OP", 3, 11, 10, True))
        self.assertEqual([x["reason"] for x in
                          classify(data, expected=3, freshness_ms=4, require_dc=False)],
                         ["sample_time_unknown", "stale_or_time_alignment"])

    def test_order_matters(self):
        with self.assertRaises(ValueError):
            classify((RECORDS[1], RECORDS[0]), expected=3, freshness_ms=4, require_dc=True)

    def test_dc_policy_can_be_not_applicable(self):
        self.assertTrue(classify((RECORDS[-1],), expected=3,
                                 freshness_ms=4, require_dc=False)[0]["data_valid"])


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--test", action="store_true")
    if parser.parse_args().test:
        unittest.main(argv=["lab"])
    else:
        print(json.dumps(classify(RECORDS, expected=3, freshness_ms=4, require_dc=True),
                         ensure_ascii=False, indent=2))

延伸學習：實作、現場案例與自我檢查

本節用簡化模型估算 EtherCAT 的週期時間下限，並示範 PDO 超過單一乙太網路幀容量時會拆成多個 frame；最後用 WKC 期望值判斷是否有 SubDevice 沒有處理 datagram。

可實跑範例：週期時間粗估、frame 拆分與 WKC 檢查

每台 ESC 的轉送延遲、線路長度都是假設值；實際數值依晶片、連接埠與拓樸而異，請以主站診斷工具量測為準。WKC 依 LRW 規則計算：被讀取 +1、被寫入 +2、讀寫皆有 +3。

下載範例 example.py

"""EtherCAT 週期時間粗估與 WKC 期望值檢查（標準函式庫，參數皆為假設值）。

frame 依序經過每個 SubDevice 後折返。粗估：
週期下限 ≈ frame 序列化時間 + 每台 SubDevice 處理延遲 × 台數 × 2（去回）＋ 線路傳播延遲
"""
LINK_MBPS = 100
ESC_DELAY_US = 0.6            # 假設每台 ESC 轉送延遲（依晶片與連接埠而異）
CABLE_NS_PER_M = 5.0          # 銅纜約 5 ns/m


MAX_ECAT_PAYLOAD = 1498       # 乙太網路 payload 1500 − EtherCAT 標頭 2


def frames_for(pdo_bytes):
    """每個 datagram 有 10 B 標頭＋2 B WKC；超過單一 frame 容量時拆成多個 frame。"""
    per_frame = MAX_ECAT_PAYLOAD - 12
    sizes = []
    while pdo_bytes > 0:
        chunk = min(pdo_bytes, per_frame)
        sizes.append(max(64, 14 + 2 + 12 + chunk + 4))      # 以太網標頭＋EtherCAT 標頭＋datagram＋FCS
        pdo_bytes -= chunk
    return sizes


def cycle_estimate(devices, pdo_bytes, cable_m):
    sizes = frames_for(pdo_bytes)
    ser = sum((s + 20) * 8 / LINK_MBPS for s in sizes)        # 另加前導碼與幀間隙 20 B
    prop = devices * ESC_DELAY_US * 2 + cable_m * CABLE_NS_PER_M * 2 / 1000
    return ser + prop, sizes


def expected_wkc(n_read, n_write, n_readwrite):
    """LRW 命令：每台被讀取 +1、被寫入 +2、讀寫皆有則 +3。"""
    return n_read * 1 + n_write * 2 + n_readwrite * 3


if __name__ == "__main__":
    for devices, per_dev in ((10, 8), (50, 8), (100, 16)):
        pdo = devices * per_dev
        us, sizes = cycle_estimate(devices, pdo, cable_m=devices * 3)
        print(f"{devices:>3} 台 × {per_dev:>2} B PDO：{len(sizes)} 個 frame {sizes} B，週期下限約 {us:6.1f} µs")
    exp = expected_wkc(n_read=4, n_write=2, n_readwrite=6)
    print(f"\n4 台只讀、2 台只寫、6 台讀寫的 LRW：期望 WKC = {exp}")
    for got in (exp, exp - 3, exp - 1):
        status = "正常" if got == exp else "異常：有 SubDevice 未處理此 datagram"
        print(f"  收到 WKC {got}：{status}")

工程現場案例：擴充到 100 軸後，週期時間從 250 µs 拉到 1 ms

某包裝線從 50 軸擴充到 100 軸，每軸 PDO 從 8 bytes 增加到 16 bytes。原本 250 µs 的週期出現 WKC 錯誤與同步抖動。範例顯示，1,600 bytes 的 PDO 已超過單一乙太網路幀容量，必須拆成 2 個 frame，週期下限約 259 µs，再加上主站處理與抖動餘裕，250 µs 已不可行。

處理方式包括：精簡 PDO 對應（移除不需要每週期更新的診斷物件，改用 SDO 非同步讀取）、把軸分配到兩個獨立的 EtherCAT 網段，或把週期放寬到 500 µs。決策前要先用主站工具量測實際的 frame 往返時間與 DC 同步誤差。

  1. 從 ESI 檔案與主站設定匯出每台 SubDevice 的 PDO 大小，加總成每週期資料量。
  2. 估算 frame 數與週期下限，預留至少 30% 的時間餘裕給主站運算與抖動。
  3. 上線後監看每週期 WKC，與期望值不符時記錄是哪個 datagram、哪個時間點。
  4. WKC 正常不代表資料新鮮，仍要檢查各軸狀態字與時間戳。

練習題與自我檢查

  1. 為什麼 MAX_ECAT_PAYLOAD 是 1,498 bytes？

    看解答

    標準乙太網路幀的 payload 最多 1,500 bytes，EtherCAT 在 payload 開頭還有 2 bytes 的 EtherCAT 標頭，因此可放 datagram 的空間是 1,498 bytes。每個 datagram 自己還要 10 bytes 標頭與 2 bytes WKC。

  2. LRW 期望 WKC 為 26，實際收到 23。可能是哪些 SubDevice 有問題？

    看解答

    少了 3，最直接的解釋是一台讀寫型 SubDevice 完全沒處理（−3）；也可能是一台只讀（−1）加一台只寫（−2）同時失效。WKC 只告訴你總和不符，要配合各站的 AL 狀態與錯誤計數器定位。

  3. ESC_DELAY_US 若是 1.0 µs，50 台的週期下限會變多少？

    看解答

    傳播部分從 50 × 0.6 × 2 = 60 µs 變成 100 µs，加上序列化約 36 µs 與線路約 1.5 µs，下限約 137.7 µs。可改常數重新執行驗證。

  4. 為什麼不建議在一般 Linux 上用 Python 直接跑 250 µs 的 EtherCAT 控制迴圈？

    看解答

    一般作業系統的排程延遲與 Python 的垃圾回收、直譯器開銷可能造成數百微秒以上的抖動，會導致錯過週期與 WKC 錯誤。Python 適合做設定、診斷與資料收集，即時控制應交給即時核心或專用主站。
