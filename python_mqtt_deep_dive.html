MQTT 深度研究

從採集閘道到歷史資料庫，把 QoS、狀態、重播、權限和驗收分開設計。

01｜工控資料流

  1. 現場控制器本地閉迴路／保護
  2. 採集閘道時間、品質、序號、離線緩衝
  3. MQTT Broker身份、主題授權、轉送
  4. 歷史服務交易寫入、去重、監測

閘道把設備的來源值、量測 UTC 時間、資料品質、單位與來源識別形成事件。監控端優先讀快照和歷史，不以 Broker 可用作為安全聯鎖或控制迴路的前提。事件到達延遲要分為採集週期、閘道排隊、轉送與持久化四段，不用 TCP 往返時間冒充畫面新鮮度。

02｜QoS 不是資料庫交易

級別協定語意（每一段）選用條件
0至多一次；PUBLISH 無該級別的協定回應高頻快照，少量丟失可接受
1至少一次；PUBLISH → PUBACK；可能重複事件需可重送，消費端以穩定事件鍵去重
2恰一次的協定傳遞；PUBLISH → PUBREC → PUBREL → PUBCOMP協定端點確需此語意，且可承受多階段往返與狀態成本

Publisher→Broker 與 Broker→Subscriber 各自交付；訂閱的核准 QoS 是接收上限，不能把原始 QoS 0 提升成交付保證。DUP 描述此連線傳送端是否在重送 PUBLISH，不是業務事件重複判定；Packet Identifier 是協定交換識別，可在交換完成後重用，不是長期全域事件 ID。

需要業務恰一次效果時，讓事件鍵與業務寫入在同一交易提交，並確認客戶端是否能延後確認至提交後。若還要呼叫外部服務，另設發件箱（outbox）及下游冪等鍵，不把 PUBACK 當資料庫提交。

03｜主題、保留訊息與連線狀態

plant/a/gw01/telemetry 承載事件；plant/a/gw01/status 放保留狀態。發布使用具體主題；訂閱篩選器的 + 只匹配一層，末尾 # 匹配多層。

  • Retain：Broker 可保存每主題末筆保留訊息，供後續訂閱取得目前快照，不是事件歷史。保留旗標搭配零位元組載荷可清除該主題的保留訊息。
  • Session：以 Client ID 識別，Session Expiry 決定中斷後保留狀態多久，Clean Start 決定本次是否捨棄舊狀態；查 CONNACK 的 Session Present，不假定續接成功。
  • Birth / LWT：連線成功後由應用發布 retained online；CONNECT 先設定 Will（遺囑）作為異常離線訊號。正常停機若想留下 offline，應主動發布再正常斷線。Will Delay 可減少短斷抖動；失聯警示仍應加心跳／超時與資料年齡，不以 retained online 推定仍在線。
  • Expiry：Message Expiry 限制 Broker 儲存及轉送的時效，與 Session Expiry 分開。閘道重播仍要用量測時間重算剩餘 TTL，消費端也要拒絕過期或不合理的未來時間。

04｜離線重播與冪等落地

  1. 產生事件鍵source + epoch + seq
  2. 記錄送出前資料有限磁碟、剩餘時效
  3. 復線分批補送保留原鍵與量測時間
  4. 交易式寫入重複略過、衝突告警

epoch 在每次真正重建序號域時更換，傳輸重連不重建；若暫存跨重開機，重播原 epoch/seq、不重新編號。序號可偵測同一 epoch 的缺口，不可把不同 epoch 的序號直接比較。晚到的舊 epoch 歷史事件不能直接覆寫目前快照，需另有快照新鮮度規則與時間同步。重播保持限速、磁碟上限、可觀察的丟棄與缺口告警。

完整 Python 離線練習：寫入、重送、衝突、過期、重開機
from dataclasses import dataclass
import sqlite3
import time


@dataclass(frozen=True)
class Sample:
    source: str
    epoch: str
    seq: int
    measured_at: int
    milli_c: int


def store(db, msg: Sample, now: int) -> str:
    # 教學只接受單一已知來源；正式環境須把身份對應到 topic 與 source。
    if msg.source != "gw01" or msg.seq < 0 or not msg.epoch:
        return "invalid"
    if not -5 <= now - msg.measured_at <= 30:
        return "expired"
    key = (msg.source, msg.epoch, msg.seq)
    data = (msg.measured_at, msg.milli_c)
    with db:
        inserted = db.execute(
            "INSERT INTO samples VALUES (?, ?, ?, ?, ?) "
            "ON CONFLICT(source, epoch, seq) DO NOTHING", key + data
        ).rowcount
        if inserted:
            return "inserted"
        saved = db.execute(
            "SELECT ts, value FROM samples WHERE source=? AND epoch=? AND seq=?",
            key
        ).fetchone()
        return "duplicate" if saved == data else "identity-conflict"


def main():
    db = sqlite3.connect(":memory:")
    try:
        db.execute("""CREATE TABLE samples (
          source TEXT, epoch TEXT, seq INTEGER, ts INTEGER, value INTEGER,
          PRIMARY KEY (source, epoch, seq))""")
        now = int(time.time())
        a = Sample("gw01", "boot-A", 3, now, 22_500)
        bad = Sample("gw01", "boot-A", 3, now, 99_000)
        late = Sample("gw01", "boot-A", 2, now - 100, 22_300)
        next_boot = Sample("gw01", "boot-B", 3, now, 22_600)
        results = [store(db, x, now) for x in (a, a, bad, late, next_boot)]
        assert results == [
            "inserted", "duplicate", "identity-conflict", "expired", "inserted"
        ]
        assert db.execute("SELECT COUNT(*) FROM samples").fetchone()[0] == 2
        print(" / ".join(results))
    finally:
        db.close()


if __name__ == "__main__":
    main()

範例僅走記憶體 SQLite，沒有連線、密碼或現場資料。它證明事件鍵與保存行為，沒有模擬 MQTT 握手、Broker 訊息過期、客戶端確認時機或程序崩潰後持久性。正式環境另驗證 SQLite／資料庫持久化、交易隔離、次序與訊息 ACK 邊界。

05｜TLS、ACL 與容量

  • 驗證伺服器憑證和名稱；裝置具有獨立可輪替身份，依需要使用 mTLS。TLS 是每段連線的防護，Broker 及可讀資料方仍需納入信任邊界。
  • 以主題 ACL 分離發布與訂閱：閘道僅寫自己資料與狀態，監看器僅讀必要範圍；不共用帳號，不給監看端控制寫入或全域萬用字元。
  • 依實際負載設定封包、QoS 1/2 同時在途數、訂閱及離線佇列的上限；收集佇列水位、重送、拒絕、磁碟及新鮮度。安全與控制流各自測試。
