## 一、依審查報告修正的內容

### 1. 品質狀態語意修正

審查報告指出「教材品質檢查通過」與「高階待確認」容易造成語意衝突。本次將品質區塊改為：

- `教材品質檢查與審查狀態`
- `結構檢查通過、語意審查待補`
- `STRUCTURE PASS`

這代表自動檢查只確認案例數量、欄位、production evidence 與互動資料結構，不再宣稱 100 個案例都已完成人工語意審查。

### 2. 快速案例新增審查狀態

針對 80 個快速案例新增可見狀態：

- 深度案例：`已人工校閱`
- 快速案例：`待深度化`
- 快速案例類型：`專案化 template starter`

每個案例的專案脈絡區塊新增：

- 審查狀態
- 程式碼對題說明
- 失敗路徑測試

這讓讀者能分辨「已深度校閱案例」與「已補工程證據但仍需逐案深化的案例」。

### 3. Production Notes Platform 補成更完整專案範本

依審查報告 P1 缺口，walkthrough 從 7 個卡片擴充為 12 個卡片，新增：

- 完整 package tree
- `pyproject.toml`
- CLI entrypoint
- config/env precedence
- repository migration
- error taxonomy
- GitHub Actions YAML
- release artifact table

原有 service/repository、pytest、package、release、rollback 卡片保留並重新排序，使流程更接近可交付 production project skeleton。
