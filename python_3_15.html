CPython 3.15t Internals & Matrix

底層無鎖四大支柱與併發架構對照

了解 CPython 3.15t 如何在移除 GIL 後避免多核心快取行爭用，並精準選擇最適合的併發模型。

01

不朽物件 (Immortal Objects)

程式碼常數（小整數、常數 tuple、字串常值）與 sys.intern() 字串的引用計數永不變更。

解決痛點：

多核心同時讀寫 None / True / "" 時不再觸發 CPU L1/L2 快取行無效化（Cache-line bouncing）。

02

偏向與延遲引用計數

物件優先由建立執行緒以非原子指令本地增減計數；模組、函式、類別方法與 threading.local 啟用延遲計數。

解決痛點：

免除每次呼叫共用函式或存取模組屬性時的昂貴硬體原子 LOCK XADD 瓶頸，單核開銷降至 1–8%。

03

QSBR 靜止態記憶體回收

Quiescent-State-Based Reclamation 讓 dict 與 list 支援完全無鎖讀取（Lock-free reads）。

解決痛點：

讀取無須加鎖；若容器擴容，舊緩衝區會延遲至所有執行緒通過 Eval Breaker 安全點後才安全釋放。

04

mimalloc 本地配置器

取代傳統依賴 GIL 保護的 pymalloc，為每個 OS 執行緒配置獨立的 Thread-Local Heap。

解決痛點：

高頻建構 frozendict 與運算結果物件時完全避免全域記憶體配置鎖爭用，維持線性多核擴展。

PEP 799 Tachyon 效能驗證與實務避坑清單

Python 3.15 內建零開銷採樣分析器 profiling.sampling（Tachyon），可即時驗證多核併發效率與 GIL 是否遭意外重啟。

PEP 799 Tachyon 零開銷採樣分析指令

點擊複製
1. 直接啟動自由執行緒直譯器
python3.15t channel_pipeline.py

使用無 GIL 建置執行（或在支援環境中透過 -X gil=0 強制關閉 GIL）。

2. 採樣所有執行緒 CPU 並輸出互動火焰圖
python3.15t -m profiling.sampling run -a --mode cpu --flamegraph -o cpu_flame.html channel_pipeline.py

-a 追蹤全部執行緒，驗證多核 Worker 是否均勻分攤 CPU 計算時間。

3. 稽核 GIL 持有時間（偵測是否誤觸重啟 GIL）
python3.15t -m profiling.sampling run -a --mode gil channel_pipeline.py

正常無 GIL 狀態下 GIL 採樣應趨近於 0%；若出現顯著佔比，代表某套件觸發了 GIL 回退。

4. 熱掛載至線上執行中的 PID 進行 15 秒即時診斷
python3.15t -m profiling.sampling attach 12345 -a --mode cpu --duration 15

無需重啟線上服務即可直接由外部行程讀取執行緒堆疊，幾乎零效能損耗。
