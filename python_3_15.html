CPython 3.15t Internals & Matrix

底層無鎖四大支柱與併發架構對照

了解 CPython 3.15t 如何在移除 GIL 後避免多核心快取行爭用，並精準選擇最適合的併發模型。

01

不朽物件 (Immortal Objects)

程式碼常數（小整數、常數 tuple、字串常值）與 sys.intern() 字串的引用計數永不變更。

解決痛點：

多核心同時讀寫 None / True / "" 時不再觸發 CPU L1/L2 快取行無效化（Cache-line bouncing）。

02

偏向與延遲引用計數

物件優先由建立執行緒以非原子指令本地增減計數；模組、函式、類別方法與 threading.local 啟用延遲計數。

解決痛點：

免除每次呼叫共用函式或存取模組屬性時的昂貴硬體原子 LOCK XADD 瓶頸，單核開銷降至 1–8%。

03

QSBR 靜止態記憶體回收

Quiescent-State-Based Reclamation 讓 dict 與 list 支援部分操作的樂觀讀取快速路徑。

解決痛點：

QSBR 延後回收可能仍被其他執行緒讀取的記憶體。部分讀取可走快速路徑，必要時仍進入同步路徑。

04

mimalloc 本地配置器

取代傳統依賴 GIL 保護的 pymalloc，為每個 OS 執行緒配置獨立的 Thread-Local Heap。

解決痛點：

執行緒本地配置降低部分配置爭用。端到端吞吐量仍受佇列、資料分割、記憶體及排程影響。

PEP 799 Tachyon 效能驗證與實務避坑清單

Python 3.15 內建統計採樣分析器 profiling.sampling（Tachyon）可觀察執行緒的 CPU 樣本分布。要確認此刻的 GIL 狀態，請在目標程序匯入依賴後讀取 sys._is_gil_enabled()。

PEP 799 Tachyon 採樣分析指令

點擊複製
1. 直接啟動自由執行緒直譯器
python3.15t python-315-learning-kit/examples/concurrency_315.py

從教材首頁所在目錄執行。範例會列出建置資訊、執行前後的 GIL 狀態及功能測試結果。

2. 採樣所有執行緒 CPU 並輸出互動火焰圖
python3.15t -m profiling.sampling run -a --mode cpu --flamegraph -o cpu_flame.html python-315-learning-kit/examples/concurrency_315.py

-a 追蹤全部執行緒，觀察 CPU 樣本落在哪些執行緒。短範例可能取不到足夠樣本。

3. GIL 陽性對照：觀察持有 GIL 時的堆疊
PYTHON_GIL=1 python3.15t -m profiling.sampling run -a --mode gil python-315-learning-kit/examples/concurrency_315.py

此命令刻意啟用 GIL。模式只保留持有 GIL 的樣本，不量測等待；請比對範例輸出的 GIL 狀態，不能憑空報表判斷。要找出哪次匯入改變 GIL 狀態，可在各次匯入前後讀取狀態並保留警告。

4. 熱掛載至線上執行中的 PID 進行 15 秒即時診斷
python3.15t -m profiling.sampling attach 12345 -a --mode cpu --duration 15

將 12345 換成目標 Python 程序的 PID。附加需要平台允許讀取該程序；取樣頻率會影響負載。
