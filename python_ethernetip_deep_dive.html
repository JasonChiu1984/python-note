01｜CIP 放在乙太網路及 TCP／UDP 之上

ODVA 現行技術總覽將 EtherNet/IP 的引入列在 2001 年。它是在標準乙太網路、IP 與常用傳輸協定之上承載 CIP（Common Industrial Protocol），不是 EtherCAT 逐站原生框架。適合支援相關設備設定檔的 PLC、遠端 I/O、變頻器或工程工具；能互通不代表點位和安全功能自動一致。

  1. PLC／I/O Scanner規劃及發起 I/O 連線、控制程式
  2. 乙太網路交換網路交換器、VLAN、負載、壅塞與回復
  3. Adapter／裝置接受連線、組裝 I/O 資料、報告狀態
  4. 診斷／歷史服務對合法來源做狀態與資料年齡驗證

典型設備類別包括 Messaging、Adapter、Scanner；連線起始方叫 Originator，回應方是 Target。Scanner 常擔任 I/O Originator，Adapter 常為 Target。真正產生某方向的資料的是其 Producer，Consumer 可以有一個或多個，不能把起始方等同於雙向的 Producer。

02｜CIP 物件模型：操作要知道路徑與服務

名詞角色典型對照
Class（類別）一組物件的共同介面Identity Object 或 Assembly Object
Instance（實例）指定類別的特定實例某個輸入組裝或實際裝置身分實例
Attribute（屬性）物件內可辨識的資料欄位產品名稱、版本、狀態或 Assembly 資料；可用性依實作
Service（服務）對目標執行的標準或廠商定義動作Get_Attribute_Single（讀取單一屬性）

顯式訊息帶服務與目標路徑，適合診斷、設定或非週期性存取；常見透過 TCP，且可分無連線或有連線的 CIP 訊息。隱式 I/O 先約定連線及資料映射，運行中常見以 UDP 承載，可為單播或多播；實際傳輸模式、觸發方式及設備支援須查裝置文件。辨識／探索有自己的服務與傳輸，不能以「所有 EtherNet/IP 顯式功能都只在 TCP」概括。

03｜Assembly、EDS 與連線生命週期

  1. 比對組態裝置識別、韌體、EDS、連線支援
  2. 確認資料方向Scanner 視角的 Input＝T→O；Output＝O→T
  3. 建立連線核對實例、長度、RPI、所有權與傳輸格式
  4. 交換與監視更新品質、序號、超時、恢復與重接

Assembly 將多個資料欄位組成 I/O 映射。確認輸入、輸出及組態實例、連線尺寸、每個資料位元／位元組、數值縮放、對齊、有效性旗標，以及含不含連線特有的額外標頭。EDS（Electronic Data Sheet）是工程工具使用的裝置描述，協助辨識參數與連線設定；不等於支援所有組合，也不能取代實際韌體手冊。

典型 I/O 建立透過 Connection Manager 的 Forward Open 類服務協商，再在連線內交換資料。連線失敗時依序比對實例、I/O 尺寸、電子鍵控／版本、RPI 可用範圍、所有權、連線數上限與交換網路。超時與重啟後，上位機需先標記品質無效並驗證收到新資料；現場輸出回退行為應依設備組態和安全設計驗收，不假設會保持前值或一律歸零。

04｜RPI 不是 PLC 掃描，也不是來源資料年齡

RPI（Requested Packet Interval）是連線請求的 I/O 封包間隔參數，需符合裝置支援及網路條件。PLC 掃描週期是程式或工作排程執行的間隔，不必與 I/O 刷新同相。來源感測更新、排隊、交換網路抖動、接收與程式讀取相位都可增加端到端年齡。

用接收端單調時鐘驗證「多久沒收到」，用已同步且可信的來源時間驗證「原始值多舊」。封包連續到達也可能重複提供同一讀值；若需要證明感測更新，另核對來源序號、時間戳與品質。應分別量測封包間隔、丟包／重連及 p95/p99 資料年齡，不拿最短 RPI 當 SLA。

05｜同步、備援、安全與資安是不同層

功能工程用途不能承諾
CIP Sync以 IEEE 1588 PTP 同步設備時間；核對授時架構及時鐘品質。不會自動降低掃描時間或保證端到端延遲。
DLRDevice Level Ring 支援網路環狀拓樸並管理環路故障，需支援設備及適當角色。不等於 PLC 或電力備援，也不保證所有雙故障均可恢復。
CIP Safety功能安全通訊，採黑通道原則並須使用完整合規的安全設計。不是加密或帳號權限；普通 I/O 和教學例不能用於安全控制。
CIP Security具相容設備和啟用設定時，安全配置可依支援模式提供身份驗證、完整性及機密性；例如 TCP/UDP 對應的 TLS/DTLS。不取代分區、存取控制、金鑰與憑證生命週期，也不假定每個產品支援所有設定檔。

先確認裝置規格、配對與授權；未確定有安全擴充時，不把一般 EtherNet/IP 通訊當成已加密。多播部署須驗證所用交換器的 IGMP／查詢器配置與流量表現，避免沒測過就假定每個連線必用多播。

"""解碼合成的 Assembly 資料；非網路封包、不連線、不寫入設備。"""
from dataclasses import dataclass
import math
from struct import Struct
import unittest

# 教學自訂映射：小端序 uint16 旗標、int16 0.01°C、uint32 序號。
LAYOUT = Struct("<HhI")
FAN_RUNNING = 1 << 0
SENSOR_VALID = 1 << 1
SYNTHETIC = bytes.fromhex("0300 2909 2a000000")


@dataclass(frozen=True)
class Feedback:
    fan_running: bool
    temp_c: float | None
    producer_seq: int


def decode(payload: bytes) -> Feedback:
    if len(payload) != LAYOUT.size:
        raise ValueError("Assembly 資料長度不符教學映射")
    flags, centi_c, seq = LAYOUT.unpack(payload)
    return Feedback(bool(flags & FAN_RUNNING),
                    centi_c / 100 if flags & SENSOR_VALID else None,
                    seq)


def quality(feedback: Feedback, now: float, received_at: float,
            local_budget_s: float) -> str:
    """使用同一 monotonic 時鐘，只量測最近接收年齡。"""
    if not all(map(math.isfinite, (now, received_at, local_budget_s))):
        raise ValueError("時間須為有限值")
    if local_budget_s <= 0 or received_at > now:
        raise ValueError("須使用同一時鐘且接收時間不得晚於當前時間")
    if now - received_at >= local_budget_s:
        return "STALE"
    return "GOOD" if feedback.temp_c is not None else "BAD_SENSOR"


class Tests(unittest.TestCase):
    def test_known_payload(self):
        self.assertEqual(decode(SYNTHETIC), Feedback(True, 23.45, 42))

    def test_lengths_and_quality_bit(self):
        for invalid in (SYNTHETIC[:-1], SYNTHETIC + b"\0"):
            with self.assertRaises(ValueError):
                decode(invalid)
        bad = decode(LAYOUT.pack(FAN_RUNNING, -123, 7))
        self.assertEqual(bad, Feedback(True, None, 7))
        self.assertEqual(quality(bad, .01, 0, .06), "BAD_SENSOR")

    def test_signed_value_and_local_stale(self):
        result = decode(LAYOUT.pack(SENSOR_VALID, -250, 8))
        self.assertEqual(result, Feedback(False, -2.5, 8))
        self.assertEqual(quality(result, .01, 0, .06), "GOOD")
        self.assertEqual(quality(result, .06, 0, .06), "STALE")
        with self.assertRaises(ValueError):
            quality(result, 0, .01, .06)


if __name__ == "__main__":
    import sys
    if "--test" in sys.argv:
        unittest.main(argv=["lab"])
    else:
        sample = decode(SYNTHETIC)
        print(sample)
        print("接收後 10 ms:", quality(sample, .010, 0, .060))
        print("接收後 80 ms:", quality(sample, .080, 0, .060))

測試涵蓋正負溫度、錯誤長度、感測無效和恰達過期邊界。此例只檢查相同本機時鐘的接收年齡；未驗證來源時間、序號換屆或實際協定交換。

07｜工控驗收：先單設備，再擴大

  1. 記錄機型、韌體、EDS、I/O 實例、位址、尺寸和設備支援的 RPI；保存手冊對照。
  2. 以隔離的試車台核對每一方向的已知輸入與狀態，檢查縮放、空值及品質傳遞。
  3. 增加預期負載，分別觀察 PLC 更新、網路及來源資料年齡；實測丟包、故障及重接前後的行為。

可實跑範例：封裝標頭與 ListIdentity 解析

封裝標頭固定 24 位元組、全部 little-endian；Identity 項目中的 Socket Address 沿用 sockaddr_in，是 big-endian。程式也示範長度欄位與實際資料不符時直接拒絕。

"""組出與解析 EtherNet/IP 封裝標頭與 ListIdentity 回應（離線，標準函式庫 struct）。

封裝標頭固定 24 位元組，全部為 little-endian：
command(2) length(2) session_handle(4) status(4) sender_context(8) options(4)
"""
import struct

HEADER = struct.Struct("<HHII8sI")
LIST_IDENTITY = 0x0063


def build_list_identity(context=b"BMS-0001"):
    return HEADER.pack(LIST_IDENTITY, 0, 0, 0, context, 0)


def parse_header(data: bytes):
    if len(data) < HEADER.size:
        raise ValueError("封包不足 24 位元組")
    cmd, length, session, status, ctx, opts = HEADER.unpack_from(data)
    if len(data) != HEADER.size + length:
        raise ValueError(f"長度欄位 {length} 與實際資料 {len(data) - HEADER.size} 不符")
    return dict(command=hex(cmd), length=length, session=session, status=status, context=ctx)


def parse_identity_item(item: bytes):
    """CIP Identity 項目（Type 0x000C）。Socket Address 為 big-endian，其餘 little-endian。"""
    (version,) = struct.unpack_from("<H", item, 0)
    family, port, ip = struct.unpack_from(">hH4s", item, 2)
    vendor, dev_type, product, rev_major, rev_minor, status, serial, name_len = \
        struct.unpack_from("<HHHBBHIB", item, 18)
    name = item[33:33 + name_len].decode("ascii")
    state = item[33 + name_len]
    return dict(version=version, ip=".".join(map(str, ip)), port=port, vendor_id=vendor,
                device_type=dev_type, product_code=product, revision=f"{rev_major}.{rev_minor:03d}",
                serial=f"0x{serial:08X}", product_name=name, state=state)


def synthetic_response():
    name = b"1756-EN2T/D"
    item = (struct.pack("<H", 1) + struct.pack(">hH4s8s", 2, 44818, bytes([192, 168, 10, 20]), bytes(8))
            + struct.pack("<HHHBBHIB", 1, 12, 166, 11, 2, 0x0030, 0x00C0FFEE, len(name)) + name + bytes([3]))
    cpf = struct.pack("<HHH", 1, 0x000C, len(item)) + item          # item count, type, length
    return HEADER.pack(LIST_IDENTITY, len(cpf), 0, 0, b"BMS-0001", 0) + cpf


if __name__ == "__main__":
    req = build_list_identity()
    print("請求（UDP 44818 廣播）：", req.hex(" "))
    print("請求標頭：", parse_header(req))
    resp = synthetic_response()
    hdr = parse_header(resp)
    print("回應標頭：", hdr)
    count, item_type, item_len = struct.unpack_from("<HHH", resp, 24)
    print(f"CPF 項目數 {count}，型別 0x{item_type:04X}，長度 {item_len}")
    for k, v in parse_identity_item(resp[30:30 + item_len]).items():
        print(f"  {k:<13} {v}")
    try:
        parse_header(resp[:-3])
    except ValueError as e:
        print("截斷封包：", e)

工程現場案例：盤點現場 PLC 與通訊模組

接手一個舊廠區時，常常沒有完整的 PLC 清冊。ListIdentity 是 EtherNet/IP 的唯讀探索指令（UDP 44818），回應包含廠商代碼、產品代碼、韌體版本、序號與產品名稱，可以在不改變設備狀態的前提下建立清冊，並找出韌體過舊、需要評估資安公告的模組。

即使是唯讀探索，也要在維護窗口、經現場同意後進行，並限制在指定網段。廣播封包可能被防火牆或交換器政策阻擋，結果不完整時要用單播逐台確認，不要直接當成「沒有設備」。

  1. 取得網段清單與執行許可，確認不會影響控制網路的頻寬。
  2. 以單播或受控廣播送出 ListIdentity，記錄每台回應的 IP、廠商代碼、產品代碼、韌體版本與序號。
  3. 把韌體版本與廠商資安公告比對，列出需要升級或加強網路隔離的設備。
  4. 清冊與網路圖一起納入變更管理，之後每次異動都更新。

練習題與自我檢查

  1. 為什麼 HEADER 用 "hH4s"？

    看解答

    EtherNet/IP 封裝與 CIP 資料採 little-endian；Socket Address 欄位直接沿用 BSD sockaddr_in 結構，依網路慣例採 big-endian（網路位元組順序）。同一個封包裡兩種順序並存，解析時要分段處理。

  2. 回應標頭的 length 是 51，Identity 項目長度是 45。差的 6 位元組是什麼？

    看解答

    CPF（Common Packet Format）前導：項目數（2 位元組）、項目型別（2 位元組）、項目長度（2 位元組）。

  3. 若產品名稱是 32 個字元，parse_identity_item() 需要修改嗎？

    看解答

    不需要。名稱是 SHORT_STRING，第一個位元組是長度，程式依長度切片；state 也依名稱長度計算位置。但應加上邊界檢查，避免長度欄位大於實際資料。

  4. 為什麼探索時用 ListIdentity，而不是直接讀寫標籤？

    看解答

    ListIdentity 不需要建立 session，也不會讀寫控制資料，對設備影響最小。讀寫標籤需要 RegisterSession 與連線，若路徑或資料型別錯誤，可能影響控制器或產生不預期的寫入。

  5. 把 synthetic_response() 的產品名稱改成 b"1769-L33ER"（10 個字元），Identity 項目長度與回應標頭的 length 各是多少？把回應截掉最後 3 位元組時，parse_header() 的錯誤訊息是什麼？

    看解答

    Identity 項目是 2（版本）＋ 16（Socket Address）＋ 15（廠商到名稱長度）＋ 10（名稱）＋ 1（state）＝ 44 位元組；標頭 length ＝ 6 ＋ 44 ＝ 50。截掉 3 位元組後訊息為「長度欄位 50 與實際資料 47 不符」（已改名稱實際執行驗證）。

    名稱長度改變會連動 state 的位置與兩層長度欄位；parse_identity_item() 依 SHORT_STRING 長度切片，所以不用改，但正式程式仍應檢查 33 ＋ name_len ＋ 1 不超過項目長度。
