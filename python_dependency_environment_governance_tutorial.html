把環境與依賴做成可交付的專案契約

很多 Python 專案不是死在功能，而是死在環境漂移：本機用系統 Python、CI 裝到不同小版號、production dev 套件混裝、requirements 沒 pin、constraints 缺席。這條路線把 runtime baseline、`venv`、requirements 分層、constraints、啟動命令、升級窗口與交付證據收斂成一個可驗證流程。

Overview

依賴與環境不治理，其他測試都不穩

先把 runtime、虛擬環境、requirements、constraints 與啟動命令講清楚，功能驗證才有意義。

Architecture

把 runtime、依賴、啟動與證據拆成四層

專案的可重現性不是單一檔案，而是一整條治理鏈。

Setup

本機就能驗證治理規則

用零外部安裝的標準庫範例，先驗 requirements 契約與 runtime 政策。

Configuration

把 requirements、constraints 與版本基線寫成規則

缺規則時，環境只是暫時可用，不是可交付。

Example

以治理樣板專案驗證依賴與環境契約

範例專案集中展示 runtime、requirements 分層、constraints 覆蓋與報告輸出。

Verification

驗證要覆蓋 compile、unittest、smoke 與 HTML

只看 `pip install` 成功不算治理完成。

Troubleshooting

環境問題要先看契約，再看框架

本機與 CI 不一致時，通常不是框架壞掉，而是依賴治理層鬆散。

Best Practices

讓依賴治理與版本發布同時存在

release note、constraints、runtime baseline 與 smoke evidence 應一起交付。
