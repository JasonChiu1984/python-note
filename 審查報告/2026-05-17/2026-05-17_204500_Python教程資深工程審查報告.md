## 1. Overview

本輪重新從資深工程師角度檢查目前 Python 教程，不再重複找新主題，而是確認目前 `v4.0.0` 的「本地知識庫 MCP 工程」是否真的達到可交付標準。

結論是：教程深度與廣度目前已足夠，`v4.0.0` 對應的本地知識庫教材、匯出腳本、MCP server、單元測試與 smoke 驗證皆已存在；本輪最高優先缺口不是新章節，而是發布清潔度：

- smoke 驗證會在 `knowledge_base/entries/` 留下測試條目
- `knowledge_base/index.json` 會被 smoke 汙染
- 若直接發布，教學範例與驗證殘留會混在正式知識庫內容中

從工程交付角度，這屬於典型的「驗證能跑，但發布不乾淨」問題。建議本輪維持 `v4.0.0`，補上 smoke 自清理與本輪 dated 驗證紀錄，而不是再升新版本。

本輪聚焦缺口：

| 缺口 | 目前狀態 | 補強方向 |

## 6. Troubleshooting

| 問題 | 可能原因 | 處理方式 |
|---|---|---|
| smoke 後多出知識條目 | 驗證腳本未清理輸出 | 在 smoke 結尾刪除 entry 並還原 index |
| 正式知識庫混入測試資料 | 直接用 repo 目錄做驗證但沒回收 | 把清理動作納入 smoke 腳本 |
| 教材已存在但更新紀錄不完整 | 驗證成功後未補 dated 文件 | 新增本輪 `審查報告` / `內容需要更新的部分` / `更新資料` |

## 7. Best Practices

- 驗證資料必須與正式知識庫資料分離，或在驗證結束後自動回收。
- smoke script 不只驗功能，也要驗發布後工作樹是否保持乾淨。
- 教學型 repo 的更新紀錄要能說清楚「新增了什麼」與「清理了什麼」。
