## 1. Overview

目前教材已具備九條主線：初級、中級、高階 100 案例、Cython、NumPy、Pandas、FastAPI、版本現代化、資料庫工程。從專案開發廣度來看，已覆蓋語法、工程化、API、資料、效能、打包、測試、部署、版本治理與資料庫交易邊界。

## 7. Troubleshooting

| 風險 | 處理方式 |
|---|---|
| 批次案例編號錯位 | 用每章 `caseNumbers` 第 10 個案例交叉檢查 |
| 品質面板仍顯示 pending | 確認 `reviewedCaseNumbers()` 納入 `semanticReviewBatchV190` |
| 入口頁與高階頁版本不同步 | 同步更新 `index.html`、高階頁 title/hero/meta、`VERSION` |
| GitHub push 受 DNS 影響 | 先完成 commit/tag；若第一次失敗，重試並回報實際結果 |

## 8. Best Practices

- 版本更新應維持「審查報告 -> 內容需要更新 -> 實作 -> 更新資料 -> commit/tag/push」的可追溯鏈。
- 高階案例的校閱狀態應區分「結構檢查」與「人工語意校閱」，避免把自動檢查誤當內容審查。
- 100/100 後，下一階段若要再提升深度，應改做可執行 sample project 或 pytest artifact，而不是繼續新增案例數。

## 9. Risk Notes

- 本輪只宣告教材內部 100 案例已完成語意校閱，不代表所有案例都有獨立可執行專案。
- 瀏覽器畫面驗證可能受本機 sandbox 限制；若 HTTP bind 或 `file://` 被阻擋，應以 HTML script parse 與資料完整性檢查作為本輪最低驗收。
- 版本標籤應指向主要內容提交；若後續補寫推送結果，需另行記錄，不應改動 tag 對應內容。
