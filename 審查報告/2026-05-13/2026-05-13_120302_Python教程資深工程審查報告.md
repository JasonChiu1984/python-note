## 1. Overview

目前教材已有九條路線：初級、中級、高階 100 案例、Cython、NumPy、Pandas、FastAPI、版本現代化、資料庫工程。v1.9.0 已把高階 100 案例語意校閱收斂到 100/100，表示「案例對題性、失敗路徑、驗收入口與 rollback 脈絡」已完成。

下一個最值得補強的缺口不是再增加案例，而是把「測試工程」做成獨立路線。現有中級與高階教材多次提到 pytest、coverage、CI gate、contract test、mutation testing 與 release evidence，但讀者缺少一條從測試策略、test double、整合測試、品質閘門到交付紀錄的完整可跑教材。

## 3. Workflow

本輪建議以最小安全增量新增第十條路線：

1. 新增 `python_testing_engineering_tutorial.html`。
2. 教材內容聚焦 testing pyramid、fixture、test double、contract test、integration test、coverage、mutation thinking、CI quality gate、release evidence。
3. 新增可執行範例 `範例程式碼/testing_quality_gate/`，使用標準庫 `unittest`、`py_compile` 與 gate script，避免額外套件阻擋本機驗證。
4. 更新 `index.html` 入口與能力地圖。
5. 更新 `VERSION`、`CHANGELOG.md`、本次更新清單與更新紀錄。

## 7. Troubleshooting

| 風險 | 處理方式 |
|---|---|
| 新路線只講理論 | 必須附可執行 sample project 與 gate script |
| 測試工具依賴阻擋本機驗證 | 本輪採標準庫 `unittest`、`py_compile`，正式專案再延伸 pytest / coverage |
| 入口頁版本與路線數不同步 | 同步更新 hero、SVG、卡片、progress 與 meta |
| GitHub push 受 DNS 影響 | 先完成 commit/tag；若 push 失敗，重試並記錄實際結果 |

## 8. Best Practices

- 測試教材應教「如何建立可維護 feedback loop」，不是只列 assertion 語法。
- 測試案例要同時覆蓋正常路徑、錯誤路徑、重試/冪等與 release smoke。
- 交付紀錄要列出實際命令與結果，避免只寫「已測試」。
- 標準庫範例可作為零依賴 baseline，後續再擴充 pytest、coverage、mypy、ruff 與 mutation testing。

## 9. Risk Notes

- 本輪新增的是測試工程 baseline，不宣稱已替所有高階 100 案例建立獨立測試專案。
- 若後續要升級成更接近 production 的測試課程，建議新增 pytest/coverage/ruff/mypy 版本，但應保留本輪零依賴範例作為最低可驗證入口。
