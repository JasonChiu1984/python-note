## 1. Overview

本輪重新從資深工程師角度檢查 Python 教程的專案開發深度、廣度與頁面內部一致性。結論是：教程主題面已足夠，不需要再新增新章節；目前最高優先缺口是發布可追溯性資訊仍有局部漂移。

具體證據有三項。第一，`index.html` 首頁版本說明已來到 `v4.2.1`，但初級主教材 `python_beginner_interactive_tutorial.html`、互動教材別名 `python_interactive_tutorial.html`、中級工程教材 `python_intermediate_engineering_tutorial.html` 的頁內並沒有明確 release version。第二，`python_local_knowledge_base_mcp_tutorial.html` 仍在 `<title>` 與 hero `status-strip` 顯示 `v4.0.0`，與知識庫維護版之後的狀態不一致。第三，首頁總覽文案仍寫「二十八條清楚路線」，但實際首頁共有 `30` 個 `<article class="card">`，且頂層 `python*_tutorial.html` 教材檔也是 `30` 份。

這些問題都不是功能缺陷，但會直接影響交付可讀性、頁面版本辨識與學習路線規劃，因此本輪應以維護版 `v4.2.2` 收斂。

## 6. Troubleshooting

| 問題 | 可能原因 | 處理方式 |
|---|---|---|
| 首頁路線數與實際檔案數不一致 | 新增教材後只更新卡片，未同步更新總覽文案 | 將路線數改由實際盤點結果回填 |
| 核心教材頁看不出發布版次 | 歷史主頁較早建立，未納入後續 version trace 慣例 | 在 title、hero、footer 補齊 release marker |
| 知識庫章節看起來停在舊版 | 維護版只改 repo 發布內容，未同步章節標示 | 更新單頁 title 與 status strip |

## 7. Best Practices

- 教材入口頁的總覽數字必須和實際卡片數、實體教材檔數同步。
- 早期建立的核心教材頁若沒有 release marker，後續維護版應補齊，避免首頁與單頁版本訊息分裂。
- Patch 版發布也應留下 dated 審查、修正清單、更新紀錄與驗證證據。

## 8. 審查結論

Python 教程目前在專案開發深度與廣度上仍符合交付要求。本輪最合理的修正不是增加新主題，而是收斂資訊一致性缺口：修正首頁 28/30 路線數錯誤、補齊初級與中級核心教材頁版本追溯、對齊本地知識庫教材頁版本標示、補齊 `v4.2.2` 維護版紀錄並完成發布。
