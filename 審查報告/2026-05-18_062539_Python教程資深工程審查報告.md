## 1. Overview

本輪重新從資深工程師角度檢查目前 Python 教程。經過 `v4.1.0` 的 CLI 自動化工程補強後，單點工程主題已經相當完整，下一個最高價值缺口不再是新增零散技術，而是補一條把既有章節收斂成可交付 reference project 的整合式藍圖。

目前教材已涵蓋：

- 測試、可觀測性、安全、非同步、發布、工業資料閘道、工作流、批次排程、型別契約、資料演進、設定治理、本地知識庫 MCP、CLI 自動化。

但從實際專案開發與交付角度，仍有三個明顯缺口：

- 缺少一條把既有章節整合成 reference project 的教學路線
- 缺少一個可直接作為新專案起始骨架的最小範例
- 缺少一份明確示範 release evidence、runbook、fail-safe、更新紀錄如何一起交付的教材

因此，本輪建議新增 `Project Delivery Blueprint` 教材與對應範例，作為全教程的整合交付入口。

## 6. Troubleshooting

| 問題 | 可能原因 | 處理方式 |
|---|---|---|
| 教材章節很多但學員不會整包交付 | 缺少 reference project | 用整合式 blueprint 收斂 |
| 每章都有測試，但不知道最後交什麼 | release evidence 沒被教成固定輸出 | 在範例中明確產生 evidence payload |
| 範例只講框架，不講責任邊界 | config / domain / service 沒拆開 | 用最小標準庫骨架先收斂邊界 |

## 7. Best Practices

- 先讓骨架可交付，再決定要不要疊 FastAPI、DB、message broker。
- 教學型 repo 若已具足夠廣度，下一步應補「整合與交付」，不是無止境加主題。
- reference project 必須同時具備 README、測試、smoke、更新紀錄與首頁入口，才算真正完成。

## 8. 審查結論

本輪建議升版到 `v4.2.0`，新增 `Project Delivery Blueprint` 教材與 reference project 範例，補足目前 Python 教程在「跨章節整合式專案交付」上的明顯缺口。
