## 6. Troubleshooting

| 問題 | 風險說明 | 處理方式 |
|---|---|---|
| search 命中率低 | metadata 過弱或 index 未同步 | 強化 `title`、`summary`、`tags` 並統一由匯出腳本更新 |
| read 找不到條目 | caller 直接猜檔名 | 一律先走 `search` 或讀 `index.json` 取得正式 `id` |
| MCP client 無回應 | stdio framing 錯誤 | 優先檢查 `Content-Length` 與 header 空行 |
| 知識庫內容漂移 | 人工直接改 entry 檔 | 維持 append-oriented 流程，只透過匯出腳本新增 |

## 7. Best Practices

- 教材必須對應實際倉庫能力，不能只放概念頁。
- `Markdown + JSON` 是本地知識治理的最小可用交付格式。
- `index.json` 應視為正式 metadata contract，而不是暫存副產品。
- `search` / `read` 驗證必須包含真實協定往返，不只看函式回傳。
- 審查報告、更新紀錄與知識庫 entry 應能相互引用，形成可交接證據鏈。
