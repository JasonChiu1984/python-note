## 1. Overview

本輪在 `v3.7.0` 已完成首頁一致性修正後，重新從專案開發深度與廣度角度審視整體教程。結論是：目前 API、資料、部署、可靠性、治理與工業應用主題已具相當深度，但仍缺一條專門處理「長期批次與排程工作」的獨立教材。

現有內容雖然分散提過：

- 高階案例中的 reconciliation、backfill、scheduler 類情境
- 非同步並發中的 worker lifecycle 與 queue backpressure
- 事件驅動可靠性的 retry、dead-letter、replay
- 資料演進治理中的 checkpoint 與回補

但缺少一條把批次作業本身的工程邊界講完整的正式路線，尤其是：

- schedule contract
- lease / worker ownership
- checkpoint / resume
- retry budget / dead-letter isolation
- backfill window / rerun evidence
- operator handoff

這是大型 Python 專案中非常常見、也非常容易在沒有框架時被做成脆弱背景腳本的區域。從資深工程師角度看，這是目前最值得補的高價值缺口。建議本輪更新為 `v3.8.0`。

## 7. Troubleshooting

| 問題 | 可能原因 | 處理方式 |
|---|---|---|
| 同一批次工作被重複跑 | 缺 lease / worker ownership | 補互斥 lease 與 owner 紀錄 |
| 工作中斷後從頭重跑 | 缺 checkpoint / resume | 補 checkpoint key 與 resume 邏輯 |
| 壞資料讓整批卡住 | 缺 retry budget 與 dead-letter | 補失敗隔離與 rerun runbook |
| 回補完成但無法交接 | 缺 rerun evidence | 補 report 與更新紀錄摘要 |

## 8. Best Practices

- 批次與排程工作要被當成正式產品功能，而不是背景腳本。
- lease、checkpoint、retry budget 與 dead-letter 要一起設計，不要各自零散出現。
- backfill 要明確界定 window、owner、reason 與驗收證據。
- smoke script 的成功輸出應可直接進 release note 與更新紀錄。
