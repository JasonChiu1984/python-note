- 版本基準：上一輪已發布 `v0.5.0`，目前工作樹已新增 NumPy、Pandas 與 FastAPI 專題內容

## 一、總結結論

目前教程已從四路線擴展成七路線：初級、中級、高階、Cython、NumPy、Pandas、FastAPI。以資深工程師角度看，主線深度已能覆蓋一般 Python 專案開發、測試、並發、打包、效能熱點、資料處理、資料工具交付與 API service 交付。

本輪最需要修正的不是再增加更多語法卡片，而是把新加入的 NumPy / Pandas 專題從「完整教材頁」推進到「可對照專案交付」，並把 FastAPI 專題正式接回入口。Cython 已有 `範例程式碼/cython_so_example/`，但 NumPy / Pandas 還缺同等級的最小可讀專案。若沒有實體範例資料夾，讀者會看到很多 production slice，但不容易直接對照 `pyproject`、`src/`、`tests/`、sample data 與 CLI 邊界。

## 三、教程內部缺失

### P1：NumPy / Pandas 缺少可對照的最小專案

目前 `範例程式碼/` 只有 Cython 範例。NumPy 與 Pandas 雖然都有 production slice，但資深工程教材需要讓讀者看到：

- `pyproject.toml` 如何宣告 runtime dependencies 與 console script。
- `src/` package boundary 如何切出純函式與 CLI。
- `tests/` 如何驗 shape、dtype、schema、missing policy、join/quality gate。
- `samples/` 如何保存固定 input，讓 wheel、PyInstaller 或 CLI smoke test 有共同驗收資料。

### P1：入口與專題頁版本需要統一

目前入口、NumPy、Pandas、FastAPI 的版本狀態不一致。若本輪補上兩個實體資料專案並納入 FastAPI 專題，應升版為 `v0.9.0`，並在入口說明這是「API service 專題納入 + 資料工程範例專案補強」。

### P2：資料專題頁需要明確連回範例程式碼

NumPy / Pandas 頁面已有打包與案例段落，但讀者需要在頁面中直接看到範例專案入口：

- NumPy：CSV 特徵矩陣、shape/dtype contract、`.npy` cache、JSON stats、CLI。
- Pandas：orders CSV、schema 驗證、missing policy、營收彙總 JSON、quality summary、CLI。

### P2：FastAPI 教材需要正式出現在入口

`python_fastapi_engineering_tutorial.html` 已具備 36 個 lesson id、進度 key `python-fastapi-completed` 與專案級 API service 內容。入口需要補卡片、路線圖節點與 `showProgress("fastapiProgress", "python-fastapi-completed", 36)`，避免讀者不知道此專題存在。

### P2：驗證流程需要涵蓋新增範例

本輪驗證不應只檢查 HTML script parse，也要檢查新增範例專案的 Python 檔案可解析，並確認 sample data 與 README 存在。若本機沒有 NumPy / Pandas runtime，不應假裝 pytest 已跑過，應明確記錄依賴門檻。
