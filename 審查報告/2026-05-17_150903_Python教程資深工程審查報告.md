## 1. Overview

本輪不是單純再找一個抽象主題補課，而是重新站在資深工程師角度檢查目前工作樹的「實作與教材是否一致」。

結論是：教程的深度與廣度已經很完整，涵蓋語法、服務、資料、部署、治理、可靠性、工業通訊、批次與工作流；但目前倉庫內其實已經存在一套可交付的本地知識庫能力：

- `knowledge_base/`
- `scripts/export_conversation.py`
- `mcp_server/knowledge_base_server.py`

這套能力已經具備：

- 對話匯出成 `Markdown + JSON`
- `index.json` 索引維護
- `search` / `read` 兩個 MCP 工具
- 可供 Codex / Claude / Cursor 指向同一份本地知識來源

但首頁教程路線尚未把這條能力納入正式教材，造成「倉庫已有實作，教程卻沒有對應學習路徑」的落差。從專案開發深度與交付一致性看，這是目前最高價值、且最適合本地驗證的缺口。建議本輪更新為 `v4.0.0`。

import json
import subprocess
import sys

def send(proc, payload):
    body = json.dumps(payload, ensure_ascii=False).encode("utf-8")
    proc.stdin.write(f"Content-Length: {len(body)}\r\n\r\n".encode("utf-8"))
    proc.stdin.write(body)
    proc.stdin.flush()

def recv(proc):
    headers = {}
    while True:
        line = proc.stdout.readline()
        if not line:
            raise RuntimeError("no response")
        text = line.decode("utf-8").strip()
        if not text:
            break
        name, value = text.split(":", 1)
        headers[name.lower()] = value.strip()
    length = int(headers["content-length"])
    return json.loads(proc.stdout.read(length).decode("utf-8"))

    [sys.executable, "mcp_server/knowledge_base_server.py"],

## 7. Troubleshooting

| 問題 | 可能原因 | 處理方式 |
|---|---|---|
| `search` 找不到條目 | title/summary/tags 太弱，或 index 未更新 | 重新匯出並補齊 metadata |
| `read` 回傳 not found | 查詢時用錯 `entry id` | 從 `index.json` 取正式 id |
| 不同工具讀到不同內容 | JSON/Markdown 或 index 格式漂移 | 只透過匯出腳本更新條目 |
| MCP server 啟動後找不到知識庫 | `cwd` 不對或相對路徑錯誤 | 固定 client `cwd` 到專案根目錄 |

## 8. Best Practices

- 先穩定 `entry`、`index`、`search/read` 三個契約，再擴張功能面。
- 人類閱讀與工具查詢要雙保留，因此 `Markdown + JSON` 是合理基本盤。
- `id`、`title`、`summary`、`tags` 應在匯出時補齊，不要事後人工修補。
- 教材要直接對應倉庫內真實實作，避免「學的是一套、用的是另一套」。
