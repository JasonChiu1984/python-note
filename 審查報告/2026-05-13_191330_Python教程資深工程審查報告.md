## 1. Overview

本次以「能否支撐真實專案開發、交付、維運與回溯」為標準重新檢查教材。既有教材已從基礎語法延伸到中級工程、高階 100 案例、Cython、NumPy、Pandas、FastAPI、版本現代化、資料庫、測試、可觀測性、安全、非同步並發、發布、工業資料閘道與部署執行環境。

結論：廣度已符合完整 Python 工程學習路線，專案開發深度也已明顯超過一般語法教程。剩餘最大缺口不是單一語法或框架，而是 CI/CD 品質閘門的獨立課程：目前測試、發布與部署章節都有提到 gate，但缺少一條把 lint、compile、unit test、coverage、版本矩陣、artifact evidence 與 GitHub Actions workflow 串成可執行交付流程的主線。

## 2. Architecture

目前教材架構可分為四層：

| 層級 | 既有內容 | 審查結果 |
|---|---|---|
| 基礎能力 | 初級、中級、100 高階案例 | 符合，可支撐由語法到架構思考 |
| 專題能力 | Cython、NumPy、Pandas、FastAPI、資料庫、非同步 | 符合，可覆蓋常見 Python 專案類型 |
| 交付能力 | 測試、可觀測性、安全、發布、部署 | 大致符合，但 CI/CD gate 仍分散 |
| 工業場域 | 工業資料閘道、Modbus、OPC UA、BACnet、MQTT | 符合本專案知識庫方向 |

建議新增一條獨立路線：

```text
source change
  -> local quality gate
  -> test / coverage / matrix
  -> artifact evidence
  -> CI workflow
  -> release decision
```

現有教材在設定管理方面已涵蓋：

- runtime env config
- deployment env var validation
- secret redaction

缺少的設定面向：

| 缺口 | 風險 | 建議補強 |

## 5. Example

建議新增標準庫範例專案 `範例程式碼/ci_quality_gate/`，避免依賴外部套件或網路，讓學生在本機即可驗證品質閘門概念。

範例應包含：

| 檔案 | 用途 |
|---|---|
| `src/ci_quality_gate/checks.py` | py_compile、unittest、coverage policy、matrix policy、evidence manifest |
| `src/ci_quality_gate/pipeline.py` | pipeline job 編排與 fail-fast 行為 |
| `scripts/run_ci_gate.py` | 一鍵 local gate |
| `tests/test_ci_quality_gate.py` | regression coverage |
| `.github/workflows/python-ci.yml` | 可讀的 GitHub Actions workflow 範本 |

## 7. Troubleshooting

| 問題 | 可能原因 | 處理方式 |
|---|---|---|
| 本機 gate 通過但 CI 失敗 | Python 版本、作業系統或路徑差異 | 在 workflow 明確寫 matrix 與 working-directory |
| coverage gate 誤判 | coverage 未產生或門檻與風險不匹配 | 先以 module/function coverage policy 示範，再接第三方工具 |
| beta lane 失敗導致 release 卡住 | beta preview 不應阻擋正式發布 | 將 3.15 beta lane 標示為 non-blocking readiness |
| artifact evidence 不完整 | CI 只看 pass/fail | 寫入 gate report、version、commit、command 與結果 |

## 8. Best Practices

- CI/CD 教材要從 workflow contract 開始，而不是只展示 YAML。
- stable runtime lane 應阻擋 release；beta preview lane 應用於相容性預警。
- local quality gate 應與 CI command 對齊，避免「本機可過、CI 不可過」。
- 每次 release 都應保存 gate evidence，包含版本、命令、結果、失敗原因與是否允許例外。
- 對工業或現場系統，CI gate 應保留 timeout、rollback、config validation 與 smoke test 的證據欄位。

## 9. 審查結論
