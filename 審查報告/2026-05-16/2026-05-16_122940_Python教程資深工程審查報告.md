## 4. Configuration

仍需補強的設定與驗收面向：

| 設定缺口 | 風險 | 建議補強 |
|---|---|---|
| schema version policy | 新舊版本同時存在時讀寫不一致 | 用 manifest 明確列出 from/to version 與相容策略 |
| expand / contract discipline | 直接刪欄位造成舊版失效 | 先 expand，再 backfill，最後 contract |
| backfill checkpoint | 長任務中斷後重跑成本高 | 保留 last_processed_id、dry-run 與報告 |
| rollback validation | 只會回退程式，不會回驗資料 | 補 reverse compatibility read 與 backup 驗證 |
| industrial fail-safe | 資料演進時誤寫現場控制欄位 | 區分 command path 與 telemetry path，採保守預設 |

## 7. Troubleshooting

| 問題 | 可能原因 | 處理方式 |
|---|---|---|
| 新版讀不到舊資料 | compat reader 缺失 | 補 schema-version aware adapter |
| backfill 中斷後重跑很慢 | 沒 checkpoint 或 dry-run | 寫入 checkpoint 並記錄 last_processed_id |
| 部署回退後資料無法讀回 | 只有 forward migration | 補 rollback 驗證與 reverse read 測試 |
| staging 正常、prod 失敗 | preflight 漏掉 drift | 比對 manifest 與實際資料欄位 |
| 工業欄位升版後誤觸控制 | command 與 telemetry 沒隔離 | 對控制欄位採保守預設與顯式開啟 |

## 8. Best Practices

- 資料演進不是單一 migration script，而是版本契約、資料驗證、backfill 與 rollback 的組合工程。
- 先補相容讀寫與報告，再做 destructive change，不要把刪欄位當第一步。
- backfill 任務要能中斷續跑、輸出報告、重新驗收；否則不算 production-ready。
- 工業自動化場景下，涉及控制命令或現場設備配置的欄位演進，必須以 fail-safe 與回退證據為優先。
