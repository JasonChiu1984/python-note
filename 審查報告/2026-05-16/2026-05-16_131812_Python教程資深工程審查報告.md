## 1. Overview

本次針對既有 `Industrial Data Gateway` 路線重新校閱，不是找新的工程主題，而是確認工業協定內容是否足夠支撐使用者在專案初期做協定選型、跨協定資料對齊與現場部署心智建模。

結論：現有工業資料閘道頁已覆蓋 Modbus、OPC UA、BACnet、MQTT 的個別 lesson card，但仍缺少一個把四種協定放在同一張工程地圖中比較的總覽層。當前教材較適合各別查閱，不利於使用者先建立全局分工心智。

## 2. Architecture

現有工業教材架構審查：

| 層級 | 既有內容 | 審查結果 |
|---|---|---|
| Gateway 概念 | Hero 架構圖、protocol cards、sample project | 已有基礎 |
| 單一協定知識 | Modbus / OPC UA / BACnet / MQTT 各 4 張 lesson card | 已具最小深度 |

## 7. Troubleshooting

| 問題 | 可能原因 | 處理方式 |
|---|---|---|
| 使用者分不清 OPC UA 與 MQTT | 只講 API 名稱，沒講資料模型差異 | 補角色分工圖與比較表 |
| BACnet 被誤解成純點位讀寫 | 沒補 routing / BBMD / FD | 補樓控拓樸說明 |
| Modbus 內容看起來太像一般 TCP client | 沒講 register / word order 心智 | 補格式對照與常見錯誤 |
| index 找不到比較入口 | 只改內頁沒改入口 | 補工業卡片第二入口與獨立卡片 |

## 8. Best Practices

- 比較工業協定時，先看它解決哪一層問題，再看 port 與 library。
- 沒有位址表示對照，就不要宣稱跨協定資料整合已可維護。
- 沒有拓樸與維運風險比較，就不要把協定選型當成單純 API 決策。
- Python 在這類場景最有價值的角色是 adapter、normalizer、publisher、client，不是盲目替代全部現場控制器。

## 9. 審查結論
