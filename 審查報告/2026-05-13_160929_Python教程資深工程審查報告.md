## 3. 需要更新的部分

### P1：新增 Packaging / Release Engineering 路線

應新增一個自包含 HTML 教材，主題包含：

- `pyproject.toml` metadata contract
- package layout、import boundary、entry point
- semantic version 與 tag policy
- changelog gate 與 release note evidence
- source archive / wheel / executable 的取捨
- deterministic artifact 與 SHA-256 checksum
- manifest、SBOM、dependency evidence
- CI release gate、smoke、rollback 與 promotion
- publish 前後的驗證與風險紀錄

### P1：新增可本機驗證的標準庫範例

應新增 `範例程式碼/packaging_release_engineering/`，以標準庫示範：

- 讀取 `pyproject.toml` 與 package `__version__`
- 驗證版本一致性
- 驗證 `CHANGELOG.md` 是否有對應版本
- 建立 deterministic source archive
- 產生 SHA-256 checksum 與 release manifest
- `unittest` 覆蓋版本 mismatch、manifest 與 archive 行為
- smoke script 驗證整體 release gate

### P2：更新入口與版本資訊

`index.html` 需要更新：

- route count 從十三條改成十四條
- 新增 Packaging Release Engineering 卡片
- SVG 路線圖新增 Packaging 節點
- progress key 新增 `python-packaging-completed`
- 版本狀態更新到 `v2.4.0`

`VERSION` 與 `CHANGELOG.md` 需要標註 `v2.4.0`。

## 6. 風險與注意事項

- 發布工程教材不應只停在 `python -m build` 指令列表，必須教 artifact evidence 與 release gate。
- 範例需避免第三方套件依賴，確保本地自動化可重跑。
- source archive 不能把 `dist/`、`__pycache__`、`.pyc` 等產物包回去。
- release gate 應明確區分本地可驗證項目與需要外部 PyPI/GitHub 權限的項目。
