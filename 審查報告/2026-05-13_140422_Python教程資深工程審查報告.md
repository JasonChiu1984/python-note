## 1. Overview

目前教材已形成十一條主線：初級、中級、高階 100 案例、Cython、NumPy、Pandas、FastAPI、版本現代化、資料庫工程、測試工程、可觀測性與維運工程。v2.1.0 已把上線後診斷、SLO、health check、runbook 與 incident evidence 補成獨立路線，專案從「能開發、能測試、能觀測」的主線已相當完整。

下一個專案開發深度缺口是「安全工程與供應鏈治理」。現有高階案例與 FastAPI 教材有提到 security、RBAC、input size、PII masking、dependency vulnerability gate，但缺少一條能從 threat model、authn/authz、input validation、secret handling、dependency manifest、audit log、rate limit 到 incident evidence 的獨立可驗證路線。對 production Python 專案而言，安全不應只是部署前掃描，而應進入需求、程式、測試、交付與維運證據。

## 7. Troubleshooting

| 風險 | 處理方式 |
|---|---|
| 教材變成安全名詞表 | 每個主題都綁定可測控制與交付證據 |
| password 範例誤導 | 使用 PBKDF2 + salt + iterations，並明確標示 production 可改用 bcrypt / Argon2 |
| authorization 散落在 controller | 以 `RolePolicy` 集中規則並用 deny-by-default 測試 |
| audit log 洩漏敏感資訊 | 範例使用 redaction，測試確認 token 被遮罩 |
| GitHub push 受 DNS 影響 | 先完成 commit/tag；若 push 失敗，重試並記錄實際結果 |

## 8. Best Practices

- 安全教材應教「如何把風險轉成控制與證據」，不是只列工具名稱。
- 身分驗證、授權、輸入驗證、secrets 與供應鏈應分層設計，避免全部塞進 handler。
- 對外錯誤回應要安全，內部 audit/log 才保留 trace id 與必要診斷資訊。
- dependency manifest、hash、弱點掃描與 release note 應成為交付證據。
- 更新紀錄與 release note 應列出實際 smoke、test、quality gate 與已知安全限制。

## 9. Risk Notes

- 本輪新增的是安全工程 baseline，不宣稱已完成 OIDC/OAuth2、JWT rotation、SAST/DAST、container scan、KMS 或雲端 secret manager 整合。
- 後續若要接近 production，可再新增 FastAPI security middleware、OpenID Connect、pip-audit/OSV、SBOM、Sigstore、KMS 與 SIEM 告警專題。
