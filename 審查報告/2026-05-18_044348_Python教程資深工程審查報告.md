## 1. Overview

本輪從資深工程師角度重看整體 Python 教程與目前交付狀態。結論是：教程主題深度與廣度目前已達可交付水準，不需要再硬補新主題；目前最需要收斂的是發布內容純度。

上一輪指出的 smoke 自清理缺口已經補上，`scripts/run_knowledge_base_mcp_smoke.py` 會在驗證後刪除暫存 entry 並還原 `knowledge_base/index.json`。但正式知識庫仍保留了 `knowledge-base-demo`、`knowledge-base-export-demo` 這類示範/驗證條目，造成「正式知識」與「驗證樣本」混放。

從專案交付角度，這會讓後續使用 MCP 查詢時把 demo 結果誤當正式知識，屬於發布清潔度缺陷。本輪應以維護版處理此問題，建議升為 `v4.2.1`。

## 6. Troubleshooting

| 問題 | 可能原因 | 處理方式 |
|---|---|---|
| MCP 搜尋結果出現 demo 條目 | 正式索引保留驗證資料 | 清理 `index.json` 與對應 entry 檔 |
| smoke 跑完工作樹變髒 | 驗證腳本未回收暫存資料 | 維持現有自清理流程並驗證 `git diff --check` |
| 教學內容正確但發布結果不專業 | 將教學示範檔直接納入正式資料集 | 把示範檔視為暫存或外部教學附件 |

## 7. Best Practices

- 教學 repo 的知識庫示範資料，應與正式可查詢知識條目嚴格分離。
- smoke script 的完成定義，除了功能通過，還要包含資料回收與工作樹清潔。
- 維護版發布應聚焦可交付品質，不必為了升版而硬加新章節。

## 8. 審查結論

Python 教程目前在專案開發深度與廣度上已符合交付要求。本輪最合理的修正不是擴張主題，而是完成知識庫發布純度收尾：移除 demo/export 驗證資料、補明文件規範、留下 dated 維護版紀錄，並以 `v4.2.1` 發布。
