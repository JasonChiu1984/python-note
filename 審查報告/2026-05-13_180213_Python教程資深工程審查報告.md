## 1. 總體結論

目前教程已涵蓋 Python 初級語法、中級工程化、高階 100 案例、Cython、NumPy、Pandas、FastAPI、版本現代化、資料庫、測試、可觀測性、安全、非同步並發、發布工程與工業資料閘道。以資深工程師角度來看，教材主幹已能支撐一般後端、資料處理、可靠性、資安、發布與工業協定 gateway 的學習路線。

本輪從 production 專案交付閉環重新校閱，最大的本機可驗證缺口是「部署與容器化執行環境」。現有 `FastAPI` 提到部署，`Packaging Release` 處理 artifact，`Observability` 處理上線後診斷，但尚未有一條獨立路線教學員如何把 Python service 放進可重跑、可健檢、可停止、可設定、可回復的 runtime。

## 3. 需要更新的部分

### P1：新增 Deployment Runtime 路線

應新增一個自包含 HTML 教材，主題包含：

- Python service runtime 架構與責任邊界
- Dockerfile layer、base image、`.dockerignore`、non-root user
- environment config、secret boundary、config validation
- process model、signal handling、graceful shutdown
- health check、readiness、dependency degraded 狀態
- structured log stdout/stderr 與 container log policy
- resource limits、CPU/memory request、timeout、restart policy
- Docker Compose service、network、volume、port 與 dependency order
- CI deployment gate、image tag、digest、rollback 與 release evidence
- industrial edge deployment 注意事項：gateway offline mode、site config、maintenance handover

### P1：新增可本機驗證的標準庫範例

應新增 `範例程式碼/deployment_runtime_service/`，以標準庫示範：

- 可從環境變數載入 runtime config
- 內建 HTTP `/healthz` 與 `/readyz`
- structured JSON log
- graceful shutdown signal handling
- dependency health 狀態模型
- Dockerfile、Compose 與 `.dockerignore` 的靜態驗證
- `unittest` 覆蓋 config、health/readiness、manifest 與 deployment file validation
- smoke script 驗證本機 runtime contract

## 6. 風險與注意事項

- 若本機環境無 Docker daemon，不應宣稱已完成真實 image build；本輪以 Dockerfile/Compose 靜態契約與 Python runtime contract 驗證為主。
- container 教材需避免把 secret 寫入 image、log 或 compose 明文範例。
- readiness 與 liveness 必須分開，避免 dependency degraded 時造成錯誤重啟策略。
- graceful shutdown 應包含 timeout，避免 worker 在部署替換時無限等待。
