Python Deployment Runtime

把 Python 服務放進可驗證的執行環境

這條路線把 Python 專案從 artifact 推進到可部署 runtime：Dockerfile、Compose、env config、health/readiness、structured log、SIGTERM graceful shutdown、resource limit、restart policy、image tag/digest、rollback 與 site handover。範例專案只使用標準庫，可在沒有 Docker daemon 的環境先驗證 runtime contract。

Runtime

先定義服務在執行環境中的責任

runtime contract 要說清楚 process、port、config、log、health 與 shutdown 行為。

Docker

Dockerfile 是可稽核的執行環境規格

base image、layer、non-root、copy boundary 與 healthcheck 都會影響 production 風險。

Config

設定要從 image 中分離出來

環境變數、secret、site config 與 dependency 狀態要有驗證規則與錯誤輸出。

Health

liveness 和 readiness 不是同一件事

健康檢查決定平台是否重啟 process；就緒檢查決定是否接流量。

Operations

容器上線後要可診斷、可停止、可限制

log、signal、resource、restart 與網路邊界是 runtime 維運的核心。

Delivery

部署要保留 tag、digest、smoke 與 rollback 證據

交付記錄要能回答部署了哪個 image、怎麼驗、失敗怎麼退。
