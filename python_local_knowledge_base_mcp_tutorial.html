MCP Server：從協定到可執行服務

認識 Host、Client、Server 三層角色，依 MCP 2026-07-28 規格的無狀態請求、server/discover 與 JSON-RPC，走到有權限邊界的工具服務。附 MCP Python SDK 2.3.0 可實跑範例與驗收客戶端。

看架構與流程開啟 Python 範例比較常見伺服器
01 / MCP SERVER

Server 的角色與責任

MCP 是 Host 將外部能力接入模型工作流程的標準介面，不是模型、資料庫或遠端 shell。Host 管理 UI、模型、安全決策與同意；Client 在每個請求宣告協定版本與能力並交換 JSON-RPC；Server 封裝外部能力並在執行前驗證授權。模型提議呼叫不等於執行權限。

角色負責不該負責
Host模型、對話、同意、權限選擇、隔離 Server 的可見資料不可把任意 Server 回傳文字當可信指令
Client連線、server/discover、每請求的版本與能力宣告、請求對應 ID 與逾時不可把成功回覆等同使用者已批准
ServerSchema、授權、執行、結果與審計；連接已核准的資料來源不可讀取授權外資料或因參數看似合法就跳過政策檢查
02 / MCP SERVER

架構圖與協定流程

讀路徑限定在 MCP Server 授權及驗證層之後；索引不直接交給模型或工具。寫入與高影響工具另行建模，在 Server 執行前驗證權限與業務條件。

資料與責任架構

  1. MCP Host應用介面與核准
  2. MCP Client連線與每請求的版本宣告
  3. MCP Server驗證身分、Schema 與資源範圍
  4. 資料來源授權後讀取合成資料或指定索引

資料準備路徑可另做 Conversation Export → Normalized JSON / Markdown → Index；Client Tools 只經 MCP Server 讀資料，驗證證據另存，不等同直接授權讀索引。

請求生命週期（2026-07-28 起無狀態）

2026-07-28 規格移除了 initialize／notifications/initialized 握手與協定層會話。每個請求各自在 _meta 帶協定版本及 client 能力（沒有能力時傳空物件）；不必綁在建立會話的單一實例。跨實例仍須一致部署，驗證授權並共用必要的應用狀態。

  1. ① discover（建議）Client 送 server/discover；Server 回 supportedVersions、capabilities，並在 _meta 帶 serverInfo
  2. ② 每請求宣告tools/list、tools/call 等請求都在 _meta 帶 io.modelcontextprotocol/protocolVersion 及 io.modelcontextprotocol/clientCapabilities
  3. ③ 版本不符Server 回 UnsupportedProtocolVersionError（-32022），data.supported 列出可用版本，Client 改用其一重送
  4. ④ 需要補資料Server 不再主動發請求；改回 resultType: "input_required"，Client 帶 inputResponses 重送原請求（MRTR）
  5. ⑤ 斷線沒有會話可恢復，進行中的請求以新 id 重送；有副作用的呼叫先確認冪等再重試
介面用途方法／結果
Tools受允許的動作，模型可提議，Host/Server 必須控權tools/list、tools/call；inputSchema／outputSchema 可用任何 JSON Schema 2020-12 關鍵字；列表結果帶 ttlMs 與 cacheScope 快取提示，並建議固定順序
Resources提供已授權、可定位的資料；URI 不是存取憑證resources/list、resources/read；可以另提供 resource template
Prompts使用者可選擇的提示模板，不代表閘道授權prompts/list、prompts/get；不要把不可信插值當規則
Client → server/discover (id=1，_meta: protocolVersion=2026-07-28 + clientCapabilities={}) → Server
Server → result (id=1，supportedVersions、capabilities、ttlMs、cacheScope；_meta: serverInfo) → Client
Client → tools/list (id=2，_meta: protocolVersion + clientCapabilities) → Server
Client → tools/call (id=3，已驗證的參數，_meta 同上) → Server
Server → result (id=3，resultType: "complete"，structuredContent) → Client

從 2025-11-25 遷移時改了什麼

項目2025-11-25（舊）2026-07-28（現行）
建立連線initialize → notifications/initialized無握手；可先呼叫 server/discover
版本與能力握手時協商一次每個請求的 _meta 都帶；HTTP 另有 MCP-Protocol-Version 標頭
HTTP 會話Mcp-Session-Id移除；需要跨呼叫狀態時由 Server 發出明確的 handle，當作一般工具參數傳遞
HTTP 標頭MCP-Protocol-VersionPOST 另須帶 Mcp-Method、Mcp-Name
Server 向 Client 要資料Server 發 sampling／elicitation／roots 請求MRTR：回 input_required，Client 重送原請求
變更通知HTTP GET 串流、resources/subscribesubscriptions/listen 長連線
已移除ping、logging/setLevel、SSE 續傳（Last-Event-ID）日誌等級改由每請求 _meta 的 io.modelcontextprotocol/logLevel 指定
列為 Deprecated—Roots、Sampling、Logging、舊 HTTP+SSE 傳輸；新實作不要採用
結果格式—所有結果必帶 resultType；Client 對舊 Server 缺欄位時視為 "complete"

相容性：同時支援兩代的「dual-era」Client 可先探測並依傳輸規格判斷是否退回 initialize。MCP Python SDK 2.x 的 Client(mode="auto") 就是這個行為，2.x 的 Server 也仍接受舊 Client 的 initialize。

安裝、版本與啟動

以下範例採官方 MCP Python SDK 2.3.0（支援 Python 3.10 以上），預設使用 2026-07-28 規格。SDK 套件版號與 MCP 協定日期版本是兩回事，測試輸出以實際取得的協定版本驗證。1.x 系列仍有維護版（例如 1.30.0），但只支援 2025-11-25 以前的握手式規格；SDK 2.x 把 FastMCP 改名為 MCPServer，Client 端改用高階 Client。用獨立虛擬環境從可信來源安裝；正式環境另外維護 lockfile、雜湊及更新流程。

04 / MCP SERVER

傳輸與部署設計

以 stdio 跑本地單使用者工具，只有需要獨立服務或跨機器時才評估 Streamable HTTP。不能直接把本機示範升格為公開服務。

傳輸如何運作上線做法
stdioClient 啟動 Server 子程序；stdin/stdout 採逐行 JSON-RPC 訊息，不能把日誌印到 stdout。版本與能力都在訊息本文的 _meta，沒有標頭層用 stderr 記錄；使用絕對命令路徑、受控工作目錄和最小權限 OS 使用者，不沿用自訂 Content-Length 分幀；stdin 關閉時 Server 應立即結束
Streamable HTTP單一 MCP 端點收 POST，每個 POST 帶 MCP-Protocol-Version、Mcp-Method（工具呼叫再加 Mcp-Name）；舊的 GET 串流改由 subscriptions/listen 取代。本例用 /mcp、本機 loopback驗證 Origin（有提供時）並限制綁定；跨機器採 HTTPS、認證、授權、限流與資源限額。無狀態設計可直接放在一般 round-robin 負載平衡器後面
  • 2026-07-28 已移除 Mcp-Session-Id。需要跨呼叫的狀態時，由 Server 產生明確的 handle，當成一般工具參數傳遞，並驗證它屬於目前的使用者。
  • HTTP 標頭的 MCP-Protocol-Version、Mcp-Method、Mcp-Name 必須與本文一致，不一致時 Server 回 HeaderMismatch（-32020）。舊 HTTP+SSE 傳輸已列為 Deprecated，不要與 Streamable HTTP 混用。
  • stdio 依本機執行環境提供授權邊界；HTTP 需要時依 MCP Authorization 驗證令牌及其 audience、scope，不接受代轉給其他資源的原令牌。2026-07-28 起，授權回應帶有 iss 時 Client 必須先核對發行者，並以 Client ID Metadata Documents 取代已列為 Deprecated 的動態註冊。

完整 Python Server 範例

使用固定合成資料，不讀檔、不連外、不寫設備。此服務不接受任意路徑、網址或指令；參數採長度與範圍驗證。實際程式可以直接下載。

requirements.txtserver.pyverify_client.py

server.py

"""唯讀 MCP 示範（規格 2026-07-28，MCP Python SDK 2.x）：固定合成資料，不讀檔、不連外、不寫入。

2026-07-28 規格是無狀態的：沒有 initialize 握手，也沒有 Mcp-Session-Id。
每個請求都在 _meta 宣告版本及 client 能力；沒有能力時使用空物件。server 提供 server/discover。
"""
import argparse
import sys
from typing import Annotated

from mcp.server import MCPServer
from mcp.server.mcpserver.exceptions import ToolError
from mcp.types import ToolAnnotations
from pydantic import Field

mcp = MCPServer("Synthetic engineering notes", version="2.0.0")
NOTES = (
    {"id": "pump", "title": "Pump", "summary": "模擬泵浦壓差"},
    {"id": "temperature", "title": "Temperature", "summary": "模擬送風溫度"},
)


@mcp.tool(annotations=ToolAnnotations(readOnlyHint=True))
def search_notes(
    query: Annotated[str, Field(min_length=1, max_length=32)],
    limit: Annotated[int, Field(ge=1, le=2)] = 2,
) -> list[dict[str, str]]:
    """依固定的假資料查詢；空白查詢不接受。"""
    needle = query.strip().casefold()
    if not needle:
        raise ToolError("查詢不能只有空白")
    # 舊規格的 Logging 功能已列為 Deprecated；stdio 伺服器的診斷訊息寫到 stderr。
    print("search_notes: accepted", file=sys.stderr)
    return [
        dict(note) for note in NOTES
        if needle in (note["title"] + " " + note["summary"]).casefold()
    ][:limit]


@mcp.resource("demo://notes/about")
def dataset_info() -> str:
    """說明資料來源。"""
    return "只提供固定合成資料，不代表真實設備狀態。"


@mcp.prompt()
def summarize_notes(topic: str) -> str:
    """回傳範本文字；不會自動查詢工具。"""
    return "請依已確認資料整理主題：" + topic[:100]


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--transport", choices=("stdio", "streamable-http"), default="stdio")
    args = parser.parse_args()
    if args.transport == "streamable-http":
        # 只綁本機；對外部署要再加 TLS、身分驗證與反向代理。
        mcp.run(transport="streamable-http", host="127.0.0.1", port=8000)
    else:
        mcp.run(transport="stdio")

驗證、故障測試與觀測

本次以 Python 3.13 與 MCP SDK 2.3.0 實跑 stdio 及 loopback Streamable HTTP，兩者都經 server/discover 取得 2026-07-28；另以 curl 直接送原始 JSON-RPC，確認結果帶 resultType、ttlMs、cacheScope 與 serverInfo，舊式 initialize 也仍可由 SDK 2.x 回應；測試涵蓋工具 Schema、有效查詢、拒絕越界及空白、資源讀取、提示模板。未測生產身分驗證、高可用或廠商伺服器。

verify_client.py

"""以 MCP Python SDK 2.x 的 Client 實際探索與呼叫 server.py 的 smoke test（規格 2026-07-28）。"""
import argparse
import asyncio
import sys
from contextlib import AsyncExitStack
from pathlib import Path

import httpx2

from mcp import Client, StdioServerParameters
from mcp.client.streamable_http import streamable_http_client

PROTOCOL = "2026-07-28"


async def main(http: bool) -> None:
    async with AsyncExitStack() as stack:
        if http:
            # This local-only exercise must not route through the ambient proxy.
            http_client = await stack.enter_async_context(
                httpx2.AsyncClient(trust_env=False, timeout=10.0)
            )
            target = streamable_http_client("http://127.0.0.1:8000/mcp", http_client=http_client)
        else:
            server = Path(__file__).with_name("server.py")
            target = StdioServerParameters(command=sys.executable, args=[str(server)])
        client = await stack.enter_async_context(Client(target, mode="auto"))
        assert client.protocol_version == PROTOCOL, client.protocol_version
        tools = {tool.name: tool for tool in (await client.list_tools()).tools}
        assert "query" in tools["search_notes"].input_schema["properties"]
        assert tools["search_notes"].annotations.read_only_hint is True
        hit = await client.call_tool("search_notes", {"query": "Pump", "limit": 1})
        assert not hit.is_error and "pump" in repr(hit.structured_content)
        invalid = await client.call_tool("search_notes", {"query": "Pump", "limit": 0})
        assert invalid.is_error
        blank = await client.call_tool("search_notes", {"query": " "})
        assert blank.is_error
        resources = (await client.list_resources()).resources
        info = await client.read_resource(resources[0].uri)
        assert "合成資料" in info.contents[0].text
        assert "summarize_notes" in {p.name for p in (await client.list_prompts()).prompts}
        prompt = await client.get_prompt("summarize_notes", {"topic": "pump"})
        assert "pump" in prompt.messages[0].content.text
        print("PASS", client.protocol_version, client.server_info.name, "HTTP" if http else "STDIO")


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--http", action="store_true")
    asyncio.run(main(parser.parse_args().http))
  • 預期輸出：PASS 2026-07-28 Synthetic engineering notes STDIO（HTTP 模式結尾為 HTTP）。
  • 記錄協定版本、Server 版本、耗時、工具名稱、成功／失敗分類及追蹤 ID；不記錄 token、完整提示或可能含個資的正文。
  • 分階段驗收：合法／非法參數、缺少權限、Server 關閉重連、逾時及資料來源不可用。
  • 準備獨立測試記錄，包含最小權限帳號的預期拒絕及審計產出；本範例沒有寫入工具。

排查與上線前檢查

先區分傳輸／協定錯誤和工具執行錯誤，不要用同一個重試策略處理所有失敗。

現象優先檢查
stdio 第一個請求逾時命令、路徑、權限、stdout 有沒有日誌破壞逐行 JSON-RPC；對方是否為只懂 initialize 的舊 Server
HTTP 回 400端點、Origin、Content-Type / Accept、MCP-Protocol-Version／Mcp-Method／Mcp-Name 標頭是否與本文一致、認證與授權
回 -32022UnsupportedProtocolVersionError：讀 data.supported，改用雙方都支援的版本重送
工具看不到server/discover 的 capabilities、tools/list、最小權限、部署 toolset，以及 ttlMs 內的快取是否過期
正常請求卻工具失敗分辨 JSON-RPC 協定錯誤與 tools/call 結果 isError；先讀驗證結果與受控日誌
斷線後資料重複讀取與寫入分開重試，副作用操作避免盲重試；2026-07-28 沒有 SSE 續傳，斷線的請求一律以新 id 重送，所以寫入工具要設計冪等鍵
舊教學的 session 程式不能用改寫 Mcp-Session-Id、ping、logging/setLevel、sampling／elicitation 主動請求等依賴；對照第 02 節的遷移表

權限、信任邊界與資料治理

MCP 宣告的唯讀 hint 是提示，不是安全控制。透過程式行為、檔案權限和最小授權讓唯讀可驗證；有副作用的動作另設核准、審計、冪等與復原。

  • 所有工具帶 allowlist，不接受任意 shell / SQL 或完整檔案系統。輸入與回傳大小均設限制，錯誤訊息不外洩實作與秘密。
  • Server 回傳的頁面、文件及提示模板是資料，不是新的權限、政策或使用者核准。
  • 外部服務憑證由密鑰管理與最小權限帳號提供；分離租戶及服務身分。
  • 正式監控應包含請求率、錯誤率、延遲、工具逾時、拒絕原因及敏感欄位遮罩；可依實際策略輪替憑證與停用工具。
