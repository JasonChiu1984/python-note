MCP Server：從協定到可執行服務

認識 Host、Client、Server 三層角色，從初始化、能力協商與 JSON-RPC 走到有權限邊界的工具服務。附可實跑的 Python SDK 教程與驗收客戶端。

看架構與流程開啟 Python 範例比較常見伺服器
01 / MCP SERVER

Server 的角色與責任

MCP 是 Host 將外部能力接入模型工作流程的標準介面，不是模型、資料庫或遠端 shell。Host 管理 UI、模型、安全決策與同意；每條 Client 連線協商能力並交換 JSON-RPC；Server 封裝外部能力並在執行前驗證授權。模型提議呼叫不等於執行權限。

角色負責不該負責
Host模型、對話、同意、權限選擇、隔離 Server 的可見資料不可把任意 Server 回傳文字當可信指令
Client連線、initialize、能力探索、請求對應 ID 與逾時不可把成功回覆等同使用者已批准
ServerSchema、授權、執行、結果與審計；連接已核准的資料來源不可讀取授權外資料或因參數看似合法就跳過政策檢查
02 / MCP SERVER

架構圖與協定流程

讀路徑限定在 MCP Server 授權及驗證層之後；索引不直接交給模型或工具。寫入與高影響工具另行建模，在 Server 執行前驗證權限與業務條件。

資料與責任架構

  1. MCP Host應用介面與核准
  2. MCP Client連線與請求協商
  3. MCP Server驗證身分、Schema 與資源範圍
  4. 資料來源授權後讀取合成資料或指定索引

資料準備路徑可另做 Conversation Export → Normalized JSON / Markdown → Index；Client Tools 只經 MCP Server 讀資料，驗證證據另存，不等同直接授權讀索引。

請求生命週期

  1. ① initializeClient 提議 protocolVersion、能力與 clientInfo
  2. ② negotiateServer 回傳支援的版本、能力與 serverInfo。不支援回傳版本則 Client 應中止
  3. ③ initializedClient 送 notifications/initialized，無 id、無回覆
  4. ④ discovery / call按能力使用 tools/list、resources/list、prompts/list 或呼叫／讀取
  5. ⑤ close / recover斷線或關閉後視傳輸重建會話；不重試不安全的副作用
介面用途方法／結果
Tools受允許的動作，模型可提議，Host/Server 必須控權tools/list、tools/call；JSON Schema 驗證 inputSchema，必要時以 outputSchema 定義 structuredContent
Resources提供已授權、可定位的資料；URI 不是存取憑證resources/list、resources/read；可以另提供 resource template
Prompts使用者可選擇的提示模板，不代表閘道授權prompts/list、prompts/get；不要把不可信插值當規則
Client → initialize (id=1) → Server
Server → result (id=1，版本與能力) → Client
Client → notifications/initialized（無 id）→ Server
Client → tools/list (id=2) → Server
Client → tools/call (id=3，已驗證的參數) → Server

04 / MCP SERVER

傳輸與部署設計

以 stdio 跑本地單使用者工具，只有需要獨立服務或跨機器時才評估 Streamable HTTP。不能直接把本機示範升格為公開服務。

傳輸如何運作上線做法
stdioClient 啟動 Server 子程序；stdin/stdout 採逐行 JSON-RPC 訊息，不能把日誌印到 stdout用 stderr 記錄；使用絕對命令路徑、受控工作目錄和最小權限 OS 使用者，不沿用自訂 Content-Length 分幀
Streamable HTTP單一 MCP 端點收 POST；可用 GET 建立 SSE 串流或回 405。本例用 /mcp、本機 loopback、JSON response驗證 Origin（有提供時）並限制綁定；跨機器採 HTTPS、認證、授權、限流與資源限額，會話 ID 不可當認證
  • 若 Server 發出 Mcp-Session-Id，Client 後續依規格帶上；會話失效時重新 initialize，而不是盲目重送寫入。
  • HTTP 後續請求帶協商的 MCP-Protocol-Version；不要將舊 HTTP+SSE 與 Streamable HTTP 當成同一傳輸。
  • stdio 依本機執行環境提供授權邊界；HTTP 需要時依 MCP Authorization 驗證令牌及其 audience、scope，不接受代轉給其他資源的原令牌。

完整 Python Server 範例

使用固定合成資料，不讀檔、不連外、不寫設備。此服務不接受任意路徑、網址或指令；參數採長度與範圍驗證。實際程式可以直接下載。

requirements.txtserver.pyverify_client.py

server.py

"""唯讀 MCP 示範：固定合成資料，不讀檔、不連外、不寫入。"""
import argparse
from typing import Annotated

from mcp.server.fastmcp import FastMCP
from mcp.types import ToolAnnotations
from pydantic import Field

mcp = FastMCP("Synthetic engineering notes", host="127.0.0.1", json_response=True)
NOTES = (
    {"id": "pump", "title": "Pump", "summary": "模擬泵浦壓差"},
    {"id": "temperature", "title": "Temperature", "summary": "模擬送風溫度"},
)

@mcp.tool(annotations=ToolAnnotations(readOnlyHint=True))
def search_notes(
    query: Annotated[str, Field(min_length=1, max_length=32)],
    limit: Annotated[int, Field(ge=1, le=2)] = 2,
) -> list[dict[str, str]]:
    """依固定的假資料查詢；空白查詢不接受。"""
    needle = query.strip().casefold()
    if not needle:
        raise ValueError("查詢不能只有空白")
    return [
        dict(note) for note in NOTES
        if needle in (note["title"] + " " + note["summary"]).casefold()
    ][:limit]


@mcp.resource("demo://notes/about")
def dataset_info() -> str:
    """說明資料來源。"""
    return "只提供固定合成資料，不代表真實設備狀態。"


@mcp.prompt()
def summarize_notes(topic: str) -> str:
    """回傳範本文字；不會自動查詢工具。"""
    return "請依已確認資料整理主題：" + topic[:100]


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--transport", choices=("stdio", "streamable-http"), default="stdio")
    mcp.run(transport=parser.parse_args().transport)

驗證、故障測試與觀測

本次以 Python 3.12.14 與 MCP SDK 1.29.0 實跑 stdio 及 loopback Streamable HTTP，兩者皆協商 2025-11-25；測試涵蓋工具 Schema、有效查詢、拒絕越界及空白、資源讀取、提示模板。未測生產身分驗證、高可用或廠商伺服器。

verify_client.py

"""經實際 MCP client 初始化、探索及呼叫的 smoke test。"""
import argparse
import asyncio
import sys
from contextlib import asynccontextmanager
from pathlib import Path

import httpx
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client
from mcp.client.streamable_http import streamable_http_client


@asynccontextmanager
async def streams(http: bool):
    if http:
        async with httpx.AsyncClient(trust_env=False) as client:
            async with streamable_http_client("http://127.0.0.1:8000/mcp", http_client=client) as (r, w, _):
                yield r, w
    else:
        server = Path(__file__).with_name("server.py")
        async with stdio_client(StdioServerParameters(command=sys.executable, args=[str(server)])) as pair:
            yield pair


async def main(http: bool):
    async with streams(http) as (read, write):
        async with ClientSession(read, write) as session:
            started = await session.initialize()
            assert await session.list_tools()
            tools = {tool.name: tool for tool in (await session.list_tools()).tools}
            assert "query" in tools["search_notes"].inputSchema["properties"]
            hit = await session.call_tool("search_notes", {"query": "Pump", "limit": 1})
            assert not hit.isError and "pump" in repr(hit.structuredContent)
            invalid = await session.call_tool("search_notes", {"query": "Pump", "limit": 0})
            assert invalid.isError
            blank = await session.call_tool("search_notes", {"query": " "})
            assert blank.isError
            resources = (await session.list_resources()).resources
            info = await session.read_resource(resources[0].uri)
            assert "合成資料" in info.contents[0].text
            assert "summarize_notes" in {p.name for p in (await session.list_prompts()).prompts}
            prompt = await session.get_prompt("summarize_notes", {"topic": "pump"})
            assert "pump" in prompt.messages[0].content.text
            print("PASS", started.protocolVersion, "HTTP" if http else "STDIO")


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--http", action="store_true")
    asyncio.run(main(parser.parse_args().http))
  • 記錄協定版本、Server 版本、耗時、工具名稱、成功／失敗分類及追蹤 ID；不記錄 token、完整提示或可能含個資的正文。
  • 分階段驗收：合法／非法參數、缺少權限、Server 關閉重連、逾時及資料來源不可用。
  • 準備獨立測試記錄，包含最小權限帳號的預期拒絕及審計產出；本範例沒有寫入工具。

排查與上線前檢查

先區分傳輸／協定錯誤和工具執行錯誤，不要用同一個重試策略處理所有失敗。

現象優先檢查
stdio initialize 逾時命令、路徑、權限、stdout 有沒有日誌破壞逐行 JSON-RPC
HTTP 初始化失敗端點、Origin、Content-Type / Accept、版本協商、認證與授權
工具看不到initialize capabilities、tools/list、最小權限及部署 toolset
正常請求卻工具失敗分辨 JSON-RPC 協定錯誤與 tools/call 結果 isError；先讀驗證結果與受控日誌
斷線後資料重複讀取與寫入分開重試，副作用操作避免盲重試；重新初始化不保證原會話完整

權限、信任邊界與資料治理

MCP 宣告的唯讀 hint 是提示，不是安全控制。透過程式行為、檔案權限和最小授權讓唯讀可驗證；有副作用的動作另設核准、審計、冪等與復原。

  • 所有工具帶 allowlist，不接受任意 shell / SQL 或完整檔案系統。輸入與回傳大小均設限制，錯誤訊息不外洩實作與秘密。
  • Server 回傳的頁面、文件及提示模板是資料，不是新的權限、政策或使用者核准。
  • 外部服務憑證由密鑰管理與最小權限帳號提供；分離租戶及服務身分。
  • 正式監控應包含請求率、錯誤率、延遲、工具逾時、拒絕原因及敏感欄位遮罩；可依實際策略輪替憑證與停用工具。
