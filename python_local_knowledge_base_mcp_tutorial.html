Overview

先定資料契約，再談 AI 工具整合

知識庫若沒有穩定格式，搜尋品質、交接與工具串接都會漂移。

Architecture

export、index、server 要明確分層

匯出、索引與服務責任分離，後續才能擴充工具而不互相污染。

Setup

零相依也能做出可用的本地知識庫

先用標準庫跑通最小閉環，再決定是否導入資料庫、向量索引或遠端服務。

Configuration

title、summary、tags 與 id 要能穩定檢索

搜尋品質往往不是演算法問題，而是前面 metadata 沒有治理。

Example

從 conversation export 到 MCP search/read 一次走完

這個專案用 `knowledge_base/`、`scripts/` 與 `mcp_server/` 組成最小可交付路徑。

Verification

同時驗格式、查詢與協定互通

只驗資料生成不夠，還要驗 MCP client 真能調用 `search` / `read`。

Troubleshooting

搜尋不準時先看 metadata 與 index

大多數問題出在匯出輸入不穩、索引沒更新或工具協定封包不完整。

Best Practices

把知識庫當正式交付物，而不是私人筆記

只要牽涉專案決策、審查與交接，就應有可重播、可驗收的輸出格式。
