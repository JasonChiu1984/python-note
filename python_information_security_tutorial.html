Python 資訊安全

從輸入驗證、資料存取及 TLS，到工控閘道的信任邊界與上線證據。

01｜先畫信任邊界

  1. 設備或外部資料
  2. 驗證、限量及標記
  3. 最小權限閘道
  4. 授權服務與稽核

將設備回傳、訊息、CSV 與上游 API 都視為不可直接信任的輸入。身份驗證回答「它是誰」，授權回答「能做什麼」，完整性檢核回答「內容能否被接受」。不能用其中一項替代另外兩項。

02｜Python 安全預設

範圍安全做法驗證證據
輸入與資料庫先限制位元組數，再驗證欄位、型別、允許清單與工程上下限。SQL 值用 DB-API 參數；表名等識別字用固定對照，不拼接外部文字。錯誤資料被拒絕；資料列數與預期相同。
傳輸使用 ssl.create_default_context()，保留憑證鏈與主機名驗證；需要內部 CA 時，安裝受信任 CA 並驗證目標名稱。設定連線／讀取逾時。合法端點可用；錯誤身份、逾期憑證或斷線時不降級成不驗證。
憑證與權限秘密由受控服務或平台注入，不寫入版本庫、範例、錯誤訊息。服務帳號只開所需權限；監看預設唯讀。一般監看身份不能寫入；具備輪替及撤銷流程。
依賴與日誌核准來源並鎖定直接及間接相依，依環境維護雜湊。記錄可追查的事件碼、時間、結果；不寫入 token、密碼或完整原始資料。建置可重現；拒絕事件可追溯且無秘密。
程序與序列化不對不可信資料反序列化 pickle；用具有明確格式及大小上限的資料。呼叫外部程式使用固定執行檔與引數陣列，維持 shell=False。以無效格式和異常長度測拒絕分支，記錄逾時行為。

03｜離線範例：驗證溫度事件後入庫

以下是完整標準庫程式。僅使用合成資料和記憶體 SQLite，不連接設備、不修改現場設定。允許的點名與量測範圍僅供教學，實務應由點表及驗收規格決定。

import json
import sqlite3

ALLOWED_POINTS = frozenset({"AHU1_SUPPLY", "AHU2_SUPPLY"})


def ingest(db, raw: bytes) -> bool:
    if len(raw) > 512:
        return False
    try:
        event = json.loads(raw)
    except (ValueError, RecursionError):
        return False
    if not isinstance(event, dict) or set(event) != {"point", "milli_c"}:
        return False
    point, value = event["point"], event["milli_c"]
    if not isinstance(point, str) or point not in ALLOWED_POINTS:
        return False
    if type(value) is not int or not -40_000 <= value <= 100_000:
        return False
    db.execute("INSERT INTO measurements VALUES (?, ?)", (point, value))
    return True


def main():
    db = sqlite3.connect(":memory:")
    try:
        db.execute("CREATE TABLE measurements (point TEXT, milli_c INTEGER)")
        samples = [
            b'{"point":"AHU1_SUPPLY","milli_c":18750}',
            b'{"point":"UNKNOWN","milli_c":23000}',
            b'{"point":"AHU1_SUPPLY","milli_c":true}',
            b'{"point":"AHU2_SUPPLY","milli_c":999999}',
            b'x' * 513,
        ]
        with db:
            outcomes = [ingest(db, raw) for raw in samples]
        rows = db.execute("SELECT COUNT(*) FROM measurements").fetchone()[0]
        assert outcomes == [True, False, False, False, False] and rows == 1
        print(f"接收 {rows} 筆；拒絕 {outcomes.count(False)} 筆")
    finally:
        db.close()


if __name__ == "__main__":
    main()

預期結果：接收 1 筆；拒絕 4 筆。此例未包含身分驗證、重送去重及資料持久化；完整服務須定義時間戳、資料來源、品質與持續保留政策。

04｜工控閘道：先保住本地控制

OT 可用性關心控制服務能否持續，功能安全關心危險發生時系統能否達到安全狀態，資安關心能否抵禦未授權操作；三者互相影響，但不能以資安措施代替獨立的安全聯鎖。

  1. 分區與資料流：設備網、採集閘道、監控平台分區，只允許核准來源、目的、方向與服務。讓 UI 讀取閘道快照，不直接控制現場設備；一般監看不開放寫入。
  2. 區分協定能力：Modbus RTU、常見未加密 Modbus TCP 與 BACnet/IP 不假設有身分驗證；BACnet/SC、OPC UA 安全設定或 MQTT over TLS 仍需核對端點、信任及授權。加密不等於允許寫入。
  3. 防止跨界連鎖：以有界佇列、逾時與重試上限隔離上位機異常；每個實體序列匯流排由單一輪詢者有序管理。保留時間戳與品質；陳舊／失聯與正常 OFF 不能共用一個值。
  4. 故障驗收：在離線測試台確認斷線、重連及憑證異常，不用在生產設備試驗。觀察本機控制持續性、首筆有效通訊、快照資料年齡、失敗數及記憶體；更新前確認備份及回復。

06｜程式碼防拷：保密、授權與完整性分開做

延伸教材：Python 程式碼保護與簽章交付 · 密碼學與加密實作。

交付到客戶控制的設備上，就不能保證程式無法被複製。停用右鍵或文字選取不會建立保護，反而影響教材閱讀與無障礙。先決定是要保護商業邏輯、限制帳號使用，還是確認交付物未遭竄改。

要降低的風險可驗收的設計無法保證什麼
客戶取得核心商業邏輯把核心規則留在受控服務；客戶端只拿必要的結果。由服務逐次檢查帳號授權、範圍和到期。API 無法避免合法輸出被轉載；需要離線運轉時，不能依賴雲端才能進入安全狀態。
安裝檔遭換置，或授權檔遭改寫簽署發布清單或授權資料；驗證端用可信的公鑰驗證，確認版本、授權範圍及期限。簽署私鑰不放在用戶端，也不隨安裝檔發送。簽章驗證來源與內容，不提供保密；加密保護處理前的內容，但不能阻止持有解密能力的端點讀取明文，也不能代替操作授權。
客戶端散布檔案明定授權條款、發放紀錄與可撤銷的帳號權限。可在經適當告知的交付物加上不含個資的發行編號，並保存對應紀錄。發行標記是追溯輔助，不會阻止拷貝，也不能單靠它認定是誰散布。
把打包誤當成保密.pyc 是位元組碼；打包器解決交付與安裝，原生擴充模組可改變散布形式。以部署與相容需求選工具，不把封裝當權限邊界。以上都無法保證不被複製、分析或修改。不要把資料庫密碼、長期 API 憑證或驗證私鑰嵌入程式。

完整性小實驗：比對可信清單中的 SHA-256

from hashlib import sha256
from hmac import compare_digest

# 這是教學用預期資料。正式部署應從獨立信任來源
# 取得預期摘要，例如先驗證已簽署的發布清單。
expected = sha256(b"gateway-release-v1").hexdigest()

def matches_release(package: bytes) -> bool:
    return compare_digest(sha256(package).hexdigest(), expected)

assert matches_release(b"gateway-release-v1")
assert not matches_release(b"gateway-release-v2")
print("完整性案例通過")

單一摘要只能比對內容：若安裝檔與摘要一起來自不可信來源，不能據此認定發布者身分。數位簽章須從建立信任、密鑰輪替與撤銷一併規劃，避免自行實作密碼演算法。

延伸學習：實作、現場案例與自我檢查

本頁第 03 節示範了驗證溫度事件後入庫。本節把驗證擴充成閘道器常用的完整檢查鏈：大小、格式、簽章、白名單、型別、時間窗、重放、範圍與變化率，並區分「拒絕」與「隔離」。

架構圖與流程圖

可實跑範例：閘道器輸入驗證鏈

每則訊息依序通過 10 道檢查（含時間戳與 nonce 的型別）。拒絕代表訊息不可信（格式、簽章、重放），直接丟棄並記錄；隔離代表訊息可信但數值可疑（超出範圍、跳變），保留供人工確認，但不送進控制邏輯。「現在時間」固定為常數，讓輸出可重現。

下載範例 example.py

"""閘道器輸入驗證：白名單點位、數值範圍、速率變化與重放檢查（標準函式庫）。

情境：MQTT 或 HTTP 收到的溫度事件，在寫入資料庫或轉給控制系統前要先驗證。
"""
import hashlib
import hmac
import json
import time

ALLOWED = {"AHU1_SAT": (5.0, 40.0, 2.0), "CHW_SUPPLY": (3.0, 15.0, 1.0)}   # 下限、上限、每分鐘最大變化
KEY = b"\x07" * 32
NOW = 1_795_800_000                                       # 固定「現在」時間，讓輸出可重現


class Validator:
    def __init__(self):
        self.last: dict[str, tuple[int, float]] = {}
        self.seen_nonce: set[str] = set()

    def check(self, raw: bytes) -> str:
        if len(raw) > 512:
            return "拒絕：訊息過大"
        try:
            msg = json.loads(raw)
        except json.JSONDecodeError:
            return "拒絕：不是合法 JSON"
        body = {k: msg.get(k) for k in ("point", "value", "ts", "nonce")}
        sig = hmac.new(KEY, json.dumps(body, sort_keys=True).encode(), hashlib.sha256).hexdigest()
        if not hmac.compare_digest(sig, str(msg.get("sig", ""))):
            return "拒絕：簽章錯誤"
        if not isinstance(body["point"], str) or body["point"] not in ALLOWED:   # list 等不可雜湊型別也拒絕，不讓 in 拋 TypeError
            return f"拒絕：未知點位 {body['point']!r}"
        if not isinstance(body["value"], (int, float)) or isinstance(body["value"], bool):
            return "拒絕：數值型別錯誤"
        if type(body["ts"]) is not int or not isinstance(body["nonce"], str):
            return "拒絕：時間戳或 nonce 型別錯誤"
        if abs(NOW - body["ts"]) > 300:
            return "拒絕：時間戳超出 ±5 分鐘"
        if body["nonce"] in self.seen_nonce:
            return "拒絕：重放（nonce 已使用）"
        lo, hi, rate = ALLOWED[body["point"]]
        if not lo <= body["value"] <= hi:
            return f"隔離：{body['value']} 超出 {lo}–{hi}"
        prev = self.last.get(body["point"])
        if prev and abs(body["value"] - prev[1]) > rate * max(1, (body["ts"] - prev[0]) / 60):
            return f"隔離：變化過快（{prev[1]} → {body['value']}）"
        self.seen_nonce.add(body["nonce"])
        self.last[body["point"]] = (body["ts"], body["value"])
        return "接受"


def make(point, value, ts, nonce, key=KEY):
    body = {"point": point, "value": value, "ts": ts, "nonce": nonce}
    body["sig"] = hmac.new(key, json.dumps(body, sort_keys=True).encode(), hashlib.sha256).hexdigest()
    return json.dumps(body).encode()


if __name__ == "__main__":
    v = Validator()
    cases = [
        ("正常", make("AHU1_SAT", 18.2, NOW - 60, "a1")),
        ("重放同一封包", make("AHU1_SAT", 18.2, NOW - 60, "a1")),
        ("跳變", make("AHU1_SAT", 26.0, NOW, "a2")),
        ("未知點位", make("AHU9_SAT", 18.0, NOW, "a3")),
        ("超出範圍", make("CHW_SUPPLY", 55.0, NOW, "a4")),
        ("過期", make("CHW_SUPPLY", 7.0, NOW - 3600, "a5")),
        ("偽造簽章", make("CHW_SUPPLY", 7.0, NOW, "a6", key=b"x" * 32)),
        ("型別錯誤", make("CHW_SUPPLY", "7.0", NOW, "a7")),
        ("非 JSON", b"<xml/>"),
    ]
    for name, raw in cases:
        print(f"{name:<8} → {v.check(raw)}")

執行方式：python example.py，只需 Python 3.10 以上，無第三方套件

工程現場案例：重放的舊封包讓冰水溫度「回到」三小時前

某雲端平台透過 MQTT 接收現場閘道器上傳的溫度，並據此調整冰水出水設定點。攻擊者在網路上擷取到一則合法封包，數小時後重新送出。平台只驗證簽章，簽章當然正確，於是溫度被「改回」舊值，設定點也跟著錯誤調整。

加入時間戳窗口與 nonce 後，舊封包會因超出 ±5 分鐘被拒絕，同一時間窗內的重送則因 nonce 已使用被拒絕。範例也示範把 bool 排除在數值之外：在 Python 中 True 是 int 的子類別，不特別檢查的話 True 會被當成 1。

  1. 列出所有外部輸入的來源與格式，為每個點位定義合法範圍與最大變化率。
  2. 驗證順序由便宜到昂貴：先檢查大小與格式，再算簽章，最後做業務檢查。
  3. nonce 或序號的保存期限至少要涵蓋時間戳窗口，並在閘道器重啟後仍有效。
  4. 隔離的資料要有人看：設定告警與每日報表，不要只寫進日誌。

練習題與自我檢查

  1. 為什麼「跳變」被隔離後，下一筆 18.5 °C 的正常訊息仍會被接受？

    看解答

    被隔離的訊息不會更新 self.last，比較基準仍是上一筆被接受的 18.2 °C，所以 18.5 °C 的變化在允許範圍內。若隔離的值也更新基準，一筆異常值就可能讓後續正常值都被判為跳變。

  2. 把 check() 中簽章驗證移到最後一步，會有什麼問題？

    看解答

    未經驗證的訊息會先更新或查詢內部狀態，攻擊者可以用偽造訊息試探白名單點位與範圍設定，或觸發大量隔離告警。先驗證簽章，後面的檢查都只處理可信來源的訊息。

  3. seen_nonce 是一個不斷成長的 set。怎麼在不影響安全性的前提下限制它的大小？

    看解答

    只需保存時間戳窗口內的 nonce：用 dict 記錄 nonce 與時間戳，定期刪除早於 NOW − 300 秒的項目。超出窗口的舊訊息本來就會被時間戳檢查拒絕。

  4. 若 value 傳入 float('nan')，範例會怎麼處理？要怎麼補強？

    看解答

    JSON 標準不允許 NaN，但 Python 的 json.loads 預設接受 NaN 字面值。NaN 與任何數比較都是 False，所以 lo <= nan <= hi 為 False，會被隔離。更明確的做法是在型別檢查時加上 math.isfinite(value)，或以 json.loads(raw, parse_constant=...) 直接拒絕 NaN 與 Infinity。

  5. 修正前的範例沒有檢查 ts 與 point 的型別。若某台閘道器韌體把 ts 送成字串 "1795800000"（簽章仍正確），或把 point 送成 ["AHU1_SAT"]，check() 會怎樣？為什麼這比回傳「拒絕」更糟？

    看解答

    實際執行修正前的程式：ts 為字串時在 abs(NOW - body["ts"]) 拋出 TypeError: unsupported operand type(s) for -: 'int' and 'str'；point 為 list 時在 body["point"] not in ALLOWED 拋出 TypeError: unhashable type: 'list'。

    驗證器拋例外時，呼叫端常見的處理是整個迴圈中斷或連線重啟，一筆格式錯誤的訊息就能讓後面正常的訊息也收不到，等於把輸入驗證變成阻斷服務的入口。現在的範例先確認 point 是字串、ts 是 int、nonce 是字串，兩種情況分別回傳「拒絕：時間戳或 nonce 型別錯誤」與「拒絕：未知點位 ['AHU1_SAT']」。原則是：驗證函式對任何輸入都只回傳判定結果，不讓例外外洩。

  6. 「跳變」案例中上一筆 18.2 °C 的 ts 是 NOW − 60。若 26.0 °C 那筆的 ts 改成 NOW + 120 或 NOW + 180（都還在 ±300 秒內），各會得到什麼結果？這對設定變化率上限有什麼提示？

    看解答

    實際執行：NOW + 120 時兩筆相隔 180 秒，允許變化 2.0 × 3 = 6.0 °C，7.8 °C 仍被隔離；NOW + 180 時相隔 240 秒，允許 2.0 × 4 = 8.0 °C，7.8 °C 被接受。

    允許變化量隨間隔放大，代表通訊中斷一段時間後的第一筆最容易「放行」大跳變；而 ts 由送端填寫，時間戳本身就影響判斷。實務上可另設單筆最大跳變的絕對上限、間隔超過一定時間時改標記為「恢復後首筆」交人工確認，並用平台收到的時間交叉核對送端 ts。
