Production Notes Platform：完整可交付專案範本

這條 walkthrough 把 100 案例收斂成一個端到端專案：需求 → code → test → CI → package → release → rollback。它不是新語法清單，而是資深工程師真正交付時會留下的證據鏈。

1. Requirement 與 SLO

需求不是「做 notes-cli」，而是能在本機可靠保存筆記、可追蹤錯誤、可在 release 後回復，並把 ADR 與 SLO 留成交付證據。

# docs/requirements.md
Goal: local notes platform for CLI/API reuse
SLO: 99.9% command success on valid input
Data: JSON v1, migration-ready
Failure: corrupted JSON must not be silently overwritten
ADR: start with JSON repository, move to SQLite at lock contention

2. Package Tree 與 pyproject

可交付教材要能讓讀者看見檔案邊界；src layout、tests、docs、runbooks 與 CI 必須能對回同一條 release gate。

3. pyproject.toml：版本與入口

版本號、依賴、測試工具與 CLI entrypoint 由同一份 metadata 管理，release note 才能和產物一致。

[project]
name = "notes-platform"
version = "0.4.0"
requires-python = ">=3.11"
dependencies = ["typer>=0.12"]

[project.scripts]
notes = "notes_platform.cli:app"

[tool.pytest.ini_options]
testpaths = ["tests"]

4. Code：service/repository 邊界

核心規則放在 service，儲存細節放在 repository；CLI/API 只負責組裝輸入與輸出。

from dataclasses import dataclass

@dataclass(frozen=True)
class Note:
    note_id: str
    text: str

class NoteService:
    def __init__(self, repo):
        self.repo = repo

    def add(self, note_id, text):
        if not text.strip():
            raise ValueError("note text is required")
        note = Note(note_id=note_id, text=text.strip())
        self.repo.save(note)
        return note

5. Config / Env Precedence

設定優先順序要寫成可測規則：defaults 保證本機可跑，config file 給使用者調整，env 覆寫 CI/部署環境。

from dataclasses import dataclass
import os

@dataclass(frozen=True)
class Settings:
    data_path: str = "notes.json"
    log_level: str = "INFO"

def load_settings(file_config: dict[str, str]) -> Settings:
    return Settings(
        data_path=os.getenv("NOTES_DATA_PATH", file_config.get("data_path", "notes.json")),
        log_level=os.getenv("NOTES_LOG_LEVEL", file_config.get("log_level", "INFO")),
    )

6. Repository Migration 與錯誤分類

JSON repository 不是玩具時，要有 schema_version、migration、資料毀損錯誤與不支援版本錯誤，CLI 才能給出修復指令。

class NotesError(Exception): ...
class DataCorruptionError(NotesError): ...
class UnsupportedSchemaError(NotesError): ...

def migrate(doc: dict) -> dict:
    version = doc.get("schema_version", 1)
    if version == 1:
        doc = {"schema_version": 2, "notes": doc.get("items", [])}
    if doc.get("schema_version") != 2:
        raise UnsupportedSchemaError(doc.get("schema_version"))
    return doc

7. Test：pytest 驗收

測試先鎖住 service 規則，再用 tmp_path 驗證 JSON repository 的實際檔案行為。

class FakeRepo:
    def __init__(self):
        self.saved = []

    def save(self, note):
        self.saved.append(note)

def test_add_note_trims_text():
    repo = FakeRepo()
    note = NoteService(repo).add("n1", "  ship it  ")
    assert note.text == "ship it"
    assert repo.saved == [note]

8. GitHub Actions：品質門禁

CI 要能判讀壞在哪一層：lint/type 是工程規格，unit/integration 是行為規格，coverage 是缺口訊號。

name: ci
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - run: python -m pip install -e .[dev]
      - run: ruff check src tests
      - run: mypy src
      - run: pytest tests -q --cov=notes_platform --cov-fail-under=90

9. Package：可重現產物

package 階段要在乾淨環境安裝 wheel，PyInstaller 則用 onedir 先排查 assets 與 hidden imports。

python -m pip install build
python -m build
python -m pip install dist/*.whl
notes --version
pyinstaller --onedir src/notes_platform/cli.py --name notes

10. Release：版本與證據

Release note 必須附測試證據、產物位置、SBOM/dependency scan 與 smoke command。

Release v0.3.0
Evidence: tests passed, coverage 92%, smoke passed
Backup: copy notes.json to notes.json.bak
Artifact: dist/notes_platform-0.3.0-py3-none-any.whl
SBOM: sbom-notes-platform-0.3.0.json
Smoke: notes --version && notes add n1 "hello"

11. Rollback：演練與回復

rollback 不是重新部署舊版而已，還要知道資料、設定與使用者操作如何復原。

pip install notes-platform==0.2.0
notes repair --from notes.json.bak
notes doctor --strict
pytest tests/smoke/test_release.py -q
runbook: verify data count, version, and audit log

12. Release Artifact Table

每次標版本都要能回看修改內容、測試證據、產物與回復路徑，不能只留下 git tag。

| Evidence | Required |
| --- | --- |
| tag | v1.8.0 |
| tests | ruff, mypy, pytest, coverage |
| package | wheel + dist smoke |
| security | pip-audit + SBOM |
| rollback | backup path + old artifact pin |
| owner | release captain + on-call |
需求要能落到測試與運維：資料是否可修復、命令是否有 exit code、錯誤是否能定位。
資深專案不是沒有取捨，而是讓後來的人知道為什麼當時選這條路，以及何時該換路。
release gate 應同時檢查功能、品質、安全、產物與 rollback；缺一項就不是完整交付。

高階工程驗收清單

完成案例後，用這份清單檢查自己是否從「會寫」走到「能交付」。

面向驗收問題證據常見缺口
架構核心規則是否不依賴框架？service/domain 可用 unit test 驗證CLI/API 直接寫規則
可靠性外部失敗是否可重試、可降級？timeout、retry、idempotency test只 catch Exception 然後 pass
效能是否有 profile 證據？cProfile、benchmark、memory snapshot憑感覺重構
安全輸入、secret、檔案路徑是否被保護？validation、secret source、path allowlist把 token 寫進程式碼
交付產物是否可重現？lockfile、CI、smoke test、release note只在自己電腦能跑
供應鏈依賴與產物是否可追溯？dependency scan、SBOM、checksum、版本鎖定只相信 build success，沒有產物證據
權限執行時權限是否最小化？permission boundary、path allowlist、read-only config工具用過大權限讀寫任意路徑
Secretsecret 是否可輪替且不落地？secret rotation runbook、遮蔽 log、雙 key windowsecret 寫進設定檔或 release artifact
Rollback部署後如何安全回復？backup、migration rollback、artifact pinning、smoke test只會重部署，不知道資料如何復原
範例輸出為教學用預期結果，不會在瀏覽器中執行 Python。高階案例強調工程判斷、取捨與驗收證據。
