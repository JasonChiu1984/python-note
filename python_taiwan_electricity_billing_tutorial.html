台灣電費計算

用 Python 算住宅分段小計，拆開機房的流動電費與基本電費。先確認合約和抄表期間，再選公式。

計算流程住宅累進商用／機房時間電價資料架構Python 實作官方來源

01｜從電表到帳單的流程圖

  1. 1｜辨識用電身分電號、供電電壓、用電類別、方案與契約。
  2. 2｜鎖定有效版本用計費起訖、費率生效日、夏月與台電離峰日曆切分。
  3. 3｜整理計量住宅按級距；時間電價按時段分桶，另算最大需量。
  4. 4｜產出可核對明細分列流動、基本與調整項，逐項對台電帳單。

kWh（度）是累計用電量；kW（瓩）是功率或需量。一段 15 分鐘用了 50 kWh，區間平均功率為 50 ÷ 0.25 = 200 kW。不能把瞬時尖峰、全月平均或所有區間 kW 加總當成計費最大需量；須依電表和合約的需量口徑。

02｜住宅一般表燈：非時間電價採分段累進

台電表列費率自 2025-10-01（民國 114 年）起實施；台電 2026-09-21 說明 2026-10-01 起維持當時費率。本教材於 2026-11-25 查核，不預判後續費率。以下只適用住宅表燈非時間電價，不是小商店營業用、高壓用電或全國平均電價。

每段用電量 = max(0, min(總度數, 該段上限) − 該段下限)。最後一段沒有上限。以 2026 年 11 月非夏月單月級距、假設用電 400 度為例：120 × 1.78 ＋ 210 × 2.26 ＋ 70 × 3.13 = 907.30 元。不是 400 × 3.13 元，也未模擬實際帳單進位。

抄表週期不是曆月。一般住宅多為隔月抄表，同季且按雙月級距時，累進上限加倍，例如 120 → 240、330 → 660。跨夏月／非夏月、費率生效日或停復用須按台電分攤計費規則處理；這支程式不自行分配跨季用電。低用量的底度費、折抵、稅額／進位及當期其他調整，請以電費單與台電試算為準，本例只計流動電費。

03｜商用、機房：把時段電量和契約需量分開

「機房」不是單一供電類別。先看供電與合約：可能是租戶分攤、一般低壓、低壓時間電價，或高壓／特高壓時間電價。二段式、三段式、特殊方案與契約種類，計費時段和基本項目不相同。住宅／一般小商店夏月和高壓以上時間電價夏月不同；台電簡表中，高壓以上夏月為 5/16 到 10/15。各年度離峰日須核對台電日曆，不可直接把全部國定假日、補班日或週六一律當離峰。

流動電費＝Σ（時段 kWh × 單價）＝212,000 元。基本電費的簡化算例：單一契約 180 kW × 150 元／kW・月＝27,000 元。合計小計 239,000 元。若最大需量 200 kW，工具只標記 20 kW 差額，並未計入超約費；實際超約計算會按契約類型、時段最大需量與台電條款判定，不能套用單一差額乘數。

若將 1,000 kWh 從尖峰挪到離峰，示範中的流動電費少 3,500 元；若最大需量沒有改變，則未必降低基本費或超約項目。反之，錯開冷凍機同時啟動，可能主要改變最大需量，而不是度數。

  • 明細與對帳輸出分段／分桶、最大需量時刻與明細；逐項對台電帳單，保留原資料與版本可重算。

核心程式碼：住宅按級距拆分，時間電價按時段加總

from decimal import Decimal as D

total = D("400")
limits = (120, 330, 500, 700, 1000, None)
rates = ("1.78", "2.26", "3.13", "4.24", "5.27", "7.03")
cost = previous = D(0)
for limit, price in zip(limits, rates):
    upper = total if limit is None else min(total, D(limit))
    cost += (upper - previous) * D(price)
    if upper == total:
        break
    previous = upper
assert cost == D("907.30")

buckets = [("10000", "6"), ("18000", "4"), ("32000", "2.50")]
energy = sum(D(kwh) * D(rate) for kwh, rate in buckets)
basic = D("180") * D("150")
assert energy + basic == D("239000.00")

延伸學習：實作、現場案例與自我檢查

本節延伸頁面前段的住宅級距與時間電價，改看機房與大樓最常被忽略的一項：契約容量與 15 分鐘需量。

可實跑範例：15 分鐘需量與超約試算

把電力表每分鐘的 kW 取樣切成 00／15／30／45 分的區間取平均，找出最高需量，再判斷超約量與分段加收。只用標準函式庫與 Decimal，避免浮點誤差。單價是假設值，換成你的契約與電價表即可。

下載範例 example.py

"""從 1 分鐘電力取樣計算 15 分鐘需量、契約超約與尖峰比例（教學模型，非帳單引擎）。

情境：機房配電盤的電力表每分鐘回傳一筆有效功率 kW（例如經 Modbus 讀回）。
台電以 15 分鐘平均功率計需量；本例找出當日最高需量並判斷是否超過契約容量。
超約部分的加收倍數（10% 以內 2 倍、超過 10% 的部分 3 倍）以參數傳入，實際以台電電價表為準。
"""
from decimal import Decimal, ROUND_HALF_UP
from datetime import datetime, timedelta

D = Decimal


def synthetic_samples(start: datetime) -> list[tuple[datetime, Decimal]]:
    """產生 4 小時的合成資料：08:00 起冰機逐台啟動，10:30 三台同時加載造成尖峰。"""
    samples = []
    for minute in range(240):
        t = start + timedelta(minutes=minute)
        kw = D(420)                                   # IT 負載與基本空調
        if minute >= 30:
            kw += D(180)                              # 第 1 台冰機
        if minute >= 60:
            kw += D(170)                              # 第 2 台冰機
        if 150 <= minute < 175:
            kw += D(260)                              # 10:30 第 3 台冰機同時加載
        kw += D(minute % 7)                           # 小幅波動
        samples.append((t, kw))
    return samples


def demand_15min(samples):
    """依 00/15/30/45 分切齊的區間求平均功率；區間樣本不足 15 筆視為資料缺漏。"""
    buckets: dict[datetime, list[Decimal]] = {}
    for t, kw in samples:
        key = t.replace(minute=t.minute - t.minute % 15, second=0, microsecond=0)
        buckets.setdefault(key, []).append(kw)
    result = {}
    for key, values in sorted(buckets.items()):
        if len(values) < 15:
            raise ValueError(f"{key:%H:%M} 區間只有 {len(values)} 筆，需先補值或標記缺漏")
        result[key] = (sum(values) / len(values)).quantize(D("0.1"), ROUND_HALF_UP)
    return result


def excess_charge(max_kw, contract_kw, unit_price, within_mult=D(2), beyond_mult=D(3)):
    excess = max(D(0), max_kw - contract_kw)
    tier1 = min(excess, (contract_kw * D("0.10")).quantize(D("0.1")))
    tier2 = excess - tier1
    charge = tier1 * unit_price * within_mult + tier2 * unit_price * beyond_mult
    return excess, tier1, tier2, charge.quantize(D("1"), ROUND_HALF_UP)


if __name__ == "__main__":
    samples = synthetic_samples(datetime(2026, 7, 15, 8, 0))
    demand = demand_15min(samples)
    peak_at, peak_kw = max(demand.items(), key=lambda kv: kv[1])
    print(f"15 分鐘區間數：{len(demand)}")
    print(f"最高需量：{peak_kw} kW（{peak_at:%H:%M}–{peak_at + timedelta(minutes=15):%H:%M}）")
    top3 = sorted(demand.items(), key=lambda kv: kv[1], reverse=True)[:3]
    print("前三高區間：" + "、".join(f"{t:%H:%M}={kw}" for t, kw in top3))

    contract_kw = D(900)
    unit_price = D("236.20")   # 假設的每 kW 月基本電費單價，僅供演算
    excess, t1, t2, charge = excess_charge(peak_kw, contract_kw, unit_price)
    print(f"契約容量 {contract_kw} kW，超約 {excess} kW（10% 內 {t1}、超過 10% {t2}）")
    print(f"假設單價下的超約加收：NT$ {charge:,}")

    # 錯開第 3 台冰機啟動（改為逐段加載，每 5 分鐘 +65 kW）的效果
    staged = []
    for t, kw in samples:
        m = int((t - samples[0][0]).total_seconds() // 60)
        if 150 <= m < 175:
            kw = kw - D(260) + D(65) * min(4, (m - 150) // 5 + 1)
        staged.append((t, kw))
    staged_peak = max(demand_15min(staged).values())
    print(f"分段加載後最高需量：{staged_peak} kW，"
          f"{'仍超約' if staged_peak > contract_kw else '未超約'}")

工程現場案例：冰水主機同時加載造成的需量尖峰

某機房夏季早上依序啟動三台冰機。前兩台錯開 30 分鐘啟動，第 3 台卻因排程與溫度設定點同時觸發，在 10:30 那 15 分鐘把平均功率推到 1,033 kW，超過 900 kW 契約容量。整個月只要這一個區間超約，當月就要按最高需量計算加收。

範例最後一段把第 3 台冰機改成每 5 分鐘加載 65 kW，最高需量只降到 946 kW，仍然超約。這說明分段加載能削減尖峰，但真正的解法往往是調整啟停排程、限制冰機負載上限（demand limit），或重新評估契約容量。

  1. 從 BAS 或電力監控系統匯出至少一個夏月的 1 分鐘或 15 分鐘功率資料，確認時間戳是本地時間且沒有缺漏。
  2. 用範例的 demand_15min() 找出每月最高需量與發生時段，對照當時的冰機、空壓機、電熱設備啟停紀錄。
  3. 在 DDC 加上需量限制邏輯：預測 15 分鐘平均將超過門檻時，先暫停可延後的負載，而不是等超約後才處理。
  4. 以 12 個月的最高需量分布評估契約容量，並把超約加收與多訂契約的基本電費一起比較。

練習題與自我檢查

  1. 某區間 15 筆 1 分鐘取樣中有 3 筆因通訊逾時缺漏，範例程式會怎麼處理？為什麼不直接用剩下 12 筆取平均？

    看解答

    程式會丟出 ValueError。用 12 筆取平均會把缺漏期間當成不存在，若缺的正好是加載瞬間，算出的需量會偏低，報表就會漏掉真正的超約。正確做法是先依電力表的累計電能（kWh）回推該區間平均功率，或把該區間標記為缺漏並人工確認。

  2. 把契約容量改成 1,000 kW 後重新執行，超約量與加收各是多少？請先手算再執行驗證。

    看解答

    最高需量 1,033.0 kW，超約 33.0 kW，全部落在 10%（100 kW）以內，只按 2 倍計：33.0 × 236.20 × 2 = 15,589.2，四捨五入為 NT$ 15,589。

  3. 為什麼需量計算要用 Decimal，而不是 float？

    看解答

    電費是金額計算，float 的二進位誤差在大量累加後會出現 0.01 元級的差異，與帳單核對時難以解釋。Decimal 可以指定精度與四捨五入規則（ROUND_HALF_UP），結果與人工計算一致。

  4. 修改 synthetic_samples()，讓第 3 台冰機延到 11:15 才啟動（此時第 1 台已卸載 100 kW），最高需量會落在哪個區間？

    看解答

    提示：把第 3 台的條件改成 195 <= minute < 220，並在 minute >= 195 時讓第 1 台的 180 改為 80。重新執行後最高需量會落在 11:15 區間，為 933.2 kW，仍略高於 900 kW。重點是要先量測、再調整排程，而不是憑感覺判斷。
