TECHNIQUE 2-1

2-1　assert：檢查內部不變條件

用在哪裡：測試和開發時，用斷言指出「若到這裡不成立，就是程式自己的錯」。例如正規化後的時間窗不應倒轉；來自使用者、設備或網路的錯誤則要有正常且不會被移除的驗證路徑。

運作流程

  1. 拒絕外部壞資料
  2. 運算整理資料
  3. 檢查內部不變條件

機制解析

語法是 assert condition, message；只有條件為假時才求值訊息並拋出 AssertionError。Python 在 -O 模式移除 assert，本例的明確 raise 仍然執行。參考 Python 語言參考〈The assert statement〉。

限制與踩坑：不要在 assert 內做寫檔、更新計數或權限驗證，因最佳化時連副作用都消失。assert (condition, message) 建出非空 tuple，通常永遠為真；正確寫法是讓逗號放在斷言的兩個運算式之間。

def window(start: int, end: int) -> tuple[int, int]:
    if end < start:
        raise ValueError("end must not precede start")
    span = end - start
    assert span >= 0, "window length invariant"
    return start, span

assert window(3, 8) == (3, 5)
try:
    window(8, 3)
except ValueError:
    pass
else:
    raise RuntimeError("invalid input was accepted")

2-2　容器逗號：尾逗號、單項 tuple 與字串串接

用在哪裡：多行設定每列各留一個尾逗號，新加設備只修改自己那一列，Git diff 可直接比對；同時避免相鄰字串常值被合成一個欄位。

運作流程

  1. 一項一行
  2. 加上尾逗號
  3. 驗證元素清單

機制解析

tuple 是由逗號形成的，(value) 只是分組；單項 tuple 寫 (value,)，空 tuple 寫 ()。list、dict、set 多行常值允許尾逗號；相鄰字串常值則由語法直接串接，不會報錯。

限制與踩坑：只靠 formatter 不能找出已經合法串接成一個字串的漏逗號。欄位清單需要元素數量／名稱測試；-O 移除驗證示例的 assert，但不會改變常值語法。

channels = [
    "supply",
    "return",
]
single = ("supply",)
grouped = ("supply")
accidental = [
    "supply"
    "return",
]
assert channels == ["supply", "return"]
assert isinstance(single, tuple) and isinstance(grouped, str)
assert accidental == ["supplyreturn"]

TECHNIQUE 2-3

2-3　with：用 context manager 管理資源

用在哪裡：讀取點表或占用鎖時，要保證例外路徑也釋放資源。with 將進場、工作與退場明確分開，免得每個呼叫處重寫 try/finally。

運作流程

  1. 取得資源
  2. 執行區塊
  3. 清理後傳出例外

機制解析

__enter__() 回傳給 as；成功進入後，__exit__(exc_type, exc, traceback) 在區塊結束時被呼叫。回傳真值可吞掉區塊例外；None 或 False 讓例外傳出。對輕量案例也可用 contextlib.contextmanager 搭配 try/finally。

限制與踩坑：__enter__() 途中失敗不會呼叫同一個管理器的 __exit__；多資源取得需要局部清理或 ExitStack。不要回傳 True 只為了安靜，否則讀取失敗會看起來像成功。

from io import StringIO

class Buffer:
    def __enter__(self):
        self.stream = StringIO()
        return self.stream

    def __exit__(self, exc_type, exc, traceback):
        self.stream.close()
        return False

try:
    with Buffer() as stream:
        stream.write("CHW01")
        raise ValueError("invalid sample")
except ValueError as exc:
    assert str(exc) == "invalid sample"
else:
    raise RuntimeError("exception was suppressed")
assert stream.closed

TECHNIQUE 2-4

2-4　底線命名：約定、名稱改寫與特殊名稱

用在哪裡：模組內部輔助函式與子類別私有儲存欄位的需求不同。前綴單底線是 API 約定，前綴雙底線是避免名稱碰撞的機制，兩者都不是存取控制。

運作流程

  1. 選公開或內部 API
  2. 判斷是否須避免子類碰撞
  3. 用行為測試契約

機制解析

_name 表示內部；沒有 __all__ 時，from module import * 會跳過底線開頭的名稱。類別內 __name（沒有兩個結尾底線）文字式改寫為 _ClassName__name；__len__ 等前後雙底線是定義好的特殊方法。class_ 可避開保留字。

限制與踩坑：不要以 __name 保護密碼：改寫後仍能存取。也不要自行編造 __something__ 當公用 API。_ 常作不使用的繫結或互動環境的上一結果；它不是語言保留的丟棄符號。

class Base:
    def __init__(self):
        self.__rate = 6

    def base_rate(self):
        return self.__rate

class Pump(Base):
    def __init__(self):
        super().__init__()
        self.__rate = 9

    def pump_rate(self):
        return self.__rate

pump = Pump()
assert (pump.base_rate(), pump.pump_rate()) == (6, 9)
assert pump._Base__rate == 6  # demonstrates that it is not private access

TECHNIQUE 2-5

2-5　四種字串格式化：依使用邊界選工具

用在哪裡：溫度狀態列要固定兩位小數，而可由其他人提供的郵件樣板則不應任意執行 Python。依格式是否在原始碼、是否需延後插值來選工具。

運作流程

  1. 選固定或可替換樣板
  2. 定義欄位與精度
  3. 驗證產出與下游逸出

機制解析

f-string（3.6+）直接執行內嵌運算式；str.format() 以欄位與格式規格重用樣板；% 常見於既有程式及 logging 的訊息加參數介面；string.Template 支援較小的 $name 替代語法。一般數值輸出可用 :.2f。

限制與踩坑：把 logging 的格式字串與參數分開可推遲訊息插值，但參數運算仍在呼叫前發生。不要為外部模板使用 eval；Template 也不負責 HTML 逸出或 SQL 安全，SQL 值須交給驅動參數。

from string import Template

device, value = "CHW01", 7.25
a = "%s %.2f" % (device, value)
b = "{} {:.2f}".format(device, value)
c = f"{device} {value:.2f}"
d = Template("$device $value").substitute(device=device, value=f"{value:.2f}")
assert a == b == c == d == "CHW01 7.25"

TECHNIQUE 2-6

2-6　指派運算式 :=：在條件中保存結果

用在哪裡：解析遙測一批行時，可能同時要知道是否成功，以及使用解析出來的值。:= 適合避免重複呼叫，但不應把一段複雜流程壓進條件。

運作流程

  1. 解析一次
  2. 比較明確哨兵
  3. 保存有效結果

機制解析

:= 從 Python 3.8 起，把右側結果指定到名稱，同時保留運算式的值。標的是單一名稱，不是屬性或索引。視上下文可能要加括號；在 if/while 內常見。

限制與踩坑：if value := parse(raw) 會把有效的 0 丟掉；以 (value := parse(raw)) is not None 區分缺測。不要過度利用生成式中的名稱繫結，當讀者須追蹤副作用時改成明確迴圈。

def parse(raw: str) -> int | None:
    try:
        return int(raw)
    except ValueError:
        return None

values = []
for raw in ["0", "bad", "12"]:
    if (value := parse(raw)) is not None:
        values.append(value)
assert values == [0, 12]

2-7　Python 之禪：把設計取捨落到可驗證行為

運作流程

  1. 分開現場語意
  2. 用明確狀態回應
  3. 測缺值、零與一般值

機制解析

標準直譯器執行 import this 可顯示彩蛋；正式文本是 PEP 20。實作上，用具名的狀態與回應取代隱藏預設，再以邊界案例建測試，將風格原則轉為可比對證據。

限制與踩坑：不要為符合單一句原則到處加入抽象層。若簡單與可讀性衝突，優先讓錯誤路徑清楚；import this 有匯入時輸出副作用，不應出現在服務啟動模組。

def classify(flow: int | None) -> str:
    if flow is None:
        return "missing"
    if flow == 0:
        return "stopped"
    return "running"

assert [classify(x) for x in (None, 0, 35)] == [
    "missing", "stopped", "running",
]

第 2 章補充

Python 命名規則：識別字、長度與格式

用在哪裡：名字要讓裝置、量測值、單位與狀態一眼可辨，也要區分合法語法、PEP 8 風格與團隊自訂規範。讀到 supply_air_temp_c，應能知道用途與單位，不必先追相鄰程式碼。

運作流程

  1. 先驗證語法與關鍵字
  2. 依用途挑選命名格式
  3. 依作用域和生命週期補語意
  4. 檢查縮寫、單位與可讀性
  5. 格式化程式行，不靠工具改名

機制解析

語法：識別字可使用底線與規範接受的 Unicode 字元；開頭不能是一般數字，後續可含數字，大小寫有別，空白和連字號不合法；保留關鍵字不能作一般名稱。Python 語法沒有固定的識別字字元數上限。Python 剖析原始碼時按 NFKC 正規化識別字。PEP 8 標準格式：函式、一般變數和參數用 snake_case，類別用 CapWords，模組常用短小寫名（需要時可用底線），套件偏好短小寫且盡量避免底線，模組層級常數用 UPPER_CASE。CapWords 中縮寫整段大寫，如 HTTPServer、MQTTClient；一般變數可用 mqtt_topic、http_status。PEP 8 的 79 字元程式行、72 字元註解／文件字串行是排版建議，不是變數名稱上限。選名長度可依語境：小範圍的迴圈索引用 i；一般局部值可先用 1–3 個詞；跨函式／跨模組名稱優先保留業務語意與必要單位，如果描述太長，考慮拆責任或把欄位放到具名物件。這些是可採用的團隊原則，不是 Python 強制規則。 作用域：函式區域名稱應貼合有限生命週期；跨模組公開名稱視為 API，改名要考量相容性。Python 依可見作用域解析名稱；不要假設區域變數和同名全域變數是同一份資料。格式化工具主要調整空白、引號和斷行，並非識別字重命名；需要一致命名時交由 lint 規則、程式碼審查和保留相容性的重構。

限制與踩坑：str.isidentifier() 只檢查識別字形式，也會接受 class；應再用 keyword.iskeyword() 排除保留字。match／case 是特定文法位置才有意義的軟關鍵字，keyword.issoftkeyword() 可做提示，不代表平常不能作變數。單前置底線 _name 只是非公開慣例；沒有 __all__ 時，from module import * 預設略過它，不是權限機制。類別內的 __name（開頭至少兩個底線、結尾不到兩個）會觸發名稱改寫以減少子類碰撞，仍可存取，不是私有保護。__name__ 這類雙前後底線保留給既有語言／函式庫協定，不為一般變數自創。既有命名與框架衝突可用 class_，避免 list、id 等遮蔽內建名稱。Unicode 可讀性因團隊而異：專案可自訂只用 ASCII，避免形似字元；此限制不應誤稱為語法，也不要對外部字典鍵直接套用識別字規則。

    def wrapper(*args, **kwargs):
        try:
            return fn(*args, **kwargs)
        finally:
            events.append(fn.__name__)
    return wrapper

@observe
def read(value):
    if value is None:
        raise ValueError("missing")
    return value

    read(None)
except ValueError:
    pass
else:
    raise AssertionError("wrapper suppressed error")

        return cls(tag)

    @staticmethod
    def valid(tag):

    pass

from functools import update_wrapper

class Counter:
    def __init__(self, fn):
        update_wrapper(self, fn)
        self.fn = fn
        self.calls = 0

    def __call__(self, *args, **kwargs):
        self.calls += 1
        return self.fn(*args, **kwargs)

@Counter
def scale(raw, *, divisor):
    return raw / divisor

機制解析

限制與踩坑：空堆疊 pop 或索引 -1 都會拋出 IndexError。不要用 pop(0) 模擬堆疊；它從相反的端點取值且要搬動其餘項。跨執行緒堆疊考慮 queue.LifoQueue，並明確決定空或滿時的行為。

def balanced(text: str) -> bool:
    expected = {"(": ")", "[": "]", "{": "}"}
    stack = []
    for ch in text:
        if ch in expected:
            stack.append(expected[ch])
        elif ch in expected.values():
            if not stack or stack.pop() != ch:
                return False
    return not stack

assert balanced("function([1, {2}])")
assert not balanced("([)]")
assert not balanced("(missing")
assert not balanced("]")

5-6　佇列（queue，FIFO）

用在哪裡：先進先出適合輪詢待辦、廣度優先搜尋或工作交接。分清楚本機資料結構與具阻塞語意的通道。

運作流程

  1. 定義 FIFO
  2. 選擇滿載策略
  3. 取出並處理
  4. 回報任務完成

機制解析

collections.deque 的 append 與 popleft 從兩端操作，通常為 O(1)。跨執行緒的 queue.Queue 可設定 maxsize 並用 put/get 的阻塞或 timeout 管理背壓；每次成功 get 對應一次 task_done，join 等未完成工作計數清零。asyncio.Queue 則用於同一事件迴圈的協程，不應直接在線程間共用。

限制與踩坑：不要用空佇列先判斷再取出；跨執行緒之間可能有競爭，應直接 get_nowait 並處理 queue.Empty。deque(maxlen=...) 滿時從另一端淘汰舊資料，不會背壓。若用哨兵關閉多個 worker，需確保每個消費者都能收到停工訊號。

from collections import deque
from queue import Full, Queue

pending = deque(["AHU01", "AHU02"])
assert pending.popleft() == "AHU01"
assert pending.popleft() == "AHU02"

channel: Queue[str] = Queue(maxsize=1)
channel.put_nowait("讀取 SAT")
try:
    channel.put_nowait("讀取 RAT")
except Full:
    pass                         # 真實系統應依契約重試、限流或回報
else:
    raise AssertionError("應觸發背壓")
job = channel.get_nowait()
try:
    assert job == "讀取 SAT"
finally:
    channel.task_done()
channel.join()

TECHNIQUE 5-7

5-7　優先佇列（priority queue）

用在哪裡：任務不是總按到達次序執行時，使用優先佇列。優先級相同仍要求 FIFO，就把單調遞增序號納入比較鍵。

運作流程

  1. 定義數字優先級
  2. 附遞增序號
  3. 推入最小堆
  4. 由根依順序取出

機制解析

heapq 是以 list 為底的最小堆積：父節點不大於子節點；根為最小值，但整個 list 不是已排序清單。heapify 建堆 O(n)，heappush/heappop 為 O(log n)，讀 heap[0] 為 O(1)。tuple 依欄位順序比較；用 (priority, sequence, payload) 避免同優先級的工作資料互相比較。跨執行緒可用 queue.PriorityQueue，排序規則仍要自行定義。

限制與踩坑：heappop 空堆拋 IndexError；直接改變堆中物件的比較鍵會破壞堆積性質，更新優先級可採加入新記錄並跳過過期版本。緊急任務源源不絕會使低優先級飢餓，上線前需定義配額或等待上限。

from heapq import heappop, heappush
from itertools import count

jobs = []
serial = count()
for rank, name in [(20, "例行巡檢"), (5, "先到告警"), (5, "後到告警")]:
    heappush(jobs, (rank, next(serial), {"name": name}))

assert jobs[0][0] == 5
ordered = [heappop(jobs)[2]["name"] for _ in range(len(jobs))]
assert ordered == ["先到告警", "後到告警", "例行巡檢"]

TECHNIQUE 6-1

6-1　寫出符合 Python 風格的 for 迴圈

用在哪裡：先描述你要走訪什麼，再選迴圈工具：只要值就直接走訪；要顯示序號用 enumerate；要同步比對兩組資料用 zip；要字典的鍵和值用 items。把索引操作留給真正在意位置、相鄰關係或原地更新的問題。

運作流程

  1. 辨認需求：值、序號或並列配對
  2. 用 for 直接讀下一筆
  3. 需要等長時用 strict=True
  4. 用測試釘住缺資料的行為

機制解析

for 會對右側物件取 iterator，再逐次取下一筆並綁定迴圈變數。enumerate 逐筆傳回 (序號, 元素)，start=1 只改序號起點，不會切掉第一筆。zip 逐筆回傳對應配對；兩端都必須等長時，可用 zip(..., strict=True)，且不需先把輸入變成串列。

限制與踩坑：普通 zip 會在最短的來源用完時結束，缺資料可能沒有警告。strict=True 只有走訪到長度差異才拋 ValueError；在途中 break 不能保證整體等長。配對中途可能已產生部分結果或副作用，需要全有全無時先完成驗證或使用交易。也不要一面走訪同一個串列，一面刪除其中元素。

def format_points(names: list[str], values: list[float]) -> list[str]:
    rows = []
    pairs = zip(names, values, strict=True)
    for number, (name, value) in enumerate(pairs, start=1):
        rows.append(f"{number}. {name}: {value:.1f} °C")
    return rows

assert format_points(["送風", "回風"], [18.25, 24.1]) == [
    "1. 送風: 18.2 °C",
    "2. 回風: 24.1 °C",
]
assert format_points([], []) == []
for names, values in [(["送風"], []), ([], [18.0])]:
    try:
        format_points(names, values)
    except ValueError:
        pass
    else:
        raise AssertionError("點位與讀值長度不符，應回報錯誤")

TECHNIQUE 6-2

6-2　生成式：Comprehension

用在哪裡：把「選哪些資料」與「每筆要轉成什麼」放在同一個局部表達式。適合簡單、無副作用的轉換；多條規則、逐筆寫日誌、錯誤復原或需要中途停止時，普通 for 更清楚。

運作流程

  1. 走訪一筆原始資料
  2. 先判斷是否保留
  3. 計算輸出欄位或鍵值
  4. 依需要建立 list、set 或 dict

機制解析

以 [結果 for 元素 in 資料 if 條件] 為例：先取元素、判斷條件，最後才計算結果。巢狀 for 的順序與對應的外層、內層迴圈相同。[] 建立 list，{值 for ...} 建立 set，{鍵: 值 for ...} 建立 dict；空集合要寫 set()，不是 {}。在 Python 3，普通 comprehension 的迴圈目標不會洩漏到外層。

限制與踩坑：list、set、dict comprehension 都會立刻走完來源並建立容器。字典遇到重複鍵會保留最後寫入的值，不能拿它來默默隱藏重複點位。尾端 if 會丟棄整筆資料；寫在結果位置的 A if 條件 else B 則會留下所有元素，只改輸出值。避免為了縮短程式把帶副作用的函式塞進 comprehension。

readings = [("AHU-1", "ok", 18.0), ("AHU-2", "bad", 80.0),
            ("AHU-3", "ok", 23.0)]
name = "外層變數"

accepted = [
    (name, round(value * 9 / 5 + 32, 1))
    for name, quality, value in readings
    if quality == "ok"
]
quality_codes = {quality for _, quality, _ in readings}
by_point = {name: value for name, value in accepted}

assert accepted == [("AHU-1", 64.4), ("AHU-3", 73.4)]
assert quality_codes == {"ok", "bad"}
assert by_point == {"AHU-1": 64.4, "AHU-3": 73.4}
assert name == "外層變數"
assert {key: v for key, v in [("A", 1), ("A", 2)]} == {"A": 2}
matrix = [[1, 2], [], [3]]
assert [v for row in matrix for v in row] == [1, 2, 3]

TECHNIQUE 6-3

6-3　List 切片：所謂「壽司算符」其實是 slice

用在哪裡：用片段、區間或取樣點表達需求，不用手算每個索引。可拿前幾筆、最後幾筆、每隔幾筆或倒序查看。重複對大型 list 切片仍會複製，資料流若只往前讀，可考慮 itertools.islice。

運作流程

  1. 確定起點與不含的終點
  2. 依方向選正或負步長
  3. 區分讀出副本與原地切片賦值
  4. 檢查巢狀物件是否仍共享

機制解析

list[start:stop:step] 組成 slice，stop 永遠不包含。正步長省略 start / stop 表示從開頭走向尾端；負步長省略兩界則從尾端反向走完。負索引相對尾端，超界切片會裁到可用範圍。讀取切片建立新 list，取 k 項約用 O(k) 時間與額外空間，但 list 裡的物件是淺層共享。

限制與踩坑：a[-1::-1] 會倒序走完，a[-1:-1:-1] 卻是空切片，省略終點不等於明寫 -1。step=0 會拋 ValueError。對 list 的步長 1 切片賦值可改變長度；其他步長做切片賦值時，右側元素數必須等於選中的位置數。切片複製也不是深複製，修改巢狀物件仍可能影響原串列。

samples = [10, 20, 30, 40, 50]
assert samples[1:4:2] == [20, 40]
assert samples[-3:] == [30, 40, 50]
assert samples[-1::-1] == [50, 40, 30, 20, 10]
assert samples[-1:-1:-1] == []
assert samples[99:] == []
selection = slice(1, 4, 2)
assert samples[selection] == [20, 40]

changed = samples[:]
changed[1:3] = [88]
assert changed == [10, 88, 40, 50] and samples[1] == 20
changed[::2] = [100, 400]
assert changed == [100, 88, 400, 50]

nested = [["送風"], ["回風"]]
copied = nested[:]
copied.append(["新風"])
copied[0].append("備援")
assert len(nested) == 2 and nested[0] == ["送風", "備援"]

TECHNIQUE 6-4

6-4　Iterator：掌握走訪器協定

用在哪裡：Iterable 回答「如何開始走訪」，iterator 則保存「目前讀到哪裡」。理解這個差別，才知道哪些資料可以再讀一遍，哪些資料來源只能消費一次。

運作流程

  1. iter 取出走訪器
  2. next 取得一筆並推進游標
  3. StopIteration 是正常結束
  4. 另開走訪器才能重新讀

機制解析

對 iterable 呼叫 iter() 會得到 iterator；對 iterator 呼叫 next() 才會讀一筆。沒有下一筆時 __next__ 拋出 StopIteration，已耗盡的 iterator 不會自行重啟。iterator 的 __iter__ 回傳自己，因此 for、list 和 next 可共用相同游標。next(it, default) 只在耗盡時給預設值，不會攔下其他錯誤。

限制與踩坑：不要把「能被 for 走訪」誤認成「能重複走訪」：同一個 iterator 傳給第二個消費者時，會從上一個消費者停下的位置開始。拿 list 重新 iter 往往可得到新的走訪器；讀檔、串流或自訂 iterable 仍要確認介面是否承諾可重開。合法資料若可能是 None，要用獨立 sentinel 區分真正耗盡。

class Countdown:
    def __init__(self, start: int):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self) -> int:
        if self.current <= 0:
            raise StopIteration
        value = self.current
        self.current -= 1
        return value

countdown = Countdown(3)
assert iter(countdown) is countdown
assert next(countdown) == 3
assert list(countdown) == [2, 1]
assert list(countdown) == []
end = object()
assert next(countdown, end) is end

data = [None, 21]
a, b = iter(data), iter(data)
assert next(a, end) is None and next(b, end) is None
assert list(a) == [21] and list(b) == [21]

TECHNIQUE 6-5

6-5　產生器函式：以 yield 暫停後再繼續

用在哪裡：當資料逐筆到來，或只想拿前幾筆結果時，用含 yield 的函式描述產生規則。保留條件判斷、暫時狀態和清理邏輯，而不需要手寫 iterator 類別或先建整張清單。

運作流程

  1. 呼叫函式：只建立物件
  2. next：執行到下一個 yield
  3. 繼續取值：沿用內部狀態
  4. 提早離開時顯式清理資源

機制解析

呼叫產生器函式只建立 generator 物件，函式本體到第一次 next 才執行。yield 交出一筆並保存執行位置與區域變數；下一次從 yield 後恢復。走到結尾或 return 就耗盡。若要把多段 iterator 依序委派給呼叫者，可用 yield from。

限制與踩坑：早停不代表資源會立即釋放：若產生器仍被其他變數引用，離開 for 不保證立刻觸發 finally。資源擁有權應由 with 或明確 close 管理；可用 contextlib.closing 包住已開始的產生器。正常結束寫 return，不要手動 raise StopIteration，後者冒出產生器時會變成 RuntimeError。

from collections.abc import Generator
from contextlib import closing

trace: list[str] = []

def good_values(rows: list[tuple[str, float]]) -> Generator[float, None, None]:
    trace.append("開始")
    try:
        for state, value in rows:
            trace.append(f"處理 {value:g}")
            if state == "ok":
                yield value
    finally:
        trace.append("清理")

records = [("bad", 99.0), ("ok", 18.0), ("ok", 20.0)]
stream = good_values(records)
assert trace == []
with closing(stream) as values:
    assert next(values) == 18.0
    assert trace == ["開始", "處理 99", "處理 18"]
assert trace[-1] == "清理" and "處理 20" not in trace
assert list(stream) == []
assert list(good_values([])) == []

TECHNIQUE 6-6

6-6　產生器運算式：把延遲求值寫成一個表達式

用在哪裡：只需簡單的逐筆轉換或過濾，且消費端可逐筆處理時，用 (結果 for ... if ...) 取代中間 list。適合 sum、any、all 或 islice 的輸入，不必為單行轉換另外定義產生器函式。

運作流程

  1. 最左來源立即求值
  2. 每次 next 才過濾並計算
  3. 讓 any 或 islice 決定讀多少
  4. 避免把一次性物件當可回放資料

機制解析

建立運算式時，最左側 for 的 iterable 表達式會立即求值，並交給 iter；取值、條件、輸出式與後續 for 則延後到消費時。any 和 all 能短路，sum 會讀到耗盡。括號是產生器運算式語法，不是建立 tuple；若要物化結果，須明寫 tuple(...) 或 list(...)。

限制與踩坑：不會先建立整批結果不代表一定會少做工作：sum 仍會讀完整條有限資料，sorted 仍要保存排序輸入，無限資料直接 sum 不會自然停止。外部變數在延遲執行時可能已變更；若規則要固定，使用含參數的產生器函式，或先固定值、建立時不要再改動它。也不要依賴用 expression 排程資源開啟時機。

from itertools import islice

trace: list[str] = []

def source():
    trace.append("建立來源")

    def rows():
        for value in [12, 20, 26, 28]:
            trace.append(f"讀取 {value}")
            yield value

    return rows()

alarms = (value - 18 for value in source() if value > 18)
assert trace == ["建立來源"]
assert list(islice(alarms, 2)) == [2, 8]
assert trace == ["建立來源", "讀取 12", "讀取 20", "讀取 26"]
assert list(alarms) == [10]
assert list(alarms) == []

threshold = 15
lazy_filter = (v for v in [16, 20] if v > threshold)
threshold = 17
assert list(lazy_filter) == [20]  # 過濾條件是在走訪時執行

TECHNIQUE 6-7

6-7　走訪器串聯：串接來源，再分層轉換

用在哪裡：資料來自多個批次、日誌檔或感測器，可先排列成單一來源，再套用品質篩選和型別轉換。把每個階段做成小型走訪器，方便各自測試，或只讓下游讀到所需筆數。

運作流程

  1. 依順序接起多個批次
  2. 略過無效品質
  3. 把保留欄位轉成統一單位
  4. 只消費所需筆數並檢查何時讀下一批

機制解析

走訪器串接有兩種常見層次：chain.from_iterable 把多個來源依序接成一條流；下游再以 generator expression、產生器函式或 map/filter 組裝處理步驟。若自己實作串接，可在 for 中用 yield from 逐段委派。zip 是同時配對多源，不是把第一批接到第二批。

限制與踩坑：chain 不會按時間戳交錯、合併排序或去除重複，它只先耗盡第一個來源，再讀下一個。一個來源無限長，後面的來源便永遠輪不到。list、sorted 或把批次過早讀成 list 都會破壞串流的記憶體優勢；如果想公平交錯，需要明確採用輪詢或其他合併規則。

from collections.abc import Iterable, Iterator
from itertools import chain

def good_temperatures(
    batches: Iterable[Iterable[tuple[str, int]]],
) -> Iterator[float]:
    merged = chain.from_iterable(batches)
    return (decic / 10 for status, decic in merged if status == "ok")

seen: list[str] = []

def batches():
    seen.append("批次 A")
    yield [("bad", 999), ("ok", 215)]
    seen.append("批次 B")
    yield []
    seen.append("批次 C")
    yield [("ok", 223), ("ok", 240)]

stream = good_temperatures(batches())
assert seen == []
assert next(stream) == 21.5 and seen == ["批次 A"]
assert next(stream) == 22.3 and seen == ["批次 A", "批次 B", "批次 C"]
assert list(stream) == [24.0]
assert list(good_temperatures([])) == []

6-8　itertools：組合有限與無限走訪器

用在哪裡：用標準函式庫表達封頂讀取、相鄰比較、累積與連續分段，能少寫容易差一的游標邏輯。先問資料是否有限、輸入是否已排序，以及下游何時才讀下一個元素。

運作流程

  1. 先用 islice 為無限來源設定上限
  2. 用 pairwise 取得相鄰差值
  3. 需要逐筆累積時用 accumulate
  4. 依鍵連續分段時用 groupby

機制解析

count 依起始值及步長持續產生值；islice 可限制讀出筆數；pairwise 產生相鄰的重疊配對；accumulate 逐筆產生累積值；groupby 遇到鍵變化才開新群組。groupby 不會重排或聚合全部相同鍵，若資料已依鍵排序，才會形成每鍵一組的結果。

限制與踩坑：不要對無限走訪器呼叫 list 或不設上限的 sum。islice 不接受負索引或負步長，不是 list 切片的通用替代品。groupby 的各組共用同一來源，要在進入下一組前消費或獨立存下該組。組合工具也不一定用固定空間：tee 的消費進度差距會累積暫存；product 會先把輸入收集成內部池。

from itertools import accumulate, count, groupby, islice, pairwise

seq = list(islice(count(start=100, step=2), 4))
assert seq == [100, 102, 104, 106]
assert list(islice(count(), 0)) == []

readings = [18, 22, 21, 25]
deltas = [curr - prev for prev, curr in pairwise(readings)]
assert deltas == [4, -1, 4]
assert list(pairwise([99])) == []
assert list(accumulate(deltas, initial=0)) == [0, 4, 3, 7]

events = [("ok", 1), ("ok", 2), ("warn", 3), ("ok", 4)]
runs = [(key, [seq for _, seq in group])
        for key, group in groupby(events, key=lambda row: row[0])]
assert runs == [("ok", [1, 2]), ("warn", [3]), ("ok", [4])]

7-3　用 dict 分派固定命令（模擬 switch）

  1. 正規化命令名稱
  2. 從允許清單取函式

機制解析

def brief(readings):
    return f"{len(readings)} 筆"

def detail(readings):
    return ", ".join(str(value) for value in readings)

HANDLERS = {"brief": brief, "detail": detail}

def run(command, readings):
    handler = HANDLERS.get(command.strip().lower())
    if handler is None:
        raise ValueError("不支援的命令")
    return handler(readings)

assert run(" Brief ", [18, 20]) == "2 筆"
assert run("detail", [18, 20]) == "18, 20"
try:
    run("delete", [18, 20])
except ValueError:
    pass
else:
    raise AssertionError("未知命令本應被拒絕")

7-4　更新字典鍵值時，避開迭代與共用物件陷阱

用在哪裡：批次整理設定時，常同時刪除舊鍵、重新命名，或複製後改巢狀設定。這些操作若混在同一迴圈，容易在更新途中失敗，或意外修改原始資料。

運作流程

  1. 先決定更新或重建
  2. 避開遍歷時增刪鍵
  3. 檢查巢狀值是否共用

機制解析

修改既有鍵的值通常不會改變迭代結構；增刪鍵時，請遍歷 list(d.items())、先收集變更，或建立新字典。dict.copy() 只複製外層，內層物件仍共用。改名時若新鍵已存在，先決定要拒絕、覆蓋或合併。

限制與踩坑：len(d) 沒變也不代表可以一邊刪鍵一邊加鍵；迭代器仍可能失效，結果也不該依賴。d.update(...) 會原地修改並回傳 None。深拷貝也不等於可複製資料庫連線等外部資源。

assert set(filtered) == {"T01"}
assert filtered["T01"] is raw["T01"]  # 重建外層仍不複製內層

edited = deepcopy(filtered)

assert raw["T01"]["enabled"] is True

for key, value in list(ids.items()):
    if key == "old":
        if "new" in ids:
            raise ValueError("改名會覆蓋既有鍵")
        ids["new"] = ids.pop(key)

shallow = defaults | override
assert shallow["serial"] == {"baud": 19200}
merged = shallow | {"serial": defaults["serial"] | override["serial"]}

運作流程

  1. 選一個小函式
  2. 列出實際執行器的指令
  3. 只測語意與結構不變量

機制解析

在 CPython，函式的 code object 保存位元組碼及常數等資訊。dis.dis(fn) 供人檢視；dis.get_instructions(fn) 回傳 Instruction 序列，方便工具逐條查看。以可執行函式語意與 code object 資訊檢驗結果；用 timeit 或效能工具另外量測實際速度。

技巧 01

惰性資料流

itertools.islice + 產生器

先決定「需要幾筆」再取值，避免為了少量結果把整份輸入載入記憶體。適合日誌、感測快照或大型 CSV 的第一階段篩選。

  1. 逐筆讀取
  2. 篩選
  3. 變換
  4. 只拿前 N 筆

避坑：產生器只能走一次，不能當快照共享；若不用切片或限時，無限來源可能永遠跑不完。

from itertools import islice

def high_readings(readings, threshold=28.0):
    for point, value in readings:
        if value >= threshold:
            yield point, round(value, 1)

def sensor_stream():
    yield "T01", 26.2
    yield "T02", 29.4
    yield "T03", 31.5
    raise AssertionError("已取足兩筆，不應繼續讀取")

first_two = list(islice(high_readings(sensor_stream()), 2))
assert first_two == [("T02", 29.4), ("T03", 31.5)]
print(first_two)

預期輸出： [('T02', 29.4), ('T03', 31.5)]

機制解析

Python 收到 yield 便暫停函式，保留區域變數與讀取位置。呼叫端下一次索取，才繼續掃描。篩選後若只拿兩筆，讀入筆數不一定是兩筆：前面的未達標資料仍須檢查。

什麼時候不要用？

不適合要反覆取用、任意索引、排序或對外提供重複可用快照時。來源若來自開啟的檔案，必須在上下文有效期間內完成消費。

提前停止與可重跑需求分開看
條件發生什麼設計取捨
list 建表會消費整個來源；結果可重複走訪需保留已讀資料
generator + islice只走到足夠數量；使用後不重設僅保持迭代狀態及取出的結果
技巧 02

用上下文保證收尾

contextmanager

把建立與釋放資源放在同一個抽象層。呼叫方保留業務動作，程序正常或丟出例外都會走到清理步驟。

  1. 進入
  2. 取得資源
  3. 執行工作
  4. finally 一定收尾

避坑：不要在 finally 吞掉原始例外；清理本身也可能失敗。真實故障時應保留原始錯誤並紀錄清理狀況。

from contextlib import contextmanager
from io import StringIO

@contextmanager
def managed_buffer():
    stream = StringIO()
    try:
        yield stream
    finally:
        stream.close()

try:
    with managed_buffer() as buffer:
        buffer.write("sample")
        raise ValueError("simulate failure")
except ValueError as exc:
    assert str(exc) == "simulate failure"
    assert buffer.closed
else:
    raise AssertionError("原始例外不應被吞掉")

print("例外後確認資源已釋放")

預期輸出： 例外後確認資源已釋放

機制解析

進入時建立資源。yield 把資源交給 with 主體；若主體出錯，例外回到 yield 位置，finally 執行完仍會向外傳遞。

什麼時候不要用？

不適合宣稱已回滾遠端副作用；close 只代表本機資源清理。跨網路寫入，要另設交易、補償或對帳。正常關閉後資料仍須遵守資源生命週期。

成功、出錯與程序被終止
條件發生什麼設計取捨
正常離開finally → 關閉回傳值可用
一般應用例外finally → 關閉 → 原錯誤向外傳播測試需主動觸發這條分支
程序被強制終止不保證執行 Python 清理程式需由外部租約或重啟機制補救
技巧 03

不可變資料快照

dataclass(frozen=True, slots=True)

用命名欄位賦予資料契約；不就地修改現有快照，需要更新時產出新物件。slots 省掉常見的每實例屬性字典，但資源收益要用實際物件量測。

  1. 來源資料
  2. 建立快照
  3. 刊登新值
  4. 讀取端使用同一筆快照

避坑：frozen 只管欄位重新賦值。內含 list 或 dict 仍可能被修改；以 tuple 和其他不可變成員組成快照。這不代表更新共享參照的複合邏輯自動安全。

from dataclasses import dataclass, replace

@dataclass(frozen=True, slots=True)
class Snapshot:
    sensor: str
    samples: tuple[float, ...]

original = Snapshot("T01", (26.2, 26.5))
updated = replace(original, samples=original.samples + (27.0,))
assert original.samples == (26.2, 26.5)
assert updated.samples[-1] == 27.0
assert not hasattr(updated, "__dict__")
print(updated)

預期輸出： Snapshot(sensor='T01', samples=(26.2, 26.5, 27.0))

機制解析

frozen 會阻止一般欄位賦值；slots 在本例用固定欄位，不建立每筆的屬性字典。replace 建立同型別新值，不會把舊快照就地改掉；tuple 裡仍須放適合共享的成員。

什麼時候不要用？

避免把需要動態掛載屬性的紀錄或經常整批重新複製的大型序列強套 slots 或 replace。跨執行緒要用具通訊契約的傳遞方式，而不是假設多步更新安全。

更新前後的兩個快照
條件發生什麼設計取捨
原本T01 → (26.2, 26.5)仍可被先前的讀取端引用
更新T01 → (26.2, 26.5, 27.0)新快照數值由 replace 建立
技巧 04

結構式分派

match / case

比起一串索引與 if，直接寫出可讀的訊息形狀，用 guard 補充業務條件。適合固定命令格式或分版本處理事件。

  1. 訊息
  2. 對照結構
  3. 驗證細節
  4. 執行或拒絕

避坑：映射模式預設允許額外鍵；未知欄位必須明確決定接受或拒絕。bool 是 int 的子類別，若協定只允許整數，要特別排除。

def dispatch(message):
    match message:
        case {"op": "poll", "interval": int(sec), **extra} \
                if type(sec) is int and 1 <= sec <= 300 and not extra:
            return ("poll", sec)
        case {"op": "stop", **extra} if not extra:
            return ("stop", None)
        case _:
            return ("invalid", None)

assert dispatch({"op": "poll", "interval": 5}) == ("poll", 5)
assert dispatch({"op": "stop"}) == ("stop", None)
for bad in (True, 0, 301, "5"):
    assert dispatch({"op": "poll", "interval": bad})[0] == "invalid"
assert dispatch({"op": "poll", "interval": 5, "unused": 1})[0] == "invalid"
print("有效命令與錯誤命令皆已驗證")

預期輸出： 有效命令與錯誤命令皆已驗證

機制解析

比對由上往下，先檢查 pattern，再執行 guard。第一個符合就進入分支；若不合規，交給 case _。int 模式會接受 bool，因此 guard 額外檢查 type(sec) is int。

什麼時候不要用？

只比對一個簡單條件時，if 更易閱讀；格式有多層欄位、型別錯誤位置或版本治理需求時，完整資料驗證應獨立建模，不宜把所有規範塞在一個 match。

結構、值域與未知欄位
條件發生什麼設計取捨
interval: 5結構、型別、範圍均通過接受
interval: true模式能匹配 int 子類，但 guard 擋下拒絕
interval: 5 + 額外欄位extra 不為空拒絕
技巧 05

結構化非同步

asyncio.TaskGroup + timeout

同一批任務跟隨同一個生命週期；一項 I/O 失敗會取消其他仍執行的同組任務。下面用 Event 確保示範的同組工作已啟動，不以猜測的排程時間測取消。

  1. 啟動同批 I/O
  2. 等待結果
  3. 任務失敗即取消同組
  4. 交接

避坑：asyncio 是協作式 I/O 並發，不等於 CPU 多核平行；避免在事件迴圈直接做重度純 Python 運算。逾時會提出取消，不是程序硬殺，且不代表外部系統已回滾。

import asyncio

async def main():
    ready = asyncio.Event()
    cleaned = asyncio.Event()

    async def sibling():
        ready.set()
        try:
            await asyncio.Event().wait()
        finally:
            cleaned.set()

    async def failing_read():
        await ready.wait()
        raise OSError("模擬通訊失敗")

    async with asyncio.timeout(2):
        try:
            async with asyncio.TaskGroup() as group:
                group.create_task(sibling())
                group.create_task(failing_read())
        except* OSError as group_error:
            assert str(group_error.exceptions[0]) == "模擬通訊失敗"
            assert cleaned.is_set()
        else:
            raise AssertionError("預期讀取失敗")
    print("同組取消與資源收尾已驗證")

asyncio.run(main())

預期輸出： 同組取消與資源收尾已驗證

機制解析

TaskGroup 讓呼叫端管理整批 coroutine 的生命週期。讀取端失敗時，其他工作收到取消；同組都結束後，由 ExceptionGroup 交回失敗資訊。timeout 以取消為基礎，並非強制殺死任何遠端操作。

什麼時候不要用？

CPU 密集且不主動讓出事件迴圈的純 Python 程式不適合直接在事件迴圈執行。數千筆 I/O 也不應一次建立同樣數量工作；加容量上限、分批或有界佇列。現場控制與緊急聯鎖不得由這份教材接管。

非同步演練的兩條結束路徑
條件發生什麼設計取捨
全部成功同組等候完成後彙整輸出順序由彙整政策決定
一筆失敗取消仍執行的 sibling → 等收尾以 ExceptionGroup 回報，並保留根因

  1. 01　命令入口match 確認操作與資料上限，拒絕 control 和布林值。
  2. 02　資料來源islice 只取允許筆數；不把整個來源先建成清單。
  3. 03　非同步採集TaskGroup 管理這批讀值，產出不可變 Snapshot。
  4. 04　結果交接contextmanager 統一關閉暫存緩衝，輸出逐行 JSON。

資料方向：命令 → 驗證 → 候選來源 → 有界批次 → 快照 → 結果。若任何一筆失敗，本例整批回報錯誤，不輸出部分 JSON；需要部分成功時，改成每筆顯式回傳成功／失敗紀錄。

圖以 3 筆合成來源為分母。這是程式驗證的資料量，不是速度、吞吐或現場量測。

  • 來源清單 3
  • 讀入並輸出 2
  • 達 28°C 提示 1

把門檻視為教材判斷值；現場告警應另定設備型號適用條件、連續時間、遲滯、失聯品質與告警責任。若資料來源在同步擷取時阻塞，這個範例的 asyncio timeout 不會中斷其前段同步工作。

"""HVAC 遙測演練：純合成 I/O，不連設備、不送控制命令。Python 3.11+。"""
import asyncio
from contextlib import contextmanager
from dataclasses import dataclass
from io import StringIO
from itertools import islice
import json
from math import isfinite
import unittest


@dataclass(frozen=True, slots=True)
class Snapshot:
    room: str
    temperature_c: float

    @property
    def high(self):
        return self.temperature_c >= 28.0


def command(message):
    match message:
        case {"op": "observe", "limit": int(n), **rest} if type(n) is int and 1 <= n <= 10 and not rest:
            return n
        case _:
            raise ValueError("僅接受 observe，limit 為 1 到 10 的整數")


def examples():
    # 模擬工作清單有 3 筆；本次只取前兩筆。
    yield ("AHU-01", 26.4)
    yield ("AHU-02", 29.2)
    yield ("AHU-03", 27.5)


async def read(sample):
    room, value = sample
    await asyncio.sleep(0)  # 交還事件迴圈，沒有真實 I/O 或網路延遲。
    if not isfinite(value):
        raise ValueError(f"{room} 讀值不合法")
    return Snapshot(room, value)


@contextmanager
def buffer():
    stream = StringIO()
    try:
        yield stream
    finally:
        stream.close()


async def collect(message, source=None):
    # 本函式每次呼叫應取得一個新來源，不共用可變 iterator。
    limit = command(message)
    selected = tuple(islice(examples() if source is None else source, limit))
    async with asyncio.timeout(2):
        async with asyncio.TaskGroup() as group:
            tasks = [group.create_task(read(sample)) for sample in selected]
    snapshots = tuple(task.result() for task in tasks)
    with buffer() as stream:
        for s in snapshots:
            row = {"room": s.room, "temperature_c": s.temperature_c, "high": s.high}
            stream.write(json.dumps(row, ensure_ascii=False, allow_nan=False) + "\n")
        return stream.getvalue()


class Checks(unittest.IsolatedAsyncioTestCase):
    async def test_bounded_reads(self):
        def source():
            yield ("AHU-02", 29.2)
            raise AssertionError("不應多讀")
        data = await collect({"op": "observe", "limit": 1}, source())
        self.assertEqual(json.loads(data), {"room": "AHU-02", "temperature_c": 29.2, "high": True})

    async def test_order_and_threshold(self):
        data = await collect({"op": "observe", "limit": 2}, examples())
        rows = [json.loads(line) for line in data.splitlines()]
        self.assertEqual([row["room"] for row in rows], ["AHU-01", "AHU-02"])
        self.assertEqual([row["high"] for row in rows], [False, True])

    async def test_reject_boolean_and_write_command(self):
        for invalid in ({"op": "observe", "limit": True}, {"op": "control", "limit": 2}):
            with self.assertRaises(ValueError):
                await collect(invalid, iter(()))

    async def test_bad_sample_reports_group_failure(self):
        with self.assertRaises(ExceptionGroup) as caught:
            await collect({"op": "observe", "limit": 2}, iter([("AHU-01", float("nan"))]))
        self.assertTrue(any(isinstance(exc, ValueError) for exc in caught.exception.exceptions))

    def test_resource_cleanup(self):
        with self.assertRaises(RuntimeError):
            with buffer() as out:
                raise RuntimeError("故障後仍須收尾")
        self.assertTrue(out.closed)

    import sys
