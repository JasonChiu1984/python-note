01 / PROOF WORKFLOW

建立能被反駁、也能被重驗的正確性論證

研究問題：在宣告的輸入域內，能否從狀態與更新規則推導出規格，而不把範例吻合或平台通過當成證明？證明回答「所有合法輸入」；測試回答「哪些具體行為已被觀察」。兩種證據缺一不可，但彼此不能取代。

  1. 01 寫規格先固定前置條件 P、後置條件 Q、錯誤與副作用。多解時比較性質，不比對特定排列。
  2. 02 找狀態關係寫出每次迴圈進入時的 I，交代 I 如何成立、如何被下一步保留。
  3. 03 證終止推出 I 加退出條件足以得到 Q。另找非負且嚴格下降的變量，或證明有限工作集。
  4. 04 設計可推翻證據寫最小反例、獨立基準、小規模窮舉；標註檢查域、未測範圍和複雜度假設。

部分正確、完全正確

部分正確性的主張是「只要程式終止，Q 成立」。總正確性還需證終止。迴圈：P ⇒ I；I ∧ guard ⇒ 下一輪 I；I ∧ ¬guard ⇒ Q。若有 early return，每個回傳點也要各自推出 Q 或規格允許的例外。這是可實作的證明義務，不是把程式改寫成自然語言。

推導例：半開區間二分

令 L 為第一個不小於目標的位置，沒有時 L=n。保持 0 ≤ left ≤ L ≤ right ≤ n。若中點值較小，所有不大於該中點的位置皆不是 L；反之 L ≤ mid。right−left 每輪下降；收斂後先檢查 L 未越界，再檢查是否真的相等。left = mid 的最小反例是候選區間僅一格、該值小於目標，區間不再縮小。

從證明轉成測試

用空集合、重複鍵、零權重等案例打到分支；再選和主方法不同的判定器（oracle），例如快取序列用簡單列表模型，而非再寫一個同型雜湊實作。小域窮舉把抽樣空間寫清楚；大域可加固定種子的隨機測試或性質，仍不能把一致視為全域證明。

評審時交哪四份證據？

一句契約；一段初始化／維持／退出／終止的推導；能讓一個錯版本失敗的最小反例；以及可重跑的測試與成本前提。如果測試失敗，先分類為規格不清、演算法推導錯、語言行為錯，或測試判定器本身錯。

LEETCODE / 001

用雜湊表記住已看過的值

Two Sum
Easy
雜湊查找官方原題 ↗

練習把「重複掃描」改成「一次走訪 + 已知狀態」，輸出的是兩個索引，不是兩個數值。

解題不變量

走到位置 i 時，seen 只保存 i 之前的元素。先找 target - value，再存入目前值，就不會把同一個索引使用兩次。

Python 語意校閱

不能寫成 if seen.get(needed)：索引 0 的布林值是假。使用 needed in seen，才能區分「不存在」與「存在且索引為 0」。

自訂資料追蹤

nums = [8, 1, 6, 4]，target = 10
8 → 找 2，未找到；記下 8:0
1 → 找 9，未找到；記下 1:1
6 → 找 4，未找到；記下 6:2
4 → 找 6，回傳 [2, 3]

邊界與契約

相同值、負數、索引 0；無解時拋出 ValueError 是本教材擴充，官方輸入保證存在唯一解。

複雜度

平均時間 O(n)，額外空間 O(n)。時間估計採雜湊表平均 O(1) 查找，不保證碰撞下的最差情況。

正確性論證與最小反例

seen 對走過的每個不同值至少保存一個先前索引。覆寫同值不會失去能否配對的資訊。命中時兩索引必異；若任一合法配對存在，走到該對較晚位置（或更早找到另一對）時一定命中。每輪消耗一筆，無剩餘輸入便終止。

可推翻的錯版本：把先查後存顛倒，[5]、target=10 就把同一索引用兩次。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def two_sum(nums: list[int], target: int) -> list[int]:
    seen: dict[int, int] = {}
    for index, value in enumerate(nums):
        needed = target - value
        if needed in seen:
            return [seen[needed], index]
        seen[value] = index
    raise ValueError("no pair adds up to target")

assert two_sum([8, 1, 6, 4], 10) == [2, 3]
assert two_sum([5, 5], 10) == [0, 1]
assert two_sum([-4, 9, 2], -2) == [0, 2]
print("#1 examples passed")

LeetCode 介面對照：twoSum(self, nums, target) → two_sum(nums, target)

LEETCODE / 020

用堆疊保留配對順序

Valid Parentheses
Easy
堆疊官方原題 ↗

練習 LIFO：最新開啟的括號必須最先結束。數量相同不代表巢狀關係正確。

解題不變量

堆疊保存尚未關閉的左括號。遇到右括號，必須先確認堆疊不是空的，再核對頂端；結束時堆疊也必須為空。

Python 語意校閱

not stack or stack.pop() != pairs[char] 利用短路求值，避免空堆疊 pop。對非括號輸入回傳 False 是教材自行定義的防禦行為。

自訂資料追蹤

s = "{[()]}"
{ → ["{"]
[ → ["{", "["]
( → ["{", "[", "("]
) ] } → 逐一彈出，最後為空

邊界與契約

空堆疊遇到右括號、交錯巢狀、未關閉；空字串視為有效是教材擴充，官方長度至少為 1。

複雜度

時間 O(n)，最差額外空間 O(n)，例如所有字元都是左括號。

正確性論證與最小反例

在已掃過且尚未違規的前綴中，堆疊依開啟順序存著所有未配對左括號。新右括號只能關閉堆疊頂端；拒絕時不存在能用後綴補救的配對。掃描終止後，空堆疊等價於所有左括號已關閉。

可推翻的錯版本：只比總數時，([)] 會被誤判為有效。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def valid_parentheses(s: str) -> bool:
    pairs = {")": "(", "]": "[", "}": "{"}
    stack: list[str] = []
    for char in s:
        if char in "([{":
            stack.append(char)
        elif char in pairs:
            if not stack or stack.pop() != pairs[char]:
                return False
        else:
            return False
    return not stack

assert valid_parentheses("{[()]}") is True
assert valid_parentheses("{(})") is False
assert valid_parentheses("]") is False
assert valid_parentheses("((") is False
assert valid_parentheses("") is True  # 教材擴充
print("#20 examples passed")

LeetCode 介面對照：isValid(self, s) → valid_parentheses(s)

LEETCODE / 704

用半開區間避免差一錯誤

Binary Search
Easy
二分搜尋官方原題 ↗

在已排序資料上，每次丟棄不可能的半邊。不要先排序再回傳索引，否則索引已不是原始位置。

解題不變量

把搜尋範圍寫成 [left, right)。當 nums[mid] 小於目標，left 移到 mid + 1；否則 right 移到 mid。最後 left 是第一個不小於目標的位置。

Python 語意校閱

while left < right 搭配 right = mid；不要把閉區間的 right = mid - 1 混進來。迴圈後還要檢查 left < len(nums)，避免目標大於所有元素時越界。

自訂資料追蹤

nums = [-8, -2, 4, 9, 13]，target = 9
[0, 5) → mid 2，值 4 → left = 3
[3, 5) → mid 4，值 13 → right = 4
[3, 4) → mid 3，值 9 → right = 3
left == right == 3 → 驗證相等，回傳 3

邊界與契約

首尾元素、找不到、單一元素；空串列與重複值是教材擴充，重複值回傳最左索引。

複雜度

時間 O(log n)，額外空間 O(1)。不切片，才不會把區間複製成本帶進搜尋。

正確性論證與最小反例

候選的是下界答案的位置，不是說所有候選元素都未比較過。mid 在 [left,right) 之內，兩個更新都縮短區間；退出可信，再做相等與邊界判定。

可推翻的錯版本：只回傳下界而未比相等時，[1,3] 找 2 會誤回傳索引 1。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def binary_search(nums: list[int], target: int) -> int:
    left, right = 0, len(nums)
    while left < right:
        mid = (left + right) // 2
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid
    if left < len(nums) and nums[left] == target:
        return left
    return -1

assert binary_search([-8, -2, 4, 9, 13], 9) == 3
assert binary_search([-8, -2, 4, 9, 13], 20) == -1
assert binary_search([7], 7) == 0
assert binary_search([], 1) == -1  # 教材擴充
print("#704 examples passed")

LeetCode 介面對照：search(self, nums, target) → binary_search(nums, target)

LEETCODE / 003

讓滑動視窗只往右移

Longest Substring Without Repeating Characters
Medium
滑動視窗官方原題 ↗

練習持續維護一段不重複的連續字串。子字串必須連續，不能跳過中間的字元。

解題不變量

last 記住字元最後出現的位置。遇到重複字元，left 移到舊位置的下一格，但絕不往左退回已排除的區域。

Python 語意校閱

關鍵是 max(left, last[char] + 1)。少了 max，遇到視窗外的舊字元會把左界倒退，可能把已重複的區段算進答案。

自訂資料追蹤

s = "abba"
a → 視窗 a，長度 1
b → 視窗 ab，長度 2
b → left = 2，視窗 b
a → 舊 a 在視窗外，left 留在 2，視窗 ba

邊界與契約

空字串、全部相同、重複字元位於視窗外、空白；中文測試是教材延伸，不是官方英數符號字元範圍的保證。

複雜度

平均時間 O(n)，額外空間 O(k)，k 是不同字元數。Python str 以 Unicode 碼位處理，不保證一個畫面字形等於一個元素。

正確性論證與最小反例

對每個 right，left 是可使尾端在 right 的視窗無重複的最小索引。新字元只能引入與其最近位置的衝突，因此以 max 保留既有左界；best 取各右端最長合法視窗的最大值。

可推翻的錯版本：不以 max 保護左界時，abba 最後一步會把 left 倒退，誤把 bba 算成長度 3。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def longest_unique(s: str) -> int:
    last: dict[str, int] = {}
    left = best = 0
    for right, char in enumerate(s):
        if char in last:
            left = max(left, last[char] + 1)
        last[char] = right
        best = max(best, right - left + 1)
    return best

assert longest_unique("abba") == 2
assert longest_unique("dvdf") == 3
assert longest_unique("zzzz") == 1
assert longest_unique("") == 0
assert longest_unique("台北台南") == 3  # 教材延伸
print("#3 examples passed")

LeetCode 介面對照：lengthOfLongestSubstring(self, s) → longest_unique(s)

LEETCODE / 056

排序後合併，不共享輸入物件

Merge Intervals
Medium
排序／區間官方原題 ↗

把重疊區間整理成不重複的覆蓋範圍。可以聯想到事件時間區段，但要先說清楚端點是否包含在內。

解題不變量

先按起點排序。已輸出的最後區間是唯一可能與下一筆重疊的候選；不重疊就新增，重疊就延伸終點。這裡採閉區間，接觸端點也合併。

Python 語意校閱

sorted 只建立新的外層串列，裡面的子串列仍可能共用。因此輸出要新建 [start, end]，不要直接 append 原始區間再修改它。

自訂資料追蹤

[[9, 11], [2, 5], [5, 8], [3, 4]]
排序 → [2,5], [3,4], [5,8], [9,11]
包含 → [2,5]
端點接觸 → [2,8]
分離 → [[2,8], [9,11]]

邊界與契約

相同端點、被包含、零長度、亂序；空輸入是教材擴充。確認函式不修改輸入，也不讓輸出內層串列與輸入共用。

複雜度

時間 O(n log n)；sorted 與輸出皆可能用 O(n) 空間。若要求原地修改，需另外明訂副作用契約。

正確性論證與最小反例

排序後，merged 恰好覆蓋已處理區間的聯集，且互不重疊。若新區間有重疊，僅可能延伸最後一段；以前的段不再變動。程式採閉區間，端點相等算重疊。

可推翻的錯版本：合併時只取新右端，[1,10] 加 [2,3] 會錯縮成 [1,3]。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def merge_intervals(intervals: list[list[int]]) -> list[list[int]]:
    merged: list[list[int]] = []
    for start, end in sorted(intervals):
        if not merged or start > merged[-1][1]:
            merged.append([start, end])
        else:
            merged[-1][1] = max(merged[-1][1], end)
    return merged

source = [[9, 11], [2, 5], [5, 8], [3, 4]]
before = [row[:] for row in source]
answer = merge_intervals(source)
assert answer == [[2, 8], [9, 11]]
assert source == before
answer[0][0] = -99
assert source == before  # 內層串列也沒有共用
assert merge_intervals([[6, 6]]) == [[6, 6]]
print("#56 examples passed")

LeetCode 介面對照：merge(self, intervals) → merge_intervals(intervals)

LEETCODE / 102

用佇列切出一層的工作邊界

Binary Tree Level Order Traversal
Medium
廣度優先搜尋官方原題 ↗

練習 BFS：以層為單位遍歷二元樹。這個「先固定本批數量，再加入下一批」的想法，也能幫助理解批次工作佇列。

解題不變量

每輪一開始固定 len(queue)。本輪只取出這麼多節點，新增的子節點留待下一輪處理，因此不會把下一層混入本層。

Python 語意校閱

使用 deque.popleft()，避免 list.pop(0) 每次搬移剩餘元素。None 是沒有節點，不是數值 0；應用 root is None 判斷空樹。

自訂資料追蹤

       10
      /  \
     6    14
      \   /
       8 12
佇列分層：[10] → [6,14] → [8,12]

邊界與契約

空樹、單一節點、只有一側的樹、值為 0。教材傳入 TreeNode 物件，不是把 LeetCode 顯示的陣列直接當樹。

複雜度

時間 O(n)；不含輸出的佇列空間 O(w)，w 是最大層寬；加上輸出空間為 O(n)。

正確性論證與最小反例

每輪開始，佇列恰好包含同一深度、由左到右的節點。固定本輪長度，消耗當前層時只把下一層依順序接到尾巴。前提是有限無環樹且沒有共享子節點；一般圖須另定已拜訪集合。

可推翻的錯版本：以「佇列非空」當內層條件，根與孩子會混入同一層。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
from __future__ import annotations
from collections import deque
from dataclasses import dataclass

@dataclass
class TreeNode:
    val: int
    left: TreeNode | None = None
    right: TreeNode | None = None

def level_order(root: TreeNode | None) -> list[list[int]]:
    if root is None:
        return []
    queue = deque([root])
    result: list[list[int]] = []
    while queue:
        layer: list[int] = []
        for _ in range(len(queue)):
            node = queue.popleft()
            layer.append(node.val)
            if node.left is not None:
                queue.append(node.left)
            if node.right is not None:
                queue.append(node.right)
        result.append(layer)
    return result

root = TreeNode(10, TreeNode(6, right=TreeNode(8)),
                TreeNode(14, left=TreeNode(12)))
assert level_order(root) == [[10], [6, 14], [8, 12]]
assert level_order(None) == []
assert level_order(TreeNode(0)) == [[0]]
print("#102 examples passed")

LeetCode 介面對照：levelOrder(self, root) → level_order(root)；平台已有 TreeNode，不需重貼教材 dataclass。

LEETCODE / 322

把最少步數寫成動態規劃

Coin Change
Medium
動態規劃官方原題 ↗

練習用已解的小問題組合大問題。每種面額可重複使用，目標是最少枚數，不是計算組合數。

解題不變量

dp[x] 代表湊出 x 所需的最少枚數。dp[0] = 0；依金額遞增，從每一種可以使用的硬幣回看 dp[x - coin]。

Python 語意校閱

amount + 1 當作不可能值，因為正整數面額湊出 amount 不會需要超過 amount 枚。面額須為正，否則遞推前提不成立。

自訂資料追蹤

coins = [1, 4, 6]，amount = 8
貪婪：6 + 1 + 1，需要 3 枚
動態規劃：dp[4] = 1
dp[8] 可由 dp[4] + 1 得到 2
答案：4 + 4

邊界與契約

金額 0、無法湊出、重複面額、貪婪失敗；負金額或非正面額拋 ValueError 是教材驗證，非官方合法輸入。

複雜度

時間 O(A × m)，空間 O(A)，A 為目標金額、m 為面額數。這是依金額數值成長的偽多項式演算法，不適合無限制的大金額。

正確性論證與最小反例

dp[x] 代表最少硬幣數，無解以 amount+1 表示。任何非空解都可移掉最後一枚硬幣；反向把該枚加到較小的最佳解也能構造候選。幣值正使依賴嚴格減少，從 0 依序填表涵蓋所有狀態。

可推翻的錯版本：最大面額優先不是保證最優：[1,3,4] 湊 6 會選 4+1+1，但 3+3 更少。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def coin_change(coins: list[int], amount: int) -> int:
    if amount < 0 or any(coin <= 0 for coin in coins):
        raise ValueError("amount must be >= 0; coins must be > 0")
    unreachable = amount + 1
    dp = [0] + [unreachable] * amount
    for subtotal in range(1, amount + 1):
        for coin in coins:
            if coin <= subtotal:
                dp[subtotal] = min(dp[subtotal], dp[subtotal - coin] + 1)
    return -1 if dp[amount] == unreachable else dp[amount]

assert coin_change([1, 4, 6], 8) == 2
assert coin_change([4, 6], 7) == -1
assert coin_change([3, 7], 0) == 0
assert coin_change([2, 2, 5], 9) == 3
print("#322 examples passed")

LEETCODE / 146

把快取淘汰策略變成可驗證狀態

LRU Cache
Medium
狀態設計官方原題 ↗

練習維護「最近使用」順序：命中與更新都會刷新順序；容量滿時，淘汰最久沒有使用的項目。

解題不變量

以 OrderedDict 的左端代表最久未使用、右端代表最新。get 命中後移到右端；put 寫入後也移到右端；超出容量才從左端移除。

Python 語意校閱

一般 dict 保留插入順序，但不能直接取代這份實作的 move_to_end / popitem(last=False)。更新既有 key 也要刷新使用順序，且不能誤淘汰別人。

自訂資料追蹤

容量 2；下列由最舊排到最新
put(7,70) → [7]
put(9,90) → [7,9]
get(7) → [9,7]
put(4,40) → [7,4]，淘汰 9

邊界與契約

命中值為 0、更新既有 key、容量 1、淘汰順序；非正容量拋 ValueError。此類別沒有同步保護，不是可直接用於多執行緒服務的完整快取。

複雜度

以雜湊平均成本計，get / put 平均 O(1)，空間 O(C)。標準函式庫簡化實作；進階可另練習 dict + 雙向鏈結串列。

正確性論證與最小反例

每個操作完成後，順序由最久未使用到最近使用，且長度不超過容量；更新既有鍵也標記為最近。新鍵使容量超限時剔除首項即可維持規格。這是循序操作的論證，不保證多執行緒原子性。

可推翻的錯版本：容量 2，放 A、B 後讀 A，再放 C，應淘汰 B。只保留插入順序會淘汰 A。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int):
        if capacity <= 0:
            raise ValueError("capacity must be positive")
        self.capacity = capacity
        self.data: OrderedDict[int, int] = OrderedDict()

    def get(self, key: int) -> int:
        if key not in self.data:
            return -1
        self.data.move_to_end(key)
        return self.data[key]

    def put(self, key: int, value: int) -> None:
        self.data[key] = value
        self.data.move_to_end(key)
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)

cache = LRUCache(2)
cache.put(7, 70)
cache.put(9, 90)
assert cache.get(7) == 70
cache.put(4, 40)
assert cache.get(9) == -1
cache.put(7, 0)
assert cache.get(7) == 0
assert list(cache.data) == [4, 7]
print("#146 examples passed")

ORIGINAL / 01

前綴和：含負值也能數出全部子區間

差分恆等式／頻率字典
原創

規格與適用域

回傳總和等於 target 的非空連續半開區間數。輸入是整數，允許空列表、負值、零及重複前綴；不修改輸入。

為何正確／為何會停

令 P[0]=0，P[j] 為前 j 項和。區間 [i,j) 合法恰在 P[i]=P[j]−target。處理右端 j 之前，字典恰記錄 P[0…j−1] 的出現次數。先計數、後記錄 P[j]，排除 i=j；每個右端只處理一次，因此無遺漏、無重算。

狀態追蹤與反例

values=[1,-1,1]，target=0；P=[0,1,0,1]。末端 j=2 命中 i=0；末端 j=3 命中 i=1 → 共 2。若 target=0 且先寫入 P[j]，單元素 [1] 就錯計空區間。

複雜度與獨立測試

雜湊平均時間 O(n)，空間 O(n)。窮舉長度 0–5、元素 −1/0/1、target −2…2，逐區間逐項求和與主演算法對照。整數運算成本採單位成本模型。

def count_target_subarrays(values: list[int], target: int) -> int:
    """Count nonempty contiguous intervals with sum target; negative values allowed."""
    prefix = count = 0
    frequencies = {0: 1}
    for value in values:
        prefix += value
        count += frequencies.get(prefix - target, 0)
        frequencies[prefix] = frequencies.get(prefix, 0) + 1
    return count

assert count_target_subarrays([1, -1, 1], 0) == 2
assert count_target_subarrays([0, 0, 0], 0) == 6
assert count_target_subarrays([], 0) == 0

ORIGINAL / 02

二分答案：求不重排資料的最小批次容量

單調性／貪婪可行性
原創

規格與適用域

給定非空正整數重量及 batches≥1，以原順序切成至多 batches 個非空連續批次，回傳最大批次重量的最小可能值。

為何正確／為何會停

對固定容量 C，將每批取到不能再放的最長前綴。切點支配：只要能處理同樣批數，貪婪第 k 批處理到的位置不早於其他合法方案的第 k 批；從前一批的支配起點移除已處理重量，剩餘同一段不會更重。故貪婪若需太多批，無合法切法。提高 C 不會讓可行變不可行，二分保留最小可行值，區間必縮小。

狀態追蹤與反例

[7,2,5,10,8] 分最多 2 批。容量 17 最少要 3 批；18 可切 [7,2,5]｜[10,8]。只拿平均下界 ceil(32/2)=16 不等於可行答案。

複雜度與獨立測試

令 R=sum(weights)−max(weights)+1；時間 O(n(1+log R))、額外空間 O(1)。窮舉長度 1–5、重量 1–3，各批數的所有切點集合。負重量會讓貪婪支配前提失效。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def min_batch_capacity(weights: list[int], batches: int) -> int:
    """Minimum capacity for at most batches nonempty, ordered, contiguous groups."""
    if not weights or any(weight <= 0 for weight in weights) or batches < 1:
        raise ValueError("require positive weights and batches, with at least one item")

    def feasible(capacity: int) -> bool:
        groups, load = 1, 0
        for weight in weights:
            if load + weight > capacity:
                groups += 1
                load = 0
            load += weight
        return groups <= batches

    low, high = max(weights), sum(weights)
    while low < high:
        middle = (low + high) // 2
        if feasible(middle):
            high = middle
        else:
            low = middle + 1
    return low

assert min_batch_capacity([7, 2, 5, 10, 8], 2) == 18
assert min_batch_capacity([2], 10) == 2
print("原創延伸範例通過")

ORIGINAL / 03

相依排序：用有效次序或循環診斷回應

圖論／拓撲排序
原創

規格與適用域

節點名稱唯一；每條 (before, after) 都用已宣告節點。回傳含所有節點、符合每條邊的任一合法次序；有環時拋 ValueError。輸入可空、可有重複邊。

為何正確／為何會停

未輸出子圖中的入度等於未處理前驅的邊數。零入度者才可入佇列；取出節點後刪除其出邊，維持入度。每個點至多輸出一次；若停下仍有未輸出節點，該子圖每點都有前驅，沿前驅必遇到重複節點，故有環。

狀態追蹤與反例

tasks=[parse,validate,publish]，邊 parse→validate→publish；加入 publish→parse 後無零入度，應報循環，不可回傳部分結果假裝成功。

複雜度與獨立測試

時間與額外空間皆 O(V+E)，空間含建立鄰接表。窮舉三點、無自環的 64 張有向圖，由節點排列枚舉判定解是否存在；另測自環、未知點與平行邊。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
from collections import deque

def dependency_order(tasks: list[str], edges: list[tuple[str, str]]) -> list[str]:
    """Return an order respecting each directed edge (before, after); reject cycles."""
    indegree = dict.fromkeys(tasks, 0)
    if len(indegree) != len(tasks):
        raise ValueError("task identifiers must be unique")
    followers: dict[str, list[str]] = {task: [] for task in tasks}
    for before, after in edges:
        if before not in indegree or after not in indegree:
            raise ValueError("edge endpoints must be declared tasks")
        followers[before].append(after)
        indegree[after] += 1
    ready = deque(task for task in tasks if indegree[task] == 0)
    ordered = []
    while ready:
        before = ready.popleft()
        ordered.append(before)
        for after in followers[before]:
            indegree[after] -= 1
            if indegree[after] == 0:
                ready.append(after)
    if len(ordered) != len(tasks):
        raise ValueError("dependency cycle")
    return ordered

order = dependency_order(["parse", "validate", "publish"], [("parse", "validate"), ("validate", "publish")])
assert order == ["parse", "validate", "publish"]
print("原創延伸範例通過")

ORIGINAL / 04

最短路徑：Dijkstra 的最小候選與過期項目

最小堆／路徑鬆弛
原創

規格與適用域

輸入有向圖（字串節點），邊權為非負整數。回傳 source 到所有可達點的最小成本；不可達點省略。source 可是只當終點出現的已知點；負權或未知 source 拋 ValueError。

為何正確／為何會停

每個有限標籤對應一條已知路徑。取出目前最小有效標籤時，若存在更短路徑，沿該路徑第一個尚未確定點的前一點已被鬆弛，非負邊保證該點標籤不大於更短路徑總長，與取最小矛盾。不重用過期項目；有效取出後該點不再改善，每條可達出邊最多探索一次。

狀態追蹤與反例

s→a=10、s→b=1、b→a=1，第一次放入的 a=10 不是最短；a=2 先出堆，10 是過期項目。把「入堆」當確定距離，會錯回 10。

複雜度與獨立測試

包含輸入掃描，時間 O(V+E+E log(E+1))、額外空間 O(V+E)，堆允許同點多候選。對三點六條可能有向邊，以缺邊／零權／權重 2 逐一組出 729 張圖，比對獨立 V−1 輪鬆弛。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
from heapq import heappop, heappush

def shortest_distances(
    graph: dict[str, list[tuple[str, int]]], source: str
) -> dict[str, int]:
    """Return distances to reachable vertices; integer edge weights must be nonnegative."""
    vertices = set(graph)
    for neighbors in graph.values():
        for vertex, weight in neighbors:
            if weight < 0:
                raise ValueError("Dijkstra requires nonnegative weights")
            vertices.add(vertex)
    if source not in vertices:
        raise ValueError("unknown source")
    distance = {source: 0}
    pending = [(0, source)]
    while pending:
        total, here = heappop(pending)
        if total != distance[here]:
            continue
        for neighbor, weight in graph.get(here, []):
            proposal = total + weight
            if neighbor not in distance or proposal < distance[neighbor]:
                distance[neighbor] = proposal
                heappush(pending, (proposal, neighbor))
    return distance

graph = {"s": [("a", 10), ("b", 1)], "b": [("a", 1)], "a": []}
assert shortest_distances(graph, "s") == {"s": 0, "b": 1, "a": 2}
print("原創延伸範例通過")

"""把刷題技巧用在現場資料：滑動視窗找最長超溫區間、雙指標合併兩條時間序列、單調堆疊找下一次升溫（標準函式庫）。"""
from collections import deque

TEMPS = [24.1, 25.3, 28.4, 28.9, 29.2, 27.5, 28.6, 29.0, 29.4, 28.8, 26.0, 28.3]


def longest_above(values, limit):
    """一次掃描：O(n) 找最長連續超溫段（類似「最長連續 1」）。"""
    best, start, cur = (0, -1), None, 0
    for i, v in enumerate(values):
        if v > limit:
            start = i if start is None else start
            if i - start + 1 > best[0]:
                best = (i - start + 1, start)
        else:
            start = None
    return best


def max_in_windows(values, k):
    """單調佇列：O(n) 求每個長度 k 視窗的最大值（LeetCode 239）。"""
    dq, out = deque(), []
    for i, v in enumerate(values):
        while dq and values[dq[-1]] <= v:
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:
            dq.popleft()
        if i >= k - 1:
            out.append(values[dq[0]])
    return out


def merge_sorted(a, b):
    """雙指標合併兩條已排序的 (時間, 來源) 序列，O(n + m)。"""
    i = j = 0
    out = []
    while i < len(a) and j < len(b):
        if a[i][0] <= b[j][0]:
            out.append(a[i]); i += 1
        else:
            out.append(b[j]); j += 1
    return out + a[i:] + b[j:]


def next_warmer(values):
    """單調堆疊：每個時間點要等幾步才會更熱（LeetCode 739）。"""
    ans, stack = [0] * len(values), []
    for i, v in enumerate(values):
        while stack and values[stack[-1]] < v:
            j = stack.pop()
            ans[j] = i - j
        stack.append(i)
    return ans


if __name__ == "__main__":
    length, start = longest_above(TEMPS, 28.0)
    print(f"最長連續超過 28 °C：{length} 筆，從索引 {start} 開始 → {TEMPS[start:start + length]}")
    print("每 3 筆視窗最大值：", max_in_windows(TEMPS, 3))
    a = [(1, "AHU1"), (4, "AHU1"), (9, "AHU1")]
    b = [(2, "CH1"), (4, "CH1"), (7, "CH1")]
    print("合併時間序列：", merge_sorted(a, b))
    print("幾步後更熱：", next_warmer(TEMPS))

工程現場案例：一年的分鐘資料，用雙層迴圈算移動最大值跑了半小時

某分析腳本要算 52 萬筆分鐘資料的 15 分鐘移動最大值，寫成每個位置往前掃 15 筆的雙層迴圈，複雜度 O(n·k)，在邊緣主機上跑得很慢；換成 60 分鐘視窗後更是慢了四倍。

單調佇列讓每個元素最多進出佇列各一次，總成本 O(n)，與視窗大小無關。實務上也可以直接用 pandas 的 rolling().max()，但理解背後的思路，才能在沒有現成函式的情況（例如自訂的告警條件）寫出有效率的程式。

  1. 先估計資料量與目前演算法的複雜度，判斷是否真的需要優化。
  2. 把問題對應到熟悉的題型：連續區間、視窗極值、合併、下一個更大元素。
  3. 用小資料寫出暴力解作為對照，確認高效版本結果相同。
  4. 有成熟函式庫時優先使用（pandas、NumPy），自寫版本用於函式庫不支援的邏輯。

練習題與自我檢查

  1. 為什麼 max_in_windows() 的佇列存索引而不是值？

    看解答

    需要用索引判斷佇列最前面的元素是否已經滑出視窗（dq[0] <= i − k）。只存值無法知道它的位置。

  2. next_warmer() 結果中有 0 代表什麼？

    看解答

    之後再也沒有更高的溫度，在資料範圍內等不到更熱的時刻。例如索引 8 的 29.4 是之後的最高值。

  3. merge_sorted() 遇到相同時間戳時，誰排在前面？這重要嗎？

    看解答

    a[i][0] <= b[j][0] 時取 a，所以時間相同時 AHU1 在 CH1 之前。這叫穩定合併；若後續處理依賴順序（例如事件先後），要明確定義同時間的排序規則。

  4. longest_above() 若要同時回傳所有長度 ≥ 3 的超溫區間，要怎麼改？

    看解答

    在每次區間結束（v <= limit 且 start 不為 None）以及迴圈結束時，檢查區間長度並加入結果清單。仍是一次掃描、O(n)。
