LEETCODE / 001

用雜湊表記住已看過的值

Two Sum
Easy
雜湊查找官方原題 ↗

練習把「重複掃描」改成「一次走訪 + 已知狀態」，輸出的是兩個索引，不是兩個數值。

解題不變量

走到位置 i 時，seen 只保存 i 之前的元素。先找 target - value，再存入目前值，就不會把同一個索引使用兩次。

Python 語意校閱

不能寫成 if seen.get(needed)：索引 0 的布林值是假。使用 needed in seen，才能區分「不存在」與「存在且索引為 0」。

自訂資料追蹤

nums = [8, 1, 6, 4]，target = 10
8 → 找 2，未找到；記下 8:0
1 → 找 9，未找到；記下 1:1
6 → 找 4，未找到；記下 6:2
4 → 找 6，回傳 [2, 3]

邊界與契約

相同值、負數、索引 0；無解時拋出 ValueError 是本教材擴充，官方輸入保證存在唯一解。

複雜度

平均時間 O(n)，額外空間 O(n)。時間估計採雜湊表平均 O(1) 查找，不保證碰撞下的最差情況。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def two_sum(nums: list[int], target: int) -> list[int]:
    seen: dict[int, int] = {}
    for index, value in enumerate(nums):
        needed = target - value
        if needed in seen:
            return [seen[needed], index]
        seen[value] = index
    raise ValueError("no pair adds up to target")

assert two_sum([8, 1, 6, 4], 10) == [2, 3]
assert two_sum([5, 5], 10) == [0, 1]
assert two_sum([-4, 9, 2], -2) == [0, 2]
print("#1 examples passed")

LeetCode 介面對照：twoSum(self, nums, target) → two_sum(nums, target)

LEETCODE / 020

用堆疊保留配對順序

Valid Parentheses
Easy
堆疊官方原題 ↗

練習 LIFO：最新開啟的括號必須最先結束。數量相同不代表巢狀關係正確。

解題不變量

堆疊保存尚未關閉的左括號。遇到右括號，必須先確認堆疊不是空的，再核對頂端；結束時堆疊也必須為空。

Python 語意校閱

not stack or stack.pop() != pairs[char] 利用短路求值，避免空堆疊 pop。對非括號輸入回傳 False 是教材自行定義的防禦行為。

自訂資料追蹤

s = "{[()]}"
{ → ["{"]
[ → ["{", "["]
( → ["{", "[", "("]
) ] } → 逐一彈出，最後為空

邊界與契約

空堆疊遇到右括號、交錯巢狀、未關閉；空字串視為有效是教材擴充，官方長度至少為 1。

複雜度

時間 O(n)，最差額外空間 O(n)，例如所有字元都是左括號。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def valid_parentheses(s: str) -> bool:
    pairs = {")": "(", "]": "[", "}": "{"}
    stack: list[str] = []
    for char in s:
        if char in "([{":
            stack.append(char)
        elif char in pairs:
            if not stack or stack.pop() != pairs[char]:
                return False
        else:
            return False
    return not stack

assert valid_parentheses("{[()]}") is True
assert valid_parentheses("{(})") is False
assert valid_parentheses("]") is False
assert valid_parentheses("((") is False
assert valid_parentheses("") is True  # 教材擴充
print("#20 examples passed")

LeetCode 介面對照：isValid(self, s) → valid_parentheses(s)

LEETCODE / 704

用半開區間避免差一錯誤

Binary Search
Easy
二分搜尋官方原題 ↗

在已排序資料上，每次丟棄不可能的半邊。不要先排序再回傳索引，否則索引已不是原始位置。

解題不變量

把搜尋範圍寫成 [left, right)。當 nums[mid] 小於目標，left 移到 mid + 1；否則 right 移到 mid。最後 left 是第一個不小於目標的位置。

Python 語意校閱

while left < right 搭配 right = mid；不要把閉區間的 right = mid - 1 混進來。迴圈後還要檢查 left < len(nums)，避免目標大於所有元素時越界。

自訂資料追蹤

nums = [-8, -2, 4, 9, 13]，target = 9
[0, 5) → mid 2，值 4 → left = 3
[3, 5) → mid 4，值 13 → right = 4
[3, 4) → mid 3，值 9 → right = 3
left == right == 3 → 驗證相等，回傳 3

邊界與契約

首尾元素、找不到、單一元素；空串列與重複值是教材擴充，重複值回傳最左索引。

複雜度

時間 O(log n)，額外空間 O(1)。不切片，才不會把區間複製成本帶進搜尋。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def binary_search(nums: list[int], target: int) -> int:
    left, right = 0, len(nums)
    while left < right:
        mid = (left + right) // 2
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid
    if left < len(nums) and nums[left] == target:
        return left
    return -1

assert binary_search([-8, -2, 4, 9, 13], 9) == 3
assert binary_search([-8, -2, 4, 9, 13], 20) == -1
assert binary_search([7], 7) == 0
assert binary_search([], 1) == -1  # 教材擴充
print("#704 examples passed")

LeetCode 介面對照：search(self, nums, target) → binary_search(nums, target)

LEETCODE / 003

讓滑動視窗只往右移

Longest Substring Without Repeating Characters
Medium
滑動視窗官方原題 ↗

練習持續維護一段不重複的連續字串。子字串必須連續，不能跳過中間的字元。

解題不變量

last 記住字元最後出現的位置。遇到重複字元，left 移到舊位置的下一格，但絕不往左退回已排除的區域。

Python 語意校閱

關鍵是 max(left, last[char] + 1)。少了 max，遇到視窗外的舊字元會把左界倒退，可能把已重複的區段算進答案。

自訂資料追蹤

s = "abba"
a → 視窗 a，長度 1
b → 視窗 ab，長度 2
b → left = 2，視窗 b
a → 舊 a 在視窗外，left 留在 2，視窗 ba

邊界與契約

空字串、全部相同、重複字元位於視窗外、空白；中文測試是教材延伸，不是官方英數符號字元範圍的保證。

複雜度

平均時間 O(n)，額外空間 O(k)，k 是不同字元數。Python str 以 Unicode 碼位處理，不保證一個畫面字形等於一個元素。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def longest_unique(s: str) -> int:
    last: dict[str, int] = {}
    left = best = 0
    for right, char in enumerate(s):
        if char in last:
            left = max(left, last[char] + 1)
        last[char] = right
        best = max(best, right - left + 1)
    return best

assert longest_unique("abba") == 2
assert longest_unique("dvdf") == 3
assert longest_unique("zzzz") == 1
assert longest_unique("") == 0
assert longest_unique("台北台南") == 3  # 教材延伸
print("#3 examples passed")

LeetCode 介面對照：lengthOfLongestSubstring(self, s) → longest_unique(s)

LEETCODE / 056

排序後合併，不共享輸入物件

Merge Intervals
Medium
排序／區間官方原題 ↗

把重疊區間整理成不重複的覆蓋範圍。可以聯想到事件時間區段，但要先說清楚端點是否包含在內。

解題不變量

先按起點排序。已輸出的最後區間是唯一可能與下一筆重疊的候選；不重疊就新增，重疊就延伸終點。這裡採閉區間，接觸端點也合併。

Python 語意校閱

sorted 只建立新的外層串列，裡面的子串列仍可能共用。因此輸出要新建 [start, end]，不要直接 append 原始區間再修改它。

自訂資料追蹤

[[9, 11], [2, 5], [5, 8], [3, 4]]
排序 → [2,5], [3,4], [5,8], [9,11]
包含 → [2,5]
端點接觸 → [2,8]
分離 → [[2,8], [9,11]]

邊界與契約

相同端點、被包含、零長度、亂序；空輸入是教材擴充。確認函式不修改輸入，也不讓輸出內層串列與輸入共用。

複雜度

時間 O(n log n)；sorted 與輸出皆可能用 O(n) 空間。若要求原地修改，需另外明訂副作用契約。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def merge_intervals(intervals: list[list[int]]) -> list[list[int]]:
    merged: list[list[int]] = []
    for start, end in sorted(intervals):
        if not merged or start > merged[-1][1]:
            merged.append([start, end])
        else:
            merged[-1][1] = max(merged[-1][1], end)
    return merged

source = [[9, 11], [2, 5], [5, 8], [3, 4]]
before = [row[:] for row in source]
answer = merge_intervals(source)
assert answer == [[2, 8], [9, 11]]
assert source == before
answer[0][0] = -99
assert source == before  # 內層串列也沒有共用
assert merge_intervals([[6, 6]]) == [[6, 6]]
print("#56 examples passed")

LeetCode 介面對照：merge(self, intervals) → merge_intervals(intervals)

LEETCODE / 102

用佇列切出一層的工作邊界

Binary Tree Level Order Traversal
Medium
廣度優先搜尋官方原題 ↗

練習 BFS：以層為單位遍歷二元樹。這個「先固定本批數量，再加入下一批」的想法，也能幫助理解批次工作佇列。

解題不變量

每輪一開始固定 len(queue)。本輪只取出這麼多節點，新增的子節點留待下一輪處理，因此不會把下一層混入本層。

Python 語意校閱

使用 deque.popleft()，避免 list.pop(0) 每次搬移剩餘元素。None 是沒有節點，不是數值 0；應用 root is None 判斷空樹。

自訂資料追蹤

       10
      /  \
     6    14
      \   /
       8 12
佇列分層：[10] → [6,14] → [8,12]

邊界與契約

空樹、單一節點、只有一側的樹、值為 0。教材傳入 TreeNode 物件，不是把 LeetCode 顯示的陣列直接當樹。

複雜度

時間 O(n)；不含輸出的佇列空間 O(w)，w 是最大層寬；加上輸出空間為 O(n)。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
from __future__ import annotations
from collections import deque
from dataclasses import dataclass

@dataclass
class TreeNode:
    val: int
    left: TreeNode | None = None
    right: TreeNode | None = None

def level_order(root: TreeNode | None) -> list[list[int]]:
    if root is None:
        return []
    queue = deque([root])
    result: list[list[int]] = []
    while queue:
        layer: list[int] = []
        for _ in range(len(queue)):
            node = queue.popleft()
            layer.append(node.val)
            if node.left is not None:
                queue.append(node.left)
            if node.right is not None:
                queue.append(node.right)
        result.append(layer)
    return result

root = TreeNode(10, TreeNode(6, right=TreeNode(8)),
                TreeNode(14, left=TreeNode(12)))
assert level_order(root) == [[10], [6, 14], [8, 12]]
assert level_order(None) == []
assert level_order(TreeNode(0)) == [[0]]
print("#102 examples passed")

LeetCode 介面對照：levelOrder(self, root) → level_order(root)；平台已有 TreeNode，不需重貼教材 dataclass。

LEETCODE / 322

把最少步數寫成動態規劃

Coin Change
Medium
動態規劃官方原題 ↗

練習用已解的小問題組合大問題。每種面額可重複使用，目標是最少枚數，不是計算組合數。

解題不變量

dp[x] 代表湊出 x 所需的最少枚數。dp[0] = 0；依金額遞增，從每一種可以使用的硬幣回看 dp[x - coin]。

Python 語意校閱

amount + 1 當作不可能值，因為正整數面額湊出 amount 不會需要超過 amount 枚。面額須為正，否則遞推前提不成立。

自訂資料追蹤

coins = [1, 4, 6]，amount = 8
貪婪：6 + 1 + 1，需要 3 枚
動態規劃：dp[4] = 1
dp[8] 可由 dp[4] + 1 得到 2
答案：4 + 4

邊界與契約

金額 0、無法湊出、重複面額、貪婪失敗；負金額或非正面額拋 ValueError 是教材驗證，非官方合法輸入。

複雜度

時間 O(A × m)，空間 O(A)，A 為目標金額、m 為面額數。這是依金額數值成長的偽多項式演算法，不適合無限制的大金額。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
def coin_change(coins: list[int], amount: int) -> int:
    if amount < 0 or any(coin <= 0 for coin in coins):
        raise ValueError("amount must be >= 0; coins must be > 0")
    unreachable = amount + 1
    dp = [0] + [unreachable] * amount
    for subtotal in range(1, amount + 1):
        for coin in coins:
            if coin <= subtotal:
                dp[subtotal] = min(dp[subtotal], dp[subtotal - coin] + 1)
    return -1 if dp[amount] == unreachable else dp[amount]

assert coin_change([1, 4, 6], 8) == 2
assert coin_change([4, 6], 7) == -1
assert coin_change([3, 7], 0) == 0
assert coin_change([2, 2, 5], 9) == 3
print("#322 examples passed")

LeetCode 介面對照：coinChange(self, coins, amount) → coin_change(coins, amount)

LEETCODE / 146

把快取淘汰策略變成可驗證狀態

LRU Cache
Medium
狀態設計官方原題 ↗

練習維護「最近使用」順序：命中與更新都會刷新順序；容量滿時，淘汰最久沒有使用的項目。

解題不變量

以 OrderedDict 的左端代表最久未使用、右端代表最新。get 命中後移到右端；put 寫入後也移到右端；超出容量才從左端移除。

Python 語意校閱

一般 dict 保留插入順序，但不能直接取代這份實作的 move_to_end / popitem(last=False)。更新既有 key 也要刷新使用順序，且不能誤淘汰別人。

自訂資料追蹤

容量 2；下列由最舊排到最新
put(7,70) → [7]
put(9,90) → [7,9]
get(7) → [9,7]
put(4,40) → [7,4]，淘汰 9

邊界與契約

命中值為 0、更新既有 key、容量 1、淘汰順序；非正容量拋 ValueError。此類別沒有同步保護，不是可直接用於多執行緒服務的完整快取。

複雜度

以雜湊平均成本計，get / put 平均 O(1)，空間 O(C)。標準函式庫簡化實作；進階可另練習 dict + 雙向鏈結串列。

展開完整 Python 範例與自訂測試
獨立可執行 · Python 3.10+
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int):
        if capacity <= 0:
            raise ValueError("capacity must be positive")
        self.capacity = capacity
        self.data: OrderedDict[int, int] = OrderedDict()

    def get(self, key: int) -> int:
        if key not in self.data:
            return -1
        self.data.move_to_end(key)
        return self.data[key]

    def put(self, key: int, value: int) -> None:
        self.data[key] = value
        self.data.move_to_end(key)
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)

cache = LRUCache(2)
cache.put(7, 70)
cache.put(9, 90)
assert cache.get(7) == 70
cache.put(4, 40)
assert cache.get(9) == -1
cache.put(7, 0)
assert cache.get(7) == 0
assert list(cache.data) == [4, 7]
print("#146 examples passed")

題目通常已保證輸入合法。服務端還要補型別、大小上限、逾時與資源預算；快取還要考慮同步、TTL、資料一致性與可觀測性，演算法題不會替你驗證這些。

看一個 Solution 介面轉接範例
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        seen = {}
        for index, value in enumerate(nums):
            needed = target - value
            if needed in seen:
                return [seen[needed], index]
            seen[value] = index
        raise ValueError("no pair adds up to target")
