01 / ARCHITECTURE

控制留在現場；上位機負責觀測

若專案需要命令通道，應以獨立具名身分、允許的節點與值範圍、寫入稽核及現場連鎖處理；本教材不提供設備控制程式，也不把 OPC UA 當即時控制或安全連鎖的替代品。此章為 Client/Server；Part 14 PubSub 是另一種通訊模型。

02 / INFORMATION MODEL

NodeId、Namespace URI、DataValue 是整合契約

示例點位型別與語意消費端驗證
CHW01/LeavingTemperatureDouble，°C；類比點可使用 AnalogItemType、EngineeringUnits、EURange保留品質和時間，再計算溫差；不把缺測填成 0
CHW01/FlowDouble，m³/h；量程由核可點表定義零流量不必然故障；對照泵浦命令與回授
Pump01/RunFeedbackBoolean；設備真實運轉回授不等於 StartCommand；來源斷線不是 OFF

位址空間由 Object、Variable、Method 等節點和具類型的 Reference 組成。BrowseName 是瀏覽用名稱，DisplayName 可本地化，皆不能當持久主鍵。記錄「伺服器身分＋命名空間 URI＋識別字類型和值」；每次新 Session 讀取 NamespaceArray 解析數字索引，不硬編碼 ns=2。教材用 URI urn:python-note:hvac:lab 與字串識別字 Plant01.CHW01.LeavingTemperature。

DataValue 包含 Value、StatusCode、可選 SourceTimestamp 與 ServerTimestamp；另記客戶端接收時間。Bad 不當正常值，Uncertain 另標註；來源時間戳不是每次發布都更新，伺服器時間不是來源採集時間。跨設備量測延遲前先同步時鐘。

03 / SECURITY

端點、應用憑證、使用者、授權分開驗證

  1. 端點。核對 URL、TransportProfile、SecurityPolicy、MessageSecurityMode、UserTokenPolicy。正式環境使用雙端核可的 SignAndEncrypt；不因連線錯誤默默退為 None。Sign 提供訊息完整性，不等於加密；實際可用政策需對照設備及組織基準。
  2. 應用身分。雙端配置 TrustList 或核可 CA。由可信管道查核憑證、ApplicationUri、主機名稱及撤銷政策；控管私鑰與到期輪替，不能自動信任 rejected 區的憑證。
  3. 使用者與角色。Session 使用者驗證與 Client 應用憑證不是同一件事。採集帳號只給核可節點所需 Browse、Read 等權限，不授權 Write、Call；用實際身分回歸驗證，不僅看設定畫面。
  4. 網路分區。白名單限定來源、目的地與連線方向；不直接曝露給公網。追蹤連線錯誤、憑證到期與授權拒絕，不把密碼和私鑰放入日志。

04 / SUBSCRIPTION

採樣、變更通知、發布是不同時間尺度

典型順序是 OpenSecureChannel → CreateSession → ActivateSession → CreateSubscription → CreateMonitoredItems。SecureChannel 保護傳輸；Session 保存使用者與服務狀態；Subscription 管理通知，三者不等同一條 TCP 連線。記錄實際 revisedSamplingInterval、revisedPublishingInterval、revisedQueueSize，以及 keep-alive/lifetime；要求值不是保證。

例如要求每 250 ms 採樣、1 s 發布，底層若每 1 s 更新一次，仍無法得到四個獨立量測。queueSize=1 適合最新值，不保證保留中間轉換；大於 1 再搭配 discardOldest 選保留較新或較早通知。類比點可測試伺服器支援的絕對 deadband，例如 0.1 °C；事件與資料變更不可混同，BACnet COV 也不是 OPC UA MonitoredItem。

估算 item 容量：每秒峰值通知 × 可容忍未送出秒數 ＋ 裕量。4 筆/s × 3 s 可先試 16，依修訂後數值與壓測調整；這不是重傳佇列容量。Keep-alive 表示 Subscription 有回應，不代表每個點位新鮮。

05 / LOSS BOUNDARIES

三層漏失：先辨識缺在哪裡

層級觀測訊號恢復邊界
源頭／MonitoredItem未取樣、被過濾、或佇列滿而丟棄。DataValue 佇列大小大於 1 時，可用 Overflow InfoBit 辨識伺服器標記；大小為 1 不可藉缺少旗標證明沒丟資料。核對 PLC 更新與來源紀錄、實際取樣間隔、deadband、滿佇列策略。Republish 不會復活尚未成為已送出訊息的變更。
Subscription 重傳追蹤同一 Subscription 的 NotificationMessage 序號和 availableSequenceNumbers。Keep-alive 不等同新資料；重傳佇列可能淘汰舊訊息。Republish 僅重取仍保留的已送出訊息。Bad_MessageNotAvailable 不證明資料完整；依缺口決定補歷史或重新同步現況。
Client／應用儲存回呼卡住、應用佇列滿、程序中斷或 DB commit 失敗。協定 ACK 不等於已持久化。記錄 dropped、backlog 與寫入錯誤；依完整性需求用可持久 spool 或上游歷史。Republish 不保證補回已 ACK 而未存盤的資料。

Read／ResendData 更新的是當前值，不是完整中間歷程。需要補洞時，要有 Historian／Historical Access 或可信來源紀錄，且保存缺口證據。

06 / RECOVERY

重連先沿用、再補傳，最後重建

  1. 偵測失聯後標記 degraded；對 transport/channel、訂閱逾時和單點品質分開處理，採有抖動的退避。
  2. 先建立新 SecureChannel，嘗試 ActivateSession 沿用可用的舊 Session；失效才建立新 Session 並在伺服器支援且身分符合時 TransferSubscriptions。無法移轉才重建 Subscription、MonitoredItems 並重新解析 namespace。
  3. 沿用或移轉成功時，依規範從下一個預期序號 Republish，直到 Bad_MessageNotAvailable，再恢復一般 Publish；若不能補全，記缺口，避免舊重傳覆蓋已接收的新值，處理序號回繞和重建訂閱世代。
  4. 對不可補的缺口 Read 或在支援時 ResendData 恢復當前狀態；依支援情況補歷史。記錄缺口時間窗、補正方式與未恢復點位。

07 / RUNNABLE LAB

Python 實驗：唯讀點位、時間戳與應用佇列

使用 Python 3.12 和 asyncua 2.1.0，同一個程序內以真實 TCP 連線跑合成 Server／Client。僅綁 127.0.0.1:48531，使用 NoSecurity 並會出現預期的未加密警告；不可把範例改為 OT 網路端點或對外綁定。

source .venv/bin/activate
python -m pip install -r requirements.txt

已實測 URI 解析、唯讀拒絕寫入、初始 7.0 °C 及附來源時間戳的 7.5 °C 通知；再讓應用佇列滿以驗證計數。未測正式設備憑證、多點負載、Server Overflow、斷線 Republish 或冗餘。

展開完整、可執行 Python 程式
"""Synthetic read-only OPC UA lab; NoSecurity on IPv4 loopback only."""
import asyncio
from datetime import UTC, datetime
import sys

from asyncua import Client, Server, ua

URI = "urn:python-note:hvac:lab"
NODE = "Plant01.CHW01.LeavingTemperature"
URL = "opc.tcp://127.0.0.1:48531/python-note-hvac/"
END = object()


class Handler:
    def __init__(self):
        self.queue = asyncio.Queue(maxsize=8)
        self.dropped = 0

    def datachange_notification(self, node, value, data):
        # Keep callbacks short. Preserve status/timestamps, not only the value.
        dv = data.monitored_item.Value
        try:
            self.queue.put_nowait(dv)
        except asyncio.QueueFull:
            self.dropped += 1


async def main():
    server = Server()
    await server.init()
    server.set_endpoint(URL)  # fixed loopback; never widen for this lab
    server.set_security_policy([ua.SecurityPolicyType.NoSecurity])
    ns = await server.register_namespace(URI)
    plant = await server.nodes.objects.add_object(ns, "Plant01_CHW01")
    sensor = await plant.add_variable(ua.NodeId(NODE, ns), "LeavingTemperature", 7.0)
    # Default AccessLevel is read-only for external clients. Server still writes.
    async with server, Client(url=URL, timeout=5) as client:
        resolved = await client.get_namespace_index(URI)
        node = client.get_node(ua.NodeId(NODE, resolved))
        assert await node.read_value() == 7.0
        try:
            await node.write_value(99.0)
        except ua.UaStatusCodeError as error:
            assert error.code in (
                ua.StatusCodes.BadUserAccessDenied, ua.StatusCodes.BadNotWritable
            ), error
        else:
            raise AssertionError("the external client unexpectedly wrote a value")
        handler = Handler()
        sub = await client.create_subscription(100, handler)
        handle = await sub.subscribe_data_change(node, queuesize=4, sampling_interval=50)
        try:
            initial = await asyncio.wait_for(handler.queue.get(), timeout=5)
            assert initial.Value.Value == 7.0 and initial.StatusCode.is_good()
            source = datetime.now(UTC)
            dv = ua.DataValue(Value=ua.Variant(7.5, ua.VariantType.Double),
                              SourceTimestamp=source)
            await sensor.write_value(dv)
            changed = await asyncio.wait_for(handler.queue.get(), timeout=5)
            assert changed.Value.Value == 7.5
            assert changed.StatusCode.is_good()
            assert changed.SourceTimestamp == source
            assert not handler.dropped
            # Explicit app-queue overflow exercise. This is not server overflow.
            for _ in range(handler.queue.maxsize):
                handler.queue.put_nowait(END)
            # Exercise the same callback method without simulating protocol loss.
            from types import SimpleNamespace
            handler.datachange_notification(node, 7.5, SimpleNamespace(
                monitored_item=SimpleNamespace(Value=changed)))
            assert handler.dropped == 1
        finally:
            await sub.unsubscribe(handle)
            await sub.delete()
    print("PASS namespace lookup, read-only access, DataValue, subscription, app queue")


if __name__ == "__main__":
    if not __debug__:
        sys.exit("Run the checks without -O.")
    asyncio.run(main())

08 / ACCEPTANCE

現場驗收：證明資料品質，不只證明連得上

測項留下的證據
容量與延遲實際點數和峰值；記錄修訂參數、p50/p95/p99 與佇列水位；時鐘同步後才做跨裝置端到端量測。
缺口隔離在核可測試環境用合成遞增點位，分別測短斷線、超過重傳窗口與 client 慢寫；比對來源數、溢出、序號缺口及 DB 成功數。
重啟及冗餘測 namespace 索引改變、對照來源與訂閱狀態；若有主備，測應用有效值時間及漏失，不能只看 TCP 恢復。
信任與權限受信及不受信端點、到期憑證、唯讀帳號拒絕寫入；確認客戶端沒有靜默降級。

起始指標：每來源 last-good age、訂閱序號缺口和 Republish 結果、每 item Overflow、應用佇列水位與丟棄、成功寫入與憑證到期。定值點的最後變更時間不可單獨當作離線證據；用符合現場語意的心跳或品質。
