1. 系統架構：各層只做自己的事

部署方式

同源模式讓同一個網站回傳 HTML 與 /api/v1 資料；前端使用相對路徑。正式部署可用 HTTPS 反向代理，讓 /api 轉到獨立 Python 服務，但對瀏覽器仍是同一來源。靜態 GitHub Pages 不執行 Python，所以這份教材在網站使用刻意標示的瀏覽器模擬，不會向 Pages 的 /api 發送請求。

工控／機房情境

不要讓瀏覽器直接連 PLC、DDC 或現場控制網。由受控閘道採集、限制讀取權限，API 再提供標準化資料。告警處置和控制寫入是不同路徑；本課的門檻預覽不保存設定，也不發出設備命令。

4. 常見 API 用法與本課契約

方法用途常見狀態與重試
GET查詢資料或狀態；條件放 query，通常沒有 body。200、304、404；讀取可依策略有限重試。
POST建立資源、送命令或執行計算。本課只做預覽。201 建立、202 接受處理、200 回傳結果；若有副作用不可盲重送。
PUT以完整資料替換固定 URI 的資源。200、204 或建立時 201；相同請求應得到相同預期效果。
PATCH部分修改；先約定格式，例如 JSON Merge Patch。200／204，資料衝突 409 或條件失敗 412；不保證冪等。
DELETE刪除指定資源，可用軟刪除保留稽核。204；重複請求的預期效果相同，狀態碼未必相同。

本課實作：GET /api/v1/telemetry?device=AHU-02（可選設備）；POST /api/v1/threshold-preview（JSON body）。PUT、PATCH、DELETE 只是契約示例，實驗未啟用這些方法。

量測時間是 Unix 秒，前端轉為毫秒才能建立 Date。正式 API 應明確定義時區、單位、取樣來源與品質詞彙，分開「量測時間」與「資料收到時間」。支援 list 分頁時約定 cursor、排序與 limit；需要防止同時覆寫時考慮 ETag + If-Match，建立／交易重試可設計伺服器端冪等鍵。

看懂失敗，再決定怎麼處理

  • 400、415：請求參數或內容格式錯；修正輸入，別無限重試。
  • 401、403：確認有效身分或角色權限；前端不靠隱藏按鈕做授權。
  • 404、409、412：檢查資源及版本前提；不要靜默覆蓋更新。
  • 429、503：服務限制或暫不可用；讀取可以尊重 Retry-After，採指數退避、抖動和上限。
  • 網路、取消、逾時：可能尚未收到 HTTP 回應。取消瀏覽器等待不保證伺服器停止，尤其不可把取消解讀成寫入撤銷。

正式環境應把資料來源、應用服務和 HTTP handler 分開，這樣能在沒有設備或網路的測試裡替換資料來源。

JavaScript：先驗狀態，再解析資料

const controller = new AbortController();
const timer = setTimeout(() => controller.abort(), 1200);
try {
  const r = await fetch("/api/v1/telemetry", {
    signal: controller.signal,
    credentials: "same-origin"
  });
  if (!r.ok) throw new Error(`HTTP ${r.status}`);
  const data = await r.json();
  validateTelemetry(data); // 完整函式在本頁原始碼
  const cell = document.createElement("td");
  cell.textContent = data.items[0]?.device ?? "無資料";
} finally {
  clearTimeout(timer);
}

Fetch 在收到 400／500 時仍會完成 Promise；只有像網路錯誤或取消才會 reject。使用 textContent 把資料當文字，避免把設備名稱當 HTML 解譯；圖條寬度則由通過驗證的數值計算並限制範圍。

並行與錯誤狀態的設計

新請求會取消舊請求，並用序號讓較早的回應無法蓋掉畫面。輪詢在上一輪結束後才排下一輪，避免 setInterval 遇到慢網路造成並發堆積。錯誤或取消保留最後成功資料，status 清楚說明目前沒有新樣本。在多頁應用也應在元件卸載時取消請求及計時；本單頁依瀏覽器生命週期運作。

先在 DevTools 的 Network 檢查 URL、方法、狀態碼與 Response，再比對 UI 的 error 文案。若是本功能的 schema 問題，HTTP 200 仍會顯示錯誤。不要將 Token、Cookie、個資放在除錯訊息或 URL。

6. 輪詢、SSE、WebSocket 怎麼選

方式方向／瀏覽器 API適合工程代價
輪詢（本課可操作）反覆 HTTP GET / fetch儀表板、幾秒更新一次每次有請求開銷；成功後排下次、錯誤退避。若後端支援，使用 ETag 降低重傳內容。
SSE（概念比較）伺服器 → 瀏覽器 / EventSource狀態、進度、遙測事件伺服器使用 text/event-stream；處理 proxy 緩衝、重連、Last-Event-ID 與心跳。原生 EventSource 不支援任意 Authorization 標頭。
WebSocket（概念比較）雙向 / WebSocket低延遲雙向協作、時序事件自行設計訊息契約、心跳、背壓、重連與權限；校驗 Origin，不能假設 CORS 自動保護握手。

更新頻率與可接受延遲是兩回事。4 個頁籤各每 3 秒查一次，約 80 次請求／分鐘；真正的流量仍取決於回應時間、退避、快取及頁籤節流。若資料只出不進，先比較輪詢和 SSE，再考慮 WebSocket。使用即時通道也要能重建目前狀態，例如先 GET 快照，再收帶事件序號的更新。

連接方式深度研究：從首屏到重連

  1. 載入

    瀏覽器拿到 HTML、CSS 與 JS，建立畫面。

  2. 快照

    Fetch 讀目前狀態；記下資料流版本與最後序號。

  3. 增量

    輪詢差異、訂閱 SSE，或交由 WebSocket 雙向訊息。

  4. 收斂

    檢查重複、缺序與過期；必要時重抓快照。

常用連接比較

以下為工程取捨，不是固定的延遲或效能排行榜。SSE、WebSocket 同樣會受代理、後端速度、瀏覽器節流與資料大小影響。

方法優點缺點與驗收適用
伺服器渲染 HTML瀏覽器只要導航即可看到首屏；不必另做快照 API。需正確轉義輸出；互動與局部刷新通常另用表單或 Fetch。驗證 HTML 錯誤頁與重整狀態。導覽、報表、靜態配置頁；可搭配後續 API。
HTTP Fetch（REST/JSON）一次請求、一次結果，容易重試讀取並使用 HTTP 快取語意。不會主動收到新資料；Fetch 對 HTTP 4xx/5xx 通常仍回傳 Response，須查 response.ok。驗證取消、逾時及 JSON 契約。初始快照、查詢、送表單或下達獨立操作。
定時輪詢沿用普通 GET、易監控；可用 ETag／304 避免重傳相同內容。仍會發出請求；更新延遲受排程與網路影響。完成後才排下一次，防止舊回應覆蓋新值。低頻儀表板，或代理不允許長連線。
長輪詢伺服器等待有變化才回覆，仍使用一般 HTTP。需占用待機請求；代理逾時、重送、連線壓力與快速重試都要量測。傳回後用游標立即續接。需要較快更新，但部署限制不便維持串流時。
SSE／EventSource伺服器→瀏覽器單向文字事件；內建重連，id 可帶回 Last-Event-ID。回補要伺服器保留歷史才成立；原生 EventSource 不能自由加自訂授權標頭。驗證代理不緩衝及心跳。事件通知、設備讀值、任務進度；寫入另外走 HTTP。
WebSocket一條連線支援雙向訊息與二進位資料，可實現即時互動。須自行設計重連、驗證、續接和流量限制；標準瀏覽器 WebSocket API 不提供接收端背壓。驗證 Origin、斷線與佇列上限。需要雙向互動、上游控制、協作等；不以連線本身代替授權。

啟動、重新連線與資料契約

  • 快照加序號

    schema_version 定義欄位相容性；stream_id 區別來源或重啟世代；seq 為同一資料流排序；value_c 和 quality 分別表示數值和品質。維護 last_seq，重複可忽略，缺號或串流世代改變要重抓。不要以時間戳直接當可靠排序鍵。

  • 避免快照與訂閱間的空隙

    快照要回傳一致水位 S，續接時只取 S 之後的事件；快照與游標須對應同一資料邊界。若後端沒有保留序號區間，別承諾逐筆補齊，應重抓快照並顯示狀態已重同步。本實驗沒有持久化，重開連接從頭模擬。

  • 限制排隊與重試

    Fetch 用 AbortController 設等待期限，不代表伺服器工作必定取消。長連線設最大佇列、最大訊息與閒置時間；可覆蓋的顯示資料可合併最新值，但告警事件不可任意丟棄。用有限的指數退避加抖動重連；授權失效不要無窮重試。

  • 跨來源不是授權

    先選同源反向代理。跨來源 HTTP 需明確的 CORS 放行，Cookie 加上 credentials 時不能以萬用來源放行，狀態變更另做 CSRF 防護。WebSocket 不依賴 CORS 預檢，後端應驗 Origin、登入與訊息授權；外部部署使用 HTTPS/WSS 並設定反向代理逾時。

WebSocket 詳解：連線、續接與慢客戶端

WebSocket 適合兩端都需要主動發送時，例如協作、狀態訂閱切換或應用層問答。若瀏覽器只接收讀值，先評估 SSE；普通查詢與命令也能以 HTTP API 完成。不要因為用了 WebSocket，就省略應答、授權或可重建的目前狀態。

連線生命週期：握手成功不等於應用就緒

  1. 建立：HTTP/1.1 的 RFC 6455 握手以 Upgrade 請求開始；伺服器接受後回 101 Switching Protocols。HTTP/2 或 HTTP/3 的 extended CONNECT 是不同機制，不能用「一定要看到 101」判定所有部署。用瀏覽器 Network/WS 時先確認代理使用的協定。
  2. 就緒：瀏覽器 open 只代表連線可送資料。若協議要訂閱，客戶端此時送 subscribe，等待同一請求的 subscribed 後才標示已訂閱。若伺服器無法驗訂閱，就回錯誤，不讓畫面誤示為正常。
  3. 傳輸：在同一條連線上，接收端按 WebSocket 訊息次序取得資料，但並行生產者仍需應用端序號、明確排序和重播政策；重連不會自動還原上一條連線。
  4. 終止：前端換頁或元件卸載關閉連線及重連計時器；後端離開接收迴圈時移除訂閱並取消 writer。1000 是正常結束、1008 表示政策違規；1006 是本端觀測到的異常中斷狀態，不能作為送出的 Close frame code。

實務技巧與驗收

連線安全

公開站用 HTTPS/WSS。瀏覽器不能由 new WebSocket() 任意加入自訂 Authorization header；可設計同站安全 Cookie 加 Origin allowlist，或經 HTTPS 核發短時有效的握手憑證，避免把長期 token 放 URL、log。Origin 檢查用於瀏覽器跨來源防護，不替代身分驗證，非瀏覽器也可自填 Origin。跨租戶讀寫應每筆驗權，不依賴 CORS 自動保護握手。

心跳與閒置逾時

協定層 Ping/Pong 用控制框，瀏覽器 WebSocket API 不開放手動傳這類控制框。若要檢查應用是否仍能服務，可定義 JSON ping/pong、比對請求 ID 和 deadline；它和 RFC 6455 控制框不同。心跳間隔依實測代理逾時與負載調整，不能保證穿過任何中介。

慢客戶端與背壓

伺服器每連線配置有界佇列和獨立 writer，廣播時不逐一等待每位客戶端。滿載時先分類：儀表板快照可依測點合併或捨棄舊值，需完整告警應保留於可重播來源，或終止連線要求重新同步。瀏覽器 bufferedAmount 只代表尚未送出的排隊位元組，不是接收端背壓或送達確認；超過應用上限時停止新增可延緩的送出，控制台顯示狀態。

續接與交付語意

快照帶 schema_version、stream_id、水位 seq。重連以去抖動的有限退避重試，從最後確認處請求續傳；若換世代、缺號、游標超出保留窗或解析失敗，先停用增量、重抓一致快照。對命令使用獨立 request/idempotency key，沒有應用確認不等於沒執行，別重播未知狀態的操作。

SSE伺服器單向推播告警、進度與時間序列代理可能緩衝、長連線要規劃復原，傳統 EventSource 不適合任意自訂 headersEventSource 接 text/event-stream；規劃事件 ID、重連、心跳與快照回補
WebSocket雙向高頻互動、現場會話狀態要自行設計重連、心跳、權限與積壓限制；不能視為慢資料的預設選項以 WebSocket 接 wss 服務；重連後以快照或版本重新同步
ETag／條件式請求快照很少改變；想減少 JSON 傳輸和處理不等於停止輪詢；驗證依表示版本，304 無回應正文If-None-Match → 304 時保留同一已驗證快照；不要對空內存做 json()
Page Visibility切換分頁、螢幕休眠時減少不必要流量只是一種前端排程策略，不是隱藏即銷毀，也不是保證準時監聽 visibilitychange；隱藏取消讀取，可見再受控更新，不能決定警報是否持續運作

把下列腳本放在輸出與重試按鈕之後（或以 defer 載入），並由同源 API 提供 {"temperature":25.2}，伺服器需正確產生 ETag。背景分頁會取消在途讀取；可見後恢復。429 或 503 若有 Retry-After 應遵守，跨大量客戶端要加入退避抖動。多次收到同值／304 只證明表示未變，資料在 PLC 的實際年齡仍看 source timestamp。

// 搭配同源唯讀 /api/latest；範例服務需自行提供。
const output = document.querySelector("#reading");   // 例如 <output id="reading">
const reload = document.querySelector("#retry");     // 例如 <button id="retry">
let timer, controller, etag, lastGood, failures = 0;
let enabled = true;
const visible = () => enabled && !document.hidden;

function schedule(delay) {
  clearTimeout(timer);
  if (visible()) timer = setTimeout(run, delay);
}

async function run() {
  if (!visible() || controller) return;             // 全程一次一個請求
  clearTimeout(timer);
  const owner = new AbortController();
  controller = owner;
  const deadline = setTimeout(() => owner.abort(), 3500);
  try {
    const response = await fetch("/api/latest", {
      cache: "no-store",
      headers: etag ? {"If-None-Match": etag} : {},
      signal: owner.signal
    });
    if (response.status !== 304) {
      if (!response.ok) throw new Error("HTTP " + response.status);
      const data = await response.json();
      if (!Number.isFinite(data.temperature)) throw new Error("Invalid reading");
      if (!visible() || owner.signal.aborted) return;
      lastGood = data.temperature;
      etag = response.headers.get("ETag");
    } else if (lastGood === undefined) {
      throw new Error("304 without a validated previous value");
    }
    if (!visible() || owner.signal.aborted) return;
    output.textContent = lastGood.toFixed(1) + " °C";
    failures = 0;
  } catch (error) {
    if (visible()) {
      failures++;
      output.textContent = lastGood === undefined ? "沒有可用資料"
        : lastGood.toFixed(1) + " °C（上次成功值，可能過舊）";
    }
  } finally {
    clearTimeout(deadline);
    controller = undefined;
    if (visible()) schedule(Math.min(30000, 1000 * 2 ** Math.min(failures, 5)));
  }
}

document.addEventListener("visibilitychange", () => {
  if (!visible()) {
    clearTimeout(timer);
    controller?.abort();
  } else if (!controller) schedule(0);
});
reload.addEventListener("click", () => { if (visible() && !controller) schedule(0); });
window.addEventListener("pagehide", () => {
  enabled = false;
  clearTimeout(timer);
  controller?.abort();
});
window.addEventListener("pageshow", () => {
  enabled = true;
  if (!controller) schedule(0);
});
schedule(0);

7. 同源、CORS、Cookie 與 API 安全

  • 同源：協定、主機、埠都相同才同源。http://127.0.0.1:8765 和 http://localhost:8765 主機不同；同主機不同埠也是跨來源。請照終端機顯示的位址，以相對路徑存取 API。
  • CORS：跨來源 JSON POST 通常先送 OPTIONS 預檢。伺服器需按受信任來源、方法與標頭放行。CORS 不等於驗證身分，也不是伺服器防火牆；非瀏覽器用戶端不執行這項瀏覽器政策。
  • credentials：fetch 預設 same-origin。跨來源如確需 Cookie 須設定 include，服務端回明確的 Access-Control-Allow-Origin 和 Access-Control-Allow-Credentials: true；不使用 *，且 Cookie 仍受 SameSite 與瀏覽器政策限制。
  • 安全：正式服務使用 HTTPS、伺服器端驗證及授權；有 Cookie 的寫入端點另外做 CSRF 防護。API 憑證不要寫入前端原始碼；後端重查每筆 resource 權限。

本課程式只綁 127.0.0.1，不啟用跨域或真實控制。Python http.server 不是正式應用伺服器；不要改綁 0.0.0.0 後將它對外提供服務。

項目驗證重點
輪詢用請求完成後才排下一次，避免 setInterval 疊請求；變更設備或頁面關閉時取消舊請求。304 不含新的快照內容，也不代表現場設備剛採樣。

class Message:
    stream: str
    seq: int

def merge(current, incoming, *, snapshot=False):
    """此模型每個 stream 內連號；重啟換 stream 必須經過可信快照。"""
    if type(incoming.seq) is not int or incoming.seq < 0 or not incoming.stream:
        raise ValueError("invalid event")
    if current is not None and incoming.stream == current.stream:
        if incoming.seq <= current.seq:
            return "ignore", current
        if snapshot or incoming.seq == current.seq + 1:
            return "apply", incoming
    elif snapshot:
        return "apply", incoming
    return "resync", current
