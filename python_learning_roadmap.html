延伸學習：實作、現場案例與自我檢查

路線圖列出了各篇教材。本節提供一個小工具：指定你的目標主題，依先修關係自動排出學習順序與預估時數，也能檢查先修關係有沒有寫成循環。

可實跑範例：依先修關係排出學習順序

使用 Python 3.9 起內建的 graphlib.TopologicalSorter。TOPICS 的時數是示意值，請依自己的基礎調整；也可以把自己的專案主題加進去，例如「BACnet 點位盤點工具」。

下載範例 example.py

"""依目標主題與先修關係，產生學習順序並估算時數（graphlib.TopologicalSorter，標準函式庫）。"""
from graphlib import CycleError, TopologicalSorter

# 主題: (預估小時, 先修主題)
TOPICS = {
    "基礎語法": (12, []),
    "檔案與 CSV": (6, ["基礎語法"]),
    "函式與模組": (8, ["基礎語法"]),
    "例外與日誌": (6, ["函式與模組"]),
    "型別提示": (4, ["函式與模組"]),
    "測試 pytest": (8, ["函式與模組", "例外與日誌"]),
    "Pandas 資料整理": (16, ["檔案與 CSV", "函式與模組"]),
    "Modbus/BACnet 讀取": (12, ["例外與日誌", "型別提示"]),
    "非同步 asyncio": (10, ["函式與模組", "例外與日誌"]),
    "FastAPI 服務": (12, ["型別提示", "非同步 asyncio", "測試 pytest"]),
    "能源報表自動化": (10, ["Pandas 資料整理", "Modbus/BACnet 讀取"]),
}


def plan(goal):
    needed, stack = set(), [goal]
    while stack:                                   # 找出目標的所有先修主題
        t = stack.pop()
        if t not in needed:
            needed.add(t)
            stack.extend(TOPICS[t][1])
    ts = TopologicalSorter({t: TOPICS[t][1] for t in sorted(needed)})   # 排序讓結果可重現
    order = list(ts.static_order())
    return order, sum(TOPICS[t][0] for t in order)


if __name__ == "__main__":
    for goal in ("能源報表自動化", "FastAPI 服務"):
        order, hours = plan(goal)
        print(f"目標：{goal}（共 {len(order)} 個主題，約 {hours} 小時，每週 5 小時約 {-(-hours // 5)} 週）")
        for i, t in enumerate(order, 1):
            print(f"  {i:>2}. {t}（{TOPICS[t][0]} h）")
    TOPICS["基礎語法"] = (12, ["測試 pytest"])      # 故意造成循環依賴
    try:
        plan("測試 pytest")
    except CycleError as e:
        print("偵測到循環先修：", " → ".join(e.args[1]))

工程現場案例：BAS 工程師的三個月學習計畫

以每週 5 小時計，「能源報表自動化」需要 8 個主題、約 74 小時，大約 15 週。順序的重點是先把檔案、函式與例外處理打穩，再碰 Modbus／BACnet：現場通訊最常見的問題是逾時、斷線與資料格式異常，沒有例外處理與日誌的程式很難除錯。

建議每完成一個主題，就用自己手邊的真實資料做一個小產出：例如匯出的點位表轉成整理後的 CSV、一週的電表資料做成日報。學習進度用產出驗收，而不是用看完幾篇教材來算。

  1. 寫下 3 個月內想完成的一個實際工具，作為目標主題。
  2. 用範例程式排出順序，把每個主題對應到本站的教材頁。
  3. 每週固定時段學習，完成主題時在教材頁勾選進度。
  4. 每四週回顧一次：哪個主題花的時間超出預估，就調整後續時數。

練習題與自我檢查

  1. 在 TOPICS 加入「資料庫 SQLite」（6 小時，先修「檔案與 CSV」），並讓「能源報表自動化」也需要它。總時數會變成多少？

    看解答

    74 + 6 = 80 小時，SQLite 會排在「檔案與 CSV」之後、「能源報表自動化」之前。

  2. 為什麼程式要用 sorted(needed) 建立圖？

    看解答

    needed 是 set，字串的雜湊順序每次執行可能不同（PYTHONHASHSEED 隨機），拓撲排序在多個合法順序間的選擇就會改變。排序後輸入順序固定，結果才可重現。

  3. CycleError 的 args[1] 裡是什麼？在真實的課程規劃中什麼情況會造成循環？

    看解答

    args[1] 是構成循環的節點序列。真實情況例如「測試」要求先會「套件發布」，而「套件發布」又把「測試」列為先修；通常代表其中一個主題太大，應該拆成入門與進階兩部分。

  4. static_order() 只給一種順序。若想知道哪些主題可以同時學，要改用哪個方法？

    看解答

    用 prepare() 後反覆呼叫 get_ready() 與 done()：每一輪 get_ready() 回傳的主題彼此沒有依賴，可以並行學習。
