美國資訊安全法規與事件通報

美國沒有一部包辦所有組織與所有事件的「資訊安全法」。同一宗事件可能同時涉及證券揭露、關鍵基礎設施、金融或醫療專法、州級個資通知與供應商合約。先辨認誰負責、哪些資料或服務受影響，再分別啟動正確的時鐘。

一手來源最後核對：2026 年 11 月 25 日 · 美國法規快照

適用決策CIRCIA 狀態通報時鐘OT／雲端案例證據與治理一手來源與變更

1｜判斷架構：同一事件，平行分流

不要拿一個門檻當通用豁免。 例如沒有確認個資外洩，不代表停機及財務衝擊不具 SEC 重大性；通知一家客戶也不自動取代機關申報。反過來，「公司是供應商」本身也不等於各條法律直接適用。

2｜CIRCIA：國會已立法，最終規則仍待公布

《2022 年關鍵基礎設施網路事件通報法》（CIRCIA）已建立制度。CISA 在 2024-04-04 公布擬議規則。OIRA 自 2026-10-01 收件，RIN 1670-AA04 截至本頁查核日仍標示 Pending Review；其 Final Rule 是審查階段，並非《Federal Register》已公布或開始執行。法條／擬議規則／審查狀態

依 6 U.S.C. § 681b(a)(7)，該條第 (a)(1)–(4) 款的義務依最終規則指定日期生效。以本次查核為準，不把 72 小時／24 小時當作已啟動的 CIRCIA 強制期限；最終公布日與生效日均須另查，不能拿送審日或統一議程的預估日代替。

  • 72 小時：制度啟動且適用時，自涵蓋實體合理相信已發生涵蓋網路事件起，向 CISA 報告。不是收到第一筆未驗證告警，也不必等調查結束。
  • 24 小時：制度啟動且適用時，自涵蓋實體因勒索軟體攻擊實際付款起算。以真正付款為觸發，不是收到勒索要求。
  • 適用範圍、補報與留存：以正式規則核定涵蓋實體、涵蓋事件、補報和證據留存；類似的聯邦通報只有在符合條件及有適用協議等要件時才可能例外，不可自行折抵。現行其他規範和契約照常，亦勿把本節理解為不得自願通報 CISA。

3｜通報時鐘與證據

這些是不同受件人、不同衡量標準。日曆日不是營業日；州法可能按居民、資料門檻、持有角色和法定例外分流。下列不是完整清單。

制度／身分觸發、期限與對象準備哪種證據
SEC Form 8-K Item 1.05
適用的美國境內申報公司		發現後不得無故拖延重大性判斷；自認定重大起通常4 個營業日內提交 SEC。司法部長認定公開將對國家安全或公共安全造成重大風險，並在原到期前書面通知 SEC，才有 Item 1.05(c) 的有限延後；聯絡執法機關本身不會暫停時鐘。重大性判定時間及批准者、合理投資人視角的定性／定量影響、尚未知的必要資訊與後續補揭露。外國私人發行人另看 Form 6-K／20-F；年報治理等要求另看 Item 106。
HIPAA／HITECH
涵蓋實體、業務夥伴		針對未受保護 PHI 的 breach。涵蓋實體通知受影響個人，須無不合理延遲、最遲發現後 60 日曆日；≥500 人事件需同期依規向 HHS 通知，<500 人原則為發現年度結束後 60 日內；超過某州或轄區 500 名居民另看媒體通知。業務夥伴對涵蓋實體通知：無不合理延遲、最遲發現後 60 日曆日；BAA 可要求更早。PHI 類別、發現日期、受影響人數與居住地、風險評估及通知證明。僅做 HVAC 遙測而沒有 PHI 的事件不能直接套用；特定非 HIPAA 健康產品還可能適用 FTC 的 Health Breach Notification Rule。
GLBA／FTC Safeguards Rule
受 FTC 主管的金融機構		依法構成 notification event，涉及至少 500 名消費者的未加密客戶資訊未經授權取得：發現後儘快、最遲 30 日通報 FTC。加密金鑰遭未授權存取也可能被視為未加密；未授權存取原則推定為取得，除非有可靠證據顯示未取得／不可能合理取得。銀行另查其監管機關規則，不應直接套用 FTC 這一列。資料種類、人數、金鑰影響、實際或推定取得證據、初次得知時間。FTC 機關通報與是否另通知個人是不同判斷。
紐約 GBL §899-aa
紐約居民的法定 private information		擁有／授權使用者：符合法定條件時向居民儘速、無不合理延遲通知，原則在發現後 30 日內，有法定執法延後等規定。非擁有的維護方須立即通知擁有／授權使用者，亦有發現後 30 日上限。州機關與徵信機構通知依條文另查。居民、資料組合、未授權存取或取得的事證、是否擁有／授權使用。依指定聯邦法對個人通知，不代表紐約州機關義務均已免除。
德州 Bus. & Com. Code §521.053符合條件時向受影響個人儘速通知，一般最遲於認定發生資料外洩後第 60 日（留意法定例外）。若涉及至少 250 位德州居民，儘速且不遲於認定後第 30 日通知州檢察長。認定時間、法定 sensitive personal information、德州居民人數；受託維護方另核對須立即通知擁有／授權使用者的條款。
供應合約／其他監管依簽約版本及主管機關規定。SLA 與通知附約可能從「懷疑」就起算，與法定事件成立時間不同。不得把合約例示的短期限當成一律適用的法律。簽約法人及分包商、哪種事件觸發、24×7 受件管道、是否需階段性更新、發送與收件證明。

4｜案例：工廠 OT 遙測上雲中斷

虛構情境：一家美國上市公司的工廠透過唯讀閘道把冷卻與設備遙測送到雲端；雲端商通知部分租戶資料無法存取。就地控制仍正常，但維護排程、能耗警報及多廠看板受影響，是否有個資或其他資料遭未授權存取仍未知。

  1. 工程與 OT：分開記錄本地控制、功能安全和遠端可視性。假設自動控制維持正常，不代表事件沒有營運或資安影響；不要在無操作授權下更動 PLC。
  2. 雲端商與工廠：分開記錄發現與相互通知；依約保留事故識別碼、租戶範圍、時間線及調查窗口。若後來發現維護員憑證或健康資料，重做資料與角色判定，不把只有設備訊號當成永遠前提。
  3. 上市申報人：揭露團隊評估停機範圍、營收／成本、客戶承諾、聲譽與可能後果。若在某週二認定重大，且其後沒有假日或合法延後，教學上的第 4 個營業日是翌週一；真正申報仍要核對 SEC 日曆與申報細節。
  4. 平行分流：這不是「一定是 CIRCIA 涵蓋事件」。先查雙方實體與正式規則狀態；再看實際資料與合約。僅有遙測停擺不能以此推定 HIPAA、金融或州個資通知已觸發，也不能反推 SEC 不重大。
案例自我檢查：週二做重大性判定，另外一條時鐘必定從週二開始嗎？

不必然。SEC 的時鐘與 HIPAA 發現日、州法判定／發現日、契約知悉時間、以及制度生效後的 CIRCIA 合理相信時點來源不同。未決分支要指定負責人與下一次檢視點。

5｜把義務變成工程證據

  • 事件資料模型：至少區分 observed_at、discovered_at、materiality_at、payer_event_at（若適用）、submitted_at；每欄附原始時區、UTC、來源、可靠程度、填寫人與修訂歷程，不以 observed_at 一欄自動代填。
  • 資料邊界：保存必要的日誌摘要、事件時間、影響版本、租戶及資料類型；將原始證據限制在授權範圍，區分公開揭露、法定報告與機敏採證。保留送件識別碼與回執，不把金鑰、完整個資或未授權的客戶資料塞進工單。
  • 自動化界線：系統可提示狀態、負責人和不同日曆，但不能用 Python 腳本自動判定法律適用或代為申報。重大性、例外、計時日曆與通報內容應由指定責任人覆核。
  • 框架不是一律法律：NIST CSF 2.0 的 Govern、Identify、Protect、Detect、Respond、Recover 可用來分工；它不是所有企業通用的法定要求，但主管規範、採購或契約可能將部分控制納入義務。查實際納入文字、版本與適用範圍。

延伸學習：實作、現場案例與自我檢查

美國的通報期限分散在不同制度，而且單位不同：SEC 用營業日、HIPAA 用日曆日、州法各有起算點。本節把本頁整理的時限寫成計算工具，並自動排除聯邦假日。

可實跑範例：多軌通報期限與營業日計算

程式依規則產生 2026–2027 年聯邦假日（遇週末依 observed 規則前後移），用來計算 SEC 8-K 的 4 個營業日。其他期限以日曆日計算。只算日期，是否適用各制度、何時構成「發現」或「認定重大」仍需逐項判斷。

下載範例 example.py

"""美國多軌通報時鐘：SEC 8-K（4 個營業日）、HIPAA（60 日曆日）、FTC Safeguards（30 日）、
州法（NY 30 日、TX 個人 60 日／州檢察長 30 日）。只算日期，不判斷是否適用。

營業日排除週末與聯邦假日；假日以 2026–2027 年的聯邦假日（含週末遞延的 observed 日）計算。
"""
from datetime import date, timedelta


def nth_weekday(year, month, weekday, n):
    d = date(year, month, 1)
    d += timedelta(days=(weekday - d.weekday()) % 7)
    return d + timedelta(weeks=n - 1)


def last_weekday(year, month, weekday):
    d = date(year, month + 1, 1) - timedelta(days=1) if month < 12 else date(year, 12, 31)
    return d - timedelta(days=(d.weekday() - weekday) % 7)


def observed(d):
    return d - timedelta(days=1) if d.weekday() == 5 else d + timedelta(days=1) if d.weekday() == 6 else d


def federal_holidays(year):
    fixed = [date(year, 1, 1), date(year, 6, 19), date(year, 7, 4), date(year, 11, 11), date(year, 12, 25)]
    floating = [nth_weekday(year, 1, 0, 3), nth_weekday(year, 2, 0, 3), last_weekday(year, 5, 0),
                nth_weekday(year, 9, 0, 1), nth_weekday(year, 10, 0, 2), nth_weekday(year, 11, 3, 4)]
    return {observed(d) for d in fixed} | set(floating)


HOLIDAYS = federal_holidays(2026) | federal_holidays(2027)


def add_business_days(start, n):
    d = start
    while n:
        d += timedelta(days=1)
        if d.weekday() < 5 and d not in HOLIDAYS:
            n -= 1
    return d


if __name__ == "__main__":
    discovered = date(2026, 11, 20)        # 發現事件
    material = date(2026, 11, 24)          # 揭露委員會認定具重大性（週二）
    print(f"發現日 {discovered}，重大性認定日 {material}（{material:%a}）")
    print(f"SEC 8-K Item 1.05：認定後 4 個營業日 → {add_business_days(material, 4)}"
          f"（11/26 感恩節不計）")
    print(f"HIPAA 個人通知上限：發現後 60 日曆日 → {discovered + timedelta(days=60)}")
    print(f"FTC Safeguards（≥500 人）：發現後最遲 30 日 → {discovered + timedelta(days=30)}")
    print(f"紐約 GBL §899-aa：原則發現後 30 日內 → {discovered + timedelta(days=30)}")
    determined = date(2026, 11, 22)
    print(f"德州（認定外洩 {determined}）：州檢察長 30 日 → {determined + timedelta(days=30)}；"
          f"個人 60 日 → {determined + timedelta(days=60)}")
    print("2026 年聯邦假日：", ", ".join(d.strftime("%m-%d") for d in sorted(federal_holidays(2026))))

工程現場案例：感恩節前一天認定重大，8-K 期限比預期晚一天

某上市公司的工廠 OT 網路遭勒索軟體入侵，11 月 20 日發現，11 月 24 日（週二）揭露委員會認定具重大性。法務原本以「4 天」估算期限為 11 月 28 日，但 SEC 用的是營業日，且 11 月 26 日是感恩節，實際期限是 12 月 1 日。反過來，若有人把期限算得太寬鬆，風險就更大。

同一事件若涉及員工健康資料（例如廠內診所系統）與紐約、德州居民資料，HIPAA、州法的期限從「發現」或「認定外洩」起算，和 SEC 從「認定重大」起算不同。範例把每一條時鐘的起點分開列出，避免用同一個日期套全部。

  1. 事件紀錄表為每個制度各設一欄起算日（發現、認定重大、認定外洩、付款等）。
  2. 營業日計算使用與公司法務一致的假日表，並保存計算當時的版本。
  3. 每條時鐘的承辦人與受件機關分開指定，避免以為通知一個機關就完成全部義務。
  4. CIRCIA 最終規則公布後，再加上 72 小時與 24 小時的時鐘與起算條件。

版本與法規更新（核對日期 2026-11-28）

練習題與自我檢查

  1. 若重大性在 2026 年 12 月 23 日（週三）認定，8-K 的期限是哪一天？

    看解答

    12/24（1）、12/25 聖誕節不計、12/28（2）、12/29（3）、12/30（4），期限為 2026-12-30。可呼叫 add_business_days(date(2026, 12, 23), 4) 驗證。

  2. 為什麼 observed() 把週六的假日移到週五、週日的移到週一？

    看解答

    這是美國聯邦假日的慣例（5 U.S.C. 6103 與 OPM 規則）。例如 2026 年 7 月 4 日是週六，聯邦機關在 7 月 3 日（週五）放假。營業日計算若不考慮 observed 日，會多算一天。

  3. HIPAA 的 60 日是「最遲」期限。若在第 10 天就完成調查卻拖到第 59 天才通知，有什麼問題？

    看解答

    HIPAA 要求「無不合理延遲」，60 日只是上限。已具備通知所需資訊卻刻意拖延，仍可能被認定違規。工具算出的日期是外部上限，內部目標應更早。

  4. 程式的假日表只產生 2026–2027 年。若事件跨到 2028 年會怎樣？怎麼改比較穩健？

    看解答

    2028 年的假日不在集合內，會被當成營業日，期限可能算早（較保守）但也可能和法務的計算不一致。可以改成依日期動態呼叫 federal_holidays(d.year) 並快取，或改用維護中的假日資料套件，並在輸出標示假日資料來源。
