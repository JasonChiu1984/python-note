Overview

外部依賴是最常見的不穩定來源

先把呼叫邊界、等待預算、重試條件與失敗處理定清楚。

Architecture

把 policy、transport 與 schema 分層

業務邏輯不應直接散落 HTTP 呼叫與 retry loop。

Setup

先用 fake transport 驗證失敗路徑

本機測試要能穩定重現 503、schema drift、rate limit 與 circuit open。

Configuration

韌性參數要有可追蹤預設值

timeout、retry、backoff、rate limit 與 circuit threshold 都應進設定與 release note。

Example

Integration Resilience 範例專案

範例用標準庫與 fake transport 示範 API / gateway 呼叫韌性，不需外網或第三方服務。

cd 範例程式碼/integration_resilience
python3 -m py_compile src/integration_resilience/*.py scripts/run_integration_resilience_smoke.py
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 scripts/run_integration_resilience_smoke.py
Verification

驗收要覆蓋成功與失敗控制面

只測 happy path 無法證明外部整合能上線。

Troubleshooting

整合問題要先分類再修

timeout、429、5xx、schema drift、非冪等寫入與 circuit open 的處理不同。

Best Practices

讓整合韌性支援交付決策

韌性策略不只是程式碼技巧，也要進監控、告警、release gate 與回退依據。
