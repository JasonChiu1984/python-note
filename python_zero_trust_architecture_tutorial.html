零信任架構：從政策決策到系統驗收

內網位置、公司所有的裝置或曾經通過登入，都不能自動取得所有資源。零信任是圍繞資源、以可驗證訊號控制請求和工作階段的做法；不是取消信任、不設防火牆，也不是買一套產品就完成。

回資訊安全教材架構授權流程IT／APIHVAC／OT遷移與驗收離線程式

架構圖｜政策控制與資料傳輸分開

  1. 身分與脈絡身分服務、裝置狀態、工作負載識別與資源標籤供決策。
  2. PE 政策引擎對主體、目標、動作與風險條件判斷允許、拒絕或終止。
  3. PA 政策管理元件依 PE 決策協調建立或終止通道，向 PEP 傳達控制指令。
  4. PEP 政策執行點實際管制請求與通道；只放行符合政策的流量，並回報遙測。

控制平面：可信訊號 → PE → PA → PEP（決策及路徑控制）資料平面：主體 → PEP → 資源（僅在授權條件成立時）

PE 與 PA 在 NIST SP 800-207 的邏輯模型共同構成政策決策點（PDP）。此處 PA 是執行 PE 決策、協調通道的元件，不是管理員手動寫政策的同義詞。PEP 可以是代理、閘道或由多個協同元件組成；這是責任劃分，不是要求部署三台主機。IdP 提供身分訊號，但不是單獨的授權裁決。政策控制平面需保護完整性、授權管理、時鐘與可用性；把策略或執行點故障視為設計情境，而不是預設放行。

常見名詞不可互換：MFA 增強身分驗證，不證明裝置健康；網路分區限制傳播，不等於每個資源都授權；ZTNA 可能是遠端存取的落實方式，不代表完整 ZTA；mTLS 可驗證連線端點及保護傳輸，不保證呼叫者有權讀某筆資料。資源標籤、擁有者、允許動作及風險訊號需要持續維護。下載可編輯 Draw.io 架構圖及授權流程

流程圖｜最小權限不只決定「能不能登入」

  1. 提出請求由受管裝置或工作負載要求特定資源和動作。
  2. 取得可信訊號驗證身分與裝置／工作負載證據，核對資源與情境。
  3. 判定與執行PE 作決策，PA 協調由 PEP 建立、限制或拒絕通道。
  4. 持續評估收到撤銷、姿態過期或風險變動，重新判斷並執行回收。
  5. 記錄與驗收記錄決策理由、政策版本與時鐘，查有效回收與本地持續運轉。

把決策單位寫成「主體 × 資源 × 動作 × 條件」。身分須區分人、服務與裝置；動態條件可能含資產健康度、憑證與裝置證據時效、工作單、資源敏感度、登入風險，以及本地主管批准的時間窗。網路位置可作風險訊號，不能當成充分證明。記錄實際用哪些訊號與缺失處理；持續評估依工作階段壽命、事件與適用風險實行，不代表每封封包都要人工重新登入。

IT／API：把登入、OAuth 授權與每筆資源檢查切開

OIDC 是常用的登入身分層；OAuth access token 用於授權存取 API，ID token 不應當作 API access token。互動式客戶端依情境採授權碼搭配 PKCE；無人服務使用部署平台支援的工作負載身分及短效憑證，不共用人員帳號或長效密鑰。API 應遵循自己的 token profile：例如驗 JWT 的簽章、允許演算法、可信 issuer、audience 及有效期間；不透明 token 按受信任授權伺服器提供的機制核驗。不可只解碼字串便信任 claims。IETF OAuth 2.0 安全最佳實務。

入口閘道以 audience、scope 與身分做粗粒度限制；實際 API 仍應依使用者或服務能否存取該客戶／廠區／對象及讀寫型別判斷。服務間存取另用工作負載身分、適用時採 mTLS 與服務策略；不要把用戶層權限不受控地轉授下游。NIST SP 800-207A 討論雲原生多地環境的應用和服務層做法，並不規定所有 PLC 或每個環境都採服務網格。

拒絕原因應對外保持適當抽象、內部可追溯；日誌記決策、policy version、資源代碼、時間與關聯 ID，不留原始 token、密鑰或不必要個資。權限更新與 JWT 存續應分開設計：短效 token 並不等於即時撤銷，須量測會話終止、撤銷傳播、政策快取生命週期和重連後失效邊界。

HVAC／OT：遠端維護失效，不應使本地迴路停擺

不要要求壽命長或資源有限的 PLC 配合雲端身分代理；可在設備群的信任邊界施行 PEP，保留能驗證的分區與本地操作流程。斷開 IdP 或政策服務時，遠端新增會話依政策拒絕／隔離，既有會話只能依事前核准的限定策略及上限處置；不能自動放寬為永久信任。現場連續性透過獨立的本地 PLC、PID、操作員站及安全設計驗證。測試時用隔離台或核准維護窗，不直接在生產環境拔線。

破窗不是共用永遠可用的管理員帳號。預先定義角色、啟用條件、受保護的憑證保管與緊急授權，鎖定資源／動作／期限、雙人核准或按現場緊急程序確認，啟動即告警與保留審計。完成後終止工作階段、回收權限、必要時輪替憑證並獨立檢討。若平常連不上 IAM，也須有經演練的本地維運方式；不把現場安全依賴遠端破窗服務。

遷移、驗收與證據：以可重做的事件判斷是否成功

CISA Zero Trust Maturity Model v2.0 用身分、裝置、網路、應用與工作負載、資料五支柱，加上可視性與分析、自動化與協調、治理三項橫向能力。Traditional、Initial、Advanced、Optimal 是規劃與自評階段，不是認證、等保判定或必須追求最高等級的要求。CISA ZTMM

  1. 先盤點資源、資料流與責任人；標示不可停止的 OT 控制與人員安全依賴。
  2. 先試點唯讀 API 或低風險遠端維護，在測試環境比較允許與拒絕的影響；配置可回復政策版。
  3. 再移轉寫入與服務間身分，按資產風險分區逐步強制；每一批均有回復條件、授權人、時間窗與舊例外到期日。
  4. 將證據納入變更管理：政策測試、APP/API 判斷、PEP 執行記錄、故障演練和憑證更新成果；例外要重審或到期收回。
驗收情境應確認的結果證據
拒絕與資源界線同身分跨廠、輸出寫入、scope/audience 不符或裝置證據過期不得放行。決策碼、無資料回傳、無狀態變更、可交叉比對的 request ID。
撤銷與輪替撤銷權限後，新舊通道停止於已約定時限。憑證輪替保有授權合法通道，過渡期後拒絕舊憑證。撤銷發出與生效時間、策略／憑證版本及重連結果。
決策依賴或網路故障遠端新增存取依預案停止、告警；本地 PLC/PID、操作員站與安全聯鎖在核准測試中維持要求。實際控制迴路趨勢、警報延遲、回復時間與驗收紀錄。
破窗與復歸僅在核准資源／時間使用，完成後自動或人工回收並驗證沒有殘留權限。核准紀錄、工單、會話關閉／憑證輪替及獨立複核。

指標用可量測的拒絕命中、誤拒、撤銷上界、恢復時間、輪替成功、實際遙測覆蓋去驗收，不以啟用 MFA 或採購產品充當完成證據。

Python 離線範例：只判斷既有可信上下文

下載 Python 範例與單元測試。固定合成資料，只示範預設拒絕、部門內單一資源唯讀、裝置證據過期、撤銷、跨廠與政策依賴故障。程式傳入的是合成身分與裝置證據；正式 PEP 必須從已驗證的身分服務、可信裝置證明及政策來源建構上下文，不接受瀏覽器自填 HTTP 標頭。沒有實作 OAuth token 驗證、撤銷通知或現場控制，不可直接接到正式系統。

"""Evaluate fictional authorization records offline; no token processing or network."""

from dataclasses import dataclass, replace
import argparse
import json
import unittest


@dataclass(frozen=True)
class Context:
    subject: str = "maintenance-reader"
    device_compliant: bool = True
    posture_age_s: int = 20
    audience: str = "hvac-support"
    action: str = "trend:read"
    resource: str = "site-a/ahu-01"
    expires_at: int = 150
    now: int = 100
    revoked: bool = False
    dependency_available: bool = True
    approved_ticket: bool = True


def evaluate(c: Context) -> tuple[bool, str]:
    """Input is an already verified context, not raw or application-supplied claims."""
    if not c.dependency_available:
        return False, "policy_dependency_unavailable"
    if c.revoked or not 0 <= c.now < c.expires_at:
        return False, "revoked_or_expired"
    if c.audience != "hvac-support":
        return False, "wrong_audience"
    if not c.device_compliant or not 0 <= c.posture_age_s <= 60:
        return False, "posture_missing_or_stale"
    if not c.approved_ticket:
        return False, "ticket_not_approved"
    if (c.subject, c.action, c.resource) != (
        "maintenance-reader", "trend:read", "site-a/ahu-01"
    ):
        return False, "outside_policy"
    return True, "allowed_read_only"


class DemoTests(unittest.TestCase):
    def test_only_approved_read(self):
        self.assertEqual(evaluate(Context()), (True, "allowed_read_only"))
        for change in (dict(action="output:write"), dict(resource="site-b/ahu-01"),
                       dict(subject="other"), dict(approved_ticket=False)):
            with self.subTest(change=change):
                self.assertFalse(evaluate(replace(Context(), **change))[0])

    def test_session_revocation_and_expiry(self):
        for change in (dict(revoked=True), dict(now=150), dict(audience="other-api")):
            self.assertFalse(evaluate(replace(Context(), **change))[0])

    def test_stale_posture_and_dependency(self):
        for change in (dict(posture_age_s=61), dict(posture_age_s=-1),
                       dict(device_compliant=False), dict(dependency_available=False)):
            self.assertFalse(evaluate(replace(Context(), **change))[0])


if __name__ == "__main__":
    p = argparse.ArgumentParser(description=__doc__)
    p.add_argument("--test", action="store_true")
    if p.parse_args().test:
        unittest.main(argv=["lab"])
    else:
        for name, c in [
            ("approved", Context()),
            ("stale", replace(Context(), posture_age_s=61)),
            ("revoked", replace(Context(), revoked=True)),
            ("different_site", replace(Context(), resource="site-b/ahu-01")),
            ("policy_unavailable", replace(Context(), dependency_available=False)),
        ]:
            allowed, reason = evaluate(c)
            print(json.dumps({"case": name, "allowed": allowed, "reason": reason}))
