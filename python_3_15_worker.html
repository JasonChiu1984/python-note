延伸學習：實作、現場案例與自我檢查
本頁的互動模擬展示了背壓與停機。本節用真正的 asyncio 程式重現：有界佇列讓 producer 在佇列滿時等待，consumer 要求停機時 TaskGroup 自動取消 producer，最後列出尚未處理的項目。
架構圖與流程圖
可實跑範例：有界佇列、TaskGroup 與優雅停機
程式使用 Python 3.11 起提供的 TaskGroup 與 except* 語法；最後一行檢查 Python 3.15 新增的 TaskGroup.cancel()。事件順序由 asyncio 排程決定，對同一版本是固定的。
下載範例 example.py
"""asyncio 工作管線：有界佇列背壓、TaskGroup 結構化併發、停機時記錄未完成項目（需 Python 3.11+）。

consumer 拋出自訂的 Shutdown 例外時，TaskGroup 會取消其他子任務（producer），再把例外包成
ExceptionGroup 往外丟，用 except* 接住。Python 3.15 起也可以從外部呼叫 TaskGroup.cancel()。
"""
import asyncio
import sys

QUEUE_SIZE = 3


class Shutdown(Exception):
    pass


async def producer(q, readings, log):
    for r in readings:
        await q.put(r)                    # 佇列滿時在這裡等待：背壓
        log.append(f"put {r}")
    await q.put(None)


async def consumer(q, out, log, stop_after):
    while True:
        r = await q.get()
        if r is None:
            return
        await asyncio.sleep(0)            # 模擬 I/O 讓出控制權
        out.append(r * 2)
        log.append(f"done {r}")
        if len(out) == stop_after:
            raise Shutdown(f"收到停機要求，已處理 {len(out)} 筆")


async def run(stop_after=None):
    q: asyncio.Queue = asyncio.Queue(maxsize=QUEUE_SIZE)
    out, log, reason = [], [], None
    try:
        async with asyncio.TaskGroup() as tg:
            tg.create_task(producer(q, list(range(1, 9)), log))
            tg.create_task(consumer(q, out, log, stop_after or 999))
    except* Shutdown as eg:
        reason = str(eg.exceptions[0])
    left = []
    while not q.empty():
        item = q.get_nowait()
        if item is not None:
            left.append(item)
    return out, log, left, reason


if __name__ == "__main__":
    print(f"Python {sys.version_info.major}.{sys.version_info.minor}；TaskGroup.cancel 可用：{hasattr(asyncio.TaskGroup, 'cancel')}")
    out, log, left, _ = asyncio.run(run())
    print("完整執行：", out)
    print("前 6 個事件：", log[:6])
    out, log, left, reason = asyncio.run(run(stop_after=3))
    print(reason, "→ 已完成", out, "；佇列中未處理", left)
    print("producer 已被 TaskGroup 取消，最後送出的是", [e for e in log if e.startswith("put")][-1])

工程現場案例：Worker 重新部署時，佇列中的讀值消失
某資料上傳 Worker 從記憶體佇列取出讀值送到雲端。每次重新部署時，程序收到停止訊號就直接結束，佇列中尚未送出的資料全部遺失，趨勢圖每次部署都出現缺口。
範例中停機時佇列裡還有 4、5、6 三筆。正確做法是停止接收新資料後，把佇列中剩下的項目寫回持久化儲存（例如 SQLite 或磁碟佇列），或在限定時間內處理完再結束。TaskGroup 保證任一子任務失敗時其他子任務都會被取消，不會留下孤兒任務。
  1. 佇列一定要設上限，並監控長度；無上限的佇列只是把問題延後成記憶體耗盡。
  2. 處理 SIGTERM：停止 producer、限時排空、把未完成項目持久化，再結束。
  3. 每筆資料帶序號，重啟後依序號補做並去重。
  4. 在測試中模擬停機，驗證「已完成＋未處理＝全部輸入」。
版本與法規更新（核對日期 2026-11-28）
  • Python 3.15 新增 asyncio.TaskGroup.cancel()，可從群組外部要求取消所有子任務，不必再自訂哨兵例外；需要支援 3.11–3.14 時，仍可用範例中的例外寫法。 來源：What's new in Python 3.15：asyncio
  • asyncio.Queue.shutdown() 自 Python 3.13 起提供：呼叫後 put() 立即拋 QueueShutDown，get() 會先把剩餘項目取完，佇列空了才拋 QueueShutDown；傳入 immediate=True 則直接清空佇列。以 CPython 3.15.2 實際執行確認前兩項行為。 來源：Python 文件：asyncio Queues
練習題與自我檢查
  1. 為什麼前 6 個事件是 put 1、2、3、4 之後才 done 1？佇列上限明明是 3。
    看解答
    consumer 先取走 1（佇列剩 2、3），producer 才能放入 4；但 consumer 在 await asyncio.sleep(0) 讓出控制權後才記錄 done 1。所以 put 4 出現在 done 1 之前，而 put 5 要等 consumer 再取走一筆。
  2. 把 QUEUE_SIZE 改成 1，停機時佇列中會剩幾筆？
    看解答
    實測只剩 1 筆（序號 4），producer 最後只送出到 put 4。佇列越小，停機時要搶救的資料越少，但 producer 等待的時間變多，吞吐量可能下降。
  3. 若 consumer 直接 raise asyncio.CancelledError 會發生什麼？
    看解答
    CancelledError 被當成該任務自己被取消，不會觸發 TaskGroup 取消其他任務；producer 會卡在 q.put() 永遠等待，整個程式不會結束。這正是本範例改用自訂例外的原因。
  4. except* Shutdown 和 except Shutdown 有什麼不同？
    看解答
    TaskGroup 會把子任務的例外包成 ExceptionGroup，一般的 except Shutdown 接不到；except* 會從群組中挑出符合的例外處理，其他例外仍繼續往外拋。
  5. 在 Python 3.15 改用 TaskGroup.cancel()：consumer 處理完 3 筆時 set() 一個 asyncio.Event，主程式在 async with 區塊內 await event.wait() 後呼叫 tg.cancel()。佇列中會剩哪些項目？序號 4 去了哪裡？
    看解答
    以 CPython 3.15.2 實測：已完成 [2, 4, 6]，佇列只剩 [5, 6]，producer 一樣停在 put 6 之後。序號 4 不見了：consumer 記錄 done 3 後立刻進入下一輪，q.get() 取出 4，接著在 await asyncio.sleep(0) 讓出控制權時被取消，4 既沒處理完也不在佇列裡。
    tg.cancel() 讓 TaskGroup 正常離開、不會拋例外，寫法比自訂例外簡潔；代價是取消可能發生在任何 await。要把「已取出、未完成」的項目記成 in-flight，在 except asyncio.CancelledError 中寫回持久化儲存後再 raise，停機時才能做到「已完成＋佇列剩餘＋in-flight＝全部輸入」。
