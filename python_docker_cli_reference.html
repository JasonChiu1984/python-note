延伸學習：實作、現場案例與自我檢查

本頁整理了 Docker 指令與預期輸出。本節把 docker ps 與 docker inspect 的 JSON 輸出交給 Python 檢查，一次找出現場最常見的容器問題：重啟迴圈、沒有健康檢查、以 root 執行、沒有記憶體上限與使用 :latest。

可實跑範例：容器健康度批次檢查

範例內嵌兩段模擬輸出；實際使用時把 docker ps -a --format '{{json .}}' 與 docker inspect 的結果存成檔案再讀入。檢查規則可依專案增減。

下載範例 example.py

"""解析 docker ps／inspect 的 JSON 輸出，找出重啟中、沒有健康檢查或以 root 執行的容器（標準函式庫）。

實際使用：docker ps -a --format '{{json .}}' > ps.jsonl；docker inspect $(docker ps -aq) > inspect.json
"""
import json

PS_JSONL = """{"Names":"bms-gateway","Image":"bms/gateway:2.4.1","State":"running","Status":"Up 3 days (healthy)"}
{"Names":"modbus-poller","Image":"bms/poller:latest","State":"restarting","Status":"Restarting (1) 12 seconds ago"}
{"Names":"influxdb","Image":"influxdb:2.7","State":"running","Status":"Up 3 days"}"""

INSPECT = [
    {"Name": "/bms-gateway", "Config": {"User": "app", "Healthcheck": {"Test": ["CMD", "python", "-m", "health"]}},
     "RestartCount": 0, "HostConfig": {"RestartPolicy": {"Name": "unless-stopped"}, "Memory": 268435456}},
    {"Name": "/modbus-poller", "Config": {"User": "", "Healthcheck": None},
     "RestartCount": 147, "HostConfig": {"RestartPolicy": {"Name": "always"}, "Memory": 0}},
    {"Name": "/influxdb", "Config": {"User": "", "Healthcheck": None},
     "RestartCount": 0, "HostConfig": {"RestartPolicy": {"Name": "no"}, "Memory": 0}},
]


def findings():
    ps = {row["Names"]: row for row in map(json.loads, PS_JSONL.splitlines())}
    for c in INSPECT:
        name = c["Name"].lstrip("/")
        issues = []
        if ps[name]["State"] == "restarting" or c["RestartCount"] > 5:
            issues.append(f"重啟 {c['RestartCount']} 次，先看 docker logs --tail 50 {name}")
        if not c["Config"]["Healthcheck"]:
            issues.append("沒有 HEALTHCHECK")
        if c["Config"]["User"] in ("", "root", "0"):
            issues.append("以 root 執行")
        if c["HostConfig"]["Memory"] == 0:
            issues.append("未設定記憶體上限")
        if ps[name]["Image"].endswith(":latest"):
            issues.append("使用 :latest 標籤，版本不可追溯")
        if c["HostConfig"]["RestartPolicy"]["Name"] == "no":
            issues.append("重開機後不會自動啟動")
        yield name, issues


if __name__ == "__main__":
    for name, issues in findings():
        print(f"{name}: {'OK' if not issues else ''}")
        for i in issues:
            print(f"  - {i}")

執行方式：python example.py，只需 Python 3.10 以上，無第三方套件；不需要安裝 Docker

工程現場案例：Modbus 輪詢容器重啟 147 次，資料庫卻沒告警

某邊緣主機以 Docker 執行閘道器、輪詢程式與 InfluxDB。輪詢容器因設定檔錯誤持續崩潰，重啟政策是 always，所以 docker ps 偶爾看到它是 Up 狀態；但因為沒有健康檢查，監控只看到「容器存在」就判定正常，趨勢資料斷了三天才被發現。

範例把這類問題變成可定期執行的檢查：重啟次數過多、缺少 HEALTHCHECK、以 root 執行、沒有記憶體上限，以及使用無法追溯版本的 :latest 標籤。InfluxDB 的重啟政策為 no，主機重開機後不會自動啟動，也被一併列出。

  1. 每個容器都定義 HEALTHCHECK，檢查實際功能（例如最近一次成功輪詢的時間），而不只是程序存在。
  2. 映像標籤使用版本號或 digest，部署紀錄可追溯。
  3. Dockerfile 指定非 root 使用者，並設定記憶體上限。
  4. 把範例的檢查排入每日排程，結果送到既有的告警管道。

練習題與自我檢查

  1. Config.User 為空字串代表什麼？

    看解答

    代表映像沒有指定使用者，容器內程序預設以 root（UID 0）執行。即使在容器內，root 權限仍會擴大逃逸或掛載卷宗被誤寫的影響範圍。

  2. HostConfig.Memory 為 0 代表什麼？為什麼要設定上限？

    看解答

    0 表示沒有限制，容器可以用到主機全部記憶體。程式記憶體洩漏時會拖垮同一主機上的其他服務；設定上限後只會影響該容器，並由重啟政策處理。

  3. 若要把「重啟次數大於 5」改成「最近一小時內重啟超過 3 次」，需要哪些資料？

    看解答

    RestartCount 是累計值，無法得知時間分布。需要定期記錄 RestartCount 與時間，計算一小時內的差值；或讀取 docker events 的 die／start 事件。

  4. 為什麼 :latest 被列為問題？

    看解答

    :latest 只是一個會移動的標籤。重新拉取映像時可能取得不同版本，事故時無法確定現場跑的是哪一版。應使用明確版本或 image digest（@sha256:…）。
