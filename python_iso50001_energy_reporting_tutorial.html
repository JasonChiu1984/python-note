ISO 50001 能源管理系統報表：從能源審查到可驗證的改善

研究實作：架構、流程、圖表與 Python 證據

以工廠一個 30 天報告期的合成資料，算能源平衡、重大能源使用、能源績效指標與基線，並把目標差異、數據品質及責任寫進管理審查。這是可採用的教學報表，不是 ISO 規定的固定模板，也不代表認證判定。

3｜正規化：把基線放回報告期條件

本例假設基期資料已建立模型：預期月電量 = 20,000 kWh + 5 kWh／良品 × Q + 80 kWh／(°C·日) × CDD。報告期 Q=10,000、CDD=150，得 82,000 kWh。CDD 的基準溫度、天氣站及期間需固定。係數是合成設定，不是由這一點資料擬合或 ISO 指定值。

  • 相關變數會隨期間變動並影響績效，例如良品、冷房度日、機台工時。靜態因素相對穩定，例如產線規模、建築面積、主要設備與配置。產線擴建後先確認模型是否仍適用，再使用預先規定的基線調整規則，記錄舊／新版本和理由。
  • 模型要有代表性基期、留出或交叉驗證、誤差與殘差檢查、變數合理性和外推限制。比較前核對資料窗、誤差及量測不確定性。若未驗證、變數明顯外推或有效資料不足，標為「不可比／待補驗」而不是把未量測的改善寫成 0%。
  • 有模型時報告估計差額並附適用範圍、誤差與合適的不確定性區間；若配適與獨立性假設不成立，不應編造信賴區間或宣稱顯著改善。應區分基線平均反應的不確定性與單期實際結果的預測區間。

發布前：主電表與分表先對帳

同期間、同邊界且分表互斥時，主表為零但分表為正，或主表減分表小於 −1,000 kWh，就標為「不可比」。 此算例假設生產設備由同一主表涵蓋；即使主分表均報零、殘差為零，只要仍有良品產出，就先標為「不可比」。對帳一致和覆蓋率達標，不代表讀值合理。 原始用電強度仍可呈現為 0，但只能用來追查資料，不能當作能效已改善的證據。保留讀值、覆蓋率和殘差供查核；調整後基線、節能量及節能率留空，報表也不判定是否達標。1,000 kWh 是範例的可設定容差；「有產出、零用電」也是此算例的資料品質規則，兩者都不是 ISO 指定條件。

5｜結果誰簽、改善如何跟進

  1. 能源管理小組定邊界、能源類型、期間、記錄保留及資料互補原則；設備與生產端驗證表號、倍率、工時與良品定義。
  2. 能源管理者／量測驗證責任人管理 EnPI、EnB、相關變數與靜態因素、重新建立基線條件、資料覆蓋／誤差，以及報表來源的可追溯性。
  3. 管理審查回看未達 820 kWh 的原因，指定查核製程運轉、空壓洩漏或冰水控制等行動所需的資源、負責人、期限和驗證方法；節省只有完成比較與驗證後才可入帳。

上線證據至少能重建：設備邊界、時間、來源及倍率原件、能源平衡表、資料更正紀錄、模型輸入與版本、目標核准與行動追蹤。報表月份、溫度基準及資料單位需明標。

參考：ISO 50001:2018、Amd 1:2024、ISO 50006:2023（EnPI 與 EnB）、ISO 50015:2014（量測驗證）、美國能源部 50001 Ready Navigator。

這是合成 EnPI／EnB 證據示範，不是 ISO 規定的通用模型或認證結論。對同一邊界，在生產量變化時把基線換算到報告期條件，再談節能差值。

原帳面增加 30 kWh；合成模型正規化後是估計少用 50 kWh。兩個符號可以同時正確，差別在分母、比較條件與證據強度。

原帳面比較
基期產量 1,000 單位、實耗 1,000 kWh；報告期 1,200 單位、實耗 1,030 kWh。
驗證：直接比較會得到 +30 kWh，但兩期生產量不同。
調整後比較
給定假設 EnB = 600 + 0.4 × 產量，報告期基線 1,080 kWh；1,080 − 1,030 = 50 kWh。
驗證：50/1,080 = 4.63% 是相對調整後基線的估計，不是「用電量下降 4.63%」。
用兩筆不能訓練

延伸學習：實作、現場案例與自我檢查

前面各節說明報表欄位與正規化原則。本節用 12 個月資料完整走一次：建立以冷房度日為變數的基線、檢查模型品質、計算報告期正規化節能量，並用 CUSUM 找出改善生效的時間點。

可實跑範例：CDD 基線迴歸、正規化節能量與 CUSUM

使用 Python 3.10 起內建的 statistics.linear_regression() 與 correlation()，不需要 NumPy。基線期與報告期都是合成資料，報告期比基線期熱，4 月起冰水系統改善。

下載範例 example.py

"""以冷房度日（CDD）建立能源基線、計算正規化節能量與 CUSUM（標準函式庫）。

基線期 12 個月：月用電 kWh 對 CDD 做線性迴歸。報告期把實際 CDD 代入基線模型，
得到「如果沒有改善會用多少電」，再與實際用電相減。CUSUM 累計差值，斜率轉負代表改善開始生效。
"""
from statistics import correlation, fmean, linear_regression

BASE_CDD = [12, 18, 65, 120, 210, 300, 355, 350, 270, 160, 60, 20]
BASE_KWH = [181_000, 188_100, 213_000, 245_600, 296_800, 354_000,
            393_000, 386_900, 341_700, 272_100, 212_800, 187_800]
REPORT_CDD = [15, 22, 80, 135, 230, 320, 370, 365, 280, 170, 70, 25]
REPORT_KWH = [178_000, 191_000, 225_000, 239_100, 284_700, 335_000,
              366_000, 364_700, 319_700, 256_800, 202_700, 173_400]
IMPROVEMENT_MONTH = 4                     # 4 月起冰水主機改為變頻並調整冰水出水溫度


def fit():
    slope, intercept = linear_regression(BASE_CDD, BASE_KWH)
    predicted = [intercept + slope * x for x in BASE_CDD]
    residuals = [y - p for y, p in zip(BASE_KWH, predicted)]
    r2 = correlation(BASE_CDD, BASE_KWH) ** 2
    cv_rmse = (fmean(r * r for r in residuals) ** 0.5) / fmean(BASE_KWH)
    return slope, intercept, r2, cv_rmse


if __name__ == "__main__":
    slope, intercept, r2, cv = fit()
    print(f"基線模型：kWh = {intercept:,.0f} + {slope:,.1f} × CDD")
    print(f"R² = {r2:.3f}，CV(RMSE) = {cv:.1%}")
    cusum = 0.0
    total_expected = total_actual = 0.0
    print("月  CDD  預期 kWh   實際 kWh   差值      CUSUM")
    for m, (cdd, kwh) in enumerate(zip(REPORT_CDD, REPORT_KWH), start=1):
        expected = intercept + slope * cdd
        diff = kwh - expected
        cusum += diff
        total_expected += expected
        total_actual += kwh
        mark = " ← 改善上線" if m == IMPROVEMENT_MONTH else ""
        print(f"{m:>2} {cdd:>4} {expected:>10,.0f} {kwh:>10,} {diff:>+9,.0f} {cusum:>+10,.0f}{mark}")
    saved = total_expected - total_actual
    print(f"報告期正規化節能量：{saved:,.0f} kWh（{saved / total_expected:.1%}）")
    raw = sum(BASE_KWH) - sum(REPORT_KWH)
    print(f"若直接比較兩年用電：{raw:,.0f} kWh（{raw / sum(BASE_KWH):.1%}），報告期較熱，低估了改善")

工程現場案例：報告期天氣比較熱，直接比較用電低估了改善

範例中報告期 12 個月的 CDD 合計比基線期多約 7%。直接把兩年用電相減，節能只有 4.2%；把報告期的實際 CDD 代入基線模型後，正規化節能量是 6.6%，差了將近 9 萬度。若只看原始用電，改善專案的效益會被天氣吃掉。

CUSUM 欄位顯示 1～3 月差值在正負之間擺動，累計值接近零；4 月起每月都明顯為負，斜率轉折正好對應冰水主機改為變頻的時間。這種圖比單一年度百分比更能說服稽核員：改善確實在某個時間點開始生效，而不是天氣或量測誤差造成。

  1. 基線期至少取 12 個月，涵蓋一個完整季節循環，並確認期間沒有重大設備增減。
  2. 變數選擇要有物理意義：空調用電用 CDD，產線用電用產量，兩者都有時可做多元迴歸。
  3. 檢查 R² 與 CV(RMSE)；殘差若有明顯季節型態，代表少了變數或平衡點溫度選錯。
  4. 報告期每月更新 CUSUM 圖，把改善措施的上線日期標上去，作為能源績效指標（EnPI）改善的證據。

練習題與自我檢查

  1. 把 IMPROVEMENT_MONTH 之前三個月的差值加總，結果接近多少？這代表什麼？

    看解答

    −5,811 + 2,945 + 1,780 = −1,086 kWh，接近零。代表改善前的實際用電與基線模型預測一致，模型沒有系統性偏差，之後的負差值才能歸因於改善措施。

  2. CV(RMSE) 是什麼？為什麼不能只看 R²？

    看解答

    CV(RMSE) 是殘差均方根除以平均用電，表示模型預測誤差占用電的比例。R² 只說明變數解釋了多少變異，若用電本身變化不大，R² 可能很低但誤差很小；反之 R² 高也可能誤差很大。兩者要一起看。

  3. 若報告期中途新增一台 200 kW 的伺服器機櫃，CUSUM 會出現什麼現象？應該怎麼處理？

    看解答

    新增日期之後 CUSUM 斜率會轉正，看起來像改善失效。這是靜態因子變化，應做非例行調整：估算新增負載的用電並從實際值扣除，或在基線模型加入對應變數，並在報告中記錄調整依據。

  4. 修改程式，同時印出每月預期值的 95% 信賴區間需要哪些資料？

    看解答

    需要基線期殘差的標準誤、樣本數與 CDD 的平均與離均差平方和。可用 statistics.stdev() 計算殘差標準差，再依簡單迴歸的預測區間公式計算；或改用 statsmodels 取得完整統計量。
