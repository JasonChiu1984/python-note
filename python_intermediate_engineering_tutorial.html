中級學習路線

中級不是背更多語法，而是學會選型：哪段程式應該拆成 service，哪種工作適合 thread，何時要 process，打包後為什麼在使用者電腦失敗。

學完會具備

能設計分層 Python 專案、寫可測試 service、判斷 I/O-bound 與 CPU-bound、使用 PyInstaller 交付工具。

不假裝簡單

GIL、cancel、timeout、hidden imports、assets path 都會用視覺流程與 step 卡拆解，不只給一段命令。

大型專案架構圖

專案長大後，穩定性來自邊界。CLI/API 只處理輸入輸出，service 管規則，repository 管資料來源，domain model 表達核心概念。

並發與平行運算決策圖

不要先問「哪個比較快」，先問工作在等什麼。等網路或檔案，多半是 concurrency；燒 CPU，才需要真正 parallelism。

notes-cli 工程版 Capstone

同一個專案線貫穿 typing、DI、logging、pytest 與打包。目標不是記住片段，而是知道一個可交付 CLI 應該長什麼樣。

交付流程

1. Domain先定義 Note 與錯誤類型。
2. Service驗證 title/body，依賴 Repo Protocol。
3. CLI只處理 argv、輸出與 exit code。
4. Testsunit test service，CLI test 驗證指令。
5. Logs邊界記錄錯誤，訊息給人看。
6. DistPyInstaller onedir 後做 smoke test。

Production notes-cli 一條到底

資深工程師不是只把功能寫出來，而是把需求、決策、邊界、測試、CI、release 與 rollback 串成可交付流程。

1. 需求與 ADR

項目教材範例資深工程判斷
需求notes-cli create/list/search/export先定 CLI UX、exit code、資料位置、錯誤訊息，而不是先寫檔案。
SLOlist 10000 筆在 1 秒內回應讓效能驗收可量測，避免「感覺很慢」。
ADRv1 用 JSON repository，v2 可遷移 SQLite記錄選擇原因、替代方案、後續轉換成本。
把「使用者能建立、搜尋、匯出 note」寫成命令與預期輸出，後面每層設計都回到這個驗收。
JSON 容易交付與除錯，但多程序寫入和查詢效能有限；ADR 讓日後換 SQLite 時有脈絡。

2. 邊界、設定、交付

notes_cli/
  cli.py              # argv, output, exit code
  services.py         # use cases
  repositories.py     # Repo Protocol + JSON implementation
  config.py           # default < config file < env
  errors.py           # UserError / DataCorruption / InfraError
預設值給本機可跑；config file 給使用者調整；環境變數覆寫 CI/部署設定；secret 不寫進 repository。
release 前跑 smoke test；發現資料 migration 失敗時，保留舊版執行檔與備份資料，rollback 不是口號。

測試實戰補強

測試要能回答三個問題：規則壞了嗎、外部邊界壞了嗎、CI 失敗時應該改哪一層。

fixtures + parametrize + fake repo

import pytest

class FakeRepo:
    def __init__(self):
        self.items = []
    def save(self, note):
        self.items.append(note)
        return note

@pytest.fixture
def service():
    return NoteService(repo=FakeRepo())

@pytest.mark.parametrize("title", ["", "   "])
def test_title_required(service, title):
    with pytest.raises(UserInputError):
        service.create(title, "body")
service 建立方式集中在 fixture，重構建構子時只改一處。
空字串、空白、過長 title 都是同一條規則，用參數化讓案例增加但測試結構不膨脹。

Repository 硬化：從 JSON demo 到可維運資料層

JSON repository 很適合中級教材，但 production 思維要補上鎖、損毀復原、schema version 與 migration。

atomic write + lock + corrupt recovery

def save_document(path: Path, data: dict) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    backup = path.with_suffix(".bak")
    tmp = path.with_suffix(".tmp")
    if path.exists():
        backup.write_bytes(path.read_bytes())
    tmp.write_text(json.dumps(data, ensure_ascii=False), encoding="utf-8")
    tmp.replace(path)

def load_document(path: Path) -> dict:
    try:
        return json.loads(path.read_text(encoding="utf-8"))
    except json.JSONDecodeError as exc:
        raise DataCorruptionError(path) from exc
atomic write 避免半寫；backup 讓 corrupt JSON 有復原路徑；多程序寫入時再加 file lock。
JSONDecodeError 要轉成 DataCorruptionError，CLI 才能提示資料檔路徑與修復方式。

schema version + migration

def migrate(doc: dict) -> dict:
    version = doc.get("schema_version", 1)
    if version == 1:
        for item in doc["notes"]:
            item.setdefault("tags", [])
        doc["schema_version"] = 2
    if doc["schema_version"] != 2:
        raise UnsupportedSchemaError(doc["schema_version"])
    return doc
變更風險驗收
新增 tags 欄位舊資料沒有 keyv1 fixture 可自動升級到 v2。
改時間格式排序與搜尋壞掉migration 前後列表順序一致。
不支援版本靜默讀錯資料明確噴 UnsupportedSchemaError。

並發實戰：Worker lifecycle 與失敗傳播

真正專案裡的 worker 不只要會跑，還要能限流、回報例外、收到停止訊號並乾淨 shutdown。

Queue backpressure + sentinel shutdown

from queue import Queue
from threading import Thread

STOP = object()
jobs = Queue(maxsize=100)

def worker():
    while True:
        item = jobs.get()
        try:
            if item is STOP:
                return
            process(item)
        finally:
            jobs.task_done()

t = Thread(target=worker)
t.start()
jobs.put(STOP)
jobs.join()
t.join(timeout=5)
Queue 無上限時 producer 可以把記憶體塞爆；maxsize 讓上游自然慢下來。
STOP 是明確停止訊號，比 daemon thread 直接消失更容易清理資源。

exception propagation + timeout

from concurrent.futures import ThreadPoolExecutor, as_completed

with ThreadPoolExecutor(max_workers=4) as pool:
    futures = [pool.submit(upload, item) for item in items]
    for future in as_completed(futures, timeout=30):
        try:
            future.result()
        except UploadError as exc:
            logger.exception("upload failed", exc_info=exc)
            raise
問題做法驗收訊號
worker 內例外消失future.result() 在主 thread 收斂CI 測到失敗會讓 command exit 1。
外部服務卡住future timeout + HTTP timeoutlog 有 timeout 與 item id。
ProcessPool 變慢量 pickle 資料大小與耗時benchmark 表格證明加速大於序列化成本。

PyInstaller 跨平台打包檢查表

打包不是只跑一行命令。真正會出問題的是 assets path、hidden imports、平台差異、設定檔位置與使用者權限。

建議命令

python -m pip install pyinstaller
pyinstaller --name notes-cli --onedir src/notes_app/cli.py
pyinstaller --name notes-cli --onefile src/notes_app/cli.py

交付前必查

dist/notes-cli/notes-cli --version
dist/notes-cli/notes-cli create "first note"
dist/notes-cli/notes-cli list
問題症狀修正方式驗收
hidden imports打包後才出現 ModuleNotFoundError補 `--hidden-import` 或 spec hiddenimports在乾淨環境跑 `--help` 和核心指令
assets path開發環境讀得到，dist 裡讀不到用 `--add-data` 並在 runtime 判斷 `sys._MEIPASS`dist 內讀設定檔與模板成功
onefile 啟動慢每次啟動要解壓縮內部工具優先 onedir，確定需求才 onefile比較啟動時間與交付便利性
跨平台macOS 產物不能直接給 Windows在目標平台各自打包Windows/macOS/Linux 分別 smoke test

spec 與 assets helper

import sys
from pathlib import Path

def resource_path(name: str) -> Path:
    base = Path(getattr(sys, "_MEIPASS", Path(__file__).parent))
    return base / name

常用打包命令

pyinstaller --name notes-cli --onedir \
  --add-data "templates:templates" \
  --hidden-import notes_cli.plugins.json_export \
  src/notes_cli/cli.py

Observability / Security / Release Checklist

中級往資深走，差別在交付後能不能看見問題、保護機密、驗證供應鏈，並在出事時演練 rollback。

Structured logs / metrics

logger.info(
    "note_created",
    extra={"note_id": note.id, "command": "create", "duration_ms": 18},
)

log 要有事件名、id、耗時、command；metrics 看成功率與延遲；SLO 定義什麼叫壞了。

Secrets / permission boundary

api_token = os.environ.get("NOTES_API_TOKEN")
if not api_token:
    raise ConfigError("NOTES_API_TOKEN required")

secret 從環境或平台 secret store 進來；設定檔可記路徑與模式，不存 token；錯誤訊息不能印出 secret 值。

SBOM / dependency scanning

python -m pip install pip-audit cyclonedx-bom
pip-audit
cyclonedx-py environment -o sbom.json

release artifact 應能回答用了哪些 dependency、是否有已知 CVE、產物從哪個 commit 打出來。

Release / rollback drill

notes --version
notes doctor
notes migrate --dry-run
notes migrate --backup
notes rollback --to backup-20260511.json

每次 release 都要有 smoke test、資料備份、回復命令與負責人；rollback 要演練，不等事故當天才想。

檢查面最低門檻資深工程驗收
Observability錯誤有 log每個 command 有 structured event、duration、error code、correlation id。
Securitysecret 不進 gitsecret rotation、最小權限、錯誤訊息遮罩、dependency scan 進 CI。
Release打包成功乾淨環境安裝、smoke test、SBOM、版本與 commit 對得上。
Rollback保留舊檔資料備份、migration dry-run、回復命令與演練紀錄。

CI 失敗判讀訓練

資深工程師不只會加 CI，還要能從失敗 log 判斷壞在哪一層：格式、型別、測試、coverage、打包或環境。

失敗案例 1：lint / type gate

ruff check src tests
F401 `json` imported but unused

mypy src
src/services.py:21: error:
Argument 1 to "save" has incompatible type "dict"; expected "Note"
F401 是格式/靜態清理問題；mypy 是契約問題，代表 service 和 repository 對資料型別看法不一致。
刪掉未用 import；再決定 repository.save 應收 Note 還是 dict，不要用 type ignore 掩蓋設計不一致。

失敗案例 2：測試 / coverage gate

pytest
FAILED tests/test_services.py::test_title_required
E   Failed: DID NOT RAISE ValueError

coverage report --fail-under=85
TOTAL 83%
這不是 CI 環境問題，是 service 規則退化：空 title 沒有被擋下。
先修 service validation，再補參數化測試；coverage 下降則代表新分支缺測，應補測而不是降門檻。

失敗案例 3：package / smoke test

python -m build
Successfully built notes-0.3.0.whl

notes --version
ModuleNotFoundError: No module named 'notes_app.templates'
wheel build 成功只代表產物生成，不代表安裝後所有 package data 都在。
確認 package-data / MANIFEST 設定，並保留安裝後 smoke test：pip install dist/*.whl && notes --version。
