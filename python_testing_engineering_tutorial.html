策略UnitIntegration品質CI
Strategy

先決定風險，再決定測試形狀

資深工程師不追求測試數量，而是讓高風險行為有快速、穩定、可診斷的回饋。

Fixtures

測試資料要可讀、可重跑、可定位

穩定測試從可控資料、時間、檔案與外部依賴開始。

Unit Tests

Unit test 鎖住業務規則與錯誤路徑

好的 unit test 應該快、窄、對題，並且能指出是哪個規則壞掉。

Integration

整合測試驗證邊界，不取代 unit test

資料庫、檔案、API、message queue 都是邊界；測試要證明邊界契約可用。

Quality

測試品質要能被量測與改進

coverage 只是一個訊號，還要看 assertion、mutation thinking、flaky triage 與缺口紀錄。

CI Gate

品質閘門要快速、清楚、可重現

CI 應把 compile、unit、integration、smoke 與 release evidence 串成可追蹤的交付流程。
